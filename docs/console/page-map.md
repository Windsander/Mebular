# 控制台页面地图（哪个设置在哪个 Tab）

## 首次上手（引导态：建新 / 加入）

家目录**真正为空**（无 `config.json`、无 `user-master-key.json`、无 `<storagePath>.identity.json`）时，`mebular serve` **不自举 root**，而是进入**引导态**：只服务 `/healthz` + `/console` 引导页 + `/app/provision/*`（其余 admin API 一律 `409 provision_required`），且**仅 loopback**。

引导页两个入口（全程 GUI，不需要命令行）：

| 入口 | 动作 | 结果 |
|---|---|---|
| **建新忆云** | `POST /app/provision/create`（设备名可改；填名字即可，带 `device-` 前缀也不会重复拼接——见「设备名归一化」） | 生成 root 主密钥 + 写 `config.json`（`joinService.enabled=true`、`mcp.http` 回环、`network` 默认）→ **自动重启** → 正常态（「＋ 邀请设备」可用） |
| **加入已有忆云** | `POST /app/provision/join`（粘贴邀请令牌；复用 fleet 令牌验签/兑换） | 取回**委派证书链**（delegated，**无主私钥**）+ 主公钥（仅公钥）+ inviter hints 入 `<home>/net/peers.json` → **自动重启** → 正常态（授权分区 = 令牌分区） |

错误可读：令牌过期 / 签名不符 / 端点不可达 / 已使用 → 页面直接显示原因；重复调 provision → `409`；失败**不残留半成品**（仍可重试）。未以服务方式运行时给出手动重启命令（`nohup mebular serve …`）。

**设备名归一化（F-ONB-1）**：设备名先 sanitize，再去掉**所有重复的 `device-` 前缀**，最后拼一次前缀 —— 输入 `TestB` / `device-TestB` / `device-device-TestB` 都得到 `device-TestB`；空名 → `device-local`。两个输入框带「将使用 deviceId: …」实时预览。

设置弹层分五个 Tab：**常用**（默认开，只读状态 + 重启向导 / 邀请设备入口）· **安全**（S3 安全卡）· **AI 助手** · **MCP 接入**（六项危险配置）· **高级**（常驻服务卡 + 忆云连接/同步字段 + 底部「诊断与恢复」只读折叠）；只读信息统一在**「关于本机」**面板（点顶栏状态徽章 `本机 · <deviceId>` 打开）。
IA 单一真源在 [`packages/console/settings-ia.js`](../../packages/console/settings-ia.js)，E1（`verify-console.mjs`）以迁移表驱动断言「不丢项：每项有且仅有唯一去处」。

**术语**：用户可见文案中表示本机所处共享网络的「网络 / Mebular」统一为「**忆云**」；产品名「Mebular 控制台」不变，「记忆域 / 记忆」不变。

E1 前后对比截图：[`screens/e1/`](screens/e1/)。

**顶栏（E1）**：只保留「＋ 邀请设备」；「连接已有地址」已撤下——它实际是**网内传输修复**，入口移到「高级 → 诊断与恢复 → 手动连接已知设备…」与设备卡「连不上？手动连接…」（不改变入网信任、不签发授权）。

**弹层交互（轮 C，六处弹层共用）**：

- **点空白**（backdrop `target === currentTarget`）与 **Esc** 关闭**最上层**弹层；一处实现全弹层受益。
- 危险语义：确认弹层的 Esc / 点空白 = **取消**（resolve false，永不等于确认）；首次上手（建新/加入）不可关闭；手动连接向导在「连接中」不可关闭。
- 背板固定不滚（`.modal { overflow: hidden }`）；滚动收进 `.modal-box`（`max-height: calc(100vh - 48px); overflow-y: auto`），六处弹层一致。

**呈现分级（轮 C）**：常显 = 名称 + 控件 + 状态（三元组相等时收成一行「生效中」）；帮助 / 机制解释 / 警告墙收进「详情」折叠；**异常自动出现**（已配置≠实际、未生效原因、待重启）。**安全卡（S3）**独占「安全」Tab 的 `#settings-security-slot`：三档状态 + 升级/降级、动态码种子、恢复码、待批准、拒绝原因；卡尾低权重「降级…」。

## 常用（只读状态 + 两个入口）

E1 三卡迁出后，常用不再承载可编辑字段：

- 常驻运行状态（`#settings-resident`：守护/临时/未运行 + 对应动作）。
- 重启向导（桌面壳内可用；重新走首次设置，不动已有配置）。
- 只读状态：P2P、邀请服务、安全等级；一个「＋ 邀请设备」入口（未启用邀请服务时由弹层就地一键启用）。
- 其余可编辑配置在「高级」与「MCP 接入」；安全动作在「安全」。

## 安全（S3 · 独立 Tab）

### 安全等级卡（只读状态 + 显式动作）

| 档 | 展示与门槛（按 SPEC §1.4 / §2.8 冻结文案） | 改道 |
|---|---|---|
| **低（默认）** | 无额外门槛（信任链仍在） | 邀请 / 移出维持现状；移出留在「更多操作」折叠内 |
| **中 · 动态码（防顺手）** | 敏感动作要 6 位动态码；**挡手不挡钥匙**（不防设备被窃） | 邀请先输码；移出提级为一等危险动作、输码后执行 |
| **高 · 设备会签** | 另一台已准入设备核对**配对号**批准；防设备被窃伪造 | 邀请/移出先出配对号并等待批准，批准后自动出令牌/执行；降级也要会签 |

- 动态码种子：显示 fingerprint；导入走分组文本/otpauth；显示种子前必须再输一次本机码（root 可生成共享种子）。种子不进事件/日志/同步。
- 恢复码：升到高档时强制生成并一次性展示（须回执「我已抄写」）；安全卡显示 keyId 前 8 与最近使用；「轮换恢复码」用旧码换新码，新码同样只显示一次。
- 待批准入口在安全卡顶部 + 星图「需要注意」；批准按钮文案「配对号一致，批准」，拒绝即时写入。验收拒绝（`rejections`）与拒绝原因在卡内与审计抬头可见。移出后在设备卡与审计显示状态「已移出」。
- 顶栏只读徽章 `🛡 安全：低/中/高`（点击 = 打开「安全」Tab）；桌面托盘同样有一行只读「安全等级」，点击只打开控制台，不做壳内写操作。
- 前后对比截图（活体 / mock / 窄屏 / 审计）：[`screens/security-tiers/`](screens/security-tiers/)。

## MCP 接入（独立 Tab，危险项）

`mcp.http.port` · `mcp.http.auth` · `mcp.http.host` · `mcp.http.tls` · `mcp.http.tlsKey` · `mcp.http.tlsCert` 六项合并为一张危险卡：改端口/鉴权/监听/TLS 会立即影响控制台自身访问方式。卡片保留改鉴权/端口的后果与自救恢复说明（bearer 可粘贴 token 自救；oauth 需 env secret，否则只能改回配置）。风险说明默认折叠在「这是什么」；命中自锁项时关键警告会进入二次确认弹层。

**邀请面板（E1 单屏 + C7 扫码即通）**：打开即见**令牌 + 二维码 + 复制**（二维码内容=令牌文本，服务端渲染 SVG，可选依赖缺省时降级为文本提示），必要安全提示一行；join 端点、`fleet join` 命令、兑换语义（作用域=令牌记忆域，默认 24h 到期自动撤销）、重新生成全部收「详情」。若加入服务未启用：弹层内「一键启用并继续」——走既有配置写路径、提示将重启守护，恢复后自动签发令牌（不再指路「设置 → 常用」）。

## 高级（常驻服务卡 + 忆云连接/同步字段 + 诊断）

| 分组 | 字段 |
|---|---|
| 常驻服务（卡片） | `joinService.enabled` · `joinService.bind` · `joinService.port` |
| 忆云连接 | `network.enabled` · `network.libp2p.listen` |
| 反熵与快照 | `sync.antiEntropy.enabled` |
| 对端与签发者 | `sync.peerWhitelist` · `sync.policyIssuers` |
| 语义召回（可选依赖） | `semantic.enabled` |

> **E1 IA 变更**：原「常用」三卡已迁出——连接两项入高级字段组、joinService 三项聚成「常驻服务」卡、MCP 六项独立成 Tab；「声明本机为引导签发者」按钮从 GUI 移除（服务端 `/admin/api/policy-issuers` 端点保留不动；设备卡/审计的引导签发者只读展示保留）。

> **暴露面收敛（B + 轮 C）**：反熵间隔/抖动、快照阈值、召回阈值属自动策略 → `internal`（GUI 不渲染，需手工编辑 `config.json`）；`network.libp2p.relayServers` 为只读（自动 relay 池 = config seeds ∪ 令牌 hints ∪ 地址簿学习，见「关于本机 · 只读状态」）；`network.libp2p.relayUnlimited` 转为 internal。字段元数据由服务端单一真源 `packages/mcp/src/config-schema.mjs` 驱动（`/admin/api/settings.configSchema`），控制台不再重复声明。

## 诊断与恢复（高级 Tab 底部只读折叠）

- **连接排障（E1）**：「手动连接已知设备…」——用于一台已加入同一忆云的设备一直未连接时手动粘贴 multiaddr 建立传输；只修复连接，不改变入网信任、不签发授权。设备卡离线时也有「连不上？手动连接…」同款入口。
- 版本与服务状态：`/healthz` 的 name/version/status、MCP 监听、TLS、控制台写入开关、P2P。
- 完整配置：`config.json` 原文（复制 / 下载）。
- **最近一次应用结果**：状态（已生效 / 重启中 / 未按预期生效 / 已回滚）、时间、字段清单、原因、备份路径、逐项校验。
- **恢复指引**：auth 误切 · host 误设 · 缺证书 · 控制台打不开（含 `MCP_INSECURE_CONFIG` / `MCP_STORAGE_LOCKED` 判读）。

## 关于本机（顶栏徽章入口，只读）

身份与存储 · **配置文件与写盘备份**（`config.json` 路径 + `.bak`，写盘路径从常页面收编到此）· **同步节奏** · **只读状态（自动推导）**（relay 池 / LAN 发现 / 桥 / 打洞 / 广播 / join 端点 / TLS / 邀请授权 TTL，均带「未生效原因」）· 运行状态（含 **地址广播**：`full/relay-only/off` 档位 · 已发布 · 已采用 · 忽略原因，C5）· 签发者状态 · **对端连接路径**（C2：每个键的 `kind/address/最近切换/lastError/候选数`，只读）· 舰队摘要 · 能力清单（27 工具 = 记忆 11 + 任务 16；与 MCP 入口同源）。

> 星图设备卡同样有一行只读「当前路径」（`direct`/`lan`/`relay` + 地址 + 起始时间；未连接时显示 `lastError`）。数据来自 core 候选地址簿（`settings.peers.paths`），只展示不改变授权。

> **同步节奏**（`sync.autoSync` / `sync.pushOnWrite`）已从 GUI 编辑面移除——默认常开、不建议关闭；需要改动请手工编辑 `config.json`。该处只读展示「已配置 vs 实际」双值。
>
> 所有可运行时项（host/port/auth/tls、listen/relay、semantic、join 等）在编辑面给**三元组**「已配置 X / 实际 Y / 未生效原因」，原因由服务端计算（`/admin/api/settings.effective`）。

## 改动即生效（无「保存 / 撤销」按钮）

「高级」与「MCP 接入」的字段**改动即写入**（勾选/选择立即、文本/数字失焦即写；写入前仍会做 host/auth/tls 组合校验）；保存按钮已从用户路径消失。

**生效（G）**：

- 改动含需重启项 → 写入后**自动重启**（服务托管时）并轮询等待恢复，或给出前台手动命令；全为即时（热路径）项 → 就地生效，不重启。
- 恢复后显示 **绿色「已生效（字段清单）」**（逐字段生效校验通过）或 **红色「未按预期生效」/「已回滚」**。
- **自锁防护**：改动命中 `mcp.http.auth` / `mcp.http.host` / `mcp.http.tls` 时先品牌确认卡二次确认（重启后控制台可能不可达；失联请手工编辑 `config.json` 改回），未确认则返回 `needsConfirmation` 且不写盘、不重启。
- **回滚兜底**：新配置启动失败（如 join 端口被占）→ 自动用 `config.json.bak` 回滚并重启旧实例；原因写入诊断折叠「最近一次应用结果」。
- 未以服务方式运行（前台 nohup）→ 返回手动命令 + 备份路径（待重启横幅保留，可「一键重启」或复制命令）。
