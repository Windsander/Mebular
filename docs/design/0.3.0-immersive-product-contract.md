## 0. 一页结论

1. **只有两种模式：轻量 MCP / 沉浸式。** 沉浸式开启即按域网络采集；不存在 `capture=local/off`，不存在首次 capture 授权，不存在“本机采集 / 云端采集”二选一。
2. **采集归属由 Agent ID + 域决定。** 同一忆云内的认证设备可按域订阅；`user` / `agent:<id>` / `task:<id>` / `default` 的归属规则不变。
3. **详情是域内共享记忆。** `DetailRecord` / `RawChunk` 写入现有图、事件日志，随现有同步跨设备；本机只保留 staging / cache / outbox，不是权威副本。
4. **跨设备详情可展开。** 只要在保留期内且未删除，域内认证设备都能读到原文/切片；只有过期、删除、配额淘汰或未订阅才诚实降级。
5. **用户 UI 只增加两项。** 设置里的「记忆模式（轻量 MCP / 沉浸式）」；高级里的「模型来源」。sidecar 启停、host 适配器、token、discovery、域订阅、采集策略全部黑盒自动。
6. **ContextCheckpoint 是结构化任务连续性对象。** 不是 compaction summary；始终上云到 `task:<taskId>` / `task:<threadId>` / `default`；revision + lease；参与者按域订阅；宿主在 compaction / task 变更时写入；sidecar 在新 turn / 压缩后主动读取并参与召回。
7. **DSH 第一优先级。** Hermes / OpenCode / OpenChamber 随后；OpenChamber 原生 memory 只读共存。
8. **29 个公共 MCP 工具不变。** 详情与 checkpoint 只走内部 capability API 和 sidecar host API，不注册为公共工具。

## 1. 模式开关

### 1.1 两个模式

| 模式 | 产品名 | MCP `memoryRuntime.enabled` | sidecar | 采集 | 自动召回 | 普通 Agent 的 `memory_*` 工具 |
|---|---|---|---|---|---|---|
| **轻量 MCP** | 轻量 MCP | `false`（默认） | 不启动、不建目录、不监听端口 | 不采集 | 无 | 保留（0.2 语义） |
| **沉浸式** | 沉浸式 | `true` | 自动启动、自动发现、自动 token | 按域采集 | 每个新人类 turn 最多一次 | 隐藏（治理白名单除外） |

**唯一真值**：

- 模式由 MCP 配置 `memoryRuntime.enabled` 拥有；sidecar 的 `GET /mode` 只读。
- host 适配器只读 sidecar discovery 的 `mode` / `state` / `capabilities`，不得自己保存模式。
- 不再有 host 级 `memoryRuntime.enabled`、`capture`、`rawCapture`、`localCapture` 作为产品开关；这些字段在 0.3 实现中删除或忽略。

### 1.2 模式切换序列

**轻量 → 沉浸式**：

1. 用户在设置里选择「沉浸式」。这是唯一一次产品选择；界面只说明“开启后会按记忆域采集并同步详情到本忆云的认证设备”，**不是** capture 授权，不再弹第二个隐私开关。
2. Console 写 MCP 配置 `memoryRuntime.enabled=true`（原子写 + `.bak`）。
3. MCP daemon 挂载 `/internal/memory/v1`，生成 capability token；异步启动 sidecar。
4. sidecar 读取 discovery / MCP 地址，完成 `/version` 握手，生成 host token，写 `<home>/memory-runtime.json`。
5. MCP 把 `mode=immersive`、`capabilities.details=true` 暴露给 Console / host 发现。
6. host 适配器（DSH 优先）自动发现 sidecar，开始 ingest / recall / checkpoint；不需要逐宿主配置。
7. 任一步失败：模式仍为 `immersive`，sidecar 状态 `degraded` / `failed`；对话继续，只是不注入记忆，不阻塞 MCP。

**沉浸式 → 轻量**：

1. Console 写 `memoryRuntime.enabled=false`。
2. MCP 撤销 capability token，停止 sidecar；sidecar flush outbox 后退出，删除 discovery / host token。
3. host 适配器看到 discovery 消失或 `mode=mcp`，停止 ingest / recall / checkpoint；不要求用户改任何宿主配置。
4. 已沉降记忆、详情、checkpoint 保留；本地 staging / cache 按保留策略清理，不删除图数据。
5. 29 个公共工具立即恢复 0.2 行为；不需要重启 MCP。

### 1.3 黑盒职责

| 组件 | 自动负责 | 用户不需要做 |
|---|---|---|
| MCP daemon | 挂载/卸载 capability API、生成/撤销 token、启动/停止 sidecar、暴露状态 | 不需要配端口、token、discovery |
| sidecar | 发现 MCP、握手、host token、域策略、采集、抽取、召回、checkpoint、outbox、retention | 不需要逐宿主配置 |
| host 适配器 | 发现 sidecar、跟随模式、采集人类 turn / 工具结果 / compaction、注入、展开详情 | 不需要选择 capture、域、token |
| Console | 只做模式开关、模型来源、状态展示、治理（为什么想起 / 纠正 / 删除） | 不需要理解 sidecar / host / 域订阅 |
| 域订阅 | 按已连接 Agent + 当前任务域自动生成 sidecar `policy.json`；物理订阅仍走现有 `sync.namespaces`；其他 Agent 域是否自动只读订阅见 O4 | 不需要逐域订阅 |

### 1.4 用户 UI：只增加两项

| 位置 | 控件 | 选项 / 行为 | 明确不出现 |
|---|---|---|---|
| 设置 → 记忆 | **记忆模式** | `轻量 MCP` / `沉浸式`；切换即执行 §1.2 | capture、raw、本机/云端二选一、首次授权 |
| 设置 → 高级 | **模型来源** | `heuristic`（默认）/ `local` / `host` / `api` / `auto` | endpoint、key、token、host 凭据 |
| 设置 → 诊断（只读） | 运行状态 | 模式、sidecar 状态、降级原因、详情配额 | 启停按钮、逐宿主开关、域订阅编辑 |

规则：

- 普通用户界面不得出现 `capture`、`local capture`、`raw capture`、`sidecar token`、`discovery`、`host adapter`、`namespace subscription` 等实现词。
- 高级里的模型来源是唯一第二个产品增量；模型密钥仍只存 `keyRef`，不在 UI 明文显示。
- Console 的记忆页、为什么想起、纠正、归档、删除保持不变；详情在记忆详情中以“原文/切片”展开，默认折叠。
- 任何“首次开启需要授权本机采集”的文案删除；只保留模式说明和失败开放说明。

### 1.5 模型来源

| 来源 | 默认 | 运行位置 | 失败行为 |
|---|---|---|---|
| `heuristic` | **是** | sidecar 进程内 | 只可能是代码 bug；返回 500 |
| `local` | 否 | sidecar + 本机 llama-server | 回退 heuristic，`degraded=true` |
| `host` | 否 | 宿主模型，宿主自然提交候选 | 无候选 → 202 pending；不偷偷换模型 |
| `api` | 否 | 显式 OpenAI-compatible endpoint | 超时/5xx → heuristic；不换供应商 |
| `auto` | 否 | host 候选可用 → local 已安装 → api 已允许 → heuristic | 不隐式联网 |

- 模型来源按设备保存；记忆数据按忆云共享；provenance 只记录来源，不让其他设备重放模型。
- 2026-10-30 冻结：0.3 默认仍是 heuristic；local Qwen 资产未发布前，不把“本地模型”写成默认体验。
- 模型来源切换不需要重启宿主；sidecar 热更新模型引擎，失败只降级。

### 1.6 宿主优先级与共存

| 顺序 | 宿主 | 接入方式 | 原生记忆 |
|---|---|---|---|
| **1** | DSH | `@mebular/dsh-plugin` 自动发现；source-tagged context message | 不导入/不替换 |
| 2 | Hermes | `MemoryProvider`；prefetch / sync_turn / on_pre_compress | `MEMORY.md` / `USER.md` 只读共存，不双写 |
| 3 | OpenCode / OpenChamber | `@mebular/opencode-plugin`；`context` hook request-only | OpenChamber 原生 memory 共存：不读条目、不导入、不替换、不双写 |

- “只读共存”指 Mebular 不读取、不导入、不镜像、不替换、不双写宿主原生记忆；不要求用户关闭原生记忆。
- DSH 是 0.3 验收第一优先级；Hermes / OpenCode / OpenChamber 可以随后补齐，但契约与测试必须同批冻结。
- host 适配器不再要求用户设置 `memoryRuntime.enabled`、`capture`、`runtimeUrl`、`token`；这些只保留为排障覆盖（环境变量 / 显式测试配置），不是产品路径。

## 2. 域内详情（DetailRecord / RawChunk）

### 2.1 对象定义

**DetailRecord 是一个域内持久对象**，写入现有图 + 事件日志，随现有同步跨设备。它不是第二套存储，也不是公共 MemoryRecord；默认不出现在 `/query`、`/search`、`/history`、`/profile`、`/skills`、`/graph`、29 个公共工具和 Console 记忆列表。

`RawChunk` 是 `DetailRecord` 的子类型：`detailKind='raw_chunk'`，表示一段原始对话/工具输出/文档切片。

```jsonc
{
  "id": "01J...",
  "type": "detail_record",
  "namespace": "agent:dsh",              // domain = namespace
  "metadata": {
    "internal": true,
    "internalObject": {
      "schema": 1,
      "kind": "detail_record",
      "detailKind": "raw_chunk",         // raw_chunk | message | tool_output | document_slice
      "threadId": "th_...",
      "recordIds": ["01J..."],
      "contentHash": "sha256:...",
      "expiresAt": 1732592000000
    },
    "provenance": {
      "source": "runtime",
      "writerType": "agent",
      "writerId": "dsh",
      "extractor": "host",
      "model": "host-provided",
      "version": "0.3.0",
      "deviceId": "device-...",
      "hostId": "h_...",
      "threadId": "th_...",
      "agentId": "dsh",
      "agentName": "DSH",
      "messageIds": ["m1"],
      "confirmation": "none",
      "at": 1730000000000
    }
  },
  "content": {
    "detailKind": "raw_chunk",
    "text": "我默认用深色主题。",
    "mime": "text/plain",
    "role": "user",                      // user | assistant | system | tool
    "messageId": "m1",
    "chunkIndex": 0,
    "turn": 3,
    "threadId": "th_...",
    "recordIds": ["01J..."],
    "contentHash": "sha256:...",
    "redaction": { "applied": false, "rules": [] },
    "retentionClass": "conversation",    // conversation | tool_output | document_slice | pinned
    "expiresAt": 1732592000000
  },
  "createdAt": 1730000000000,
  "updatedAt": 1730000000000
}
```

字段约束：

| 字段 | 必填 | 说明 |
|---|---|---|
| `type` | 是 | 固定 `detail_record`；不新增第二套节点类型。 |
| `namespace` / `domain` | 是 | 必须等于所链接 MemoryRecord / ContextCheckpoint 的 domain；不允许跨域详情节点。 |
| `detailKind` | 是 | `raw_chunk` / `message` / `tool_output` / `document_slice`。 |
| `text` | 是 | UTF-8；单条 ≤256 KiB；不得为空。 |
| `mime` | 否 | `text/plain` / `text/markdown` / `application/json`；默认 `text/plain`。 |
| `role` | `raw_chunk` 必填 | `user` / `assistant` / `system` / `tool`。 |
| `messageId` / `chunkIndex` / `turn` | 否 | 宿主稳定 ID；用于去重与定位。 |
| `threadId` | 否 | 任务/会话线程；有 task 域时必须与域一致。 |
| `recordIds` | 是 | 链接的 MemoryRecord id；必须同域、非空；没有可链接记录时只保留 staging，不写详情。 |
| `contentHash` | 是 | `sha256(text)`；去重键 `(domain, detailKind, contentHash, chunkIndex)`。 |
| `redaction` | 否 | `{applied, rules}`；发送前脱敏标记。 |
| `retentionClass` | 是 | 见 §2.6；服务端按策略计算 `expiresAt`。 |
| `expiresAt` | 是 | Unix ms；0 表示按 retention 计算；不接受超过策略上限。 |

### 2.2 域、owner 与 provenance

1. **domain = namespace**，复用现有域语法与同步订阅；不新增详情专属 namespace。
2. 一个 DetailRecord 只能属于一个 domain。若同一段原始文本支撑多个域的记录（例如 `user` 偏好 + `agent:dsh` 观察），sidecar 必须按目标域分别写入；每个域一份，ID 不同，`contentHash` 相同。禁止一个节点跨域引用。
3. `ownerType` / `ownerId` 由 domain 推导，客户端不得伪造：

   | domain | ownerType | ownerId |
   |---|---|---|
   | `user` | `user` | `u_...` |
   | `agent:<id>` | `agent` | `<id>` |
   | `task:<id>` | `other` | `task:<id>` |
   | `default` / `shared` / `system` / 旧 namespace | `other` | 同 domain |

4. `provenance` 记录写入者、来源设备、宿主、thread、messageIds；读取方必须能区分“我的详情”与“其他 Agent 的详情”。
5. MemoryRecord 的 `provenance.detailIds` 指向 DetailRecord；旧字段 `rawChunkIds` 只作为兼容别名，0.3 新写入不再依赖它。
6. DetailRecord 不建必需边；引用只用 `content.recordIds` / `provenance.detailIds`，不新增边类型。
7. 详情不是普通记忆事实：它不参与 profile / skills / graph 默认查询，不得被当成用户画像或系统指令。

### 2.3 存储与同步

| 对象 | 存放 | 权威 | 跨设备 |
|---|---|---|---|
| DetailRecord / RawChunk | 现有图 + 事件日志，经 capability `/detail` 写入 | **是** | 是，随现有同步 / 域订阅 |
| 本机 staging（未确认/未抽取的 chunk） | `<home>/memory-runtime/staging/` | 否 | 否 |
| 本机 detail cache（已沉降详情的只读缓存） | `<home>/memory-runtime/cache/` | 否 | 否 |
| outbox（detail 写/删重试） | `<home>/memory-runtime/outbox/` | 否 | 否 |
| RecallTrace | `<home>/memory-runtime/traces.jsonl` | 否 | 否 |

规则：

- **不建第二套存储/同步。** 详情的权威副本只有图 + 事件日志；同步、快照、墓碑、订阅全部复用现有机制。
- 本机 staging 只保存“已接收、尚未成功写入 capability”的 chunk；成功写入后删除。staging 默认 24h，最多 256 MiB；不是可召回来源。
- 本机 cache 可以缓存已沉降详情文本，用于离线只读；读取必须标 `source='cache'`、`stale=true`，不得冒充最新原文；删除/墓碑同步后立即失效。
- sidecar 重启后从 capability 重新拉取详情；staging/cache 丢失不影响已沉降详情。
- 详情不进入事件摘要、日志、Console 列表、trace 正文；事件只记录 `node_created` / `node_updated` / `node_deleted` 与节点 id。

### 2.4 Capability 受控端点

新增内部端点，不新增公共 MCP 工具：

```text
POST /internal/memory/v1/detail
```

统一信封、loopback + capability token、幂等规则与现有 capability 相同。`op`：

#### `op=write`

```jsonc
{
  "requestId": "req_...",
  "actor": { "type": "agent", "agentId": "dsh" },
  "op": "write",
  "items": [
    {
      "clientItemId": "det_01",
      "domain": "user",
      "detailKind": "raw_chunk",
      "threadId": "th_...",
      "recordIds": ["01J..."],
      "role": "user",
      "text": "我默认用深色主题。",
      "mime": "text/plain",
      "messageId": "m1",
      "chunkIndex": 0,
      "turn": 3,
      "contentHash": "sha256:...",
      "redaction": { "applied": false, "rules": [] },
      "retentionClass": "conversation",
      "expiresAt": 0,
      "provenance": { "source": "runtime", "extractor": "host", "threadId": "th_...", "messageIds": ["m1"] }
    }
  ]
}
```

```jsonc
{
  "results": [
    { "clientItemId": "det_01", "status": "created", "id": "01J...", "domain": "user", "detailKind": "raw_chunk", "contentHash": "sha256:..." }
  ],
  "created": 1,
  "duplicates": 0,
  "failed": 0,
  "partial": false
}
```

- 批量 ≤100；单条 ≤256 KiB；请求体 ≤2 MiB。
- 校验原子、落库逐项；失败项返回 code，成功项保留，`partial=true`。
- `recordIds` 必须非空、存在、同域、非内部（DetailRecord 本身除外）；不存在则 422 `validation_failed`，不建悬空引用。没有可链接记录/checkpoint 的 chunk 只留在 staging，抽取结束后丢弃，不写详情。
- 去重键 `(domain, detailKind, contentHash, chunkIndex)`；同键返回既有 id，`status='duplicate'`。
- 写入 `node_created` 事件；不新增事件类型。

#### `op=get`

```jsonc
{ "actor": { "type": "agent", "agentId": "dsh" }, "op": "get", "id": "01J...", "includeText": true, "maxBytes": 4096 }
```

```jsonc
{
  "detail": {
    "id": "01J...",
    "type": "detail_record",
    "kind": "detail_record",
    "detailKind": "raw_chunk",
    "domain": "user",
    "ownerType": "user",
    "ownerId": "u_...",
    "text": "我默认用深色主题。",
    "truncated": false,
    "redacted": false,
    "expiresAt": 1732592000000,
    "availability": ["available"],
    "recordIds": ["01J..."],
    "provenance": { }
  }
}
```

- 默认 `includeText=true` 只允许单条；`maxBytes` 夹紧到 64 KiB。
- 过期但未清理 → 410 `detail_expired`；已墓碑 → 410 `detail_deleted`；无权限 → 403 `domain_read_forbidden`；不存在 → 404 `not_found`。
- 读取不返回其他域的详情；不得用 id 猜测跨域内容。

#### `op=list`

```jsonc
{
  "actor": { "type": "agent", "agentId": "dsh" },
  "op": "list",
  "domains": ["user", "agent:dsh"],
  "threadId": "th_...",
  "recordIds": ["01J..."],
  "detailKinds": ["raw_chunk"],
  "limit": 20,
  "offset": 0,
  "includeText": false
}
```

- `includeText` 默认 false；list 只返回元数据（id/domain/detailKind/role/messageId/chunkIndex/expiresAt/contentHash），避免一次拉取大量原文。
- 需要原文时逐条 `op=get`；一次展开最多 3 条。
- `domains` 最多 16；未订阅/未同步域默认跳过并 warning，`strictDomains=true` 时 403。

#### `op=delete`

```jsonc
{ "requestId": "req_...", "actor": { "type": "user" }, "op": "delete", "ids": ["01J..."], "reason": "user_requested" }
```

```jsonc
{ "deleted": ["01J..."], "notFound": [], "forbidden": [], "partial": false }
```

- 写墓碑 `deletedAt` + `metadata.deletedReason`，随 `node_deleted` 事件同步；不物理删除。
- `user` / `system` 可删除任意域；`agent` 只能删除自己域内、自己写入的详情。
- `reason`：`user_requested` / `record_deleted` / `retention_expired` / `quota_evicted` / `checkpoint_deleted`。
- 删除详情不删除 MemoryRecord；详情不可用后 `detailAvailable=false`。

### 2.5 Sidecar 展开端点

宿主不直接访问 `/internal/memory/v1/detail`；只通过 sidecar：

```text
POST /memory-runtime/v1/recall/:recallId/expand
```

请求：

```jsonc
{
  "agentId": "dsh",
  "threadId": "th_...",
  "fragmentId": "mf_...",
  "detailKinds": ["raw_quote"],
  "maxBytes": 4096
}
```

响应：

```jsonc
{
  "recallId": "rr_...",
  "fragmentId": "mf_...",
  "detail": {
    "id": "01J...",
    "kind": "detail_record",
    "detailKind": "raw_chunk",
    "format": "verbatim",
    "text": "我默认用深色主题。",
    "truncated": false,
    "redacted": false,
    "availability": ["available"],
    "citations": [{ "id": "01J...", "type": "detail_record", "domain": "user" }],
    "owner": { "role": "user", "domain": "user" },
    "provenance": { }
  },
  "degraded": false,
  "warnings": []
}
```

规则：

- `recallId` + `fragmentId` 必须来自 10 分钟内的本地 trace；sidecar 校验 agent/domain 后，用 capability `/detail` 读取。
- 一次最多展开 3 条；`maxBytes` 夹紧 8192。
- 不可用时 HTTP 200，`detail=null`，`availability` 给出原因，不编造原文。
- 宿主不得用 `/detail` 枚举其他会话；`/expand` 只能展开本次召回出现过的 fragment。
- 管理/治理读取：`GET /memory-runtime/v1/details/:id`（admin）用于 Console “为什么想起 / 查看原文”；普通 host token 不开放列表。

### 2.6 保留策略

| `retentionClass` | 默认保留 | 适用 | 说明 |
|---|---|---|---|
| `conversation` | 30 天 | 人类/assistant 对话切片 | 默认；域策略可缩短到 1 天，最长 365 天 |
| `tool_output` | 7 天 | 工具结果/日志摘要 | 大段日志优先淘汰 |
| `document_slice` | 90 天 | 文件/文档引用 | 只存文本切片，不存二进制 |
| `pinned` | 直到删除 | 用户明确保留/治理需要 | 0.3 不默认产生；仅显式治理动作 |

- `expiresAt = min(writeAt + classDays, policy.maxExpiresAt)`；`expiresAt=0` 由服务端按 class 计算。
- MCP daemon 每日维护任务扫描过期 detail：写墓碑 `reason='retention_expired'`，随同步传播；不删除关联 MemoryRecord / Compact / Checkpoint。
- 删除/墓碑后读取返回 410；sidecar cache 立即失效。
- 详情保留不短于其链接记录的必要证据期：若记录仍有效，允许 `conversation` 30 天到期后只保留 gist；不得把过期详情当原文。
- 旧 `retention.rawDays` 只表示本地 staging 天数，不再表示权威 Raw 保留；实现中改名为 `stagingHours`。

### 2.7 配额与 compact

**默认配额**（服务端强制，可在域策略内收紧；不出现在普通 UI）：

| 项 | 默认 | 超限行为 |
|---|---|---|
| 单条 DetailRecord | 256 KiB | 413 `payload_too_large` |
| 单域详情总量 | 256 MiB | 先淘汰最旧 `tool_output`，再淘汰最旧 `conversation`；仍超 → 413 `detail_quota_exceeded` |
| 单忆云详情总量 | 1 GiB | 同上，按域公平淘汰 |
| 单 thread 详情 | 64 MiB | 同上，优先保留最近 7 天 |
| 单次 detail write | 100 条 / 2 MiB | 413 |

**compact / GC**：

- DetailRecord 不进入 `Compact` 的 `sourceIds`；Compact 仍然只压缩 MemoryRecord，避免“摘要把原文吞掉”。
- 详情维护只做**无损合并**与**淘汰**：同一 message 的相邻 chunk 可合并为一个 `message`；不调用模型生成新摘要；不改变文本。
- 配额淘汰写墓碑 `reason='quota_evicted'`；`status.counts.detailBytes` / `detailQuota` 可见；MemoryRecord 保留，`detailAvailable=false`。
- `Compact` 的 stale 规则不变；详情过期不使 Compact stale。记录删除使 Compact stale，并级联删除该记录的详情。
- 不做第二套 compact 文件、索引或摘要存储。

### 2.8 加密与隐私

- **传输**：capability 与 sidecar 只监听 loopback；同步继续走现有加密/鉴权通道。详情不经过公共 `/mcp`。
- **静态**：详情文本作为图节点 `content.text`，沿用现有图存储加密（如启用）；本机 staging/cache 目录 `0700`、文件 `0600`；不额外写明文日志。
- **脱敏**：sidecar 在写入前按宿主提供的 `redaction` 与内置模式脱敏 token/key/password/Authorization；`redaction.applied=true` 时读取方看到的是脱敏文本，必须标 `redacted=true`，不得称为原文。
- **逻辑隔离**：0.3 仍是同忆云逻辑域隔离，不是按 Agent 的密码学隔离；拿到本机存储/进程权限的攻击者可读全部。文档、Console、README 必须明确。
- **不新增密钥体系**：不引入 per-detail key、第二套 KMS 或第二套同步加密。

### 2.9 删除与墓碑

| 动作 | DetailRecord | MemoryRecord | Compact | Checkpoint |
|---|---|---|---|---|
| 用户删除一条记忆 | 级联墓碑链接详情（`reason=record_deleted`），无其他 live 记录引用时生效 | 墓碑 | 标 stale，不级联删除 | 不删除 |
| 用户删除详情 | 墓碑 | 保留，`detailAvailable=false` | 不变 | 不变 |
| 记录保留策略到期 | 按详情 retention 独立墓碑 | 按记录策略 | 不变 | 不变 |
| 删除 Checkpoint | 不级联删除详情；除非详情仅被该 checkpoint 引用 | 不变 | 不变 | 墓碑 |
| 配额淘汰 | 墓碑 `quota_evicted` | 保留 | 不变 | 不变 |

- 所有删除走现有 `node_deleted` 事件 + 墓碑，不物理删除；跨设备随同步传播。
- 删除后下一 turn 不再召回；sidecar 的 fuzzy 索引 / cache 按事件或 TTL 失效。
- `detailAvailable=false` 时，回忆只能说“这条记忆的原文已删除/过期”，不得用摘要加引号冒充原文。

### 2.10 订阅与过滤

- **物理订阅**：现有 `sync.namespaces` / `namespace_subscription`；detail 的 namespace 就是 domain，所以不需要新订阅协议。
- **逻辑过滤**：`/detail` 与 `/expand` 只返回请求 `domains` 内的详情；sidecar 在发请求前按 `policy.json` 过滤；capability 再用域语法/订阅状态兜底。
- **默认域**：`user`、`agent:<self>`、`default`、当前 `task:<currentThread>`；`shared` 仅显式/已订阅；`system` 默认不进入召回；`agent:<other>` 在已订阅或点名时加入。
- **跨 Agent**：其他 Agent 的详情必须带 `ownerType=agent`、`agentId`、`agentName`、`deviceId`、`hostId`；不得冒充自己的记忆。
- **认证设备**：同一 `cloudId` 内、已同步该域的认证设备可订阅并读取；不新增 per-record ACL，也不承诺抵御拿到本地存储的攻击者。
- **旧 `missing_cross_device` 作废**：不再把“原文只在写入设备”作为常态；只有 `pending_sync`（同步中）、`expired`、`deleted`、`quota_evicted`、`not_subscribed`、`redacted_only` 才是诚实降级原因。

### 2.11 跨设备展开流程

```text
设备 A DSH 写入
  → sidecar A /ingest
  → capability /write（MemoryRecord）+ /detail（DetailRecord）
  → 图 + 事件日志 + 现有同步
  → 设备 B 的 MCP 应用事件

设备 B Hermes 下一 turn
  → sidecar B /context
  → capability /query（拿到 gist + detailIds）
  → 用户追问原文
  → sidecar B /recall/:recallId/expand
  → capability /detail op=get
  → 返回原文 + provenance(device A)
```

- 只要详情在保留期内、未删除、域已订阅，设备 B 就可以展开；不需要回连设备 A。
- 若设备 B 尚未同步到该节点：`availability=['pending_sync']`，最多等 2 个同步周期；不要谎称“原文只在设备 A”。
- 若已过期/删除/配额淘汰：`availability=['expired'|'deleted'|'quota_evicted']`，注入文本明确说明，不伪造 quote。

### 2.12 大小限制汇总

| 项 | 上限 |
|---|---|
| 单条 `text` | 256 KiB |
| 单次 write items | 100 |
| 单次 request body | 2 MiB |
| `op=get` `maxBytes` | 64 KiB |
| `op=list` `limit` | 50 |
| `/expand` 条数 | 3 |
| `/expand` `maxBytes` | 8192 |
| `domains` | 16 |

## 3. 结构化 ContextCheckpoint

### 3.1 定义

ContextCheckpoint 是**任务连续性对象**，不是 compaction summary，不是聊天摘要，不是本地恢复文件。它描述“这个任务现在到哪、为什么、下一步是什么”，让另一个设备/下一个 turn 能继续工作。

- 始终上云：`task:<taskId>` / `task:<threadId>` / `default`。
- 默认内部对象，不进入普通 query / history / profile / skills / graph。
- 写入经 capability `/internal-object` `kind='context_checkpoint'`；本地只缓存，不保存权威副本。
- summary 只是降级形态，不能替代结构化字段。

### 3.2 Schema

`state` 使用 schema 2：

```jsonc
{
  "schema": 2,
  "contentMode": "structured",          // structured | summary_only
  "task": {
    "key": "task:th_...",               // 必须等于 domain
    "threadId": "th_...",
    "fleetTaskId": null                 // 可空；只作引用，不读 fleet store
  },
  "goal": "完成 Mebular 0.3 详情跨设备展开",
  "constraints": [
    { "id": "c1", "text": "不新增公共 MCP 工具", "source": "user" }
  ],
  "decisions": [
    { "id": "d1", "text": "详情复用图/事件/同步", "reason": "不建第二套存储", "at": 1730000000000, "recordIds": ["01J..."] }
  ],
  "progress": {
    "done": [{ "id": "p1", "text": "契约冻结", "recordIds": [] }],
    "doing": [{ "id": "p2", "text": "sidecar 详情写入" }],
    "blocked": [{ "id": "p3", "text": "等待模型资产", "reason": "发布未闭环" }]
  },
  "nextSteps": [
    { "id": "n1", "text": "DSH 真实旅程", "owner": "dsh" }
  ],
  "files": [
    { "path": "packages/mcp/src/memory-capability.mjs", "role": "write", "status": "in_progress" }
  ],
  "openQuestions": [
    { "id": "q1", "text": "详情跨域复制还是单域引用？", "blocking": true }
  ],
  "references": {
    "recordIds": ["01J..."],
    "detailIds": ["01K..."],
    "messageIds": ["m1"],
    "fleetTaskId": null,
    "urls": []
  }
}
```

顶层仍保留 `summary`（兼容现有 capability）：

- `contentMode='structured'`：`summary` 可为 null 或一句人类可读索引；结构化字段是权威。
- `contentMode='summary_only'`：`summary` 必填，`goal/constraints/decisions/progress/nextSteps/files/openQuestions` 必须为空数组或 null；读取方必须标 `degraded=true`、`reason='checkpoint_summary_only'`。
- 宿主只有 summary 时，不得把它拆成结构化字段冒充完整 checkpoint；只能写 `summary_only`。
- 模型生成的内容不得写入 `constraints` / `decisions` 作为权威；除非宿主明确标注来源。

### 3.3 字段限制

| 字段 | 上限 |
|---|---|
| `goal` | 2 KiB |
| `constraints` | 32 项 × 1 KiB |
| `decisions` | 50 项 × 2 KiB |
| `progress.done/doing/blocked` | 各 50 项 × 1 KiB |
| `nextSteps` | 32 项 × 1 KiB |
| `files` | 100 项 × 512 B |
| `openQuestions` | 32 项 × 1 KiB |
| `references.recordIds/detailIds/messageIds` | 各 200 |
| `state` 总大小 | 256 KiB |
| `summary` | 64 KiB |

### 3.4 域与键

| 场景 | domain | checkpoint key | 读取 | 写入 |
|---|---|---|---|---|
| 有 fleet taskId，且宿主把它作为稳定任务键 | `task:<taskId>` | `(cloudId, taskId)` | 任务参与者（域订阅） | 任务参与者 + lease |
| 有普通 threadId | `task:<threadId>` | `(cloudId, threadId)` | 任务参与者（域订阅） | 任务参与者 + lease |
| 没有显式任务域 | `default` | `(cloudId, agentId, threadId)` | 同一 Agent / user / system | 同一 Agent / user / system |

- `task.key` 必须等于 domain；`task.threadId` 必须等于路径 `threadId`；`task.fleetTaskId` 只作引用。
- **不要求 sidecar 直接读 fleet store**：sidecar 只保存/读取 `references.fleetTaskId`；任务 DAG、状态、owner 仍由 `@mebular/fleet` 拥有。
- fleet taskId 不合法或不存在时，不阻断 checkpoint；只是无法关联任务，`references.fleetTaskId=null` 并 warning。
- `default` 只承接没有显式任务域的内容；不把用户事实写进 `default` 冒充 `user`。

### 3.5 revision、lease 与参与者

- `default`：revision 按 `(cloudId, agentId, threadId)` 单调；同一 Agent 多设备共享；其他 Agent 不读写。
- `task:*`：revision 按 `(cloudId, taskKey)` 单调，**所有参与者共享同一个 revision**；`updatedBy.agentId` 记录本次写入者。
- 租约：默认 60s，`hostId` 由服务端计算；其他 host 持有 → 409 `checkpoint_lease_held`；`force=true` 仅 user/system。
- 冲突：`expectedRevision` 不匹配 → 409 `revision_mismatch`；宿主 GET 当前 revision 后重试一次；仍失败保持 pending，不盲目覆盖。
- 读取：`task:*` 参与者按域订阅可读；`default` 仅同一 `(agentId, threadId)` 或 user/system。
- 写入：`task:*` 参与者且具备该域写权限；`default` 仅同一 Agent；user/system 可治理。
- 0.3 不做 per-record ACL；上述是逻辑约束。

### 3.6 宿主写入时机

| 宿主 | 触发 | 必须写入 |
|---|---|---|
| DSH | `compaction/start → summary → replacement → end` 完成后 | 结构化 state + summary 索引 + recordIds/detailIds/fleetTaskId |
| Hermes | `on_pre_compress` / `on_session_end` | 结构化 state；没有 summary 就 `summary_only` + `summary:null` |
| OpenCode / OpenChamber | `session.compaction.ended` / task 变更 | 结构化 state + compaction 元数据 |
| 任意宿主 | 用户明确“记住任务/继续任务” | 结构化 state；不要求 compaction |

- 宿主在 compaction / task 变更时写入；不要求每个 turn 都写 checkpoint。
- 写入失败：保持 pending；不谎称 committed；不阻塞对话。
- 宿主必须提交 `agentId`、`threadId`、`domain`、`state.schema=2`、`contentMode`；`hostId` 由 sidecar/MCP 注入。

### 3.7 Sidecar 读取与召回

- **新 turn**：`/context` 带 `includeCheckpoint=true` 时，sidecar 读取当前 `(agentId, threadId)` 或 task 域的 checkpoint。
- **压缩后**：宿主写完 checkpoint 后，sidecar 在下一个 `/context` 主动读取；不依赖宿主把 summary 再塞进 query。
- **参与召回**：checkpoint block 顺序在 `self` 之后、`compact` / `fragment` 之前；内容标记 `trust='untrusted'`、`kind='checkpoint'`。
- **结构化 checkpoint**：渲染 goal / constraints / decisions / progress / nextSteps / files / openQuestions / references；按预算截断，保留 goal + nextSteps + blocking。
- **summary_only**：只渲染摘要，`degraded=true`、`reason='checkpoint_summary_only'`；不得让模型以为这是完整任务状态。
- **无 checkpoint**：不注入空块；沉默。
- **过期**：`expiresAt < now` 不注入；`checkpoint_expired` 可见；不删除关联记录/详情。
- **跨设备**：设备 B 同 task key 可读；revision/lease 不阻止只读。

### 3.8 与 compaction summary 的关系

- compaction summary 是宿主压缩历史的产物；checkpoint 是任务状态。
- 宿主可以把 summary 放在 `summary` 字段作为人类可读索引，但不能替代 `goal/constraints/...`。
- 只有 summary 时：`contentMode='summary_only'`；读取方必须降级标记。
- sidecar 不得用 summary 生成结构化字段；不得把 summary 当“已完成/下一步”的证据。
- Compact（长期记忆压缩）与 checkpoint 是不同对象：Compact 是 MemoryRecord 的派生摘要；Checkpoint 是任务连续性状态。

### 3.9 删除、过期与治理

- 删除 checkpoint：user/system；写墓碑；不删除 MemoryRecord / DetailRecord。
- 过期：读取返回 `null`；异步清理；不删除关联记录。
- 纠正：用户可编辑 checkpoint 的 goal/nextSteps 等字段（治理路径）；写新 revision，保留旧 revision 历史节点。
- 删除后下一 turn 不再注入；sidecar cache 失效。

## 4. 单一 UI

### 4.1 设置信息架构

```text
设置
├─ 记忆
│  └─ 记忆模式：[轻量 MCP] [沉浸式]        ← 唯一新增控件 1
├─ 高级
│  └─ 模型来源：[heuristic] [local] [host] [api] [auto]  ← 唯一新增控件 2
└─ 诊断（只读）
   ├─ sidecar 状态 / 降级原因
   ├─ 详情配额 / 保留
   └─ 为什么想起 / 纠正 / 删除
```

- “记忆模式”是设备级；同忆云另一台设备可以仍是轻量。
- 模式开关同时联动：MCP capability 挂载、sidecar 启停、host adapter 发现、域订阅、模型来源可用性。用户不需要逐项操作。
- 高级模型来源只影响 sidecar 抽取/摘要；不影响 host 自身模型；host 候选仍按宿主能力自动提交。
- 诊断只读；不提供“启动 sidecar / 停止 sidecar / 配 token / 配 discovery / 配域订阅”按钮。

### 4.2 模式开关文案

推荐中文：

- 轻量：`轻量 MCP：只提供记忆工具，不自动采集、不自动注入。`
- 沉浸式：`沉浸式：自动按记忆域采集并同步详情；认证设备可订阅，每个新对话最多注入一次背景记忆。`
- 切换确认：`开启后，本设备会按记忆域采集对话与任务详情，并同步到本忆云的认证设备。可随时切回轻量。`
- 失败：`记忆运行时暂不可用，对话不受影响；稍后自动重试。`

禁止文案：

- `仅本机采集` / `云端采集` 二选一。
- `首次开启需要授权采集`。
- `请为每个宿主配置 capture`。
- `原文只保留在写入设备`（作为常态）。

### 4.3 高级模型来源

| 选项 | 显示条件 | 说明 |
|---|---|---|
| `heuristic` | 总是 | 默认；无模型也能用 |
| `local` | 模型包已安装 | 未安装则禁用并说明，不自动下载 |
| `host` | 宿主支持候选 | 不读宿主凭据；无候选则 pending |
| `api` | 已配置 keyRef + allowRemote | 不显示明文 key |
| `auto` | 总是 | 按 host→local→api→heuristic 选择，不隐式联网 |

### 4.4 不进入普通 UI 的实现细节

- sidecar 启停、端口、token、discovery、host adapter 安装、域订阅、capture 策略、retention 数值、配额数值、内部对象类型。
- 这些只在诊断/日志/管理员 API 中以只读或排障形式出现；不得成为用户必须完成的步骤。
- 现有 Console 的“Runtime”术语改为“记忆运行时”；不得把 sidecar 叫 “Runtime”。

### 4.5 保留的治理能力

- 为什么想起：来源、时间、置信度、匹配词、展开原因；不暴露其他 Agent 未授权内容。
- 纠正：更新 MemoryRecord，写 `SUPERSEDES`/`validTo`；旧详情保留为历史证据，不作为当前事实召回。
- 删除：删除记录级联删除其详情；删除详情保留记录；删除后不再召回。
- 归档：默认不召回；可恢复。
- 这些治理动作仍是用户可见的，不属于“新增第三个设置”。

### 4.6 宿主不需要逐宿主配置

- DSH / Hermes / OpenCode / OpenChamber 适配器默认自动发现；显式 `runtimeUrl` / token 仅作为排障覆盖。
- 适配器不保存 `memoryRuntime.enabled` / `capture`；只读 sidecar discovery 的 `mode` / `state`。
- 宿主安装后不需要“开启记忆”二次开关；模式由 Mebular 设置统一控制。
- OpenChamber 原生 memory 不因 Mebular 开启而关闭；Mebular 不读/不导入/不替换/不双写。

**DSH 注入通道例外（2026-10-31 C6b 冻结）**：

- DSH `0.2.1-rc.2` 没有非持久的模型上下文通道：`agent/pre-step` 的 `UserMessage[]`、`agent.inject()`、system-prompt runtime-context provider、tool `additionalContexts` / `deferContext` 最终都进入 durable session log；`agent/request` 明确不能修改 messages。因此“模型可见”与“写入 session log”在该宿主上不可分离。
- DSH 继续使用 `role='user'` + `source.kind='mebular-memory'` 的 source-tagged context message；它不是 `source.kind='user'`，不渲染成用户气泡，也不进入用户可见历史。
- DSH durable `session.v4.jsonl` 会留下 source-tagged 快照，这是平台限制，不伪造“完全不写 session log”。适配器每个 human turn 先剔除历史 memory 消息，并用 session surface replacement 把上一轮的 memory 节点替换为当前轮快照；无命中轮替换为空 system 节点（DSH 不把它投影为模型消息），因此模型请求不会累积旧注入，无命中也不携带上一轮块。
- DSH 当前 UI 没有独立 context injection 面板；验收以真实 model request（恰好一条当前块、无命中零块）、DOM/截图无用户气泡或记忆正文、以及 durable log 中所有块均为 source-tagged 为准。

### 7.7 执行顺序

```text
C1 详情数据模型（capability /detail + 图节点）
  → C2 sidecar 采集/详情写入/outbox
    → C3 host 自动接入（DSH 优先）
    → C4 checkpoint schema 2 + 读取/召回
      → C5 单一 UI
        → C6 真实用户旅程 + 截图
          → C7 全量测试/发布
```

- 每一步都不得出现 capture；不得新增公共工具；不得建第二套存储/同步/任务协议。
- C1/C2 先做数据模型与幂等，再做 UI；否则 UI 会掩盖后端缺口。

### 8.1 Chief 决策（2026-10-30）

| ID | 决策 |
|---|---|
| O1 | 接受按域复制 DetailRecord；同域内仍按 `contentHash` 去重。发布前测放大比例；超过配额时按域保留策略淘汰。 |
| O2 | task checkpoint 保持“参与者 + 域写权限 + revision/lease”；`force=true` 仅 user/system，不把任务锁给单个 Agent。 |
| O3 | 接受 30 / 7 / 90 天默认保留；按域可缩短，普通 UI 不暴露。 |
| O4 | 同忆云已认证 Agent 的 `agent:*` 默认只读订阅；读取带 provenance，用户可删除/治理；不做逐域开关。 |
| O5 | `summary_only` checkpoint 进入召回，但必须 `degraded=true`、`reason=checkpoint_summary_only`。 |
| O6 | 删除 MemoryRecord 级联墓碑其 DetailRecord；Compact 只标 stale，不级联删除记录/详情。 |
| O7 | 允许离线读详情 cache，但必须标 `source=cache` / `stale=true`；不得冒充最新原文。 |
| O8 | `/detail` 使用独立内部端点；`internal-object` 保持 compact/self/checkpoint 单对象语义。 |
| O9 | 接受 256 MiB/域、1 GiB/云默认配额；发布前按真实数据校准。 |
| O10 | 0.3 默认 heuristic；local Qwen 资产闭环前不宣称本地模型默认体验。 |
| O11 | DSH 若真实 UI 把注入渲染成用户气泡，直接禁用注入并标 `injection_channel_unsupported`；不合成用户消息。 |
| O12 | Hermes 无结构化字段时允许 `summary_only`，必须降级；没有 summary 也不编造。 |
