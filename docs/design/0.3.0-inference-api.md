# Mebular 0.3.0 Sidecar Models 与 Inference API

**状态**：C8c / 2026-10-31
**命名契约**：[`0.3.0-models-and-inference.md`](./0.3.0-models-and-inference.md)
**上位契约**：[`0.3.0-memory-runtime-sidecar.md`](./0.3.0-memory-runtime-sidecar.md)、[`0.3.0-immersive-product-contract.md`](./0.3.0-immersive-product-contract.md)
**代码**：`packages/memory-runtime/src/sidecar/inference/` 与 `sidecar/inference-provider.ts`
**原语**：`packages/memory-runtime/src/inference/`（下载、manifest、硬件探测、llama-server supervisor、引擎资产清单）

---

## 0. 一句话

**models 与 inference 是 Memory Runtime sidecar 的子能力：models 管目录/安装/选择，inference 管执行；不是独立 daemon，也不在 MCP 进程内。**

- 一个 home 一个 sidecar；模型安装、下载、引擎、provider 都归这个 sidecar。
- Qwen / Llama 只是“模型包 + engine adapter”；未来 Ollama / MLX / OpenAI-compatible 只增加 adapter，不按模型拆服务。
- MCP / Console / CLI 只通过 sidecar host API（`/memory-runtime/v1/models`）访问；MCP 进程不加载模型、不 spawn `llama-server`。
- 不新增公共 MCP 工具，29 工具不变。
- 轻量模式不启动 sidecar、不建模型目录、不下载模型。

## 1. 边界

| 事项 | 归属 |
|---|---|
| 模型包文件、下载/续传、sha256 校验、原子安装 | sidecar（复用 `inference/ModelStore`） |
| 安装任务、取消、重试、重启恢复 | sidecar（`inference/model-installer.ts`） |
| llama.cpp 引擎资产下载/校验/安全解压/状态 | sidecar（`inference/engine-installer.ts`） |
| llama-server 子进程、健康检查、熔断 | sidecar（`inference/engine.ts` 拥有 `InferenceProcess`，包装 `inference/LlamaServerEngine`） |
| 目录、硬件推荐、激活/停用、热切换 | sidecar（`inference/service.ts`） |
| 记忆写入、图、事件日志、同步 | MCP / 忆云；sidecar 没有图写入路径 |
| 模型下载 UI | Console（C8f）；本阶段不实现 |
| MCP 薄代理 / Console 调用 | MCP `serve.mjs`（C8c）：只转发 sidecar host API，不读模型目录、不写配置、不启引擎 |

**禁止**：

- 新增独立模型 daemon 或第二个 sidecar。
- 在 MCP 进程内 `import` 模型引擎、启动 `llama-server`、保存模型文件。
- 把 inference 作为第二套记忆库或同步源。
- 为了切换模型重启 sidecar（激活/停用是进程内热切换）。
- 在 API 视图、日志、安装任务中返回 host token、capability token、API key、模型绝对路径或引擎 token。

## 2. Host API

所有端点沿用 sidecar 既有安全基线：

- 只监听 loopback；拒绝非 loopback Host / Origin。
- 除 `/health` 外必须 `Authorization: Bearer <hostToken>`。
- 统一信封 `{ok, requestId, apiVersion, data, warnings, degraded}`。
- 错误只返回稳定 `code` + 脱敏短句；安装任务的 `packId` / 文件名可以出现，路径不可以。

### 2.1 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/models` | 目录 + installed + active + hardware + recommended + install state + engine 资产状态 |
| GET | `/models/:id/status` | 单包状态、manifest 可用性、引擎与安装任务 |
| POST | `/models/:id/install` | 创建安装任务；`202` + `jobId`；同一时间只允许一个 |
| GET | `/installs/:jobId` | 任务状态/进度/速度/ETA/结构化错误 |
| POST | `/installs/:jobId/cancel` | 取消当前任务并清理 partial |
| POST | `/models/:id/activate` | 校验安装 → 启动引擎 → 健康检查 → 热切换 provider |
| POST | `/models/:id/deactivate` | 回退 heuristic、停止引擎、保留模型文件 |
| POST | `/models/:id/start` | 只启动引擎，不改 provider 配置 |
| POST | `/models/:id/stop` | 只停止引擎，不改 provider 配置 |
| POST | `/models/:id/remove` | 卸载模型文件；active 时先 deactivate |
| GET | `/inference` | 当前来源（`config.source`）、active provider、引擎、安装任务、推荐、已安装包、warnings |
| POST | `/inference/settings` | 进程内切换 `heuristic`/`host`/`api`/`auto`；`local` 返回 `400 pack_required` |

#### 2.1.1 `/inference` 与 `/inference/settings`

`GET /inference` 返回 `InferenceSettingsView`：

```jsonc
{
  "config": { "source": "heuristic" }, // 持久化的 model.source
  "active": { "source": "heuristic", "packId": null, "modelId": null, "engine": { /* ... */ } },
  "engine": { /* lifecycle + 引擎资产状态；不含路径 */ },
  "install": null,
  "recommended": { "kind": "local", "packId": "qwen3-8b-instruct-q4_k_m" },
  "installedPackIds": [],
  "warnings": []
}
```

`POST /inference/settings` 只接受 `{ "source": "heuristic" | "host" | "api" | "auto" }`：

- `heuristic`：停引擎、`activePackId=null`、`config.model.source=heuristic`，reconfigure 并持久化；
- `host` / `api` / `auto`：local 正在运行时先停引擎，再更新 source、reconfigure 并持久化；
- `local` 不被接受，返回 `400 pack_required`；本地模型只能通过 `POST /models/:id/activate` 激活；
- 全部为进程内热切换，**不重启 sidecar**；持久化失败只返回 `config_persist_failed` warning。

### 2.2 `/version` capability

```jsonc
{
  "capabilities": {
    "models": {
      "install": true,
      "activate": true,
```

`sources` 是兼容字段：此前 `capabilities.models` 是字符串数组；0.3.0 起改为结构化对象并把来源列表放进 `sources`。

## 3. 安装任务

### 3.1 状态机

```text
POST /models/:id/install
        │
        ▼
   downloading ──cancel──► cancelled（abort + 清理 partial）
        │
        ▼
    verifying ──failure──► failed（结构化 error.code）
        │
        ▼
   installing ──failure──► failed
        │
        ▼
    completed

sidecar 重启时：
   downloading/verifying/installing ──► interrupted
   partial 保留；再次 install 由 ModelStore 续传
```

- 任务持久化到 `<dataDir>/inference/install.json`（0600，原子写）。
- 同一时间只有一个活动任务；第二个 install 返回 `409 install_in_progress` 并带当前 `jobId`。
- 已安装且未 `force` 返回 `409 already_installed`。
- 失败/取消/中断后可直接再次 `POST install` 重试；`completed` 后需 `force=true` 才覆盖。
- 取消时 `AbortSignal` 传给 `ModelStore.download`，完成后调用 `clearPartial`；不会留下孤儿引擎（安装不启动引擎）。
- 若取消与原子提交赛跑、文件已经落盘，任务返回 `completed` + warning `install_completed_before_cancel`，不谎报 `cancelled`。
- sidecar 正常停止时任务标记 `interrupted`，**不清理 partial**，下次启动可续传。
- 进度回调只更新内存；磁盘写入按 500ms 节流，状态变化立即写。
- 公开 job 不包含绝对路径、下载 URL、token 或原始异常消息。

### 3.2 安装前检查

在创建任务前按 manifest（缺失时回退目录包要求）检查：

| 检查 | 失败 code |
|---|---|
| 平台/架构 | `platform_unsupported` |
| 最低内存 | `memory_insufficient` |
| 最低磁盘（同时不小于 manifest 总字节） | `disk_insufficient` |
| GPU required | `platform_unsupported` |
| 完整 manifest 缺失 | `manifest_missing` |
| manifest 非法/不匹配 | `manifest_invalid` / `manifest_mismatch` |

manifest 默认读取 `<dataDir>/model-manifests/<packId>.json`。sidecar **不猜下载地址或 sha256**；缺失即结构化失败。测试通过注入 fake resolver 覆盖。

### 3.3 安装阶段（model → engine）

`ModelInstallJob` 增加 `phase: 'model' | 'engine'`：

```text
downloading / verifying / installing（phase=model）
        │ 模型文件原子提交、校验通过
        ▼
installing（phase=engine，progress 为引擎安装进度）
        │ EngineInstaller.ensureInstalled()
        ▼
completed（warnings: model_installed, engine_ready）
```

- 引擎已安装且校验通过：引擎阶段立即完成（仍记录 `engine_ready`）。
- 引擎安装失败：job `failed`，`error.code` 为 `engine_*`，模型文件保留；`warnings` 含
  `model_installed`、`engine_install_failed`。重试 `POST /models/:id/install` 时若模型已安装
  而引擎未就绪，只补引擎阶段，不重新下载模型。
- 取消/中断同样 abort 引擎下载；引擎临时目录被清理，模型 partial 仍按原策略保留。
- `progress` 是当前 phase 的进度，不是模型+引擎的加权总和；客户端应同时读取 `phase`。

### 3.4 EngineInstaller 状态机

引擎资产由 sidecar 私有 `EngineInstaller` 管理，不是模型包，也不是 service：

```text
not_installed
   │ ensureInstalled()，只解析官方 engine-assets 清单
   ▼
downloading → verifying → extracting → installing
   │                                        │
   │ cancel                                 ├─► installed（state.json 0600）
   ▼                                        └─► failed（清理临时目录）
cancelled
```

- 状态文件：`<dataDir>/inference/engine/state.json`（0600、原子写），字段包括
  `release/platform/arch/asset/sha256/binaryReady/installedAt/verifiedAt`；不写绝对路径。
- 下载只使用 `resolveEngineAsset({platform, arch})` 返回的官方
  `ggml-org/llama.cpp` release URL；不接受任意 URL。
- 归档先校验 `sizeBytes` + sha256，再**先列出条目**：拒绝绝对路径、`..`、空段、
  盘符、反斜杠、符号链接、硬链接与未知条目类型；只允许 `archiveRoot` 下的普通文件/目录。
- 解压到随机临时目录，确认 `binaryPath` 是预期普通文件后，原子 rename 到
  `<engine>/current`；POSIX 上 `chmod 0755`，Windows 保留 `llama-server.exe`。
- 失败、取消或进程崩溃后不留下半安装状态；启动时清理 partial/extract，必要时恢复 backup。
- `status()` / `binaryPath()` 只暴露 `installed/release/platform/arch/asset/binaryReady/reason`，
  不返回绝对路径、下载 URL 或 token。

引擎失败码（稳定）：

| code | 含义 |
|---|---|
| `engine_asset_unsupported` | 当前平台/架构没有官方资产 |
| `engine_not_installed` | 引擎尚未安装或安装状态未通过校验 |
| `engine_download_failed` / `engine_http_error` | 下载失败 |
| `engine_size_mismatch` / `engine_checksum_mismatch` | 归档大小或 sha256 不一致 |
| `engine_extract_failed` | 归档不安全/损坏/解压失败 |
| `engine_binary_missing` | 归档缺少预期 `llama-server` |
| `engine_install_failed` / `engine_storage_unavailable` | 提交或存储失败 |
| `cancelled` | 用户取消或 sidecar 停止 |

`activate` / `startEngine` 启动前必须 `ensureInstalled()` 并使用 `binaryPath()`；未安装或未校验
不能启动。`activate` 失败回退 heuristic；`start` 返回上述结构化 code，不阻塞对话。

### 3.5 InferenceProcess 生命周期

`InferenceProcess` 是 sidecar 私有的 llama.cpp 受管子进程（managed-child），不是 service：

- `LlamaCppInferenceEngine` 是唯一持有者，最多一个 `InferenceProcess`；
- service 是启动/停止/切换的唯一 owner；`inference-provider` 只能通过注入 facade 获取连接；
- 生命周期：`idle → starting → ready → busy → idle → stopped`，崩溃后 `crashed → backoff`，
  连续崩溃进入 `circuit_open`；
- 没有公开 API、独立 token、独立安装或配置；不承载记忆、不写图、不参与同步；
- 生产装配使用 `requireBinaryPath=true`：懒启动时没有 EngineInstaller 校验过的路径就拒绝 spawn；
- 切换模型先停旧进程再启新进程，不重启 sidecar；失败不拖垮 sidecar。

## 4. 目录与硬件

`GET /models` 返回：

- 精选目录（Qwen 4B/8B/14B/30B-A3B，具体以 `inference/catalog.ts` 为准）；
- 每个包的 `state`（`not_installed|downloading|verifying|installed|corrupt|failed|unsupported`）；
- `installedBytes` / `expectedBytes` / `verifiedAt`；
- `manifest.available`（是否具备设备完整 manifest）；
- `supported`（当前硬件是否满足最低要求；未探测为 `null`）；
- `active`（当前 provider 是否就是该包）；
- `install`（属于该包的最近任务）；
- `hardware`（平台、架构、内存、磁盘可用量、GPU；不含磁盘路径）；
- `recommended`（复用 `inference/detect.recommendModel`；没有可用包时 `kind=heuristic`）；
- `engine`（`installed/release/platform/arch/asset/binaryReady/reason/state/progress`；
  不含绝对路径或下载 URL）。

硬件探测在 sidecar 启动后异步预热并缓存 60s；不会为 `/status` 阻塞启动。推荐结果不触发下载或联网。

## 5. 激活、停用与热切换

### 5.1 activate

```text
POST /models/:id/activate
  → 包已安装？
  → ModelStore.verify(packId)（流式 sha256）
  → 解析已安装 manifest，找到 .gguf
  → 硬件最低要求检查
  → EngineInstaller.ensureInstalled()（官方资产、sha256、安全解压；已安装则跳过）
  → EngineAdapter.start(modelPath, binaryPath)（启动 + 健康检查）
  → 更新内存 config：model.source=local, model.local.pack=<id>, path=null
  → SidecarInferenceProvider.reconfigure(settings)
  → 持久化 config.json（原子写；失败只 warning）
```

- **不重启 sidecar**；`restartRequired` 恒为 `false`。
- 成功返回 `activated=true`、`active=local`、`engine` 状态。
- 引擎启动/健康检查失败：停止引擎、回退 `heuristic`、返回 `activated=false` + 稳定 `reason`（如 `engine_unavailable`）+ `warnings`（含 `engine:<engineCode>`）。不阻塞对话。
- 硬件不满足：不启动引擎，回退 `heuristic`，返回结构化 reason。
- 未安装 / 校验失败：`409 not_installed` / `409 model_corrupt`，不切换 provider。
- 如果同一包已 active，再次 activate 幂等返回。

### 5.2 deactivate

- 停止引擎；
- `model.source=heuristic`，`model.local.pack` 保留为“上次选择”；
- 不删除模型文件；
- 持久化 config，sidecar 重启后保持 heuristic。

### 5.3 start / stop

- 只控制引擎，不修改 `model.source` / `model.local.pack`。
- `start` 要求包已安装并通过硬件检查；`stop` 在引擎属于其他包时返回 `409 engine_pack_mismatch`，避免误停。
- 显式 stop 后，下一次模型调用仍可能按需懒启动；这是“只控制引擎”的语义，不是 provider 切换。

### 5.4 remove

- active 包先执行 deactivate；
- 该包有进行中的安装任务时先 cancel；
- 调用 `ModelStore.uninstall` 删除模型文件/partial/staging/backup；
- 不删除内置 catalog manifest（代码常量），以便重新安装；
- 不影响已沉降记忆（sidecar 本来就不是记忆权威）。

### 5.5 引擎所有权

- `inference/service.ts` 是引擎生命周期的唯一 owner；`inference/engine.ts` 最多持有一个 `llama-server` 子进程。
- 生产装配时 `service.createGateway` 也注入给 `SidecarInferenceProvider`，避免模型层自行决定 provider 客户端；gateway 本身无状态，每次请求创建。
- `sidecar/inference-provider.ts` 通过注入的 `localEngine` facade 获取连接；注入后不再创建/缓存多份引擎。保留 `createEngine` 注入点给未接 service 的测试/嵌入用法。
- 切换 pack/path 时 adapter 先停旧引擎再启动新引擎，避免两个大模型同时驻留。
- `inference-provider.ts` 的 `reconfigure(settings)` 更新 source/local/api；自有引擎在 local 配置变化时停止，外部注入引擎由 service 停止。

## 6. 失败回退

| 故障 | 行为 |
|---|---|
| 模型下载失败 | 任务 `failed` + 结构化 code；对话不受影响 |
| 校验失败 | `failed` / `model_corrupt`；不激活 |
| 引擎资产未安装/校验失败/解压失败 | 安装任务 `failed`（`engine_*`）；模型文件保留；activate 回退 `heuristic`；start 返回结构化错误 |
| 引擎启动超时/崩溃/熔断 | provider 回退 `heuristic`，`degraded=true`；对话继续 |
| 模型推理失败 | 既有 `SidecarInferenceProvider` 回退 heuristic；只告警，不切第三方 API |
| 硬件/磁盘不足 | 安装前拒绝；激活时回退 heuristic |
| 安装状态文件损坏 | 忽略旧任务；warning `install_state_unreadable` |
| config 持久化失败 | 热切换仍生效，返回 `config_persist_failed` warning |
| sidecar 重启 | 活动安装标 `interrupted`；partial 保留；按 config 恢复 local target（懒启动） |

**不**自动切换到远程 API；**不**用空结果伪装“没有记忆”；**不**因模型失败阻塞 MCP 启动、29 工具或对话。

## 7. 轻量模式

轻量 MCP 不启动 sidecar，因此：

- 没有 `/memory-runtime/v1` 进程、没有模型 host API；
- 不创建 `<home>/memory-runtime/models`、不写 `inference/install.json`；
- 不下载模型、不启动 `llama-server`；
- MCP 仍只有 29 个公共工具，inference 不会在 MCP 进程内加载；
- 已存在的历史模型文件不会被删除或修改（只有显式 `remove`/`uninstall --purge` 才删除）。

---

### 7.1 MCP / CLI 薄代理

- `GET /admin/api/models` / `status` 只转发 sidecar `/models`、`/inference`，并做展示字段适配；
- `POST /admin/api/models/:action` 映射为 sidecar install/activate/cancel/remove/start/stop；
  `pause`/`resume`/`import` 明确 `unsupported`，`test` 只做 sidecar 状态/健康检查，不启动 MCP 侧引擎；
- `GET/POST /admin/api/memory-runtime/model-source` 读写 sidecar 来源；`local` 必须带 `pack` 并调用
  `/models/:pack/activate`；MCP 不再直接写 `<home>/memory-runtime/config.json`，也不再重启 sidecar；
- 轻量/未就绪统一返回结构化 `memory_runtime_disabled` / `memory_runtime_unavailable`；
- `mebular models` 有 daemon 时走 admin proxy，无 daemon 返回 `daemon_unavailable`，不再本地下载或启动引擎。

## 8. 未来 adapter

inference 按“能力”而不是“模型品牌”拆分：

```text
InferenceEngine
  ├─ LlamaCppInferenceEngine（当前，GGUF + llama-server）
  ├─ OllamaInference（未来：本机 Ollama HTTP）
  ├─ MlxInference（未来：Apple MLX）
  └─ RemoteInference（未来：显式远端 endpoint）
```

- 新 adapter 只实现 `prepare/start/getView/stop/dispose`，复用同一套安装任务、目录、激活/停用、状态与回退逻辑。
- Qwen / Llama 只作为 manifest/catalog 中的模型包，不新增服务。
- 不按模型拆 daemon，不新增公共 MCP 工具，不建立第二套记忆存储或同步。
