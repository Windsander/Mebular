# Mebular 0.3.0 MCP Memory Capability API（内部契约 v1）

**状态**：v1.0 / G0-A 冻结稿，2026-10-30
**上位契约**：[`0.3.0-memory-runtime-contract-v2.md`](./0.3.0-memory-runtime-contract-v2.md)
**实现位置**：`@mebular/mcp` 的 `src/memory-capability.mjs`，运行在 **MCP daemon runtime** 内
**调用方**：只允许 `@mebular/memory-runtime` sidecar（本机 loopback）
**不是**：公共 MCP 工具面；不得注册为 MCP tool；不得暴露给 `/mcp` 客户端

---

## 0. 一页结论

- Base path：`http://127.0.0.1:<mcpPort>/internal/memory/v1`
- 认证：**loopback + capability token**；无 OAuth、无 cookie、无 CORS。
- 能力：读（query/search/history/profile/skills/graph）、写（write/update/delete/archive）、内部对象（compact/self/checkpoint）、状态（status/sync/namespaces/version）。
- 归属：所有写请求带 `domain`，服务端推导 `ownerType` / `ownerId`；所有读结果带 `domain` / `owner` / `provenance`。
- 持久化：只调用现有 `MemoryService` / `Mebular` 公共方法；不直接开 `GraphStore` / `EventLog`；不新增事件类型、不新增同步协议。
- 幂等：`Idempotency-Key` 或 `requestId`；批量逐项 `clientItemId`；24h 本地账本 + 内容哈希兜底。
- 事务：**校验原子、落库逐项**；没有跨节点事务；崩溃后按幂等重放补齐，响应明确 `partial`。
- 版本：`capabilityApiVersion=1`；major 不兼容直接拒绝；minor 只做加法。
- 大小：body ≤ 2 MiB；批量 ≤ 100；单条内容 ≤ 256 KiB；其余见 §9。
- 与 29 工具：capability 是内部能力，不是第 30 个工具；公共工具的名称、参数、返回、scope 全部不变。

## 1. 传输、路径与生命周期

### 1.1 Base path

```text
http://127.0.0.1:<mcpPort>/internal/memory/v1
```

- 与 `/mcp`、`/healthz`、`/admin/api/*` **同端口**，但路径空间独立。
- **stdio `mebular mcp` 不承载 capability API**；sidecar 只连接 MCP daemon（HTTP）。轻量 stdio 模式不启动 sidecar。
- 只监听 loopback（`127.0.0.1` / `::1`）。不监听 `0.0.0.0`、LAN、WAN。
- 不经过反向代理；若部署了反代，必须在反代层拒绝 `/internal/**`。
- 不支持 HTTP/2 特殊语义；普通 HTTP/1.1 JSON 即可。

### 1.2 挂载条件

| MCP 配置 | `/internal/memory/v1` | 说明 |
|---|---|---|
| `memoryRuntime.enabled=false`（默认，轻量） | **不挂载**（或仅保留返回 404 `capability_disabled` 的守卫） | 无 token 文件、无 sidecar、无业务处理 |
| `memoryRuntime.enabled=true`（沉浸式） | 挂载 | MCP 生成 capability token；允许 sidecar 连接 |

- 切换 `enabled` 不需要重启 MCP daemon；配置应用后动态挂载/卸载。
- 卸载时立即撤销 token；已建立的 sidecar 连接在下一次请求收到 401，随后退出或降级。
- 轻量模式不得因为 capability 模块加载而创建目录、端口、进程或模型文件。

### 1.3 版本

- 路径中的 `v1` 是 capability API major 版本；破坏性变更走 `/internal/memory/v2`。
- `capabilityApiVersion` 固定为 `1`；`schemaVersion` 固定为 `1`（wire schema）。
- 响应可追加字段；客户端必须忽略未知字段。
- 未知路径返回 404 `not_found`；未知方法返回 405 `method_not_allowed`。

## 2. 认证与调用方

### 2.1 Capability token

- MCP daemon 在 `memoryRuntime.enabled=true` 时生成：
  - 至少 32 字节随机；base64url；长度约 43 字符。
  - 进程内保存 `{tokenId, tokenHash, issuedAt, expiresAt, capabilities}`。
  - 只通过两种方式交给 sidecar：
    1. MCP 启动 sidecar 子进程时注入 `MEBULAR_CAPABILITY_TOKEN`；
    2. 写入 `<home>/memory-runtime/capability-token`（`0600`），供手动启动/重启的 sidecar 读取。
  - 文件内容只含 `{version:1, token, issuedAt, expiresAt, mcpPid}`；**不含**其他秘密。
- Token 权限：`memory.read`、`memory.write`、`memory.admin`（sidecar 需要治理/内部对象）。Token 不绑定单个 Agent；Agent 身份由请求体 `actor` 声明，属于逻辑约束（见 §6）。
- 轮换：MCP 每次启动生成新 token；旧 token 立即失效。sidecar 收到 401 后重读 token 文件并重试**一次**；仍失败进入 `degraded`，不阻塞宿主。
- Token 不得出现在：URL query、日志、错误详情、`status`、`runtime.json`、Console、事件、同步。

### 2.2 Loopback 校验

服务端在路由前检查：

1. `req.socket.remoteAddress` 必须是 `127.0.0.1`、`::1`、`::ffff:127.0.0.1` 之一；否则 403 `loopback_required`。
2. `Host` 头必须是 `127.0.0.1:<port>`、`localhost:<port>` 或 `[::1]:<port>`；否则 403。
3. 若存在 `Origin` 头，必须是 loopback 自身；否则 403。
4. 不返回任何 `Access-Control-Allow-*` 头。
5. 不支持 cookie 认证；`Cookie` 头被忽略。

### 2.3 Actor

所有读/写请求必须带 `actor`：

```jsonc
{
  "actor": {
    "type": "agent",          // "agent" | "user" | "system"
    "agentId": "opencode",    // type=agent 必填
    "userId": "u_...",        // type=user 可选；服务端以身份为准
    "displayName": "OpenCode" // 仅显示，不参与域键
  }
}
```

| actor.type | 适用 | 说明 |
|---|---|---|
| `agent` | sidecar 代表某个 Agent | 必须带稳定 `agentId`；显示名只作 provenance |
| `user` | 用户治理 / Console 代理 | 可读全部域、写 user、删除/归档 |
| `system` | MCP 内部维护 | 只用于内部对象/迁移，不作为普通召回 actor |

服务端校验：

- `agentId` 必须匹配 `^[a-z0-9][a-z0-9._-]{0,63}$`；否则 400 `invalid_agent_id`。
- `actor.type='agent'` 但缺 `agentId` → 400 `invalid_request`。
- `actor.type='system'` 只允许 capability token 的 admin 能力；普通 sidecar 请求不得使用（403 `forbidden_scope`）。
- `actor` 不是认证；拿到 token 的本地调用方可以声明任意 actor。0.3 不做 token 到 Agent 的密码学绑定；sidecar 必须按本地 policy 约束自己代表的 Agent。

## 3. 通用信封、字段与分页

### 3.1 请求头

| 头 | 必填 | 说明 |
|---|---|---|
| `Authorization: Bearer <token>` | 是 | capability token |
| `Content-Type: application/json` | POST 是 | UTF-8 |
| `Idempotency-Key` | 写请求建议 | `[A-Za-z0-9._:-]{1,200}`；与 body `requestId` 二选一 |
| `X-Request-Id` | 否 | 调用方追踪 id；服务端回显 |
| `X-Mebular-Capability-Version` | 否 | 调用方期望的 major；不匹配 409 `capability_version_unsupported` |

### 3.2 响应头

| 头 | 说明 |
|---|---|
| `X-Request-Id` | 服务端生成或回显 |
| `X-Mebular-Capability-Version` | 固定 `1` |
| `X-Mebular-Degraded` | `true` / `false` |
| `Retry-After` | 429/503 时给出秒数 |

### 3.3 成功信封

```jsonc
{
  "ok": true,
  "requestId": "req_01J...",
  "capabilityVersion": 1,
  "data": { },
  "warnings": [],
  "degraded": false
}
```

### 3.4 失败信封

```jsonc
{
  "ok": false,
  "requestId": "req_01J...",
  "capabilityVersion": 1,
  "error": {
    "code": "domain_write_forbidden",
    "message": "Agent 不能写入其他 Agent 的记忆域",
    "retryable": false,
    "details": { "domain": "agent:hermes", "actor": "opencode" }
  }
}
```

- `message` 是短句，不含正文/密钥。
- `details` 只放非敏感结构；不得放完整 raw、token、Authorization、模型 prompt。
- 未知错误 code 由客户端按字符串处理。

### 3.5 时间、ID、编码

- 时间：Unix ms（整数）。
- 节点 ID：现有 ULID 字符串；本地对象 ID 使用 `rc_` / `tr_` / `ext_` 前缀（不进入此 API）。
- 文本：UTF-8；`content` 是结构化对象；`text` 是服务端生成的扁平字符串（给模型消费）。
- 未知字段：服务端忽略；客户端也必须忽略响应中的新增字段。
- `null` 与缺省：可空字段返回 `null`，不返回 `undefined`。

### 3.6 分页

- `limit`：1–50，默认 10（与公共工具上限一致）。
- `offset`：≥0，默认 0。
- 响应：`{items/records, total, offset, limit, hasMore}`。
- 不使用 cursor；现有 MemoryService 是 offset 语义，0.3 不引入新分页协议。

## 4. 对象与域字段

### 4.1 归属四元组（所有持久对象）

```jsonc
{
  "domain": "agent:opencode",
  "ownerType": "agent",
  "ownerId": "opencode",
  "provenance": {
    "source": "runtime",
    "writerType": "agent",
    "writerId": "opencode",
    "extractor": "host",
    "model": "host-provided",
    "version": "0.3.0",
    "deviceId": "device-...",
    "hostId": "h_...",
    "threadId": "th_...",
    "agentName": "OpenCode",
    "messageIds": ["m1"],
    "rawChunkIds": ["rc_..."],
    "confirmation": "none",
    "at": 1730000000000
  }
}
```

规则：

- `domain` 由写请求给出；服务端按 §5.1 推导 `ownerType` / `ownerId`。
- 客户端提交 `ownerType`/`ownerId` 时，服务端必须校验；不一致返回 400 `owner_mismatch`。
- `provenance` 由客户端提交来源字段，服务端补 `deviceId`、`hostId`、`version`、`at`；客户端不能覆盖服务端字段。
- `provenance` 不进入普通记忆文本；只作为 metadata 返回。
- `rawChunkIds` 只在本机有意义；跨设备读取时可能为空，读取方不得据此判断记忆不存在。

### 4.2 MemoryRecord 视图

```jsonc
{
  "id": "01J...",
  "type": "fact",                    // entity | fact | episode | skill | meta
  "kind": "preference",              // fact 的语义细分：fact | preference | observation | ...
  "domain": "user",
  "namespace": "user",               // v2 中 domain=namespace；保留字段兼容
  "ownerType": "user",
  "ownerId": "u_...",
  "provenance": { },
  "content": { "subject": "user", "predicate": "theme", "object": "dark", "confidence": 0.9 },
  "text": "user prefers dark theme",
  "tags": ["ui"],
  "validFrom": 1730000000000,
  "validTo": null,
  "createdAt": 1730000000000,
  "updatedAt": 1730000000000,
  "score": 0.91,
  "why": "vector+keyword",
  "detailAvailable": true,
  "legacy": false
}
```

- `kind` 映射：`fact` / `preference` / `observation` → 节点 type `fact`（preference 带 `preference` tag；observation 是 fact 的语义）；`episode` / `skill` / `entity` / `meta` 原样。
- `legacy=true`：0.2 数据，无 `metadata.internal`/provenance；域按 namespace 推导。
- `detailAvailable=false`：只有沉降摘要/跨设备缺 Raw；不得伪造原文。
- `score`/`why` 只在 query/search/recall 结果出现；列表/详情可省略。

### 4.3 内部对象视图

```jsonc
{
  "id": "01J...",
  "type": "compact",                 // compact | self_record | context_checkpoint
  "kind": "compact",
  "domain": "notes",
  "ownerType": "other",
  "ownerId": "notes",
  "internal": true,
  "provenance": { },
  "content": { },
  "createdAt": 0,
  "updatedAt": 0
}
```

- 内部对象不出现在 `/query`、`/search`、`/history`、`/profile`、`/skills`、`/graph` 的默认结果中。
- 只能通过 `/internal-object` 读写。
- 所有内部对象节点必须带 `metadata.internal=true`；core 只依赖这个通用标记，不认识 runtime 类型名。

## 5. 域、归属与权限

### 5.1 域 → owner 推导

| domain | ownerType | ownerId |
|---|---|---|
| `user` | `user` | `userId`（`u_...`） |
| `agent:<id>` | `agent` | `<id>` |
| `default` | `other` | `default` |
| `task:<id>` | `other` | `task:<id>` |
| `shared` | `other` | `shared` |
| `system` | `other` | `system` |
| 旧 namespace（`notes` 等） | `other` | 该 namespace |

### 5.2 写权限

| 目标 domain | actor=user | actor=agent（域所有者） | actor=agent（其他） | actor=system |
|---|---|---|---|---|
| `user` | 允许 | 仅 `provenance.confirmation='explicit'` | 同左；否则 403 | 允许 |
| `agent:<self>` | 允许 | 允许 | 禁止 | 允许 |
| `agent:<other>` | 允许 | 禁止 | 禁止 | 允许 |
| `default` | 允许 | 允许 | 允许 | 允许 |
| `task:<thread>` | 允许 | 参与者 + thread 匹配 | 参与者 + thread 匹配 | 允许 |
| `shared` | 允许 | 允许 | 允许 | 允许 |
| `system` | 仅 admin | 禁止 | 禁止 | 允许 |
| 旧 namespace | 允许 | 按显式域授权 | 按显式域授权 | 允许 |

补充：

- “其他 Agent 写 `agent:<other>`”永远禁止；订阅只给读权限。
- `user` 域写入缺少 `confirmation` → 403 `domain_write_forbidden`，`details.allowedDomain` 给出 `agent:<actor>`，方便 sidecar 降级。
- `system` 域只用于内部维护；普通 sidecar 不写。
- 删除/归档：user/system 可治理全部；agent 只能治理自己域内且 `provenance.writerId` 为自己的记录；否则 403 `forbidden_scope`。
- 0.3 不做 per-record ACL；以上是逻辑约束。

### 5.3 读权限与默认域

默认域（请求未给 `domains`）：

| 端点 | 默认域 |
|---|---|
| `query` / `search` | `user`、`agent:<actor>`、`default`、`task:<currentThread>` |
| `history` | 同上 |
| `profile` | `user` + 非 Agent 域的 legacy 用户事实 |
| `skills` | `user`、`agent:<actor>`、`default`、`shared` |
| `graph` | 起点所在域 + 默认域 |
| `internal-object` compact | 来源域 |
| `internal-object` self_record | `agent:<target>` |
| `internal-object` context_checkpoint | 记录所在域 |

显式域：

- `domains` 最多 16 个；每项必须是合法域。
- **capability 服务端不持有 per-Agent 授权表**：它按请求域返回，并用写权限矩阵兜底；按 Agent 的读/写授权由 sidecar 的 `policy.json` 在发请求前执行（见 sidecar 文档）。
- `strictDomains=true` 时，任一未知/未同步域 → 403 `domain_read_forbidden`；默认 `false`，逐项 warning 并跳过。
- capability token 持有者仍可读取本机全部已同步数据；这是逻辑隔离，不是密码学隔离。
- 其他 Agent 域只有显式列出才返回；结果必须带 `ownerType=agent`、`provenance.agentId`、`agentName`、`deviceId`/`hostId`。
- 0.2 的任意 namespace（`notes` 等）是显式 Other 域，不自动进入默认域；sidecar 需在 `policy.json` 的 `readDomains` 显式加入。`default` 默认包含。
- 0.3 不新增 namespace ACL；`memory.read` 等价能力仍是本云全量读。capability 的域过滤是**产品级逻辑隔离**，不是密码学隔离。

### 5.4 订阅

- 物理订阅：现有 `sync.namespaces` / `namespace_subscription`；空 = 全部；语义不变。
- capability API 不修改订阅；只读 `GET /namespaces` 暴露当前状态。
- 订阅变化继续走现有 MCP/CLI/Console；不新增 `POST /subscribe`，不新增同步协议。
- sidecar 的按 Agent 授权是本地 policy，不是订阅；不得把 policy 写进图或同步。

## 6. 端点契约

> 以下示例省略外层 `ok/requestId/data/warnings`，只写 `data`；实现必须使用统一信封。所有时间单位 ms。

### 6.1 `GET /version`

**认证**：capability token（若已挂载）
**用途**：版本/能力探测；sidecar 启动时第一步。

```jsonc
{
  "capabilityApiVersion": 1,
  "schemaVersion": 1,
  "mcpVersion": "0.3.0",
  "coreVersion": "0.3.0",
  "features": {
    "domains": true,
    "owner": true,
    "provenance": true,
    "batchWrite": true,
    "idempotency": true,
    "internalObjects": ["compact", "self_record", "context_checkpoint"],
    "sync": true,
    "graph": true
  },
  "limits": {
    "maxBodyBytes": 2097152,
    "maxBatchItems": 100,
    "maxContentBytes": 262144,
    "maxDomains": 16,
    "maxLimit": 50,
    "maxGraphDepth": 5,
    "maxCheckpointStateBytes": 262144,
    "maxCompactSources": 200
  },
  "domains": {
    "reserved": ["user", "default", "shared", "system"],
    "agentPrefix": "agent:",
    "taskPrefix": "task:",
    "policyDomain": "__policy__"
  }
}
```

- major 不兼容：sidecar 退出 `version_incompatible`。
- 未挂载：404 `capability_disabled`。

### 6.2 `GET /status`

**Query**：`actor`（JSON 编码或 `agentId`）、`includeCounts=true|false`
**用途**：身份、初始化、计数、同步、限制。

```jsonc
{
  "initialized": true,
  "identity": {
    "cloudId": "cl_...",
    "userId": "u_...",
    "profileId": "default",
    "deviceId": "device-...",
    "hostId": "h_..."
  },
  "counts": {
    "nodes": 1234,
    "memoryRecords": 1200,
    "compacts": 4,
    "checkpoints": 2,
    "selfRecords": 1
  },
  "domains": [
    { "domain": "user", "ownerType": "user", "count": 120 },
    { "domain": "agent:opencode", "ownerType": "agent", "count": 80 },
    { "domain": "default", "ownerType": "other", "count": 900 }
  ],
  "sync": {
    "running": true,
    "pendingEvents": 0,
    "subscriptions": { "mode": "all", "namespaces": [] },
    "lastSyncAt": 1730000000000
  },
  "limits": { "maxBodyBytes": 2097152, "maxBatchItems": 100, "maxLimit": 50 }
}
```

- 计数是近似值，不保证与 EventLog 水位强一致。
- 不返回 token、key、raw 文本。

### 6.3 `GET /namespaces`

**Query**：`actor`、`includeCounts=true|false`
**用途**：域/namespace、订阅、计数。

```jsonc

  "domains": [
    {
      "domain": "agent:hermes",
      "ownerType": "agent",

      "lastUpdatedAt": 1730000000000

    {
      "domain": "notes",
      "ownerType": "other",
      "ownerId": "notes",
      "namespace": "notes",
```

**用途**：语义/关键词召回（sidecar 的召回基础）。

```jsonc

  "limit": 20,
  "offset": 0,
  "includeHistory": false,
  "includeArchived": false,
  "filters": {
    "tags": ["ui"],
    "createdAfter": 0,
    "createdBefore": 0,
    "entity": "user",
    "minConfidence": 0.5
  }

```


### 6.10 `POST /write`

**用途**：sidecar 沉降 MemoryRecord；单条/批量。

```jsonc
// request
{
  "requestId": "req_01J...",       // 可选；等价 Idempotency-Key
  "actor": { "type": "agent", "agentId": "opencode" },
  "items": [
    {
      "clientItemId": "cand_01",  // 可选；批量逐项幂等
      "domain": "agent:opencode",
      "kind": "observation",
      "content": { "content": "项目使用 pnpm workspace" },
      "tags": ["tooling"],
      "relatedTo": ["01J..."],
      "provenance": {
        "source": "runtime",
        "extractor": "heuristic",
        "model": null,
        "threadId": "th_...",
        "messageIds": ["m1"],
        "rawChunkIds": ["rc_..."],
        "confirmation": "none"
      }
    },
    {
      "clientItemId": "cand_02",
      "domain": "user",
      "kind": "preference",
      "content": { "entity": "user", "preferenceType": "theme", "value": "dark", "confidence": 0.9 },
      "provenance": {
        "source": "runtime",
        "extractor": "host",
        "confirmation": "explicit",
        "threadId": "th_..."
      }
    }
  ]
}
```

```jsonc
// response data
{
  "results": [
    { "clientItemId": "cand_01", "status": "created", "id": "01J...", "domain": "agent:opencode", "ownerType": "agent", "ownerId": "opencode" },
    { "clientItemId": "cand_02", "status": "duplicate", "id": "01K...", "domain": "user", "ownerType": "user", "ownerId": "u_..." }
  ],
  "created": 1,
  "duplicates": 1,
  "failed": 0,
  "partial": false,
  "replayed": false
}
```

规则：

- `items` 1–100；`content` 必填，按 `kind` 校验；shape 见下表。
- `kind`：`fact` / `preference` / `episode` / `skill` / `entity` / `observation`。
- `domain` 必填；**sidecar 必须显式给出，不得让服务端猜**；`owner` 由服务端推导；客户端提交不一致 → 400 `owner_mismatch`。
- `relatedTo` 只允许已存在、非内部、可读域的节点；不存在的引用丢弃并加 warning，不建悬空边。
- 校验**原子**：任一 item schema/域/owner 校验失败 → 422 `validation_failed`，**不写任何 item**。
- 落库**逐项**：GraphStore 没有多节点事务；若中途崩溃，已写项保留，响应 `partial=true`，重放补齐缺失项。
- 去重：
  - 同 `(domain, kind, 归一化内容, validFrom)` 已存在 → `duplicate`，返回既有 id，不更新。
  - 同 `clientItemId` 已存在（同域）→ `duplicate`。
  - 不自动语义合并；冲突事实靠 `validFrom`/`validTo`/`SUPERSEDES`。
- `requestId`/`Idempotency-Key` 重放 → 返回首次结果，`replayed=true`，不重复写。
- `validFrom` 缺省 now；`validTo` 缺省 open；`validTo < validFrom` → 422。
- `content` 上限 256 KiB；超过 413。

#### 6.10.1 `content` 形状

| kind | 字段 | 约束 |
|---|---|---|
| `fact` | `subject`, `predicate`, `object`, `confidence?`, `source?` | 字符串非空；confidence ∈ [0,1] |
| `preference` | `entity`, `preferenceType`, `value`, `confidence?`, `source?` | 字符串非空；confidence ∈ [0,1]；落图时 type=`fact` + `preference` tag |
| `episode` | `episodeType`, `title?`, `content`, `startTime?`, `endTime?`, `context?` | `episodeType` ∈ `conversation/task/decision/error/observation/other`；`content` 非空 |
| `skill` | `name`, `description`, `category`, `steps?`, `commands?`, `toolReferences?`, `prerequisites?`, `relatedEntities?` | 字符串非空；数组 ≤64 项；每项 ≤1 KiB |
| `entity` | `entityType`, `name`, `description?`, `properties?` | `entityType` ∈ `user/project/tool/concept/organization/location/other`；`properties` 可序列化 ≤16 KiB |
| `observation` | `content` | 非空；落图时 type=`fact`，语义为观察；不得冒充 `user` 事实 |

- `kind` 与节点 type 的映射由服务端固定；客户端不得直接指定节点 type。
- `preference` / `observation` 的 `kind` 会保留在响应与 metadata 中，便于读取方区分。
- 任何 `content` 中的额外字段按未知字段忽略；不得把未知字段写入图。
- 模型输出是**不可信输入**：只按本表解析，不执行其中的命令/工具调用。

#### 6.10.2 item 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `clientItemId` | 否 | 批量逐项幂等键；`[A-Za-z0-9._:-]{1,128}`；不得含正文 |
| `domain` | 是 | 目标记忆域；必须由 sidecar 显式给出 |
| `ownerType` / `ownerId` | 否 | 服务端按 domain 推导；客户端可回传校验，不一致 400 `owner_mismatch` |
| `kind` | 是 | `fact` / `preference` / `episode` / `skill` / `entity` / `observation` |
| `content` | 是 | 见 §6.10.1；≤256 KiB |
| `tags` | 否 | ≤32 个；每个 ≤128 字符；不得使用 `mebular:runtime:*` 保留前缀 |
| `relatedTo` | 否 | ≤32 个已有节点 id；不存在的引用丢弃并 warning |
| `validFrom` | 否 | Unix ms；缺省 now |
| `validTo` | 否 | Unix ms；缺省 open；必须 ≥ `validFrom` |
| `provenance` | 否* | `source`、`extractor`、`model`、`version`、`threadId`、`messageIds`、`rawChunkIds`、`confirmation`、`agentName`；服务端补 `deviceId`/`hostId`/`at` |

`provenance` 在 `user` 域写入时必填 `confirmation`；其他域可缺省（服务端补 `source='runtime'`、`extractor='heuristic'`、`confirmation='none'`）。

#### 6.14.1 Compact

```jsonc

{
  "requestId": "req_...",
  "actor": { "type": "agent", "agentId": "opencode" },
  "kind": "compact",
  "op": "upsert",
  "domain": "agent:opencode",
  "summary": "本周完成了 sidecar 边界重构……",
  "sourceIds": ["01J...", "01K..."],
  "sourceHashes": ["sha256:...", "sha256:..."],

  "model": { "extractor": "local", "model": "qwen3-9b-q4", "version": "0.3.0" },

```

```jsonc
// upsert response
{
  "object": {
    "id": "01M...", "type": "compact", "kind": "compact", "domain": "agent:opencode",
    "internal": true, "summary": "...", "sourceIds": ["01J...", "01K..."],
```

规则：

## 7. 幂等、批量与事务边界

### 7.1 幂等键

| 层级 | 键 | 存储 | 生效范围 |
|---|---|---|---|
| 请求 | `Idempotency-Key` 或 body `requestId` | MCP 本地账本 `<home>/memory-runtime/capability-idempotency.json`（`0600`） | `(tokenId, route, key)` |
| 批量项 | `clientItemId` | 节点 `metadata.clientItemId`（随图同步） | `(domain, clientItemId)` |
| 内容 | 归一化内容 hash | 节点内容 | `(domain, kind, hash, validFrom)` |

规则：

- 请求级账本保留 24h，最多 5000 条；LRU 淘汰；不进入图、不同步。
- 同 key 重放：返回首次成功响应 + `replayed:true`；不重新执行。
- 同 key 不同 body hash：409 `idempotency_conflict`。body hash 使用 canonical JSON（键排序、无多余空白）。
- 账本丢失：`clientItemId` 与内容 hash 仍可防重；最坏产生一次重复，不丢数据。
- `clientItemId` 不得包含用户正文；只允许 `[A-Za-z0-9._:-]{1,128}`。
- 幂等账本是过渡数据，不是权威；不得用于跨设备去重。

### 7.2 批量

| 端点 | 上限 | 校验 | 落库 | 失败返回 |
|---|---|---|---|---|
| `/write` | 100 | 原子：任一项非法 → 422，不写 | 逐项 | `results[]` + `partial` |
| `/update` | 100 | 原子 | 逐项 | 同上 |
| `/delete` | 100 | 原子（id/权限） | 逐项 | `deleted/notFound/forbidden` |
| `/archive` | 100 | 原子 | 逐项 | 同上 |
| `/internal-object` | 1 对象 | 单对象 | 单节点事件 | 4xx |

### 7.3 事务边界

- **没有跨节点事务。** GraphStore 是逐节点事件；capability 不引入两阶段提交。
- **校验原子**：请求级 schema/域/owner/权限全部通过后才开始写。
- **落库逐项**：中途崩溃可能留下前缀；响应 `partial=true` 并列出已完成项；sidecar outbox 用同一幂等键重放，补齐缺失项。
- **单对象原子**：checkpoint/self 的单次 upsert 是一个节点事件；revision 检查在写前。
- **compact**：单节点；源记录不变；失败不产生半个 compact。
- **不承诺**：写入成功即已同步到其他设备；只承诺已进入本地图和事件日志，后续由现有同步传播。

### 7.4 重试建议

- 429/503：指数退避（1s、2s、4s…，上限 60s），尊重 `Retry-After`。
- 409 `revision_mismatch`：重新读取后重试；不要盲目覆盖。
- 409 `idempotency_conflict`：换新 key 或修正 body；不要复用。
- 422/403：不重试；记录 warning，丢弃该候选或降级到 `agent:<self>`。
- 网络错误：只有请求未到达/响应丢失时才重试；用同一 `Idempotency-Key`。

## 8. 错误码

| HTTP | code | 含义 | retryable |
|---|---|---|---|
| 400 | `invalid_request` | JSON/schema/字段非法 | false |
| 400 | `invalid_agent_id` | agentId 格式非法 | false |
| 400 | `invalid_thread_id` | threadId 格式非法 | false |
| 400 | `domain_invalid` | 域语法非法 | false |
| 400 | `domain_mismatch` | compact/checkpoint 域不一致 | false |
| 400 | `owner_mismatch` | 客户端 owner 与服务端推导不一致 | false |
| 400 | `internal_kind_invalid` | 内部对象 kind/op 非法 | false |
| 401 | `capability_token_invalid` | 缺/错 token | false |
| 403 | `loopback_required` | 非 loopback 调用 | false |
| 403 | `domain_write_forbidden` | actor 不能写该域 | false |
| 403 | `domain_read_forbidden` | strict 模式下不能读该域 | false |
| 403 | `forbidden_scope` | 治理/系统动作权限不足 | false |
| 404 | `not_found` | 对象/域/路径不存在 | false |
| 404 | `internal_object` | 公共入口访问内部对象 | false |
| 404 | `capability_disabled` | 轻量模式未挂载 capability API | false |
| 405 | `method_not_allowed` | 方法不支持 | false |
| 409 | `revision_mismatch` | checkpoint/self 版本冲突 | true（重读后） |
| 409 | `update_conflict` | 节点 `expectedUpdatedAt` 冲突 | true（重读后） |
| 409 | `idempotency_conflict` | 同 key 不同 body | false |
| 409 | `capability_version_unsupported` | major 不兼容 | false |
| 409 | `checkpoint_lease_held` | 其他 host 持有租约 | true（租约过期） |
| 413 | `payload_too_large` | body/内容/state 超限 | false |
| 422 | `validation_failed` | 批量校验失败（原子拒绝） | false |
| 429 | `rate_limited` | 限流；带 `Retry-After` | true |
| 500 | `internal` | 未分类错误 | true |
| 503 | `capability_unavailable` | MemoryService/图不可用 | true |
| 503 | `sync_unavailable` | 同步未启用/不可用 | true |

- 错误响应不得包含 token、key、完整正文、模型 prompt。
- `details` 可包含 `domain`、`actor`、`field`、`index`、`currentRevision`、`currentUpdatedAt` 等非敏感信息。
- 未知 code：客户端按字符串透传，不崩溃。

## 9. 大小、限流与性能预算

### 9.1 大小

| 项 | 上限 | 超限 |
|---|---|---|
| 请求体 | 2 MiB | 413 `payload_too_large` |
| 批量 items | 100 | 413/422 |
| 单条 `content` | 256 KiB | 413 |
| `query` 文本 | 8 KiB | 413 |
| `domains` | 16 | 400 `invalid_request` |
| `tags` | 32 个 × 128 字符 | 400 |
| `messageIds` | 64 | 400 |
| `graph.maxDepth` | 5 | 钳制或 400 |
| `limit` | 50 | 钳制 |
| checkpoint `state` | 256 KiB | 413 |
| compact `summary` | 64 KiB | 413 |
| compact `sourceIds` | 200 | 413 |
| `provenance` 序列化 | 8 KiB | 413 |

### 9.2 限流（建议基线）

| 类别 | 限额 |
|---|---|
| 读（query/search/history/profile/skills/graph/status/namespaces） | 600 req/min/token，burst 60 |
| 写（write/update/delete/archive/internal-object） | 120 req/min/token，burst 30 |
| sync POST | 10 req/min/token |
| version | 不单独限流（计入读） |

- 超限 429 + `Retry-After`。
- 不静默截断；context token 预算由 sidecar 负责，不在 capability 层。

### 9.3 性能预算（建议，非硬承诺）

- 10k MemoryRecord 的 `query`（heuristic）p95 < 150ms。
- `write` 单条 p95 < 50ms（本机 SSD，不含同步）。
- `status` p95 < 100ms（10k 节点）。
- 批量 100 条 heuristic 写入 < 2s。
- 任何端点不得因为同步/模型调用阻塞超过 5s；超时返回 503/504。

## 11. 与公共 29 工具的关系

### 11.1 映射

| Capability 端点 | 公共工具（不变） | MemoryService 方法 | 说明 |
|---|---|---|---|
| `POST /write` | `memory_write` / `memory_write_batch` | `writeRecords` | capability 增加 domain/owner/provenance；公共工具保持 0.2 |
| `POST /query` | `memory_query` | `query` | 类型展开/域过滤/分页/内部归档过滤共用同一实现 |
| `POST /search` | `memory_search` | `search` | 同上（含关系端点过滤） |
| `POST /history` | `memory_history` | `history` | 同上 |
| `POST /profile` | `memory_profile` | `profile({domains})` | capability 传授权域；公共工具仍全局 |
| `POST /skills` | `memory_skills` | `skillPage({domains})` | capability 增加域过滤与 total |
| `POST /graph` | `memory_graph` | `graph({domains})` | 深度/边类型/域/内部归档过滤共用 |
| `POST /delete` | `memory_delete` | `delete` | 相同墓碑语义 |
| `POST /archive` | `memory_archive` | `archive` | 相同归档语义 |
| `GET /status` | `memory_status` | `stats` + `status` | capability 域计数来自 `MemoryService.stats`；公共字段不变 |
| `GET /namespaces` | 无 | `stats` | 域统计与公共 `memory_status` 同源 |
| `GET/POST /sync` | `memory_sync` | `syncStatus` / `sync` | GET 额外字段由 capability 组装，数据源统一 |
| `GET /version` | 无 | 无 | 新内部能力 |
| `POST /internal-object` | 无 | 无 | Compact/Self/Checkpoint 受控入口（唯一允许直接 GraphStore 写入的例外） |
| `memory_import` | 保留 | `import` | capability v1 不提供导入；批量导入仍走公共工具，不是第二套实现 |
| `task_*`（16） | 保留 | `@mebular/fleet` `TASK_TOOLS` | capability 不涉及任务面；MCP task tools 与 fleet CLI 共用同一 handler |

### 11.2 边界

- capability API **不注册**为 MCP tool；`mebular tools` 仍 29。
- capability API 不改变公共工具的参数/返回字段；preference/observation 的语义类型展开与 capability 共用同一规则。
- capability API 不向公共工具暴露 `includeInternal`。
- capability API 不是 `/mcp` 的子路径；MCP 客户端无法通过工具调用它。
- capability API 只允许 sidecar 的 host token 调用；不签发 OAuth scope。
- 公共工具仍是 0.2 响应形状（无 agent 域字段）；域隔离在 capability/sidecar 层。
- 如果未来要把 capability 暴露为公共工具，必须新开契约；0.3 不做。

### 11.3 共享实现

- capability 与公共工具都调用同一个 `MemoryService`，避免两套语义。
- 类型展开、域/namespace、分页、内部/归档过滤、legacy profile、graph 深度/边过滤都在 `MemoryService` 执行；capability 只做授权域、owner/provenance 投影和响应信封。
- `status` / `namespaces` 的计数与域来自 `MemoryService.stats()`；`/sync` GET 来自 `MemoryService.syncStatus()`，不在 capability 里另扫图或另拼同步状态。
- 内部对象写入是唯一例外：由 capability 调用 `Mebular.graph` 的公共节点方法，不直接打开 `GraphStore` 文件；普通 MemoryRecord 不得走这条路径。
- 任务面只有 `@mebular/fleet` 的 `TASK_TOOLS` handler；MCP 适配器在无稳定 Agent 身份时显式使用 `board`，fleet CLI 的 `--agent` 是同一 handler 的显式覆盖。capability v1 不提供任务端点。
- 事件类型仍为 `node_created` / `node_updated` / `node_deleted`；不新增。

## 12. 安全与审计

### 12.1 审计

每次 capability 调用记录一条结构化日志（MCP 侧）：

```jsonc
{
  "at": 1730000000000,
  "requestId": "req_...",
  "actorType": "agent",
  "actorId": "opencode",
  "endpoint": "write",
  "domain": "agent:opencode",
  "count": 2,
  "status": 200,
  "tookMs": 12,
  "degraded": false
}
```

- 不记录正文、query 全文、token、key、模型 prompt。
- 审计日志可写 `<home>/logs/memory-capability.jsonl`（现有日志目录），轮转沿用 MCP 日志策略。
- 治理动作（delete/archive/internal-object delete）额外记录 `targetIds`（只记 id）。

### 12.2 禁止事项

- 禁止把 capability token 写进 URL/query。
- 禁止在 capability API 上启用 CORS。
- 禁止把 capability API 暴露到非 loopback。
- 禁止 capability API 读写 `__policy__`。
- 禁止 capability API 返回 raw 文本；Raw 只在 sidecar 本地。
- 禁止 capability API 直接调用模型/网络；它只做记忆读写。
- 禁止 capability API 创建第二套同步/事件。

### 12.3 失败开放

- capability API 不可用：sidecar 读缓存、写 outbox；宿主不阻塞。
- capability API 返回 5xx：sidecar 指数退避；不把失败当“空记忆”写回。
- capability API 返回 403/422：sidecar 记录 warning，丢弃/降级候选；不重试。
- 公共 MCP 工具不受 capability 故障影响。

## 13. 版本演进

| 变更 | 版本策略 |
|---|---|
| 新增加法字段 | v1 内允许；客户端忽略未知字段 |

- MCP 升级不自动升级 sidecar；版本握手失败时失败开放。
- 契约测试 fixtures 按 major 目录存放：`v1/`、未来 `v2/`。
