## 0. 结论摘要

1. **0.2 是底座，0.3 是增量。** 现有 MCP 的 29 个公共工具、daemon 生命周期、单写者锁、鉴权、同步协议、忆云拓扑全部保持。0.3 不替换、不重写、不迁移底座。
2. **一个能力提供者。** `@mebular/mcp` 继续提供公共 MCP 工具面，并新增**内部** Memory Capability API；**不新增公共 MCP 工具**。
3. **一个独立 sidecar。** `@mebular/memory-runtime` 是独立进程/独立包，位于 MCP 能力层之上。它负责采集、抽取、召回、上下文组装、compact、self、checkpoint、trace 和模型编排。
4. **不建立第二套记忆库。** Memory Runtime 不打开 `GraphStore` / `EventLog`，不定义第二套同步协议，不直接写图。所有持久记忆经 MCP capability API 写入现有图与事件日志，再由现有同步进入忆云。
5. **轻量 MCP 模式完全不启动 sidecar。** 默认模式仍是 `mcp`；用户在沉浸式模式中只做一次选择，之后由 MCP daemon 自动管理 sidecar。
6. **三类角色、四类键。** `user` / `agent:<agentId>` / `default`（Other 兜底）三类记忆域；`ownerType`、`ownerId`、`domain`、`provenance` 是每条记录的归属四元组。其他 Agent 仍是 `agent:<otherId>`，不是 `other` 域。
7. **持久记忆全部上云。** 所有 Agent 的 MemoryRecord、Compact、SelfRecord、ContextCheckpoint 都经 MCP 进入忆云。**不再提供 `sync=cloud` / `sync=local`，也不再提供 `runtime.self.sync`。**
8. **本地只留过程数据。** RawChunk / RecallTrace / cache/index/outbox / 模型文件与设备配置是本地、可重建、非权威数据。**2026-10-30 修正**：RawChunk / DetailRecord 的权威副本改为域内图对象，随现有同步跨设备；本地只保留 staging / cache / outbox，见 §15。删除本地数据不影响已沉降记忆与详情。
9. **命名彻底分离。** “MCP daemon runtime”与“Memory Runtime sidecar”是两个不同概念，代码、CLI、目录、端口、配置文件、文档都不得混用（见 §1）。
10. **当前 PR 的内嵌 runtime/inference 是原型。** 合并前必须完成边界重构：core 不 import runtime，MCP 不 import memory-runtime 业务实现，sidecar 不 import core 内部存储（见 §9）。

## 1. 术语与命名（冻结）

### 1.1 四个概念

| 概念 | 正式名称 | 所属包 | 进程 / 入口 | 用户命令 | 数据/发现文件 | HTTP 面 |
|---|---|---|---|---|---|---|
| **MCP 守护运行时** | **MCP daemon runtime** | `@mebular/mcp` + `@mebular/core` | `mebular serve` / `mebular-serve` service | `mebular runtime ...`（既有） | `<cloudRoot>/runtime/<version>/`、`<home>/runtime.json` | `/mcp`、`/healthz`、`/admin/api/*` |
| **记忆运行时旁车** | **Memory Runtime sidecar** | `@mebular/memory-runtime` | `mebular-memory-runtime serve` | `mebular memory-runtime ...`（新增） | `<home>/memory-runtime/`、`<home>/memory-runtime.json` | `/memory-runtime/v1/*` |
| **记忆能力内部接口** | **MCP Memory Capability API** | `@mebular/mcp`（`memory-capability.mjs`） | 运行在 MCP daemon 内 | 无公共命令 | `<home>/memory-runtime/capability-token`、幂等账本 | `/internal/memory/v1/*` |
| **公共 MCP 工具面** | **MCP tools（29）** | `@mebular/mcp` | stdio `mebular mcp` / HTTP `/mcp` | `mebular tools` | 无 | `/mcp` |

### 1.2 命名规则（强制）

- `mebular runtime` **只**表示 MCP daemon 生命周期（resolve / install / service / upgrade / supervise 等）。不得把 sidecar 命令挂到 `mebular runtime` 下。
- sidecar 的 CLI 组固定为 `mebular memory-runtime`；包名固定 `@mebular/memory-runtime`；可执行文件名固定 `mebular-memory-runtime`。
- sidecar 数据目录固定 `<home>/memory-runtime/`。**不得**写入 `<cloudRoot>/runtime/`：后者是 MCP daemon 的共享安装根，含 `current.json`、按版本安装的 `node_modules`。
- 0.3 原型曾把 Raw/Trace/checkpoint 写到 `<home>/runtime/`，与 daemon 安装根同名；v2 全部改到 `<home>/memory-runtime/`。旧原型目录不读取、不迁移（该原型未发布）；开发环境可直接清理。
- sidecar 发现文件固定 `<home>/memory-runtime.json`；MCP daemon 的 `runtime.json` 语义不变。
- 宿主侧 API 固定 `/memory-runtime/v1`；MCP 内部能力 API 固定 `/internal/memory/v1`。
- **0.3 原型中的 `/runtime/v1` 在发布前删除。** 该路径从未发布，不提供兼容层；DSH / Hermes / OpenChamber / OpenCode 适配器必须改到 `/memory-runtime/v1`。
- 记忆相关配置不再使用 `runtime.*`。MCP 侧只用 `memoryRuntime.*`（生命周期开关）；sidecar 自己的设置放 `<home>/memory-runtime/config.json`。`runtime.*` 如出现，只允许是 MCP daemon 的既有语义，不得承载记忆运行时配置。
- 文档与代码注释中禁止单独使用 “Runtime” 指代 sidecar；必须写全 “Memory Runtime sidecar” 或 “MCP daemon runtime”。

### 1.3 环境变量（固定前缀）

| 变量 | 作用 | 由谁设置 |
|---|---|---|
| `MEBULAR_MEMORY_RUNTIME_URL` | 覆盖 sidecar 发现文件，指向 `/memory-runtime/v1` | 宿主/调试 |
| `MEBULAR_MEMORY_RUNTIME_BIN` | 覆盖 sidecar 可执行文件路径 | MCP daemon/桌面端 |
| `MEBULAR_MEMORY_RUNTIME_TOKEN` | 覆盖 sidecar host token 文件 | MCP daemon 启动子进程时注入 |
| `MEBULAR_MEMORY_RUNTIME_DISABLE=1` | 禁止自动启动 sidecar（排障/测试） | 用户/CI |
| `MEBULAR_CAPABILITY_TOKEN` | sidecar 访问 MCP capability API 的令牌 | MCP daemon 启动子进程时注入 |
| `MEBULAR_MEMORY_RUNTIME_HOME` | 覆盖 sidecar 本地数据目录 | 测试/多 profile |

### 2.1 层图

### 2.2 三条数据流

**轻量 MCP（默认）**

```text
宿主模型 → /mcp（memory_query / memory_write / ...）
        → MemoryService → GraphStore / EventLog → 现有同步 → 忆云
```

不启动 sidecar，不采集 raw，不调用模型，不产生 Compact / Self / Checkpoint。

**沉浸式（sidecar）**

```text
宿主对话/任务 → /memory-runtime/v1/ingest
             → sidecar staging（未沉降 chunk）
             → 候选抽取（heuristic / local / host / api）
             → 去重、归属校验
             → /internal/memory/v1/write
             → MemoryService → GraphStore / EventLog → 现有同步 → 忆云

宿主下一轮 → /memory-runtime/v1/context
          → /internal/memory/v1/query + internal-object
          → 组装有预算的上下文块 → 宿主注入模型
```

**治理**

```text
用户 / Console → MCP admin 或 sidecar admin
             → 现有 MemoryService.delete / archive / update
             → 墓碑 / archivedAt 随事件同步
             → sidecar 缓存按事件或 TTL 失效
```

### 2.3 依赖方向（强制）

允许：

```text
hosts ──► memory-runtime ──HTTP──► mcp ──► core
hosts ──► mcp ──► core
mcp ──spawn/health──► memory-runtime（只通过进程与 HTTP，不 import）
```

禁止：

```text
core ──► runtime / inference / memory-runtime
mcp ──► memory-runtime 的业务实现（RuntimeService / local-store / model / recall）
memory-runtime ──► GraphStore / EventLog / SyncManager / MemoryService
memory-runtime ──► 第二套持久记忆库或同步协议
```

MCP 只允许 import sidecar 的**生命周期适配**（启动、停止、健康、发现），不得 import 其抽取、召回、模型、存储代码。

**依赖的单向性**：运行时的数据依赖是 sidecar → MCP capability API；MCP 只在沉浸式模式下可选地管理 sidecar 进程，不 import 它、不要求安装它。轻量模式完全没有这条依赖。代码/构建上两者互不依赖；生命周期上 MCP 是 sidecar 的管理者，不是它的调用方。

### 2.4 两个进程的职责边界

| 能力 | MCP daemon runtime | Memory Runtime sidecar |
|---|---|---|
| 29 个公共 MCP 工具 | 拥有 | 不拥有、不注册 |
| 图 / 事件 / 同步 / 忆云 | 拥有 | 不接触 |
| 鉴权 / 单写者 | 拥有 | 沿用 MCP 的 capability token |
| daemon 安装/升级/service | 拥有 | 不参与 |
| 对话采集 / 候选抽取 | 不做 | 拥有 |
| 碎片化召回 / 上下文组装 | 不做 | 拥有 |
| Detail / staging / Trace / outbox | 不做 | 拥有（staging 本地；Detail 经 capability） |
| 本地模型 / 第三方模型 | 不做 | 拥有 |
| Compact / Self / Checkpoint 编排 | 只提供受控写入 | 拥有 |
| sidecar 启动/停止/健康 | 只做生命周期适配 | 自身实现 |

MCP 可以为 Console 提供 sidecar `status/config/metrics` 的**薄代理**（转发 HTTP，不实现记忆逻辑）；浏览器不接触 host token。代理不属于“MCP import sidecar 业务”。

## 4. 角色与记忆域

### 4.1 三类角色

| 角色 | 记忆域 | 典型内容 | 写入者 | 读取者 |
|---|---|---|---|---|
| **User** | `user` | 用户事实、偏好、画像、用户明确保存的内容 | 用户；或经用户确认/策略授权的 Agent，记录仍归 User | 本云所有已授权 Agent；用户自己 |
| **Agent** | `agent:<agentId>` | Agent 自述、关系记忆、学习到的上下文、自我模型 | 该 Agent（域所有者） | 该 Agent；被授予读权限/订阅的其他 Agent；用户 |
| **Other** | `default`（兜底）/ `task:<threadId>` / `shared` / `system` / 旧 namespace | 不属于 user 或某个 Agent 的通用内容、任务 checkpoint、共享状态、系统对象 | 任务参与者、系统、现有 MCP 通用写入 | 任务参与者、被授权订阅者 |

关键澄清：

- **其他 Agent 不是 Other 域。** Hermes 的记忆是 `agent:hermes`，不是 `other`。Other 只表示“不属于 user 或任何 Agent”的第三类内容。
- **`default` 是 Third/Other 的兜底，不是用户域。** Agent 不得把用户事实/偏好写进 `default` 来冒充用户信息；未确认的 Agent 观察留在自己的 `agent:<id>`。
- **`user` 与 `agent:<id>` 是平级域。** 用户域不属于任何 Agent，Agent 域也不属于用户；两者通过订阅 + provenance 共享。
- **0.3 是逻辑隔离，不是密码学隔离。** 同一忆云的设备在物理上可读到已同步数据；capability API 和 sidecar 按域过滤，防止误用，不承诺抵御拿到本地存储的攻击者。

### 4.2 记忆域语法（冻结）

```text
domain        := 'user'
               | 'agent:' agentId
               | 'default'
               | 'task:' threadId
               | 'shared'
               | 'system'
               | legacyNamespace            // 0.2 任意 namespace，按 Other 处理

agentId       := /^[a-z0-9][a-z0-9._-]{0,63}$/
threadId      := /^[A-Za-z0-9._:-]{1,128}$/
legacyNamespace := 现有 namespace 规则；不得以 '__' 开头（'__policy__' 除外，且它不是记忆域）
```

规则：

1. **新写入的 `domain` 就是节点的 `namespace`。** 0.3 不引入第二套域字段；`domain` 是 namespace 的角色化视图。这样同步、订阅、快照、Console 全部复用现有机制。
2. `user`、`agent:<id>`、`default`、`task:<id>`、`shared`、`system` 是保留域名；`__policy__` 仍是策略域，不是记忆域；其他 `__*` 保留。
3. `agentId` 必须稳定；Agent 显示名只放 `provenance.agentName` / sidecar 注册表，不参与域键。
4. 0.2 的任意 namespace（如 `notes`、`project-x`）原样保留，解释为 **Other 的显式域**，`domain` 等于该 namespace。不迁移、不改名。
5. 0.2 的 `default` 数据原样保留，按 Other 兜底兼容；**不强制迁移到 `user`**。新的用户信息由 sidecar 在用户确认后写入 `user`。
6. `task:<threadId>` 中的 `threadId` 必须与 checkpoint 的 `threadId` 一致；没有显式任务域时 checkpoint 落 `default`。
7. Compact 的 `domain` 必须与全部 `sourceIds` 的域一致；跨域 compact 拒绝（`domain_mismatch`）。
8. SelfRecord 的 `domain` 必须是 `agent:<agentId>`，且 `agentId` 与记录内容一致。

### 4.3 归属四元组

每条进入 capability API 的持久对象都带：

```jsonc
{
  "ownerType": "user" | "agent" | "other",
  "ownerId": "u_..." | "<agentId>" | "<domain>",
  "domain": "user" | "agent:opencode" | "default" | "task:th_..." | "shared" | "system" | "notes",
  "provenance": {
    "source": "mcp" | "runtime" | "host" | "import" | "legacy",
    "writerType": "user" | "agent" | "system" | "runtime" | "host" | "import",
    "writerId": "u_..." | "opencode" | "system" | "runtime",
    "extractor": "user" | "heuristic" | "local" | "host" | "api",
    "model": "qwen3-9b-q4" | "host-provided" | null,
    "version": "0.3.0",
    "deviceId": "device-...",
    "hostId": "h_...",
    "threadId": "th_...",
    "agentName": "OpenCode",          // 仅显示，不参与域键
    "messageIds": ["m1", "m2"],
    "detailIds": ["01K..."],
    "rawChunkIds": ["rc_..."],        // 兼容别名；0.3 新写入用 detailIds
    "confirmation": "explicit" | "policy" | "none",
    "at": 1730000000000
  }
}
```

推导规则：

| domain | ownerType | ownerId | 说明 |
|---|---|---|---|
| `user` | `user` | `userId`（`u_...`） | 用户域 |
| `agent:<id>` | `agent` | `<id>` | 域所有者 |
| `default` | `other` | `default` | 第三类兜底 |
| `task:<id>` | `other` | `task:<id>` | 任务/线程 |
| `shared` | `other` | `shared` | 显式共享 |
| `system` | `other` | `system` | 系统对象，仅 admin 写 |
| 旧 `notes` 等 | `other` | 该 namespace | 0.2 显式域 |

- 客户端**不得**伪造 `ownerType`/`ownerId`；capability 服务端按 `domain` 推导。客户端提交的值与推导不一致时返回 `owner_mismatch`。
- `provenance` 只描述来源，不是可执行配置；读取方不得因为看到 `extractor='api'` 就调用对方模型。
- `provenance` 不得包含密钥、完整 raw 文本、Authorization、cookie。

### 4.4 0.2 数据解释

| 0.2 数据 | 0.3 解释 |
|---|---|
| 无 `metadata.internal` 的 entity/fact/episode/skill/meta | MemoryRecord legacy；`source='legacy'`；`ownerType` 按 namespace 推导 |
| 无 namespace | `default` → Other |
| `namespace='default'` 的 user 偏好 | **仍是 Other 兜底**；不冒充 `user`；profile 读取时按“legacy 用户事实”兼容返回 |
| 任意旧 namespace（`notes` 等） | 显式 Other 域；domain=namespace |
| `validTo=9999999999999` | 当前有效；API 输出 `null` |
| `deletedAt` / `metadata.archivedAt` | 墓碑 / 归档；默认不召回 |
| 旧 tag / `metadata.relatedTo` | 原样保留 |
| `__policy__` | 策略域；不是记忆域；capability API 不读写 |
| 未知 type（`task_event` 等） | 忽略；既不是 MemoryRecord，也不是内部对象 |

### 4.5 域不变量

- `user` 只放用户信息；Agent 的观察、推断、自我描述不得写入 `user`，除非用户明确确认。
- Agent 未确认的观察留在 `agent:<id>`；只有明确授权/确认后才进入 `user`，且 `provenance.confirmation` 必须为 `explicit`。
- SelfRecord 永远在 `agent:<agentId>`；不得写 `user`，不得写 `default`。
- ContextCheckpoint 永远上云：优先 `task:<threadId>`，无显式任务域时 `default`；不得留在本地作为权威。
- Compact 与来源同域；不得把 `user` 与 `agent:*` 压进同一个 compact。
- 任何域都不得绕过 MCP 直接写图；capability API 是唯一写入口。

### 4.6 身份标识

| 标识 | 作用域 | 生成/来源 | 跨设备 | 说明 |
|---|---|---|---|---|
| `cloudId` | 忆云 | `cl_` + 主密钥公钥摘要 | 稳定 | 跨设备身份；sidecar 发现与 capability 都使用它 |
| `userId` | 忆云内用户 | `u_` + 同一摘要 | 稳定 | 记录 owner；0.2 默认仍是 `'user'` 兼容值 |
| `profileId` | 本机 profile | 现有 `profiles.json` | 本机 | 用于 MCP `/healthz` 与 sidecar 发现 |
| `deviceId` | 设备 | 现有身份文件 | 设备生命周期 | 事件 author |
| `hostId` | 本机 sidecar 宿主 | `h_` + 设备/home 摘要 | 本机 | checkpoint 租约、provenance |
| `agentId` | 逻辑 Agent | 宿主声明/内置 descriptor | 集成稳定 | 域键；名称只显示 |
| `threadId` | 会话/任务线程 | 宿主提供 | 线程生命周期 | checkpoint 键的一部分 |

规则：

- 0.3 保持 `/healthz.cloudId` 的旧义（本机 profile id），不破坏现有 Supervisor/App 比较；新增稳定 `cloudTrustId`（即本表 `cloudId`）与 `profileId` 字段。sidecar discovery 同时返回 `cloudId` 与 `profileId`，不得把两者混用。
- `agentId` 是**断言**，不是认证；0.3 不做 token 到 Agent 的绑定。capability token 持有者可声明任意 actor，sidecar 按本地 policy 约束自己。
- `hostId` 由 sidecar/MCP 计算，客户端不能提交；用于 checkpoint 租约与 provenance。
- `cloudId`/`userId` 使用主密钥公钥摘要；取不到时 sidecar 不启动，MCP capability `status` 返回 `cloudId:null`、写接口 503。
- `cloudName`/`agentName` 只作显示，不参与身份、域键或冲突判定。

## 5. 对象与存储归属

### 5.1 总表

| 对象 | 是否持久记忆 | 存放位置 | 写入路径 | 跨设备 | 权威性 |
|---|---|---|---|---|---|
| **MemoryRecord**（entity/fact/episode/skill） | 是 | 现有图 + 事件日志 | capability `/write`、`/update` | 是，按域订阅 | 权威 |
| **Compact** | 是，派生 | 现有图 + 事件日志 | capability `/internal-object`（`kind=compact`） | 是，随来源域 | 派生，不改源记录 |
| **SelfRecord** | 是 | 现有图，`agent:<id>` 域 | capability `/internal-object`（`kind=self_record`） | 是，按域订阅 | Agent 自我模型 |
| **ContextCheckpoint** | 是 | 现有图，`task:<id>` / `default` 域 | capability `/internal-object`（`kind=context_checkpoint`） | 是 | 任务/线程恢复点 |
| **DetailRecord / RawChunk** | 是，域内详情 | 现有图 + 事件日志 | capability `/detail`（`detail_record`） | 是，按域订阅 | 域内可订阅详情，按保留策略过期/删除 |
| **RecallTrace** | 否 | `<home>/memory-runtime/traces.jsonl` | sidecar 本地 | 否 | 诊断/反馈 |
| **本地 checkpoint 缓存** | 否 | `<home>/memory-runtime/cache/` | sidecar 本地 | 否 | 云端 checkpoint 的只读缓存，可重建 |
| **staging（未沉降 chunk）** | 否 | `<home>/memory-runtime/staging/` | sidecar 本地 | 否 | 有界暂存，成功即删，不是权威 |
| **outbox** | 否 | `<home>/memory-runtime/outbox/` | sidecar 本地 | 否 | 有界重试队列，成功即删 |
| **索引 / cache** | 否 | `<home>/memory-runtime/cache/` 或内存 | sidecar 本地 | 否 | 可重建派生数据 |
| **模型文件 / 模型配置** | 否 | 设备模型目录 / sidecar config | 用户显式安装 | 否 | 设备能力 |

### 5.2 规则

1. **沉降不是写本地缓存。** “沉降”指经 MCP capability API 写入现有图/事件，再由现有同步进入忆云。sidecar 本地永远不是持久记忆的权威。
2. **所有 Agent 持久记忆上云。** MemoryRecord、Compact、SelfRecord、ContextCheckpoint 没有“本地模式”。本地只保存缓存/outbox；缓存丢失不影响已沉降记忆。
3. **不再有 `sync=cloud` / `sync=local`。** ContextCheckpoint 不再二选一；它在语义上始终是云端任务状态。`runtime.self.sync` 同样删除。任何 API、配置、文档、Console 都不得再出现这两个选项。
4. **Raw/详情不是本地私货。** 原始片段先进入本机 staging；抽取完成后，按目标 domain 写成 `DetailRecord`（`detailKind=raw_chunk`）经 capability 写入图/事件，随现有同步跨设备。staging 只用于重试与抽取，不是可召回来源。
5. **Compact 不是本地摘要文件。** 它是图内派生对象，带 `sourceIds` / `sourceHashes`；源记录变化时读取标记 `stale=true`，不自动删除源记录。
6. **碎片化召回结果是临时视图**，不单独持久化；只有被确认/沉降的内容才成为 MemoryRecord、Compact 或 DetailRecord。
7. **outbox 只用于 MCP 暂时不可用时的有界重试。** 成功写入后立即删除；不得成为第二权威，不得保存无限历史。
8. **删除/归档/墓碑沿用现有 MCP/core 语义。** sidecar 缓存要随同步事件或 TTL 失效；删除后不得再被召回。删除 MemoryRecord 级联墓碑其链接 DetailRecord；Compact 只标 stale，不级联删除。
9. **跨设备详情可展开。** 只要详情在保留期内、未删除且域已订阅，域内认证设备可读取原文/切片；只有 `pending_sync` / `expired` / `deleted` / `quota_evicted` / `not_subscribed` / `redacted_only` 才诚实降级。旧的“原文只在写入设备”不再是常态。
10. **重启恢复。** sidecar 重启后持久记忆/详情从 MCP/图恢复；本地 staging/Trace/cache 丢失不影响已沉降记忆；outbox 重放幂等。

### 5.3 内部对象判别与 metadata

- 所有内部对象（Compact / SelfRecord / ContextCheckpoint / DetailRecord）落图时：
  - `metadata.internal = true`（唯一通用判别键）；
  - `metadata.internalObject = { schema: 1, kind: 'compact'|'self_record'|'context_checkpoint'|'detail_record', ... }`（sidecar 语义细节，core 不读）；
  - 节点 type 分别为 `compact` / `self_record` / `context_checkpoint` / `detail_record`；
  - 不添加 `mebular:runtime:*` tag；不写 `__self__` / `__checkpoint__`。
- core 的通用可见性只检查 `metadata.internal === true` 与保留 namespace（`__*`，`__policy__` 除外）；core 不认识 `compact` 等类型名。
- 普通 MemoryRecord 不设置 `metadata.internal`，不受内部过滤影响。
- 内部对象与源记录/任务的关系只用 `content.sourceIds` / `content.recordIds` 表达，**不创建边**；旧 `memory_graph` 不会从用户记录走到内部对象。0.3 不新增必需边类型。
- 旧原型内部对象（仅开发环境）不承诺兼容；0.3 发布版不产生 `metadata.runtime`。开发环境可清空这些内部对象，不需要迁移脚本；普通 MemoryRecord 仍按 0.2 数据保留，不迁移。
- `metadata.internal` 与 `metadata.internalObject` 由 capability 服务端写入/校验；客户端不得通过 `/update` 修改。

### 5.4 模型层（sidecar 内部）

模型只属于 Memory Runtime sidecar，不属于 MCP/core；配置与模型文件设备本地，不进入忆云。

| 来源 | 运行位置 | 网络 | 默认 | 用途 | 失败 |
|---|---|---|---|---|---|
| `heuristic` | sidecar 进程内 | 无 | **是** | 规则抽取、关键词扩展、gist 选择 | 只可能是代码 bug；返回 500 |
| `local` | sidecar + 本机 llama-server | 无（模型已安装） | 否 | 本地 Qwen 抽取/摘要/排序 | 回退 heuristic，`degraded=true` |
| `host` | 宿主模型 | 宿主决定 | 否 | 宿主提交 CandidateRecord；sidecar 不反向调用 | 无候选 → 202 pending；不偷偷换模型 |
| `api` | 第三方 OpenAI-compatible | 有，需显式允许 | 否 | 无本地算力时的抽取/摘要 | 超时/5xx → heuristic；不换供应商 |

规则：

- 不读宿主 token/endpoint；host 来源只接受宿主自然提交的候选。
- `api` 必须同时配置 endpoint/model/keyRef 且 `allowRemote=true`；密钥只存引用（`env:`/`keychain:`/`file:`）。
- 模型失败只回退 heuristic；不自动切第三方；所有降级在 `status.degraded` / `warnings` 可见。
- 模型包显式安装、校验 manifest/sha256/license；不静默下载/更新。
- 模型配置按设备保存；记忆数据按忆云共享；provenance 只记录来源，不让其他设备重放模型。

## 6. 读 / 写 / 订阅权限

### 6.1 Actor

| actor | 说明 | 能做什么 |
|---|---|---|
| `user` | 用户本人（Console / 用户命令） | 读本云全部域；写 `user`；治理删除/归档；管理订阅/授权 |
| `agent:<id>` | 某个 Agent（sidecar 代其调用） | 读默认域 + 被授权域；写自己的 `agent:<id>`、`default`、参与中的 `task:*`、`shared`；经确认写 `user` |
| `system` | MCP 内部/维护任务 | 写 `system`；内部对象；不做普通召回 |
| `legacy` | 0.2 数据来源 | 只读；按 namespace 推导 owner |

### 6.2 写权限矩阵

| 目标 domain | user | 域所有者 Agent | 其他 Agent | system/admin |
|---|---|---|---|---|
| `user` | 允许 | 仅 `provenance.confirmation='explicit'` 且用户确认/策略授权 | 同左，禁止静默写 | 允许（治理） |
| `agent:<self>` | 允许 | 允许 | 禁止 | 允许（治理） |
| `agent:<other>` | 允许（治理） | 禁止 | 禁止 | 允许（治理） |
| `default` | 允许 | 允许 | 允许 | 允许 |
| `task:<thread>` | 允许 | 仅参与者且 thread 匹配 | 仅参与者且 thread 匹配 | 允许 |
| `shared` | 允许 | 允许 | 允许 | 允许 |
| `system` | 仅 admin | 禁止 | 禁止 | 允许 |
| 旧 namespace（Other） | 允许 | 按显式域授权 | 按显式域授权 | 允许 |

补充：

- “其他 Agent 写 `agent:<other>`”永远禁止，即使订阅了该域；订阅是读权限，不是写权限。
- `user` 域写入必须带 `provenance.confirmation` 与 `provenance.source`；缺失时返回 `domain_write_forbidden`，sidecar 应把该候选降级写入 `agent:<self>`，或丢弃并记录 warning。
- 删除/归档属于治理动作：user 可治理全部；Agent 只能治理自己域内、自己写入的记录；`memory.admin` 等价者（本地 capability token）可治理全部。
- 0.3 不做按 Agent 的密码学隔离，也不做 per-record ACL；上述是逻辑约束。

### 6.3 读权限与默认范围

**默认查询范围（capability API 未显式给 `domains` 时）**：

| 端点 | 默认域 | 说明 |
|---|---|---|
| `query` / `search` | `user`、`agent:<actor>`、`default`、`task:<currentThread>` | 当前任务域仅在请求带 `threadId` 时加入 |
| `history` | 同上 | 只返回 conversation episode；不含内部对象 |
| `profile` | `user` + 非 Agent 域中的 legacy 用户事实 | 兼容 0.2 `subject='user'` 的旧事实；返回 `legacy=true`，不写回 |
| `skills` | `user`、`agent:<actor>`、`default`、`shared` | 技能可复用；其他 Agent 的技能需显式域/授权 |
| `graph` | 起点所在域 + 默认域 | 起点不在可读域 → 404 `not_found`（不暴露存在性）；strict 模式 → 403 `domain_read_forbidden`；不遍历内部对象 |
| `internal-object`（`compact`） | 来源域 | 调用方必须能读全部 sourceIds |
| `internal-object`（`self_record`） | `agent:<target>` | 仅同一 Agent 或 user/admin；其他 Agent 需显式授权 |
| `internal-object`（`context_checkpoint`） | 记录所在域 | `task:*`：任务域参与者可读；`default`：仅同一 `(agentId, threadId)` 或 user/admin |
| `detail`（`detail_record`） | 记录/详情所在域 | 域内已订阅/已同步；同一 `domains` 过滤；`user`/`system` 可治理全部 |

**显式域与订阅**：

- 请求可带 `domains: string[]`（最多 16 个）。capability API 只按请求返回；**按 Agent 的读授权由 sidecar 在发起请求前按 `policy.json` 过滤**，capability 不假装知道 Agent 的授权。capability 只校验域语法、是否在本机已知/已订阅；`strictDomains=true` 时未知/未同步域逐项 403 `domain_read_forbidden`，默认逐项 warning 并跳过。
- 其他 Agent 的域默认不读；要读必须显式列 `agent:<other>`，并由 sidecar 的本地授权策略确认。
- 物理同步范围由现有 namespace 订阅决定；逻辑可读范围由 sidecar 的 `policy.json`（按 Agent 的读/写域授权）决定。两者都不能替代对方：
  - 没有同步到本机的数据，读不到；
  - 同步到本机但对当前 Agent 未授权的域，capability 请求不会主动列出，sidecar 也不得代其读取。
- 0.3 不新增同步订阅命令/协议；订阅变更继续走现有 MCP/CLI/Console 的 namespace 机制。
- 0.2 的任意 namespace（`notes`、`project-x` 等）是**显式 Other 域**，不自动进入默认范围；需要时在 sidecar `policy.json` 的 `readDomains` 中显式加入。`default` 仍默认包含，保证 0.2 兜底数据可召回。

**其他 Agent 读取的返回要求**：

- 每条结果必须带 `ownerType`、`ownerId`、`domain`、`provenance.agentId`、`provenance.agentName`、`provenance.deviceId`/`hostId`、`provenance.threadId`（如有）。
- 读取方必须能区分“我的记忆”与“某 Agent 的记忆”；不得把来源信息抹掉后混入自己的上下文。
- 跨设备详情在保留期内可展开；若详情已过期/删除/配额淘汰，才标 `detailAvailable=false` 并给出 `expired` / `deleted` / `quota_evicted` 等原因，不得声称有原文。

### 6.4 公共 MCP 工具与域过滤的关系

- 29 个公共工具保持 0.2 语义：它们没有 agent 身份，也不做域授权；`memory_query` 仍可看到本云所有 namespace 的普通记忆。**0.3 不改变这一点。**
- 域过滤、默认范围、owner/provenance 增强只作用于 **capability API** 与其上的 sidecar。公开工具如果需要域过滤，由调用方用既有 `filters.namespace` 完成。
- 公共工具不理解 domain owner；通过 `memory_write` 直接写 `user` / `agent:*` 的语义由调用方负责，capability 才强制 owner/confirmation。0.3 不改变公共工具的 0.2 行为，也不假装它是域隔离的。
- 这是有意为之：把 0.2 工具改成按 Agent 过滤会破坏兼容性，也会让“同一云内共享记忆”失效。按 Agent 的逻辑隔离属于 sidecar 层，不属于公共工具面。

### 6.5 订阅与授权的存储

- 同步订阅：现有 `sync.namespaces` / `namespace_subscription` 记录，语义不变。
- Agent 读/写域授权：sidecar 本地 `policy.json`（设备级、不跨设备、不同步），结构见 `0.3.0-memory-runtime-sidecar.md`。
- 授权不是新的同步协议，也不是新的 ACL 服务；它只在 sidecar 组装请求时使用，并由 capability API 的写权限规则兜底。
- 用户可在 Console 查看/修改授权；修改立即生效，不需要重启 sidecar。

### 7.3 版本握手

- Capability API 版本：`1`（`capabilityApiVersion`）。
- Sidecar 协议版本：`1`（`apiVersion`）。
- MCP daemon 在 `/internal/memory/v1/version` 返回 `capabilityApiVersion`、`schemaVersion`、`mcpVersion`、`coreVersion`、`features`、`limits`。
- sidecar 启动时先读 MCP 版本；major 不匹配 → 退出 `version_incompatible`；minor 只做加法。
- sidecar 自身 `/health`、`/status` 返回 `runtimeVersion`、`capabilityApiVersion`、`minMcpVersion`、`maxMcpVersion`；MCP 只在兼容时复用已有 sidecar，否则停止并替换。
- 版本不兼容时，宿主失败开放：不注入记忆，对话继续。

### 8.2 数据兼容

- 不执行迁移、不补字段、不改 ID、不改 namespace、不重签事件。

### 8.3 回滚

1. 停止并卸载 sidecar：`mebular memory-runtime uninstall`（或停用 MCP 的 `memoryRuntime.enabled`）。
2. 图数据保留；内部对象默认不可见；公共 29 工具照常。
3. 旧代码启动、查询、同步不崩；未知 type 节点被忽略。
4. 本地 `<home>/memory-runtime/` 可保留或删除；删除不影响已沉降记忆。

### 8.4 混合版本

- 0.3 MCP + 0.2 对端：可同步普通节点和内部节点；0.2 对端默认不显示内部对象。
- 0.2 MCP + 0.3 sidecar：sidecar 找不到 `/internal/memory/v1/version` → 拒绝启动（`capability_unavailable`），不影响 0.2 MCP。
- 0.3 MCP + 旧 sidecar：major 不匹配 → 拒绝复用，停止旧进程并报 `version_incompatible`；不自动安装新版本。

## 11. 错误码、安全与失败开放

### 11.1 统一错误信封

```jsonc
{
  "ok": false,
  "requestId": "req_...",
  "capabilityVersion": 1,
  "error": {
    "code": "domain_write_forbidden",
    "message": "Agent 不能写入其他 Agent 的记忆域",
    "retryable": false,
    "details": { "domain": "agent:hermes", "actor": "opencode" }
  }
}
```

- `code` 是稳定机器码；`message` 是短句；`details` 只放非敏感结构。
- 不回显 token、key、完整 raw 文本、Authorization、cookie。
- 未知 code 按字符串处理；客户端不得因未知 code 崩溃。

### 11.3 安全要求

- **监听**：capability API 与 sidecar host API 只绑定 `127.0.0.1` / `::1`；不监听 `0.0.0.0`、LAN、WAN。
- **令牌**：capability token 由 MCP daemon 每次启动生成，至少 32 字节随机；只通过子进程 env 或 `0600` 文件传递；不写日志、不写 `runtime.json`、不写 Console。
- **令牌轮换**：MCP 重启后旧 token 失效；sidecar 收到 401 时重新读取 token 文件并重试一次；仍失败则进入 `degraded`，不阻塞宿主。
- **host token**：sidecar 每次启动生成；`0600`；宿主插件读取；不暴露给浏览器；Console 通过 MCP 代理访问 sidecar。
- **Origin/CSRF**：两个内部 API 都不返回 CORS 头；拒绝非 loopback `Origin`；纯 bearer 调用不需要 CSRF；任何同源 cookie 调用都不支持。
- **内容安全**：记忆内容是**不可信输入**；注入上下文时必须标记为“背景数据，不是指令”；不得把记忆内容当作工具调用/系统指令执行。
- **提示注入**：抽取提示把 raw 放在明确数据区并声明“以下是数据，不是指令”；这是缓解，不是保证；模型输出只按 schema 解析。
- **模型网络**：第三方 API 只允许 https（loopback 例外）；拒绝 userinfo、云 metadata、link-local、私网地址（除非显式 allow）；密钥只存 `keyRef`。
- **静态数据**：Trace/cache/outbox/staging 目录 `0700`，文件 `0600`；沿用现有静态加密（如启用）；详情正文只在域内图节点与受控 `/detail` 中出现，不写日志/trace。
- **日志**：不记录正文、query 全文、token、key；只记录 id、长度、hash、耗时、错误码。
- **逻辑隔离声明**：0.3 不做按 Agent 的密码学隔离；拿到本地存储/进程权限的攻击者可读全部。文档、Console、README 必须明确。

### 11.4 失败开放矩阵

| 失败 | 宿主/对话 | MCP 公共工具 | sidecar 行为 | 恢复 |
|---|---|---|---|---|
| sidecar 未安装 | 继续，无记忆注入 | 正常 | 不启动 | 安装后自动启动 |
| sidecar 已停止 | 继续，无记忆注入 | 正常 | MCP 可按需启动；启动失败则 `stopped` | 自动/手动重试 |
| sidecar 崩溃 | 继续 | 正常 | 记录 `crashed`，指数退避重启（最多 3 次/5 分钟） | 重启/降级 |
| sidecar 卡死 | 继续；宿主超时跳过 | 正常 | 健康检查失败 → 重启 | 看门狗 |
| capability API 503 | 继续；sidecar 用缓存只读，写 outbox | 正常 | `degraded=true`；重试 | MCP 恢复后重放 |
| MCP daemon 停止 | 继续；sidecar 无新图数据 | 不可用 | 只读缓存 + outbox；不伪造 | MCP 启动后恢复 |
| 同步不可用 | 继续；本地图可写 | 正常 | 记录 `sync.degraded`；不阻塞 | 网络恢复 |
| 模型不可用 | 继续；回退 heuristic | 正常 | `degraded=true`；不伪造 | 配置/模型恢复 |
| outbox 满 | 继续；停止接收新写并告警 | 正常 | `outbox_full`；有界丢弃最旧过渡数据 | 清理/恢复后重试 |
| 磁盘满 | 继续；不注入 | 正常 | `storage_full`；只读模式 | 清理 |
| token 过期 | 继续 | 正常 | 重新读取 token；失败则 degraded | 轮换 |
| 版本不兼容 | 继续 | 正常 | 退出 `version_incompatible` | 升级 |
| 端口冲突 | 继续 | 正常 | 改用临时端口并更新 discovery；失败则退出 | 重试 |

共同规则：

- **任何 sidecar 故障都不阻塞对话**；宿主最多等待注入预算（建议 300ms），超时即跳过。
- **任何失败都不静默**：`status.degraded`、`warnings[]`、`X-Mebular-Degraded` 至少一处可见。
- **不得用过期记忆冒充最新**；缓存读取必须带 `source='cache'` 与 `stale=true`。

| O14 | **详情域内共享** | DetailRecord / RawChunk 写入现有图/事件/同步；域内认证设备可订阅；不建第二套存储/同步；详情删除/过期才诚实降级。 |

### 13.3 不做

1. **不做多自然人账号/成员 ACL**：一个忆云仍是一个用户主密钥；没有按人授权。
2. **不做按 Agent 的密码学隔离**：域过滤是逻辑约束，不是加密；拿到本地存储/进程权限的攻击者可读全部。
3. **不做数据迁移/重写/重签**：不补字段、不改旧 ID/namespace/tag/事件；0.2 数据按 legacy 解释。
4. **不做第二套记忆库/同步协议/事件类型**：复用图、事件日志、订阅、快照。
5. **不新增公共 MCP 工具**：29 个冻结；capability 不是 tool。
6. **不做 Raw/详情仅本机**：详情按域写入图/事件/同步；本机只 staging/cache/outbox。只有过期、删除、配额淘汰或未订阅才不提供原文。
7. **不做自动全量对话采集**：只有宿主显式 `ingest` 的片段被处理。
8. **不做宿主模型反向调用**：不读宿主 token/endpoint；host 来源只接受宿主提交的候选。
9. **不做本地 checkpoint/self 权威模式**：没有 `sync` 二选一；本地只是缓存/outbox。
10. **不做跨忆云合并/联邦**：不同 `cloudId` 不合并。
11. **不做 per-record ACL / namespace 级 ACL**：沿用现有订阅 + sidecar policy。
12. **不做自动模型下载/静默升级**：模型包和 sidecar 安装都显式；升级失败回滚。
13. **不做删除级联**：删除源记录不自动删除 compact；compact 标 stale。
14. **不改公共 29 工具的默认查询语义**：域隔离只在 capability/sidecar 层。

## 14. 给后续执行会话的硬性提示

1. **先做边界，再做功能。** W1 先让 core 无 runtime/inference 依赖、MCP 无 RuntimeService；否则 W2/W3 会把原型越埋越深。
2. **不要为了让旧测试绿而保留反向依赖。** 旧测试是基线，不是架构。
3. **不要把 capability API 做成第二个公共 MCP 工具面。** 它只给 sidecar；不注册 tool，不出现在 `mebular tools`。
4. **不要把 sidecar 做成 MCP 的插件模块。** 它是独立进程/独立包；MCP 只 spawn/health/stop。
5. **不要给 checkpoint/self 加本地模式。** 本地只有缓存；写入必须成功到云端（或进 outbox）才算完成。
6. **不要给其他 Agent 建 `other` 域。** 其他 Agent 永远是 `agent:<id>`。
7. **不要让 `default` 变成用户域。** 用户信息写 `user`；未确认观察留 `agent:<self>`。
8. **不要在 core 里写 runtime 类型名。** core 只知道 `metadata.internal` 和保留 namespace。
9. **不要新增同步协议/事件类型。** 复用现有节点、事件、订阅、快照。
10. **所有失败都要可见且不阻塞对话。** 没有静默降级。

### 14.1 建议落地顺序

## 15. Chief 修正冻结（2026-10-30，覆盖旧 capture / Raw-local 假设）

> 本节是本文件的最新口径。正文与本节冲突时，以本节和 [`0.3.0-immersive-product-contract.md`](./0.3.0-immersive-product-contract.md) 为准。历史段落保留，不再作为实现依据。

### 15.1 取消 capture

- 沉浸式开启即按域网络采集；没有 `capture=local/off`，没有首次 capture 授权，没有本机/云端二选一。
- 采集归属由 `agentId + domain` 决定；域内认证设备可按现有订阅读取。
- 本地只有 staging / cache / outbox；不是权威副本，成功写入后删除 staging。
- 任何 API、配置、Console、host adapter、文档、测试不得再新增或依赖 `capture` 字段；旧字段在实现中删除，读到旧配置时给 `legacy_config_unsupported`，不静默沿用。

### 15.2 域内详情

- 新对象 `DetailRecord`（节点 type `detail_record`，`metadata.internal=true`，`metadata.internalObject.kind='detail_record'`）；`RawChunk` 是 `detailKind='raw_chunk'` 的子类型。
- 详情 domain = 链接 MemoryRecord / ContextCheckpoint 的 domain；同一文本支撑多个域时按域各写一份，ID 不同、`contentHash` 相同。
- 详情写入现有图 + 事件日志，随现有同步；**不建第二套存储/同步**。本机只 staging/cache/outbox。
- capability 新增内部 `POST /internal/memory/v1/detail`（write/get/list/delete）；不新增公共 MCP 工具。
- 保留策略按 `retentionClass`：conversation 30 天、tool_output 7 天、document_slice 90 天、pinned 显式；过期/配额/删除都写墓碑并同步。
- 配额：单条 256 KiB、单域 256 MiB、单云 1 GiB、单 thread 64 MiB；超限先淘汰最旧 tool_output，再淘汰最旧 conversation，写 `quota_evicted`。
- 详情不进入 Compact 的 `sourceIds`；Compact 仍只压缩 MemoryRecord。详情维护只做无损合并与淘汰，不调用模型生成新摘要。
- 删除 MemoryRecord 级联墓碑其链接 DetailRecord；Compact 只标 stale，不级联删除。删除详情不删除记录。
- 跨设备详情可展开；旧的 `missing_cross_device` 常态作废，改为 `pending_sync` / `expired` / `deleted` / `quota_evicted` / `not_subscribed` / `redacted_only`。

### 15.3 单一 UI

- 普通用户只增加：设置里的「记忆模式（轻量 MCP / 沉浸式）」；高级里的「模型来源」。
- sidecar 启停、host 适配器、token、discovery、域订阅、采集策略全部黑盒自动；不要求逐宿主配置。
- DSH 第一优先级；Hermes / OpenCode / OpenChamber 随后；OpenChamber 原生 memory 只读共存。
- 任何“Runtime / 本机采集 / 首次 capture 授权 / 原文只在写入设备”的用户文案删除。

### 15.4 结构化 ContextCheckpoint

- ContextCheckpoint 不是 compaction summary；`state.schema=2`，字段：goal、constraints、decisions、progress（done/doing/blocked）、nextSteps、files、openQuestions、references。
- 始终上云：`task:<taskId>` / `task:<threadId>` / `default`；`task.key=domain`；`threadId` 与域一致；`fleetTaskId` 只作引用，sidecar 不直接读 fleet store。
- `task:*` 的 revision 按 `(cloudId, taskKey)` 共享；`default` 按 `(cloudId, agentId, threadId)`；lease 默认 60s；参与者按域订阅读取；写入需参与者 + lease。
- 宿主在 compaction / task 变更时写入；sidecar 在新 turn / 压缩后主动读取，并参与召回。
- `contentMode='summary_only'` 必须标 `degraded=true`、`reason='checkpoint_summary_only'`；summary 不得冒充结构化字段。
- 任何 `sync` / `checkpoint.sync` / `self.sync` 字段仍返回 400 `legacy_sync_unsupported`。

### 15.5 验收口径替换
