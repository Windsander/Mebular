# Mebular 0.3.0 Memory Runtime 技术契约（草案）

**状态**：草案 v0.1，执行会话 A，待 chief 审定  
**基线**：`main` a784149，分支 `feat/0.3.0-memory-runtime`  
**依据**：`docs.design/spec-001-memory-model.md`、`src/memory/*`、`src/hermes/*`、`packages/mcp/src/serve.mjs`、`packages/mcp/src/config-schema.mjs`、`packages/console` 的 settings / memories 实现  
**约束**：本文件只定义契约，不包含实现，不修改任何源码；0.2 既有数据不重写、不迁移。

## Chief decisions（2026-10-29）

以下为 0.3.0 实现基线，覆盖草案中的待定项：

- `/healthz.cloudId` 保持旧义；0.3 新增稳定 `cloudTrustId` 与 `profileId`，0.4 再改名。
- 0.3 只支持单云单用户；不引入多自然人 ACL，不做按 Agent 的密码学隔离。
- Raw 采集：轻量 MCP 默认 `off`；用户选择沉浸式时默认 `local`（在模式选择处做一次性授权），不额外暴露第二个隐私开关。Raw 仍只在本机保留、默认不跨设备；云端 raw 留作后续显式开关。
- Checkpoint 默认本地；SelfRecord 默认云；两者都不进入普通记忆查询。
- 精选本地模型：Qwen 9B（默认）、Qwen 27B（高质量）、Qwen 4B（轻量）；Qwen 32B 不进入精选目录，走高级自定义端点。
- 不新增 `runtime_*` MCP 工具；Runtime 走 `/runtime/v1`，现有 29 个 MCP 工具名和语义不变。
- OpenChamber 原生 memory 保留，不导入、不替换、不双写；轻量 MCP 必做，沉浸式仅作为 OpenCode 插件 opt-in，必须做版本/能力检测。
- Host 当前对话模型只接受宿主自然提交的候选或宿主侧 companion 调用；Runtime 不反向读取宿主凭据、不伪造当前模型。
- 0.3.0 内部按 G0–G5 推进，但对外一次性发布完整范围；不以局部阶段作为发布版本。

## 0. 结论摘要

1. **存储层不动**：继续使用现有 `GraphStore` / `EventLog` / `StorageAdapter`。节点仍是 ULID、事件仍是内容寻址并签名；不新增事件类型、不改同步线协议。
2. **Runtime 是服务层**：新增 `RuntimeService`，复用现有 `MemoryService` / `MemoryStore`；MCP 仍是薄壳，29 个工具名和语义不变。
3. **六个对象两种落点**：
   - **图节点**：`MemoryRecord`（复用现有 entity/fact/episode/skill）、`Compact`、`ContextCheckpoint`（云同步时）、`SelfRecord`（云同步时）。
   - **本地对象**：`RawChunk`、`RecallTrace` 默认只在本机 Runtime 存储，不进图、不进事件日志、不同步；`ContextCheckpoint` / `SelfRecord` 选本地模式时也是这样。
4. **内部对象默认不可见**：按“节点类型 + `metadata.runtime.internal` + 保留 namespace”三重判定。`memory_query` / `memory_search` / `memory_history` / `memory_profile` / `memory_skills` / `memory_graph` 的默认结果与 0.2 完全一致。
5. **身份是单云单用户**：一个忆云一个用户主密钥，`cloudId` 由用户主密钥公钥稳定派生；`userId` 是同一云内的用户锚点；`agentId` 是逻辑 Agent 标识；`hostId` 是本机 Runtime 宿主；`threadId` 是会话/任务线程。0.3 **不引入多自然人账号和按 Agent 的密码学隔离**。
6. **两种接入模式共用一份数据**：轻量 MCP 模式由宿主模型主导；沉浸式 Runtime 模式由 Runtime 负责采集、抽取、压缩、召回和 checkpoint。模式是**设备级配置**，切换不迁移、不重写、不删除任何节点。
7. **模型来源四种**：heuristic（默认）、本地 Qwen 精选包、宿主当前对话模型（只接受宿主自然提交的候选，不反向调用宿主 API）、第三方 OpenAI-compatible API。配置和密钥是设备本地的，永不进入共享记忆。
8. **新 API 走 `/runtime/v1`**，复用现有 bearer / OAuth scope（`memory.read` / `memory.write` / `memory.admin`），不新增 MCP 工具名。

## 1. 现状与设计约束

### 1.1 现有存储与事件模型

| 现有能力 | 事实 | 对 Runtime 的意义 |
|---|---|---|
| 节点 | `Node { id: ULID, type: string, content, tags, metadata, namespace, validFrom, validTo, deletedAt }` | Runtime 对象优先复用节点；新类型是普通节点 |
| 边 | `Edge { source, target, relation, namespace }`；关系名小写 | 0.3 不新增必需边类型；MemoryRecord 继续用现有边 |
| 事件 | `node_created` / `node_updated` / `node_deleted` / 边事件 / tag 事件；事件 ID 为内容寻址；节点事件载荷是完整节点 | Runtime 节点自动获得同步、签名、墓碑、审计 |
| namespace | 缺失一律视为 `default`；`__policy__` 是保留策略域 | Runtime 用少量保留域隔离内部对象 |
| 查询 | 默认记忆类型是 entity/fact/episode/skill/meta；`history` 只查 `episode` 且 `episodeType='conversation'` | 新类型天然不进入默认查询；仍需防御性过滤 |
| 生命周期 | `deletedAt` 墓碑；`metadata.archivedAt` 归档；默认不召回 | Runtime 对象沿用同一语义 |
| 同步 | 事件日志 + 分区订阅 + 快照；订阅空 = 全部 | Runtime 不新增同步协议；内部对象的同步由 namespace / 本地存储决定 |

### 1.2 现有接口面

| 面 | 现状 | 0.3 契约 |
|---|---|---|
| MCP | 13 个 `memory_*` + 16 个 `task_*`，共 29 个工具；stdio 与 HTTP `/mcp` 同注册表 | 工具名、参数、返回形状不变；不新增 `runtime_*` MCP 工具 |
| CLI | `mebular memory_*` 与 MCP 同 handler；`mebular tools` 列出 29 个 | 既有命令不变；新增 `mebular runtime ...` 作为独立命令组 |
| Console | `/admin/api/memories` 列表、settings 配置、overview 状态 | 默认隐藏内部对象；新增 Runtime 状态区；不改变旧行字段 |
| 核心库 | `MemoryService` 是记忆唯一实现；`HermesMemoryProvider` 是薄壳 | `MemoryService` 公共方法保持；新增独立 `RuntimeService` |
| 同步 | 节点/事件/namespace 已贯通 | Runtime 节点作为普通节点同步；本地对象不进入同步 |

### 1.3 硬约束

- **不迁移**：0.2 节点不补字段、不改 ID、不改 namespace、不重签事件。
- **不丢数据**：模式切换、模型不可用、Runtime 未初始化都不得删除已有记忆。
- **不隐式联网**：没有任何模型请求会在用户未配置且未逐次允许时发出。
- **不泄密**：API key、token、完整 raw 文本不得出现在日志、错误、`/status`、Console 或同步事件中。
- **不破坏旧客户端**：0.2 的 MCP / CLI / Console 读路径看到的默认结果不变；旧节点仍可读写。
- **单写者**：同一 home 仍由现有 `serve` / stdio 锁保证单写者；Runtime 不另起第二个图写入者。

## 2. Runtime 对象与图映射

### 2.1 通用信封

所有 Runtime 对象共享以下逻辑信封；落图时字段分散到 `content`、`metadata.runtime`、节点字段中。

```ts
type RuntimeObjectKind =
  | 'memory_record'
  | 'raw_chunk'
  | 'compact'
  | 'context_checkpoint'
  | 'recall_trace'
  | 'self_record';

type RuntimeVisibility =
  | 'user'          // 用户共享记忆
  | 'relationship'  // 关系记忆（仍是用户记忆的一种形状）
  | 'agent-self'    // Agent 自我记录
  | 'task'          // 任务/线程 checkpoint
  | 'local';        // 仅本机

interface RuntimeEnvelope {
  schema: 1;
  kind: RuntimeObjectKind;
  id: string;                       // 图节点 id，或本地对象 id（rc_/tr_ 前缀）
  cloudId: string;
  userId: string;
  agentId: string;
  hostId?: string;                  // 本机宿主；默认不进入共享元数据
  threadId?: string;
  namespace: string;                // 缺失按 default
  visibility: RuntimeVisibility;
  sync: 'cloud' | 'local';
  internal: boolean;                // 内部对象=true；MemoryRecord=false/缺失
  provenance: {
    source: 'legacy' | 'mcp' | 'host' | 'runtime' | 'import';
    extractor: 'user' | 'heuristic' | 'local' | 'host' | 'api';
    model?: string;                 // 模型 id / pack id；不含密钥
    version?: string;
    at: number;
    deviceId?: string;
    messageIds?: string[];
  };
  createdAt: number;
  updatedAt: number;
  deletedAt?: number;
}
```

**落图约定**：

```jsonc
{
  "id": "01J...",
  "type": "compact",              // 或 context_checkpoint / self_record
  "content": { "schema": 1, "...": "..." },
  "metadata": {
    "runtime": {
      "schema": 1,
      "kind": "compact",
      "internal": true,
      "cloudId": "cl_...",
      "userId": "u_...",
      "agentId": "opencode",
      "visibility": "user",
      "sync": "cloud",
      "provenance": { "source": "runtime", "extractor": "local", "model": "qwen3-...", "at": 0 }
    }
  },
  "tags": ["mebular:runtime:internal", "mebular:runtime:kind:compact"],
  "namespace": "notes",
  "createdAt": 0,
  "updatedAt": 0
}
```

`metadata.runtime` 是唯一判别键；0.2 节点没有它，按 legacy 处理。

### 2.2 六对象映射总表

| 对象 | 落点 | 图节点 type | namespace | 同步 | 默认查询可见 | 说明 |
|---|---|---|---|---|---|---|
| `MemoryRecord` | 现有图节点 | `entity` / `fact` / `episode` / `skill`（`meta` 仅兼容旧数据） | 用户域，默认 `default` | 是，按域订阅 | 是 | 不新增包装节点；`metadata.runtime` 可选 |
| `RawChunk` | 本机 Runtime 存储 | 无 | 无（本地） | 否 | 否 | 0.3 不进图；只有抽取出的 MemoryRecord 进入共享记忆 |
| `Compact` | 图节点 | `compact` | 与来源记录同一域；一个 compact 只能属于一个域 | 是，随来源域 | 否 | 摘要 + 来源 ID；不替代源记录 |
| `ContextCheckpoint` | 本地文件或图节点 | `context_checkpoint`（仅云同步时） | `__checkpoint__`（仅云同步时） | 默认否；显式 `sync=cloud` 才同步 | 否 | 任务/线程恢复点；有 revision / lease / TTL |
| `RecallTrace` | 本机 Runtime 日志 | 无 | 无（本地） | 否 | 否 | 诊断与反馈；环形保留 |
| `SelfRecord` | 本地文件或图节点 | `self_record`（仅云同步时） | `__self__`（仅云同步时） | 建议是，按 agent 逻辑过滤 | 否 | 同一 Agent 的长期自我模型；不是用户画像 |

> **为什么 RawChunk / RecallTrace 不进图**：它们是过程数据，不是“稳定、可跨设备复用的记忆”。不进图就从结构上保证它们不会出现在 `memory_query` / `memory_history`、不会被旧 Console 列出、不会被同步到其他设备，也不会污染图遍历。只有抽取后的 `MemoryRecord` 才进入共享记忆。这与 `MEMORY_POLICY` 的“过程产物留在原 provider”一致。

### 2.3 各对象字段

#### 2.3.1 RawChunk（本地）

```ts
interface RawChunk {
  schema: 1;
  id: string;                 // rc_<ULID>
  threadId: string;
  agentId: string;
  hostId: string;
  role: 'user' | 'assistant' | 'system' | 'tool';
  text: string;               // 单块上限 256 KiB；超过由调用方切块
  mime: 'text/plain' | 'text/markdown' | 'application/json';
  at: number;                 // Unix ms
  messageId?: string;
  turn?: number;
  chunkIndex?: number;
  contentHash: string;        // sha256 hex；去重键
  redaction: { applied: boolean; rules: string[] };
  expiresAt: number;          // 默认 now + runtime.retention.rawDays
}
```

- 存储：本机 `<home>/runtime/raw/`（实现可用 JSONL/SQLite）；若启用静态加密，沿用现有 `StorageCipher`；未启用时文件权限 `0600`，`/status` 给出 `rawCaptureUnencrypted` 警告。
- 写入去重：`(cloudId, agentId, threadId, contentHash, chunkIndex)` 唯一；同内容重复提交返回已有 id，`duplicate=true`。
- 不进入 `GraphStore`、不 append `EventLog`、不参与同步。
- 过期清理：启动时一次 + 每日一次；显式删除立即生效。
- 0.3 不提供“共享 raw”；如果未来需要，必须新增 `__raw__` 域与独立开关，不能由当前 `capture` 隐式开启。

#### 2.3.2 MemoryRecord（共享记忆）

沿用现有五类节点内容，不新增必填字段：

| kind | 节点 type | 关键内容 | 现有语义 |
|---|---|---|---|
| 事实 | `fact` | `subject`, `predicate`, `object`, `confidence`, `source` | `validFrom` / `validTo`；`SUPERSEDES` |
| 偏好 | `fact` + tag `preference` | 同上，`predicate` 为偏好类型 | `profile` 读取 |
| 情节 | `episode` | `episodeType`, `title`, `content`, `context`, `startTime`, `endTime` | `history` 读取 `conversation` |
| 技能 | `skill` | `name`, `description`, `category`, `steps`, `commands` | `skills` 读取 |
| 实体 | `entity` | `entityType`, `name`, `description`, `properties` | 关系端点 |
| 元数据 | `meta` | `metaType`, `name`, `value` | 仅兼容旧数据；Runtime 不新建 |

Runtime 写入的 record 可以带：

```jsonc
"metadata": {
  "runtime": {
    "schema": 1,
    "kind": "memory_record",
    "internal": false,
    "cloudId": "cl_...",
    "userId": "u_...",
    "agentId": "opencode",
    "visibility": "user",
    "sync": "cloud",
    "provenance": {
      "source": "host",
      "extractor": "host",
      "model": "host-provided",
      "at": 0,
      "messageIds": ["m1"]
    }
  }
}
```

- 通过现有 `MemoryService.write` / `storeExtraction` 写入时，可省略 `metadata.runtime`；这类节点按 legacy 处理，不要求补写。
- 不因 Runtime 给 record 增加 `mebular:runtime:*` tag；用户 tag 保持原样，避免污染现有 `tags` 过滤。
- `meta` 节点继续按 0.2 行为可查；Runtime 不把它当作内部对象。
- `validTo` 的哨兵值 `9999999999999` 继续表示“当前有效”；对外 API 归一化为 `null`。

#### 2.3.3 Compact（派生摘要）

```ts
interface CompactContent {
  schema: 1;
  summary: string;             // 只含摘要，不含 raw 原文
  sourceIds: string[];         // MemoryRecord 节点 id
  sourceHashes: string[];      // 源记录内容哈希，用于陈旧判定
  strategy: 'summary' | 'dedupe';
  model: { extractor: string; model?: string; version?: string };
  tokenCount: number;
  stale: boolean;              // 源记录被删除/更新后由读取时计算
}
```

- 节点：`type='compact'`；`metadata.runtime.internal=true`；`kind='compact'`。
- namespace：**必须与来源记录同一 namespace**；跨域压缩禁止，调用方应拆成多个 compact。
- 同步：随来源域订阅；不新增同步协议。
- 默认不可见：`memory_query` / `history` / `profile` / `skills` / `graph` 均排除；`/runtime/v1/context` 可在 token 预算内注入摘要，并附 `sourceIds` 引用。
- 生命周期：compact 是派生对象，删除 compact 不影响源记录；源记录墓碑后 compact 读取时标 `stale=true`，不自动删除。
- 不建图边：来源关系存 `sourceIds`，不创建 `compact -> record` 边，避免旧 `memory_graph` 从用户记录反向走到内部对象。

#### 2.3.4 ContextCheckpoint（任务/线程恢复点）

```ts
interface ContextCheckpointContent {
  schema: 1;
  threadId: string;
  agentId: string;
  revision: number;            // 单调递增，服务端分配
  state: Record<string, unknown>; // 不透明 JSON；上限 256 KiB
  summary?: string;
  recordIds: string[];         // 相关 MemoryRecord，可为空
  originHostId: string;
  lease: { hostId: string; until: number }; // 60s 租约，防双活恢复
  expiresAt: number;           // 默认 now + runtime.retention.checkpointDays
}
```

- 本地模式（默认）：存 `<home>/runtime/checkpoints/<cloudId>/<agentId>/<threadId>.json`，原子写、`0600`，不进入图/事件/同步。
- 云模式（`sync='cloud'`）：节点 `type='context_checkpoint'`、namespace `__checkpoint__`、`metadata.runtime.internal=true`；随 `__checkpoint__` 订阅同步。
- 读取键：`(cloudId, agentId, threadId)`；不同 Agent 即使 threadId 相同也互不可见。
- 写冲突：请求带 `expectedRevision`；不匹配返回 `409 revision_mismatch`。租约被其他 `hostId` 持有时返回 `409 checkpoint_lease_held`；`force=true` 仅 `memory.admin` 可用。
- 过期：读取时若 `expiresAt < now` 返回 `checkpoint: null` 并异步清理；不删除关联 MemoryRecord。
- 不进入 `memory_query` / `history`；`/runtime/v1/context` 可在 `includeCheckpoint=true` 时注入。

#### 2.3.5 RecallTrace（本地诊断）

```ts
interface RecallTrace {
  schema: 1;
  id: string;                 // tr_<ULID>
  cloudId: string;
  agentId: string;
  hostId: string;
  threadId?: string;
  at: number;
  queryHash: string;          // sha256(query)
  queryPreview: string;       // 脱敏后最多 200 字；可配置不存
  namespaces: string[];
  hits: Array<{ id: string; type: string; score?: number; rank: number }>;
  model: { query?: string; embedding?: string; extractor?: string };
  tookMs: number;
  degraded: boolean;
  feedback?: { useful: boolean; reason?: string; at: number };
}
```

- 只存本机 `<home>/runtime/traces.jsonl`；环形保留（默认 7 天 / 最多 2000 条）。
- 不存完整正文、不存 raw 文本、不存模型 prompt/response。
- 只有 `GET /runtime/v1/traces/:id`（admin）和 feedback 写入口；不参与同步。
- `runtime.trace='off'` 时 `recall` 不生成 trace，feedback 返回 404。

#### 2.3.6 SelfRecord（Agent 自我）

```ts
interface SelfRecordContent {
  schema: 1;
  agentId: string;
  revision: number;
  displayName?: string;
  goals: string[];
  traits: string[];
  preferences: Record<string, unknown>;
  capabilities: string[];
  boundaries: string[];
  updatedAt: number;
}
```

- 默认云模式：节点 `type='self_record'`、namespace `__self__`、`metadata.runtime.internal=true`；也可配置为本地文件。
- 唯一性：逻辑键 `(cloudId, agentId)`；因为 `GraphStore` 只能生成 ULID，允许并发创建多个节点；有效记录按 `(revision, updatedAt, id)` 取最大，旧节点隐藏、不自动删除，避免并发丢数据。
- 访问：`/runtime/v1/self/:agentId` 默认只允许同一 `agentId`（逻辑约束）；admin 可读全部。不是密码学隔离。
- 不进入 `memory_query` / `profile`；不是用户画像。
- 不建图边；与实体的关联用 `agentId` 字符串，不创建 `describes` 边，避免旧图遍历看到内部对象。

### 2.4 边

**0.3 不新增必需边类型。** 规则：

- `MemoryRecord` 继续使用现有 `EdgeTypes`（`prefers` / `works_on` / `related_to` / `supersedes` 等）。
- 内部对象与源记录的关系用 `content.sourceIds` / `recordIds` 表达，**不建边**。原因：旧版 `memory_graph` 会沿入边/出边遍历，内部边会把 `compact` / `checkpoint` 泄漏给 0.2 客户端。
- 如果将来需要图可视化，新增 `derived_from` / `compacts` / `checkpoints` 边必须同时引入 `metadata.runtime.internal` 过滤，且不能在本契约冻结前启用。
- 现有 `SYNCED_FROM` / `CONFLICT_RESOLVED` 语义不变，Runtime 不使用它们。

### 2.5 tag 与 metadata

| 项 | 约定 |
|---|---|
| 内部 tag 前缀 | `mebular:runtime:`（保留前缀；用户 tag 不使用） |
| 内部节点 tag | `mebular:runtime:internal`、`mebular:runtime:kind:<kind>`；可选 `mebular:runtime:agent:<agentId>` |
| 判别键 | `metadata.runtime.schema=1` + `metadata.runtime.kind` + `metadata.runtime.internal` |
| 现有 metadata | `archivedAt`、`relatedTo` 等保持原义；`metadata.runtime` 不覆盖它们 |
| 不加到 record 的 tag | 不为 MemoryRecord 添加 `mebular:runtime:*`，避免改变用户既有 tag 过滤 |
| 保留 metadata 键 | `runtime` 由 Runtime 独占；用户自定义 metadata 不得写入 `runtime` |

### 2.6 ID、幂等与去重

| 对象 | ID | 幂等键 | 去重规则 |
|---|---|---|---|
| MemoryRecord | 现有 ULID | 调用方 `requestId` + 内容哈希 | 同 `(kind, namespace, 归一化内容, validFrom)` 已存在则返回既有 id，`duplicate=true`；不自动合并 |
| RawChunk | `rc_<ULID>` | `(cloudId, agentId, threadId, contentHash, chunkIndex)` | 重复提交返回既有 id |
| Compact | 节点 ULID | `sha256(namespace + strategy + sorted(sourceIds))` | 同键返回既有 compact；源变化则生成新 compact |
| Checkpoint | 本地文件名或节点 id | `(agentId, threadId, revision)` + `Idempotency-Key` | revision 冲突 409；同 key 重放返回同结果 |
| RecallTrace | `tr_<ULID>` | 无（诊断对象） | 不去重；环形保留 |
| SelfRecord | 节点/本地 id | `(cloudId, agentId)` + `revision` | 多节点取最大 `(revision, updatedAt, id)` |

- 图节点 ID 继续用 ULID，**不改为内容寻址**；内容寻址只用于事件 ID，避免同内容更新导致边引用断裂（与现有 phase-4 决策一致）。
- `cloudId` 必须写入所有图内 Runtime 对象的 `metadata.runtime`；本地对象写入本地记录。
- `requestId` 作用域为 `(cloudId, endpoint)`，本地保留 24h；重复请求返回首次结果并带 `duplicate:true`。

### 2.7 默认可见性与查询排除

定义统一判定：

```ts
const INTERNAL_NODE_TYPES = new Set([
  'compact',
  'context_checkpoint',
  'self_record',
  'raw_chunk',        // 0.3 不落图，防御性保留
  'recall_trace',     // 0.3 不落图，防御性保留
]);

function isInternalObject(node) {
  return INTERNAL_NODE_TYPES.has(node.type)
    || node.metadata?.runtime?.internal === true
    || (typeof node.namespace === 'string'
        && node.namespace.startsWith('__')
        && node.namespace !== '__policy__');
}
```

默认行为：

| 入口 | 默认排除方式 | 0.2 结果 |
|---|---|---|
| `memory_query` | 候选类型仍为 entity/fact/episode/skill/meta；末尾再过 `isInternalObject` | 不变 |
| `memory_search` | 同上；`types` 只接受五类记忆类型，拒绝内部类型 | 不变 |
| `memory_history` | 只查 `episode` + `episodeType='conversation'`；RawChunk 不是 episode | 不变 |
| `memory_profile` | 只读 entity/fact；SelfRecord 不是 fact | 不变 |
| `memory_skills` | 只读 `skill` | 不变 |
| `memory_graph` | 过滤内部节点；起点是内部对象时返回空（或 404）；不建内部边 | 不变 |
| `memory_status` | 计数包含全部节点，但新增 `runtime` 分项 | 旧字段不变 |
| Console `/admin/api/memories` | 默认过滤 `isInternalObject` 与 `__*`；`includeInternal=1` 仅 admin | 旧行不变 |
| `memory_delete` / `memory_archive` | 内部 id 默认拒绝 `internal_object`；Runtime admin 端点可操作 | 旧行为不变 |
| CMF / import / export | 默认跳过 `metadata.runtime.internal` 与 `__*`；导入拒绝保留域 | 旧数据不受影响 |

- 不向 MCP 暴露 `includeInternal`。管理员只能通过 `/runtime/v1/objects` 或 Console 的 admin 开关查看。
- `memory_graph` 的 `startId` 如果是内部对象，返回 `404 internal_object`，不返回部分图。
- 防御性过滤是必须的：即使未来有人通过 `GraphStore` 直接写入 `compact` 节点，公共记忆查询也不会泄漏。

### 2.8 0.2 数据兼容

**不执行迁移。** 读取时按以下规则解释：

| 0.2 数据 | 0.3 解释 |
|---|---|
| 无 `metadata.runtime` 的 entity/fact/episode/skill/meta | `MemoryRecord` legacy；`userId='user'` 别名；`agentId='legacy'`；`source='legacy'`；不补写 |
| 无 namespace | `default` |
| `validTo=9999999999999` | 当前有效；API 输出 `null` |
| `deletedAt` 非空 | 墓碑；默认不召回；`includeHistory` 可读 |
| `metadata.archivedAt` 数字 | 归档；默认不召回；`includeArchived` 可读 |
| 旧 tag / `metadata.relatedTo` | 原样保留；不重写 |
| `task_event` 等未知 type | Runtime 忽略；不属于 MemoryRecord，也不属于内部对象 |
| `__policy__` 节点/事件 | 现有策略语义；Runtime 不读写 |
| 旧 `episode` conversation | `memory_history` 原样返回；RawChunk 不会被误认成 episode |

**回滚 0.3 → 0.2**：图节点是普通节点，旧代码会忽略未知 type；事件仍是 `node_*`，旧代码可应用；本地 `runtime/` 文件旧代码不读。不会丢已有记忆。旧 Console 可能把新节点列出来（见风险 R2），但不会读坏。

### 2.9 生命周期与保留

| 对象 | 默认保留 | 删除语义 | 归档 |
|---|---|---|---|
| MemoryRecord | 永久 | 墓碑 `deletedAt`，随事件同步 | `metadata.archivedAt`，可逆 |
| RawChunk | 7 天 | 本地删除，无墓碑、无同步 | 不适用 |
| RecallTrace | 7 天 / 2000 条 | 环形覆盖 | 不适用 |
| Compact | 随源记录 | 可墓碑；源记录不受影响 | 可归档但不建议 |
| Checkpoint | 30 天 | 本地删除或节点墓碑 | 不适用 |
| SelfRecord | 永久 | 节点墓碑；同 agent 可重新创建 | 不适用 |

- 清理任务只处理本地对象与过期 checkpoint；**绝不自动删除 MemoryRecord**。
- 删除源 MemoryRecord 不级联删除 compact；读取 compact 时标 `stale=true`，上下文注入时降权。
- 墓碑/归档继续沿用 0.2 的合作式语义：已同步到对端的旧副本无法强制回收。

## 3. 身份与所有权

### 3.1 标识定义

| 标识 | 作用域 | 生成 / 来源 | 稳定性 | 是否秘密 | 是否同步 |
|---|---|---|---|---|---|
| `cloudId` | 忆云（跨设备） | `cl_` + `sha256(用户主密钥公钥 raw)[0:32]` 小写 hex | 跨设备稳定 | 否（公钥哈希） | 由记录携带，不单独同步 |
| `userId` | 忆云内用户 | `u_` + 同一摘要 `[0:16]` | 跨设备稳定 | 否 | 记录元数据 |
| `deviceId` | 设备 | 现有 `<storage>.identity.json` | 设备生命周期 | 公钥公开 | 事件 author |
| `hostId` | 本机 Runtime 宿主 | `h_` + `sha256(deviceId + "\0" + homeKey)[0:16]` | 安装/宿主生命周期 | 否 | 仅本地/需要时 |
| `agentId` | 逻辑 Agent | 宿主声明或内置 descriptor；`^[a-z0-9][a-z0-9._-]{0,63}$` | 集成稳定 | 否 | 记录/self |
| `threadId` | 会话/任务线程 | 宿主提供；缺省 `th_<ULID>`；`^[A-Za-z0-9._:-]{1,128}$` | 线程生命周期 | 可能敏感 | checkpoint/记录 |
| `profileId` | 本机忆云注册表 | 现有 `profiles.json` | 本机稳定 | 否 | 不同步 |
| `namespace` | 记忆域 | 用户/配置 | 域稳定 | 否 | 节点/事件 |

**派生细节**：

- `cloudId` / `userId` 使用根用户主密钥公钥；委派设备从证书链根证书取公钥；取不到时 `/runtime/v1/status` 返回 `cloudId: null`、`initialized:false`，写接口 503。
- `cloudName` 只是展示名，不参与身份、不参与冲突判定。
- `agentId` 是**断言**，不是认证。持有 `memory.write` 的调用方可以声明任意 agentId；0.3 不做 token 到 agent 的绑定。需要时在 0.4 增加 `token.agentId` 约束。
- `hostId` 由服务端计算，客户端不能提交；用于 checkpoint 租约和本地 provenance。
- `threadId` 由宿主提供；不同 Agent 可以使用相同 threadId，但 checkpoint 键包含 `agentId`，不会串。
- 旧数据的事实 subject 仍是 `'user'`；`userId` 是 envelope 所有者，不强制改写真值。`MemoryService.userId` 默认仍是 `'user'`，保证 `profile` 兼容。

### 3.2 `cloudId` 与现有 `/healthz.cloudId` 的冲突

现状：`/healthz` 的 `cloudId` 实际是**本地 profile id**（`default` / `[a-z0-9_]+`），用于 Runtime Supervisor 判断端口上是不是目标忆云；它不是跨设备稳定标识。

本契约：

- **0.3 保持 `/healthz.cloudId` 原义不变**，避免破坏 App / CLI / DSH 的 `cloud_mismatch` 判断。
- `/healthz` 新增 `profileId`（与旧 `cloudId` 同值）和 `cloudTrustId`（本契约的 `cloudId`）。
- `/runtime/v1/status` 的 `identity.cloudId` 使用本契约的稳定值；同时返回 `identity.profileId`。
- 0.4 再把 `/healthz.cloudId` 重命名为 `profileId`，并保留一个过渡期别名。

> 这是需要 chief 拍板的事项 D1。若要求“一个字段只表示一个含义”，也可以现在就把 `/healthz.cloudId` 改成稳定值，但必须同步改 Supervisor 的所有比较逻辑和兼容测试，风险更高。

### 3.3 所有权边界

| 边界 | 包含对象 | 读 | 写 | 同步 | 默认进入记忆查询 |
|---|---|---|---|---|---|
| **用户共享** | MemoryRecord（fact/preference/skill/entity/episode），用户 namespace | 同云所有已授权设备/Agent；受 namespace 订阅 | `memory.write` | 是，按域 | 是 |
| **关系记忆** | 带实体/边的 MemoryRecord；`metadata.runtime.visibility='relationship'` | 与所在 namespace 相同 | `memory.write` | 是，按域 | 是 |
| **Agent self** | SelfRecord | 同一 `agentId`（逻辑）；admin 全部 | 同一 `agentId` | 默认云；可配本地 | 否 |
| **任务 checkpoint** | ContextCheckpoint | 同一 `(agentId, threadId)`；admin 全部 | 同一 `(agentId, threadId)` | 默认本地；显式云 | 否 |
| **内部派生** | Compact | Runtime context builder；admin | Runtime compact | 随源域 | 否 |
| **原始/轨迹** | RawChunk / RecallTrace | 本机同 host；admin | Runtime | 永不 | 否 |

关键澄清：

- **“用户共享”指同一忆云内该用户的所有设备与 Agent，不是多个自然人共享一个忆云。** 当前协议只有设备证书，没有成员账号；多自然人共享需要新的身份层，0.3 不做。
- **“关系记忆”不是独立权限域**：它仍是 MemoryRecord，区别在形状（实体 + 边）。没有按关系对（A-B）粒度的 ACL；要限制同步范围，请使用专用 namespace（如 `rel:project-x`）。
- **Agent self 是逻辑边界，不是密码学边界**：同一忆云的所有设备在物理上都能读到 `__self__` 域；Runtime 按 `agentId` 过滤，其他 Agent 默认看不到。若要求“其他 Agent 即使拿到存储也读不到”，需要按 Agent 加密，0.3 不做。
- **Checkpoint 是任务状态，不是记忆**：默认本地，避免把任务中间态同步给所有设备；需要跨设备恢复时显式 `sync='cloud'`。

### 3.4 跨设备 / 跨 Agent 同步语义

| 对象 / 场景 | 跨设备 | 跨 Agent | 机制 |
|---|---|---|---|
| MemoryRecord | 是，按 namespace 订阅 | 是；同一记录对所有 Agent 可读 | 现有事件日志 + 快照 |
| Compact | 是，随源 namespace | 是；但仅通过 context 注入，不进入普通查询 | 普通节点事件 |
| SelfRecord | 是（`sync=cloud` 时） | 否；按 `agentId` 过滤 | `__self__` 节点事件 |
| Checkpoint | 默认否；`sync=cloud` 时是 | 否；按 `agentId` + `threadId` 过滤 | 本地文件或 `__checkpoint__` 节点 |
| RawChunk | 否 | 否 | 本地存储 |
| RecallTrace | 否 | 否 | 本地日志 |
| 新设备首次同步 | 已订阅域的 MemoryRecord / Compact / Self / 云 Checkpoint 随快照进入 | 按对象过滤 | 现有 snapshot |
| 设备退订 | 不再接收未来事件；本地旧副本保留（合作式） | — | 现有订阅语义 |
| 设备移出 | 现有 `device_revoke` 语义；新事件不采纳 | — | 现有策略 |
| 跨忆云 | 不支持；不同 `cloudId` 不合并 | — | 主密钥不同 |

**不新增同步协议**：Runtime 节点就是普通节点。旧 0.2 对端会应用未知 type 的节点（GraphStore 不校验 type），但不会在默认查询中返回；这保证混合版本不崩，代价是旧端存储会有不可见节点（风险 R2）。

### 3.5 冲突与一致性

| 对象 | 冲突策略 |
|---|---|
| MemoryRecord | 追加式记录；事实用 `validFrom` / `validTo` / `SUPERSEDES`；不做自动语义合并 |
| Compact | 同 `(namespace, strategy, sourceIds)` 幂等；不同来源生成多个 compact；context 选择最新且 `stale=false` |
| Checkpoint | `revision` 单调 + 60s `lease`；`expectedRevision` 不匹配 409；租约被其他 host 持有 409；`force` 仅 admin |
| SelfRecord | 多节点取最大 `(revision, updatedAt, id)`；旧节点隐藏，不自动删除 |
| RawChunk | 内容哈希去重；同 hash 不同文本视为冲突，拒绝并报 `content_hash_mismatch` |
| RecallTrace | 无冲突；环形覆盖 |

- 墙钟不用于权威排序；沿用现有事件向量时钟。`revision` 是 Runtime 层的应用级乐观并发控制。
- 跨设备同时写 checkpoint：租约只能降低概率，不能完全替代分布式锁；见风险 R9。

## 4. 两种接入

### 4.1 轻量 MCP（默认）

**定位**：Mebular 是宿主 Agent 的“跨设备记忆工具”，不接管上下文、不采集原始对话、不调用模型。

数据流：

```text
宿主模型/Agent
  → MCP memory_query / memory_search / memory_profile / ...
  → MemoryService → GraphStore / EventLog
  → 同步到同云其他设备
```

- 写入只有宿主显式 `memory_write` / `memory_write_batch`；不自动从对话抽取。
- 不产生 RawChunk、Compact、Checkpoint、SelfRecord（除非管理员显式调用 runtime API）。
- 现有 29 个工具、参数、返回形状不变；`memory_policy` prompt 不变。
- 默认 `runtime.mode='mcp'`；0.2 用户升级后行为不变。

### 4.2 沉浸式 Runtime

**定位**：宿主把会话片段、任务状态和候选抽取交给 Runtime；Runtime 负责抽取、压缩、召回、上下文组装和 checkpoint。宿主仍可继续使用 MCP 工具。

数据流：

```text
宿主对话/任务
  → POST /runtime/v1/ingest（chunks + 可选 candidates）
  → RuntimeService
      ├─ RawChunk 本地保存（capture=local）
      ├─ heuristic / local / host / api 抽取 → MemoryRecord
      ├─ Compact 生成
      └─ Checkpoint 保存
  → POST /runtime/v1/recall / context
  → 宿主把 context blocks 注入模型
```

- 不强制宿主使用 Mebular 的模型；宿主可以只提交 candidates（`extractor='host'`），Runtime 只负责校验、去重、落库。
- 不做“自动接管所有对话”：只有调用 `/ingest` 的片段才会被处理。
- `capture='off'` 时仍可抽取：请求里的 chunks 只用于本次抽取，不落本地。默认 `off`；需要本地回看/重试才开 `local`。

### 4.3 模式切换：不迁移、不丢数据

`runtime.mode` 是**设备本地配置**，不是共享记忆；同云不同设备可以一个跑 `mcp`、一个跑 `immersive`，共享的 MemoryRecord 完全一致。

| 切换 | 行为 |
|---|---|
| `mcp → immersive` | 立即生效（无需重启）；Runtime 懒加载现有 MemoryRecord 建索引；不重写、不复制节点；后续 ingest 才开始产生 Runtime 对象 |
| `immersive → mcp` | 立即生效；停止采集/抽取/checkpoint 写入；已有 MemoryRecord / Compact / Self / 云 Checkpoint 保留；本地 Raw/Trace 按保留策略保留；`memory_*` 照常可读 |
| 写入端点 | `mcp` 模式下 `ingest` / `checkpoint PUT` / `compact` 返回 `409 mode_mismatch`；`status` / `recall` / `context` / `checkpoint GET` / `self GET` 仍可读 |
| 索引 | 切换不重建向量索引；沿用现有 `MemoryStore` 懒回填；Runtime 自己的倒排/缓存可丢弃重建，不影响图 |
| 数据迁移 | **无**。没有任何 `ALTER`、没有节点 type 转换、没有事件重放 |
| 回滚 | 切回 `mcp` 即回到 0.2 行为；Runtime 对象仍在图中但默认不可见 |

**验收判据**：

- 切换前后 `memory_query` 返回的 MemoryRecord id 集合一致。
- 切换前后节点总数只增减 Runtime 新写入的对象，不发生既有节点重写。
- 切换前后同一记录的 `createdAt`、`id`、`namespace`、`tags` 不变。
- 切换过程中断（进程崩溃）后重启，模式取最后一次原子写入的 config；数据不丢。

|---|---|---|---|---|

## 5. 模型来源

### 5.1 四种来源

| 来源 | 运行位置 | 网络 | 默认 | 用途 | 回退 |
|---|---|---|---|---|---|
| `heuristic` | Mebular 进程内 | 无 | **默认** | 规则化抽取：偏好句式、明确事实、任务/决策 episode；查询关键词扩展 | 自身始终可用 |
| `local` | 本机子进程/进程内 | 无（模型已安装） | 关闭 | 本地 Qwen 精选包做抽取、摘要、候选排序 | `heuristic` |
| `host` | 宿主模型 | 由宿主决定 | 关闭 | 宿主把当前对话模型产出的结构化候选提交给 Runtime；Runtime 不调用宿主 API | `heuristic`（仅当宿主未提交候选时，raw 仍可规则抽取） |
| `api` | 第三方 OpenAI-compatible | 有，需显式允许 | 关闭 | 抽取/摘要；适合无本地算力 | `heuristic`；不自动换供应商 |

**关键限制（“仅宿主自然提供”）**：

- Runtime **不会**读取宿主的环境变量、token、模型 endpoint，也不会反向调用宿主模型。
- 宿主使用当前对话模型时，必须自己把结果整理成 `CandidateRecord[]`，随 `ingest` 提交，或在 `extraction` pending 后回填。
- 如果宿主只提交 raw 文本、不提交候选，`extractor='host'` 会返回 `202 pending`，不会偷偷改用其他模型；调用方可以改为 `heuristic` / `local` / `api`，或回填候选。

### 5.2 配置项

新增 `runtime` 配置组；沿用 `config-schema.mjs` 的扁平 path 风格，便于 Console 渲染和待重启判定。

| 配置 path | 类型 | 默认 | 热生效 | 说明 |
|---|---|---|---|---|
| `runtime.mode` | `mcp` \| `immersive` | `mcp` | 是 | 设备级；切换不迁移 |
| `runtime.capture` | `off` \| `local` | `off` | 是 | 是否保留 RawChunk；`local` 仅本机 |
| `runtime.trace` | `off` \| `local` | `local` | 是 | 是否记录 RecallTrace |
| `runtime.retention.rawDays` | int | `7` | 是 | RawChunk 保留天数 |
| `runtime.retention.traceDays` | int | `7` | 是 | Trace 保留天数 |
| `runtime.retention.checkpointDays` | int | `30` | 是 | Checkpoint 过期天数 |
| `runtime.model.source` | `heuristic` \| `local` \| `host` \| `api` \| `auto` | `heuristic` | 是 | `auto` 解析顺序见 5.4 |
| `runtime.model.local.pack` | string \| null | `null` | 是 | 本地精选包 id；不自动下载 |
| `runtime.model.local.path` | string \| null | `null` | 是 | 本地包目录；为空用 `<home>/runtime/models/<pack>` |
| `runtime.model.local.threads` | int | `4` | 是 | 本地推理线程数 |
| `runtime.model.api.baseUrl` | string \| null | `null` | 是 | 必须 https（loopback 例外） |
| `runtime.model.api.model` | string \| null | `null` | 是 | 第三方模型名 |
| `runtime.model.api.keyRef` | string \| null | `null` | 是 | 密钥引用，见 5.3 |
| `runtime.model.api.allowRemote` | bool | `false` | 是 | 总开关；false 时 api 来源不可用 |
| `runtime.model.api.timeoutMs` | int | `10000` | 是 | 单次请求超时 |
| `runtime.checkpoint.sync` | `local` \| `cloud` | `local` | 是 | 默认本地 |
| `runtime.self.sync` | `local` \| `cloud` | `cloud` | 是 | 默认跨设备同一 Agent |
| `runtime.limits.maxChunkBytes` | int | `262144` | 是 | 单 chunk 上限 |
| `runtime.limits.maxContextTokens` | int | `12000` | 是 | context 预算上限 |
| `runtime.limits.maxRecall` | int | `50` | 是 | 单次召回上限 |

- 旧 `config.json` 没有 `runtime` 时全部取默认，不需要迁移。
- `runtime.mode` / `capture` / `trace` / `checkpoint.sync` / `self.sync` 建议热生效；模型包和 baseUrl 可要求重启（与 `semantic` 一致），契约不强制。
- 配置写入仍走现有 `POST /admin/api/config` 的校验、原子写、`.bak` 和待重启判定；不新建配置面。

### 5.3 密钥存放

`runtime.model.api.keyRef` 只接受引用，不接受明文：

| 形式 | 示例 | 规则 |
|---|---|---|
| 环境变量 | `env:MEBULAR_RUNTIME_MODEL_API_KEY` | 进程启动时读取；不写入 config |
| 系统钥匙串 | `keychain:mebular-runtime/<cloudId>` | macOS Keychain / Windows Credential Manager / libsecret；首选 |
| 文件 | `file:secrets/runtime-model.key` | 相对 `<home>`；权限 `0600`；不得放在共享存储/同步目录 |
| 无 | `null` | 依次尝试 `MEBULAR_RUNTIME_MODEL_API_KEY`、钥匙串、默认文件；都无则 api 不可用 |

- **禁止**：`apiKey` 明文、`Authorization` 写入 `config.json`、写入 graph metadata、写入事件、写入 Console、写入日志。
- `/runtime/v1/status` 只返回 `credential: { configured: true|false, source: 'env'|'keychain'|'file'|null }`，不返回值、不返回末四位。
- 错误信息统一脱敏：移除 `Authorization`、`api_key`、`token`、`secret`、`password` 等键；模型响应体不进入错误详情。
- 本地 Qwen 包：安装目录 `<home>/runtime/models/<pack>/`，带 `manifest.json`（版本、sha256、license、context length、quantization）；安装命令显式执行，支持离线导入；不自动更新、不静默下载。

### 5.4 失败与回退

| 场景 | 行为 |
|---|---|
| `heuristic` | 永远可用；不联网；失败只可能是代码 bug，返回 500 |
| `local` 未安装 / 校验失败 / 推理失败 | `model_unavailable`；若 `fallback=heuristic`（默认）则规则抽取，`degraded=true`；否则 503 |
| `host` 未提交候选 | `202 {status:'pending'}`；不自动换模型；宿主可回填或改来源 |
| `host` 候选格式错误 | 全量非法 → 400；部分非法 → 接受合法项，`warnings[]` 列出丢弃项 |
| `api` 未配置 / `allowRemote=false` | `remote_not_allowed` / `model_unavailable`；不发起请求 |
| `api` 超时 / 5xx / 429 | 重试最多 1 次（429 尊重 `Retry-After`）；仍失败 → 回退 heuristic；熔断 5 次/60s；不换供应商 |
| 查询 embedding 失败 | 回退现有关键词基线；`degraded=true`；不伪造 relevance |
| Compact 模型失败 | 保留源记录，不生成 compact；返回 `compact_failed`；不影响记忆 |
| Context 组装失败 | 返回已有 blocks + `warnings`；checkpoint 损坏则跳过，不阻塞 recall |

- **ingest 不因模型失败丢数据**：chunks 已接收（`capture=local` 时已落本地；`off` 时本次请求内处理）；抽取失败记录 `extraction.status='failed'`，可用 `POST /runtime/v1/extractions/:id` 重试或改来源。
- 所有降级必须出现在 `status.degraded` / `warnings`，不允许静默。

### 5.5 每设备配置 vs 共享记忆

| 项 | 作用域 | 是否同步 | 说明 |
|---|---|---|---|
| `runtime.mode` | 设备 | 否 | 一个设备可轻量，另一个可沉浸 |
| `runtime.capture` / retention | 设备 | 否 | 本地隐私策略 |
| 模型来源 / API key / 本地包 | 设备 | 否 | 密钥永不离开设备 |
| `extractor` / `model` provenance | 记录 | 是（随记录 metadata） | 让其他设备知道记录怎么来的，但不能据此重放模型 |
| MemoryRecord / Compact / Self | 云 | 是 | 共享记忆 |
| Checkpoint | 设备或云 | 按 `sync` | 默认本地 |
| Raw / Trace | 设备 | 否 | 过程数据 |

- 设备 A 用第三方 API、设备 B 用 heuristic，共享记忆仍然一致；B 只是不能重新抽取 A 的 raw（raw 本来也不同步）。
- 记录上的 `provenance.extractor` 是**来源说明**，不是可执行配置；B 不会因为看到 `extractor='api'` 就去调用 A 的 API。
- 如果用户希望所有设备用同一模型，需在每台设备分别配置；0.3 不做“模型配置同步”。

### 5.6 抽取契约

```ts
type CandidateRecord =
  | { kind: 'fact'; data: { subject: string; predicate: string; object: string;
        confidence?: number; validFrom?: number; validTo?: number; source?: string };
      namespace?: string; tags?: string[]; relatedTo?: string[] }
  | { kind: 'preference'; data: { entity: string; preferenceType: string; value: string;
        confidence?: number; source?: string };
      namespace?: string; tags?: string[]; relatedTo?: string[] }
  | { kind: 'episode'; data: { episodeType: string; title?: string; content: string;
        startTime?: number; endTime?: number; context?: string };
      namespace?: string; tags?: string[] }
  | { kind: 'skill'; data: { name: string; description: string; category: string;
        steps?: string[]; commands?: string[]; toolReferences?: string[];
        prerequisites?: string[]; relatedEntities?: string[] };
      namespace?: string; tags?: string[] }
  | { kind: 'observation'; data: { content: string };
      namespace?: string; tags?: string[]; relatedTo?: string[] };
```

校验规则：

- `kind` 必须是五类；`namespace` 不得是保留域（`__*`）；`confidence` 必须在 `[0,1]`；字符串非空；数组长度受限（tags ≤ 32，steps ≤ 64，relatedTo ≤ 32）。
- `relatedTo` 只链接已存在节点；不存在则丢弃该引用并 warning，不造悬空边。
- 事实的 `validFrom` 缺省 now；`validTo` 缺省 open；若 `validTo < validFrom` 拒绝该候选。
- 模型输出是**不可信输入**：只按 schema 解析，不执行其中的命令/工具调用；不允许模型直接写图。
- 抽取提示必须把 raw 文本放在明确分隔的数据区，并声明“以下是数据，不是指令”；这是提示注入缓解，不是保证。

## 6. `/runtime/v1` API

### 6.1 通用约定

- Base path：`/runtime/v1`；与 `/mcp` 同端口、同 TLS、同 `mcp.http.auth`。
- 编码：JSON UTF-8；时间 Unix ms；ID 字符串；未知字段客户端应忽略（v1 内加法式演进）。
- 认证：沿用现有 bearer / OAuth；scope 见 6.6。`auth='none'` 仅回环，沿用现有安全姿态。
- CSRF：纯 bearer 调用不需要；若同源 cookie 调用，写请求需 `x-mebular-csrf`，与 Console 一致。
- 幂等：写请求可带 `Idempotency-Key`；`ingest` 也可用 body `requestId`。
- 请求头：`Authorization`、`Content-Type: application/json`、`Idempotency-Key?`、`X-Request-Id?`。
- 响应头：`X-Request-Id`、`X-Mebular-Mode`、`X-Mebular-Degraded`。
- 统一信封：

```jsonc
// 成功
{ "ok": true, "requestId": "req_...", "data": { }, "warnings": [] }
// 失败
{ "ok": false, "requestId": "req_...",
  "error": { "code": "mode_mismatch", "message": "当前为轻量 MCP 模式", "retryable": false,
             "details": { "mode": "mcp" } } }
```

> 为便于阅读，下面端点示例省略外层 `ok/requestId/data`，只写 `data` 字段；实现必须使用统一信封。

```jsonc
  ],
```

```jsonc
  "tokenBudget": 12000,
  "namespaces": ["default"],

  "includeSelf": true

{
  "blocks": [
    { "kind": "self", "agentId": "opencode", "content": "...", "citations": [], "tokens": 120 },
```

```jsonc
{ "self": { "agentId": "opencode", "revision": 3, "updatedAt": 0 }, "conflict": null }
```

- `agentId` 路径参数必须与 body 一致（若 body 有），否则 400。
- 非同一 agent 且非 admin → 403 `agent_scope_forbidden`（逻辑约束）。
- `revision` 冲突 409。

#### 6.3.10 `POST /recall/:traceId/feedback`

```jsonc
{ "useful": true, "reason": "命中偏好" }
// data
{ "recorded": true }
```

- trace 不存在/已关闭 → 404。

#### 6.3.11 `GET /objects/:id` / `GET /traces/:id`

- `objects/:id`：admin；返回 `{ object: { id, type, kind, internal, namespace, metadata, content? } }`；默认 `includeContent=false`，`?includeContent=true` 才返回完整 content。
- `traces/:id`：admin；仅本地；返回 trace 结构；不含 raw 正文。

### 6.4 错误码

| HTTP | code | 含义 |
|---|---|---|
| 400 | `invalid_request` | JSON/schema/字段非法 |
| 400 | `invalid_agent_id` | agentId 格式非法 |
| 400 | `invalid_thread_id` | threadId 格式非法 |
| 400 | `namespace_reserved` | 写入 `__*` 保留域 |
| 400 | `namespace_mismatch` | compact 跨域 |
| 400 | `content_hash_mismatch` | 同 hash 不同内容 |
| 401 | `unauthorized` | 缺/错 token |
| 403 | `forbidden_scope` | scope 不足 |
| 403 | `agent_scope_forbidden` | 跨 Agent 读写 self/checkpoint |
| 403 | `cloud_checkpoint_disabled` | 未允许云 checkpoint |
| 404 | `not_found` | 对象/抽取/trace 不存在 |
| 404 | `internal_object` | 公共接口访问内部对象 |
| 409 | `mode_mismatch` | 轻量模式调用写端点 |
| 409 | `revision_mismatch` | checkpoint/self 版本冲突 |
| 409 | `checkpoint_lease_held` | 其他 host 持有租约 |
| 409 | `cloud_mismatch` | 请求头 cloud 与服务端不一致 |
| 413 | `payload_too_large` | body/chunk/state 超限 |
| 422 | `extraction_invalid` | 候选全部非法 |
| 429 | `rate_limited` | 限流；带 `Retry-After` |
| 500 | `internal` | 未分类错误 |
| 503 | `runtime_not_ready` | 未初始化/图不可用 |
| 503 | `model_unavailable` | 模型不可用且不允许回退 |
| 503 | `remote_not_allowed` | api 来源未允许 |

`error.message` 是给人看的短句；`details` 只放非敏感结构；不得回显 token/key/raw 文本。

### 6.5 限流与大小

- 默认每 token/IP 60 req/min；`ingest` 10 req/min；`recall`/`context` 120 req/min。
- body ≤ 2 MiB；chunks ≤ 100；单 chunk ≤ 256 KiB；checkpoint `state` ≤ 256 KiB；candidates ≤ 200。
- 超限返回 413/429；不做静默截断（除 context token 预算的显式 `truncated=true`）。

### 6.6 Scope 映射

| 能力 | Scope |
|---|---|
| status / recall / context / checkpoint GET / compact GET / self GET | `memory.read` |
| ingest / extraction POST / checkpoint PUT / self PUT / feedback | `memory.write` |
| mode / compact POST / checkpoint DELETE / objects / traces | `memory.admin` |

- 不新增 `runtime.*` scope，避免现有 token 需要重新签发。
- `memory.read` 是云内读权限，不按 namespace 细分；这是现有模型的限制，见风险 R13。

### 7.2 必须冻结的语义

1. **0.2 默认查询不变**：`memory_query` 默认五类记忆；`history` 只返回 conversation episode；内部对象不得出现。
2. **不做数据迁移**：不得为了 Runtime 改写旧节点、旧事件、旧 namespace、旧 tag。
3. **模式不迁移**：`mcp` / `immersive` 是同一存储的两种投影；切换不得复制/转换记录。
4. **Raw/Trace 不同步**：0.3 不得把 raw 文本或 trace 放进图、事件或共享域。
5. **内部对象不进普通图**：不得创建从用户记录到内部对象的边；引用用 ID 数组。
6. **模型不隐式调用**：host 来源只接受候选；api 来源必须配置 + `allowRemote` + 请求允许。
7. **密钥不入 config/图/日志**：只允许 `keyRef`。
8. **单写者**：Runtime 不绕过现有 `serve` / stdio 锁。
9. **MCP 工具面 29 个不变**：不新增/不改名/不删除；Runtime API 独立。
10. **同步线协议不变**：不新增事件类型；Runtime 节点是普通节点。

### 7.3 配置键

第 5.2 节列出的 `runtime.*` 键为 v1 冻结集合；新增只能追加，默认值不得改变既有行为。

### 7.4 API

`/runtime/v1` 的路径、方法、scope、错误码、必填字段为 v1 冻结；响应可追加字段。破坏性变更走 `/runtime/v2`。

### 7.5 兼容承诺

- 0.2 数据：可读、可查、可同步、可回滚；不重写。
- 0.2 客户端：MCP/CLI 默认结果不变；Console 旧字段不变。
- 0.3 客户端：未知字段忽略；未知错误码按 `error.code` 字符串处理。
- 混合版本：旧对端可应用新节点事件；新对端可读旧节点；不要求同时升级。

## 9. 风险

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | `cloudId` 与 `/healthz.cloudId` 语义冲突 | Supervisor 误判、跨设备身份混乱 | 0.3 保持旧字段，新增 `cloudTrustId`；0.4 再改名（D1） |
| R2 | 旧 Console 列出新节点 | 用户看到 compact/self/checkpoint 行 | 新节点放保留域；Console 默认过滤；升级包同发；旧端最坏只多几行，不丢数据 |
| R3 | 保留域被默认订阅同步 | `__self__` / `__checkpoint__` 进入所有设备 | 默认 checkpoint 本地；self 逻辑过滤；文档明确“同云设备可读”；需要密码学隔离则 0.4 |
| R4 | Raw 采集含密钥/隐私 | 本地泄露 | 默认 `capture=off`；`local` 时 0600 + 可选静态加密；TTL；`/status` 警告；不自动上传 |
| R5 | 本地 Qwen 包体积/许可/算力 | 安装失败/用户体验差 | 精选包显式安装、manifest/checksum/license；默认 heuristic；不静默下载 |
| R6 | 宿主模型接入碎片化 | 不同宿主行为不一致 | 只冻结 CandidateRecord；host 未提供时 pending，不猜；文档给示例 |
| R7 | API key 跨平台存储 | 钥匙串不可用/泄露 | keyRef 三选一；文件 0600；只读状态；脱敏测试 |
| R8 | Checkpoint 双活恢复 | 两个 host 同时恢复同一线程 | revision + 60s lease；force 仅 admin；仍非强分布式锁（R9） |
| R9 | Checkpoint 租约不是强锁 | 极端并发下覆盖 | 0.3 接受“最后写入 + revision 检测”；0.4 可引入单写者协调 |
| R10 | Compact 摘要失真 | 模型看到错误摘要 | 摘要附 sourceIds；`stale` 检测；context 注入时优先源记录；不删除源 |
| R11 | 重复抽取/记录膨胀 | 记忆库噪声 | requestId/contentHash 去重；候选键去重；先查后写；不自动合并冲突 |
| R12 | 混合版本存储膨胀 | 旧端存未知节点 | 同步仍工作；旧端不可见；文档说明；后续可清理 |
| R13 | `memory.read` 是云内全量读 | 任意 token 可读所有 namespace | 0.3 沿用现有 scope；namespace ACL 是后续工作；文档明确 |
| R14 | Runtime HTTP 新攻击面 | 本地/局域网未授权写 | 沿用现有 auth/TLS/loopback；写 scope；CSRF；body 限制；Origin 检查 |
| R15 | Agent self 逻辑隔离被绕过 | 其他 Agent 读 self | 明确非密码学；token 级 agent 绑定留 0.4；敏感内容不要写 self |
| R16 | 性能/上下文过大 | 延迟/成本 | tokenBudget；limit；截断；异步 compact；本地缓存 |
| R17 | 用户期待多自然人共享 | 产品预期不符 | 明确单云单用户；多用户需新身份层，不在 0.3 |
| R18 | 回滚后 Runtime 配置残留 | 旧代码忽略未知 config | 旧代码应保留未知键；文档建议回滚时保留 `runtime` 段 |

## 10. 不做的内容

1. **不做多自然人账号/成员 ACL**：没有 userId 登录、没有按人授权；一个忆云仍是一个用户主密钥。
2. **不做按 Agent 的密码学隔离**：Self/Checkpoint 的隔离是 Runtime 逻辑过滤，不是加密。
3. **不做数据迁移/重写/重签**：不补 `metadata.runtime`、不改旧 namespace/tag/ID。
4. **不做自动对话全量采集**：只有显式 `/ingest` 的片段被处理；MCP 模式不采集。
5. **不做宿主模型反向调用**：不读宿主 token、不猜 endpoint、不代理宿主 API。
6. **不做自动模型下载/自动更新**：本地包显式安装；API 配置显式。
7. **不新增同步线协议/事件类型**：Runtime 节点是普通节点；本地对象不同步。
8. **不新增/不改名 MCP 工具**：29 个工具冻结；Runtime 走 HTTP。
9. **不做破坏性 compact**：不删除/覆盖源记录；compact 只是派生摘要。
10. **不做跨忆云合并/联邦**：不同主密钥/cloudId 不合并。
11. **不做 namespace 级 ACL**：沿用现有订阅；`memory.read` 仍是云内读。
12. **不做自动冲突语义合并**：事实仍靠 validFrom/SUPERSEDES；不自动判断“哪条是真的”。
13. **不做 Raw/Trace 的 Console 展示**：不提供全文浏览；只有 admin 调试接口。
14. **不做 Runtime 专用加密密钥**：沿用现有静态加密；`encryptionKeyId` 仍是占位。
15. **不改变 0.2 默认查询/历史/画像/技能结果**。

## 12. 建议实施顺序（不含实现）
