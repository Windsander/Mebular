# Mebular 0.3.0 Memory Runtime Sidecar（进程与生命周期契约）

**状态**：v1.0 / G0-A 冻结稿，2026-10-30
**上位契约**：[`0.3.0-memory-runtime-contract-v2.md`](./0.3.0-memory-runtime-contract-v2.md)
**内部 API**：[`0.3.0-mcp-capability-api.md`](./0.3.0-mcp-capability-api.md)
**包名**：`@mebular/memory-runtime`
**可执行文件**：`mebular-memory-runtime`
**CLI 组**：`mebular memory-runtime ...`
**定位**：独立进程、独立包、可选增量；位于 MCP 能力层之上，不在 MCP 进程内运行

---

## 0. 一页结论

- **独立进程**：`mebular-memory-runtime serve`；由 MCP daemon 或用户启动；不嵌入 `mebular serve`。
- **独立包/独立版本**：`@mebular/memory-runtime`；版本与 MCP/core 解耦；启动时做 capability API 握手。
- **只走 HTTP**：所有持久记忆通过 `/internal/memory/v1` 写入 MCP；sidecar 不打开图/事件日志/同步。
- **一个 home 一个实例**：`<home>/memory-runtime/` + 启动锁 + discovery；不做多实例共享。
- **轻量模式零副作用**：不启动、不建目录、不监听端口、不写 token、不下载模型。
- **沉浸式自动管理**：用户只做一次模式选择；MCP daemon 负责 spawn/health/stop；失败开放。
- **本地只有过程数据**：Raw、Trace、cache、outbox、模型、配置；不是权威，可重建/可过期。
- **所有持久记忆上云**：MemoryRecord、Compact、SelfRecord、ContextCheckpoint 都经 capability 写入忆云；**没有 `sync=cloud` / `self.sync`**。
- **单写者不变**：MCP 仍是唯一图写入者；sidecar 没有图写入路径。
- **命名不混用**：`mebular runtime` 仍是 MCP daemon；sidecar 只用 `mebular memory-runtime`。

## 1. 与 MCP daemon runtime 的区别（强制）

| 维度 | MCP daemon runtime | Memory Runtime sidecar |
|---|---|---|
| 包 | `@mebular/mcp` + `@mebular/core` | `@mebular/memory-runtime` |
| 进程 | `mebular serve` / `mebular-serve` service | `mebular-memory-runtime serve` |
| CLI | `mebular runtime ...`（既有） | `mebular memory-runtime ...`（新增） |
| 主管 | 用户/App/服务单元 | MCP daemon（自动）或用户（手动） |
| 默认端口 | 7331（既有） | 7341（可回退临时端口） |
| 发现文件 | `<home>/runtime.json` | `<home>/memory-runtime.json` |
| 数据/安装目录 | `<cloudRoot>/runtime/<version>/` | `<home>/memory-runtime/` |
| 是否写图 | 是，唯一写者 | 否，只经 capability API |
| 是否必需 | 0.2/0.3 轻量模式必需 | 仅沉浸式可选 |
| 失败影响 | MCP 不可用 | 对话继续，只是不注入记忆 |
| 升级方式 | 共享 runtime install/upgrade | 独立 npm 包/桌面端捆绑 |
| 环境变量前缀 | `MEBULAR_RUNTIME_*`（既有） | `MEBULAR_MEMORY_RUNTIME_*` |

**禁止**：

- 把 sidecar 的数据写入 `<cloudRoot>/runtime/`（会与 daemon 安装目录冲突）。
- 把 sidecar 命令挂到 `mebular runtime` 下。
- 把 sidecar 叫 “Runtime” 而不加 “Memory Runtime sidecar”。
- 让 MCP import sidecar 的 `RuntimeService` / 抽取 / 召回 / 模型代码。
- 让 sidecar import `@mebular/core` 的 `GraphStore` / `EventLog` / `SyncManager` / `MemoryService`。

## 2. 进程模型

### 2.1 进程形态

```text
MCP daemon（mebular serve）
  │  spawn（仅 memoryRuntime.enabled=true）
  ▼
mebular-memory-runtime serve --parent-pid <mcpPid>
  ├─ HTTP server: 127.0.0.1:<port>/memory-runtime/v1
  ├─ capability client → 127.0.0.1:<mcpPort>/internal/memory/v1
  ├─ local store: raw / traces / cache / outbox
  ├─ model runtime: heuristic / local / host candidates / api
  └─ lifecycle: lock / discovery / health / token
```

- **不是** MCP 的 worker thread、不是 in-process 模块、不是插件。
- 自动启动时是 MCP 的子进程；父进程退出 → sidecar 收到 parent watch → 优雅退出。
- 手动启动时无 parent watch；由用户 `stop` 或系统重启管理。
- 同一用户、非 root；不申请额外权限；不监听非 loopback。
- Node.js ≥ 20；无原生依赖（本地模型运行时除外，作为可选外部进程）。

### 2.2 单实例

- 每个 `<home>` + `cloudId`（profile）只允许一个 sidecar。
- 启动锁：`<home>/memory-runtime/start.lock`，内容 `{pid, startedAt, cloudId, profileId, command}`，`0600`。
- 锁存在且 pid 存活 → 不启动第二个；尝试 attach 现有 discovery。
- 锁存在但 pid 不存在 / 超过 30s 未更新 → 视为陈旧锁，原子接管。
- 第二个 `start` 不报错，返回 `{attached:true, url, version}`。
- 多 profile 切换：先停止当前 sidecar，再以新 `<home>`/cloud 启动；不并行共享。

### 2.3 状态机

```text
not_installed ──install──► stopped ──start──► starting ──health──► ready
                                                     │              │
                                                     │              ├──degrade──► degraded
                                                     │              │              │
                                                     └──fail──► failed ◄──fail────┘
ready/degraded ──stop──► stopping ──exit──► stopped
```

| 状态 | 含义 | 宿主可见 | 可注入记忆 |
|---|---|---|---|
| `not_installed` | 包/可执行文件不存在 | `status.state` | 否 |
| `stopped` | 已安装，未运行 | discovery 不存在 | 否 |
| `starting` | 已 spawn，等待 health | `starting` | 否 |
| `ready` | health + capability 握手成功 | discovery 存在 | 是 |
| `degraded` | 进程活着，但 capability/模型/同步/磁盘异常 | discovery 存在，`degraded=true` | 有限（缓存只读/回退） |
| `stopping` | 收到停止信号，flush 中 | `stopping` | 否 |
| `failed` | 启动失败/崩溃循环/版本不兼容 | `error.code` | 否 |

- `failed` 不自动无限重启：3 次/5 分钟后退避到 5 分钟；用户可手动 `start` 重置。
- 状态变化写日志并发事件（本地）；MCP `/admin/api/overview` 只读展示。

### 2.4 启动流程（自动/手动共用）

1. 读取 `<home>/memory-runtime/config.json`；不存在则用安全默认（`capture=off`、`trace=local`、`heuristic`）。
2. 获取启动锁；若已有健康实例 → attach 并返回。
3. 读取 MCP 发现：`<home>/runtime.json` 或 `MEBULAR_MCP_URL`；确定 `/internal/memory/v1`。
4. `GET /internal/memory/v1/version`：
   - 404 `capability_disabled` → 退出 `capability_disabled`（轻量模式不应启动 sidecar）。
   - 401 → 读取 capability token；失败退出 `capability_token_invalid`。
   - major 不匹配或 MCP 版本不在 `[minMcpVersion, maxMcpVersion]` → 退出 `version_incompatible`。
5. 初始化本地存储（目录/权限/清理过期数据）。
6. 启动 HTTP server（默认 `127.0.0.1:7341`；占用则 `0` 临时端口）。
7. 生成 host token；写 `host-token`（`0600`）。
8. 写 discovery（原子 tmp+rename）。
9. 启动 outbox replay、retention、health heartbeat。
10. 进入 `ready`；若 capability 暂不可用但版本可探测 → `degraded`，继续重试。

启动超时：默认 5000ms（`memoryRuntime.startTimeoutMs`）；超时杀进程并 `failed`。

### 2.5 停止流程

1. 标记 `stopping`；停止接收新写（返回 503 `stopping`）。
2. 尝试 flush outbox（最多 2s）；未完成的保留在磁盘。
3. 关闭 HTTP server；写最后一条日志。
4. 删除 discovery；删除 host token（或保留供下次启动？**删除**，避免旧 token 复用）。
5. 释放启动锁。
6. 正常退出码 0；5s 内未退出 → SIGKILL。
7. **不删除**图数据、本地 Raw/Trace/cache/outbox（除非显式 `--purge`）。

### 2.6 父进程 watch

- 自动启动时传 `--parent-pid <pid>`；sidecar 每 2s 检查父进程：
  - 父进程不存在 → 优雅停止（flush outbox 后退出）。
  - 父进程被替换（MCP 重启）→ 退出，由新 MCP 重新启动。
- 手动启动不带 `--parent-pid`；不因终端关闭而退出（detached）。
- MCP 停止时也会显式调用 stop；parent watch 是兜底，不是唯一机制。

## 3. 端口、发现与健康

### 3.1 端口

| 项 | 值 |
|---|---|
| 默认 host | `127.0.0.1` |
| 默认 port | `7341` |
| 端口占用 | 回退 `0`（内核分配临时端口），写 discovery |
| 最大端口尝试 | 7341–7350；全部占用则临时端口 |
| 非 loopback | 拒绝启动（`bind_not_loopback`） |

- 端口不是契约；宿主必须读 discovery，不得硬编码 7341。
- MCP 只通过 discovery 找到 sidecar；不扫描端口。

### 3.2 Discovery 文件

`<home>/memory-runtime.json`（`0600`，原子写）：

```jsonc
{
  "schema": 1,
  "kind": "mebular-memory-runtime",
  "pid": 12345,
  "host": "127.0.0.1",
  "port": 7341,
  "url": "http://127.0.0.1:7341/memory-runtime/v1",
  "healthUrl": "http://127.0.0.1:7341/memory-runtime/v1/health",
  "cloudId": "cl_...",
  "profileId": "default",
  "runtimeVersion": "0.3.0",
  "apiVersion": 1,
  "capabilityApiVersion": 1,
  "minMcpVersion": "0.3.0",
  "maxMcpVersion": "0.3.x",
  "state": "ready",
  "degraded": false,
  "tokenFile": "<home>/memory-runtime/host-token",
  "startedAt": 1730000000000,
  "updatedAt": 1730000000000,
  "capabilities": {
    "ingest": true,
    "recall": true,
    "context": true,
    "checkpoint": true,
    "compact": true,
    "self": true,
    "models": ["heuristic", "host"]
  }
}
```

规则：

- **不包含 token**；只包含 `tokenFile` 路径。
- `updatedAt` 每 5s 心跳；超过 15s 未更新视为 stale；超过 30s 视为 dead。
- 进程退出时删除；崩溃残留由下一次启动/健康检查清理。
- 版本/cloudId/profileId 不匹配 → MCP 不复用，停止并重启。
- 宿主读取顺序：`MEBULAR_MEMORY_RUNTIME_URL` > discovery > 错误 `sidecar_unavailable`。

### 3.3 健康与就绪

`GET /memory-runtime/v1/health`

- **无需 token**（只暴露最小信息）；仅 loopback。
- 进程活着就返回 200；`ready` 字段表示是否可接流量。

```jsonc
{
  "ok": true,
  "state": "ready",
  "ready": true,
  "degraded": false,
  "pid": 12345,
  "runtimeVersion": "0.3.0",
  "apiVersion": 1,
  "capabilityApiVersion": 1,
  "uptimeMs": 120000,
  "cloudId": "cl_...",
  "profileId": "default"
}
```

就绪条件（全部）：

1. HTTP server 在监听。
2. capability `/version` 在最近 5s 内成功（或缓存未过期）。
3. 本地存储可写（至少 tmp 可写）。
4. outbox 未满（或允许只读降级）。
5. 模型未处于不可恢复的启动失败（模型失败只降级，不阻止 ready；`degraded=true`）。

健康检查失败：

- MCP 200ms 超时；连续 3 次失败 → 停止并重启。
- 宿主 200ms 超时；失败即跳过注入，不阻塞对话。

### 3.4 启动锁

`<home>/memory-runtime/start.lock`：

```jsonc
{ "pid": 12345, "startedAt": 1730000000000, "cloudId": "cl_...", "profileId": "default", "command": "serve" }
```

- `O_CREAT|O_EXCL` 创建；已存在则读 pid/时间。
- pid 存活且 `startedAt` < 30s → 等待 discovery（最多 5s）。
- pid 不存在或锁 > 30s → 删除并接管。
- 不依赖文件锁 API 的跨平台差异；pid 检查 + 原子 rename 足够。

## 4. Token 模型

### 4.1 两个方向、两个 token

| Token | 生成方 | 使用方 | 存储 | 生命周期 |
|---|---|---|---|---|
| **Capability token** | MCP daemon | sidecar → MCP | 进程 env 或 `<home>/memory-runtime/capability-token`（`0600`） | MCP 进程生命周期；重启即轮换 |
| **Host token** | sidecar | 宿主 → sidecar | `<home>/memory-runtime/host-token`（`0600`） | sidecar 进程生命周期；重启即轮换 |

- 两者都是 bearer；只允许 loopback。
- 不得复用同一个 token；不得把 capability token 交给宿主。
- 不得把 host token 交给浏览器；Console 通过 MCP 代理访问 sidecar（MCP 读 host token 文件，同用户）。
- 调试覆盖：`MEBULAR_MEMORY_RUNTIME_TOKEN` 可覆盖 host token（仅测试/排障）；`MEBULAR_MEMORY_RUNTIME_HOME` 可覆盖本地数据目录。

### 4.2 文件格式

`host-token`：

```jsonc
{ "version": 1, "token": "<base64url>", "issuedAt": 1730000000000, "expiresAt": 0 }
```

`capability-token`（MCP 写）：

```jsonc
{ "version": 1, "token": "<base64url>", "issuedAt": 1730000000000, "expiresAt": 0, "mcpPid": 1234 }
```

- `expiresAt=0` 表示“进程生命周期内有效”，由重启/停止轮换；不按墙钟自动过期。
- 如果未来需要短时 token，可写绝对时间；0 仍表示不过期。

- 文件权限必须 `0600`；POSIX 上组/其他可读 → 拒绝使用并 `token_permissions_insecure`。
- Windows 上 ACL 无法用 `st_mode` 表达时，降级为“同用户可读”并记录 warning；不伪造安全。
- 目录 `0700`。
- 读取后不在内存外持久化；不写日志。

### 4.3 轮换与失败

- sidecar 启动时生成新 host token；旧 token 立即失效。宿主收到 401 → 重读 token 文件 → 重试一次。
- MCP 重启生成新 capability token；sidecar 收到 401 → 重读 capability-token → 重试一次；仍失败 → `degraded`，继续用缓存/outbox，不退出。
- token 文件缺失 → sidecar 启动失败 `capability_token_missing`；MCP 侧 `status` 报 `sidecar_token_missing`。
- token 过期 → 401；不自动延长；由生成方轮换。

### 4.4 认证失败

| 场景 | HTTP | code | 行为 |
|---|---|---|---|
| 缺 Authorization | 401 | `unauthorized` | 不执行 |
| token 错误 | 401 | `invalid_token` | 不执行；不泄漏期望值 |
| token 过期 | 401 | `token_expired` | 触发轮换 |
| 非 loopback | 403 | `loopback_required` | 拒绝 |
| Origin 非 loopback | 403 | `forbidden_origin` | 拒绝 |
| 权限不足（admin） | 403 | `forbidden_scope` | 不执行 |

## 5. 自动启动与自动停止

### 5.1 自动启动条件（全部满足）

1. MCP daemon 正在运行（HTTP 模式；**stdio 模式不启动**）。
2. MCP 配置 `memoryRuntime.enabled=true`（用户选择沉浸式）。
3. `MEBULAR_MEMORY_RUNTIME_DISABLE` 未设置。
4. sidecar 已安装且版本可解析。
5. 当前 `<home>`/profile 没有健康 sidecar。
6. MCP capability API 已挂载且 token 已生成。
7. 不在安装/升级/测试/配置校验等禁止阶段。

触发点：

- MCP daemon 启动时（配置已启用）。
- 用户切换 `memoryRuntime.enabled=false → true`。
- 宿主第一次调用 `/memory-runtime/v1/*` 且 discovery 不存在（惰性启动）。
- sidecar 崩溃后的看门狗重启（受退避限制）。
- 手动 `mebular memory-runtime start`。

**不触发**：

- `mebular mcp`（stdio）。
- `mebular memory_*` CLI。
- `mebular tools`。
- `mebular runtime install|upgrade|service install`。
- 配置校验、单元测试、CI（除非显式启用）。
- 轻量模式下的任何请求。

**非阻塞**：自动启动是异步的；MCP 先完成自身就绪（29 工具、同步、鉴权），再 spawn sidecar。sidecar 启动失败只影响沉浸式记忆，不阻塞 MCP 启动、工具调用或对话。

### 5.2 自动停止条件

| 条件 | 行为 |
|---|---|
| 用户切到轻量（`enabled=false`） | MCP 调用 stop；flush outbox；删除 discovery |
| MCP daemon 正常停止 | stop；sidecar 退出 |
| MCP daemon 崩溃 | parent watch 2s 内退出；outbox 保留 |
| profile/cloud 切换 | stop 当前；新 profile 重新启动 |
| 安装/升级 | 先 stop；升级后按配置重启 |
| 空闲 | 默认**不**自动停止；可选 `idleStopMinutes`（默认 0=关闭） |
| 连续崩溃 | 进入 `failed`；不无限重启 |

- 停止不等于删除：Raw/Trace/cache/outbox 保留；用户显式 `--purge` 才删本地数据。
- 停止不影响图数据；已沉降记忆仍在忆云。

### 5.3 轻量模式零副作用（验收硬指标）

开启/运行轻量模式时，必须满足：

- 没有 `mebular-memory-runtime` 进程。
- 没有 sidecar 监听端口（7341–7350、临时端口均无）。
- 没有创建 `<home>/memory-runtime/`（或已存在但不新增文件）。
- 没有 `memory-runtime.json`、`host-token`、`capability-token`。
- 没有 Raw/Trace/cache/outbox 写入。
- 没有模型文件下载、没有模型进程。
- 没有 `/internal/memory/v1` 路由（404 `capability_disabled`）。
- 29 个公共工具、daemon 生命周期、同步、鉴权完全不变。
- MCP 启动日志不出现 “memory runtime starting/spawn” 等副作用。

> 注意：用户之前使用过沉浸式时，`<home>/memory-runtime/` 可能已存在。轻量模式只要求**不新增/不修改**，不要求删除历史本地数据；删除是显式 `uninstall --purge`。

### 5.4 首次切换沉浸式

1. 用户在 Console 选择“沉浸式”；一次性提示 Raw 本地采集（默认 `local`，可关闭）。
2. Console 写 MCP 配置 `memoryRuntime.enabled=true`（原子写 + `.bak`）。
3. MCP 挂载 capability API、生成 token。
4. MCP 解析 sidecar；未安装 → `not_installed`，提示安装（不自动下载）。
5. 已安装 → 启动；写 discovery；状态 `ready`。
6. 宿主读取 discovery，开始 ingest/recall。
7. 任何一步失败：模式仍可保持 `enabled=true`，但 `degraded`；对话继续，无记忆注入。

## 6. 本地存储

### 6.1 目录

```text
<home>/memory-runtime/
  config.json             sidecar 设备配置（0600）
  policy.json             Agent 读/写域授权（0600，可选）
  agents.json             agentId → 显示名注册表（0600，可选、本地）
  host-token              host token（0600）
  capability-token        MCP 写入（0600，可选）
  raw/                    RawChunk（JSONL 分日/分线程）
  traces.jsonl            RecallTrace 环形日志
  cache/                  召回索引、checkpoint/self 缓存
  outbox/                 待重试 capability 请求
  outbox/dead/            永久失败请求（不自动重试）
  models/                 本地模型包（显式安装）
  logs/sidecar.jsonl      结构化日志
  tmp/                    原子写临时文件
```

- 目录 `0700`，文件 `0600`；启动时检查/修复权限。
- **不得**写入 `<cloudRoot>/runtime/`、`<home>/runtime/` 或图存储目录。
- 所有持久记忆在 MCP/图；这里的任何文件都可删除（除未发送 outbox 外），删除不影响已沉降记忆。
- `agents.json` 只保存 `agentId`、显示名、首次/最近出现时间；显示名不参与域键，不同步，不是身份权威。

### 6.2 RawChunk

```jsonc
{
  "schema": 1,
  "id": "rc_<ULID>",
  "cloudId": "cl_...",
  "agentId": "opencode",
  "hostId": "h_...",
  "threadId": "th_...",
  "role": "user" | "assistant" | "system" | "tool",
  "text": "...",
  "mime": "text/plain",
  "at": 1730000000000,
  "messageId": "m1",
  "turn": 3,
  "chunkIndex": 0,
  "contentHash": "sha256:...",
  "redaction": { "applied": true, "rules": ["api_key"] },
  "expiresAt": 1730604800000
}
```

- 单块 ≤ 256 KiB；超过由调用方切块；总请求 ≤ 2 MiB。
- 去重键：`(cloudId, agentId, threadId, contentHash, chunkIndex)`。
- 明文不进入图、事件、同步、日志、trace。
- 保留默认 7 天；启动 + 每日清理；显式删除立即生效。
- `capture=off`：不落盘；本次请求内使用后丢弃。

### 6.3 RecallTrace

- `<home>/memory-runtime/traces.jsonl`；环形 7 天 / 2000 条。
- 字段：`id, at, agentId, threadId, queryHash, queryPreview(≤200 字，可关), domains, hits[{id,type,score,rank}], model, tookMs, degraded, feedback`。
- 不存完整 query、完整正文、模型 prompt/response。
- `trace=off` 时不生成；feedback 返回 404。

### 6.4 Cache

- 召回索引：可重建；按事件/TTL 失效；删除不影响图。
- checkpoint/self 缓存：只缓存云端对象；带 `revision`、`updatedAt`、`source='cache'`。
- 缓存读取必须标记 `stale`/`source`；不得把缓存当权威。
- 缓存目录可随时清空；下次从 capability 重新拉取。

### 6.5 Outbox

- 一项 = 一个 capability 写请求（`write/update/delete/archive/internal-object`）+ 幂等键。
- 有界：默认 1000 项 / 16 MiB；满时**停止接收新写**，返回 503 `outbox_full`，不丢已有项。
- 重放：启动时 + 每 5s（指数退避到 60s）；成功即删除；幂等键保证只写一次。
- 永久失败（400/403/422）：移动到 `outbox/dead/`，记录 code；保留 30 天；`status` 可见；不无限重试。
- Outbox 不是第二权威：只保存“已由宿主确认、尚未到达 MCP”的请求；不得用于跨设备/长期存储。
- 磁盘满：不创建新 outbox；进入 `storage_full` 降级；宿主收到明确错误。

### 6.6 保留与清理

| 数据 | 默认保留 | 清理 |
|---|---|---|
| Raw | 7 天 | 启动 + 每日；可配 0=立即 |
| Trace | 7 天 / 2000 条 | 环形 |
| Cache | 30 天 / 可重建 | LRU/TTL |
| Outbox dead | 30 天 | 每日 |
| 模型文件 | 直到用户卸载 | 显式 |
| 配置/token | 直到卸载 | 显式 |

- 清理只处理本地过程数据；**绝不自动删除图内 MemoryRecord/Compact/Self/Checkpoint**。
- 删除本地数据后，已沉降记忆仍从 MCP/图恢复。

### 7.2 授权文件

`<home>/memory-runtime/policy.json`（`0600`，可选；缺省用安全默认）：

```jsonc
{
  "schema": 1,
  "agents": {
    "opencode": {
      "readDomains": ["user", "default", "agent:opencode", "task:*"],
      "writeDomains": ["agent:opencode", "default", "task:*", "shared", "user"],
      "userWriteConfirmation": true
    },
    "hermes": {
      "readDomains": ["user", "default", "agent:hermes", "agent:opencode"],
      "writeDomains": ["agent:hermes", "default", "task:*", "shared", "user"],
      "userWriteConfirmation": true
    }
  }
}
```

- 设备本地、不同步；不是 ACL 服务。
- 默认（Agent 无条目）：读 `user`、`default`、`agent:<self>`、当前 `task:*`；写 `agent:<self>`、`default`、参与中的 `task:*`、`shared`；不读其他 Agent。
- `writeDomains` 包含 `user` 时仍需 `confirmation='explicit'`（`userWriteConfirmation=true`）；不包含则完全禁止写 `user`。
- 0.2 任意 namespace（如 `notes`）不自动进入默认读域；需要时显式加入 `readDomains`。`default` 默认读，保证 0.2 兜底数据可召回。
- `task:*` 是模式，表示“当前请求的 threadId 对应的任务域”；解析时只允许 `task:<currentThread>`。
- 修改后热加载；非法条目拒绝并保留旧策略。
- 这只是逻辑约束；capability token 持有者仍可读全部。不得在文档/Console 宣称密码学隔离。

## 8. Host API（`/memory-runtime/v1`）

### 8.1 通用

- 认证：`Authorization: Bearer <hostToken>`；`/health` 例外。
- **不支持 `auth=none`**；除 `/health` 外，所有端点必须 host token。loopback 不是授权。
- 只 loopback；无 CORS；不支持 cookie。
- 统一信封与 capability 相同：`{ok, requestId, apiVersion, data, warnings, degraded}`。
- 时间 ms；未知字段忽略；`apiVersion=1`。
- 请求体 ≤ 2 MiB；错误码见 §11。
- **Host API 使用 `agentId`，不直接使用 capability 的 `actor`**；sidecar 负责构造 `actor`。宿主不得把 capability actor 透传进来。
- `actor` 仅作为旧适配器兼容别名：只接受 `{type:'agent', agentId}` 且与顶层 `agentId` 一致；不一致返回 400 `invalid_request`。新适配器只用 `agentId`。
- 召回/上下文的完整字段、预算和沉默规则以 [`0.3.0-fragmented-recall.md`](./0.3.0-fragmented-recall.md) §8 为准；本节只给最小形状。`namespaces` 作为 `domains` 的兼容别名接受，`domains` 优先。

### 8.2 端点

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/health` | 无 | 存活/就绪/版本 |
| GET | `/status` | read | 模式、模型、计数、outbox、降级 |

| GET | `/namespaces` | read | 域 + 授权 + 订阅视图 |
| POST | `/ingest` | write | 采集 + 抽取 + 沉降 |

| POST | `/recall` | read | 碎片化召回 |
| POST | `/context` | read | 上下文组装 |

| PUT | `/checkpoints/:threadId` | write | 写入（始终上云） |

### 8.3 Ingest

```jsonc

  "agentId": "opencode",
  "threadId": "th_...",
  "domain": "agent:opencode",          // 可选；缺省按内容类型
  "capture": "local",                  // off | local；缺省取 config
  "extractor": "auto",                 // heuristic | local | host | api | auto
  "allowRemote": false,
  "chunks": [
    { "role": "user", "text": "...", "at": 1730000000000, "messageId": "m1", "turn": 1, "chunkIndex": 0, "contentHash": "sha256:..." }
  ],
  "candidates": [ /* extractor=host 时由宿主提交 */ ]

```

```jsonc
// response data
{
  "accepted": { "chunks": 1, "records": 1 },
  "rawChunkIds": ["rc_..."],
  "records": [{ "id": "01J...", "domain": "agent:opencode", "kind": "observation" }],

  "duplicate": false,
  "degraded": false

```

- `extractor=host` 且无 candidates → 202 `{status:'pending'}`；不偷偷换模型。

- `domain` 缺省时由 sidecar 按授权决定：用户事实/偏好只有在 `policy.writeDomains` 允许 `user` 且 `confirmation='explicit'` 时才写 `user`，否则降级到 `agent:<self>`；任务/共享内容按 `task:<threadId>` / `shared`；无法判定时写 `agent:<self>`，不写 `default` 冒充用户域。
- capability 不可用：候选进 outbox，返回 202 `queued:true`；`rawChunkIds` 仍按 capture 返回；`degraded=true`。
- 单请求 chunks ≤100；单 chunk ≤ `maxChunkBytes`；超限 413。
- 抽取失败不丢 raw（若 capture=local）；记录 `extraction.status='failed'`；可用 `POST /extractions/:id` 回填/重试。

```jsonc

  "summary": "已完成第 2 步",
  "recordIds": ["01J..."],
  "domain": "task:th_...",             // 可选；有显式任务域时给
```

```jsonc
// PUT response（正常）
{ "checkpoint": { "threadId": "th_...", "agentId": "opencode", "revision": 4, "domain": "task:th_...", "lease": { "hostId": "h_...", "until": 0 }, "expiresAt": 0, "pending": false } }
```

- **没有 `sync` 参数**；出现 `sync` → 400 `legacy_sync_unsupported`。
- 写入必须走 capability `/internal-object`；本地只写缓存。
- capability 不可用：入 outbox，返回 202 `pending:true`；宿主不依赖 revision；恢复后补写并更新缓存。
- GET：先缓存，再 capability；capability 不可用时返回缓存 + `source='cache'`、`stale=true`、`degraded=true`。
- revision/lease 语义由 capability 服务端执行；sidecar 不自行分配权威 revision。
- 过期：`expiresAt < now` → `checkpoint:null`；不删除关联 MemoryRecord。

### 8.7 Self

- `PUT /self/:agentId` 始终走 capability `/internal-object`（`kind=self_record`）；本地缓存。
- 没有 `sync` 参数；没有本地模式。
- capability 不可用 → 202 `pending:true` + outbox；GET 返回缓存 + `stale`。
- 只允许同一 Agent 或 user/admin；其他 Agent 读需显式授权。
- Self 不进入普通召回；不作为用户画像。

```jsonc

  "domain": "agent:opencode",

  "sourceIds": ["01J...", "01K..."],
  "threadId": "th_...",                // 可选；用于来源选择

```

- `POST /compact` 生成摘要（heuristic/local/host/api），然后 capability `/internal-object` upsert。
- 只允许单域；跨域 400 `domain_mismatch`。
- 源记录不改；compact 派生；stale 由 capability 读取时计算。
- capability 不可用 → outbox；返回 202 `queued:true`。

## 9. 日志与指标

### 9.1 日志

- 文件：`<home>/memory-runtime/logs/sidecar.jsonl`；`0600`。
- 轮转：10 MiB × 3；保留 3 个历史文件。
- 格式：一行一个 JSON 对象：

```jsonc
{
  "at": 1730000000000,
  "level": "info",
  "event": "recall",
  "requestId": "req_...",
  "agentId": "opencode",
  "threadId": "th_...",
  "domains": ["user", "agent:opencode"],
  "hits": 3,
  "tookMs": 24,
  "degraded": false
}
```

- **不记录**：正文、query 全文、raw 文本、token、key、模型 prompt/response、Authorization。
- 错误日志只记录 `code`、`message`（脱敏）、`requestId`、`endpoint`。
- 用户可 `mebular memory-runtime logs --tail 100`；Console 只显示最近事件摘要。

### 9.2 指标

- 本地 JSON 快照；不引入 Prometheus/OTel 依赖。
- 关键指标：
  - 生命周期：启动次数、崩溃次数、启动耗时、当前状态。
  - 召回：次数、p50/p95、空结果率、cache 命中率、注入 token/字节。
  - 沉降：ingest 次数、候选数、写入成功/重复/失败、outbox 深度。
  - 模型：来源、回退次数、失败原因。
  - 同步：capability 可达性、pending events。
- 指标不包含用户内容；可按 Agent 聚合，但不跨设备上报。

### 9.3 事件（本地）

可选写 `<home>/memory-runtime/logs/events.jsonl`，用于 Console 时间线：

- `sidecar.started/stopped/crashed/degraded`
- `capability.unreachable/recovered`
- `outbox.queued/replayed/dead`
- `model.fallback`
- `config.changed`

不进入图/事件日志/同步。

## 10. 安装、升级与版本握手

### 10.1 安装

- 独立发布：`npm install -g @mebular/memory-runtime@0.3.0`。
- 桌面端可选捆绑：作为独立目录/独立二进制，不合并进 MCP 进程。
- MCP 不自动下载/安装 sidecar；只检测并提示。

- 首次启动创建 `<home>/memory-runtime/`；安装本身不创建用户记忆数据。

#### 10.1.1 可执行文件解析顺序

1. MCP 配置 `memoryRuntime.command`（显式绝对路径）。
2. 环境变量 `MEBULAR_MEMORY_RUNTIME_BIN`。
3. 桌面端/安装器提供的捆绑路径（与 MCP 同版本目录，独立文件）。
4. `PATH` 中的 `mebular-memory-runtime`。
5. 都找不到 → `not_installed`；不下载、不猜路径。

解析结果必须记录 `source`（config/env/bundled/path），`status` 可见；不记录完整路径到同步数据。

### 10.2 升级

1. 停止 sidecar（保持 outbox）。
2. 安装新版本包（用户/桌面端）。
3. 校验新版本 `apiVersion` 与 MCP `capabilityApiVersion` 兼容。
4. 启动新版本；读旧配置/缓存/outbox；不迁移图数据。
5. 如果新版本配置 schema 不兼容 → 明确 `config_upgrade_required`；不静默丢弃。
6. 升级失败 → 保留旧包/旧 discovery；回滚启动旧版本。

- 不做双实例并行升级；不做热替换。
- 升级不改变图/事件/同步；不重写记忆。

### 10.3 卸载

```text
mebular memory-runtime stop
mebular memory-runtime uninstall          # 移除包/可执行文件；保留数据
mebular memory-runtime uninstall --purge  # 同时删除 <home>/memory-runtime/
```

- 卸载前停止；删除 discovery/token/lock。
- `--purge` 是显式动作；默认保留 raw/trace/cache/outbox，便于重装恢复。
- **不删除图内记忆**；已沉降数据仍在忆云。
- 卸载后轻量模式完全不受影响。

### 10.4 版本握手

```text
sidecar 启动
  → GET <mcp>/internal/memory/v1/version
  → 检查 capabilityApiVersion major
  → 检查 mcpVersion ∈ [minMcpVersion, maxMcpVersion]
  → 成功：继续；失败：退出 version_incompatible
```

字段：

| 字段 | 来源 | 说明 |
|---|---|---|
| `capabilityApiVersion` | MCP | 必须为 1（0.3.x） |
| `schemaVersion` | MCP | wire schema；sidecar 只接受 1 |
| `mcpVersion` | MCP | 用于 `min/max` 判断 |
| `runtimeVersion` | sidecar | 0.3.x |
| `apiVersion` | sidecar | `/memory-runtime/v1` |
| `minMcpVersion` / `maxMcpVersion` | sidecar | 支持的 MCP 范围 |

兼容规则：

- sidecar 0.3.x ↔ capability API 1 ↔ MCP 0.3.x。
- MCP 0.2 无 capability API → sidecar 拒绝启动，不阻塞 MCP。
- 未来 capability v2：sidecar 必须显式支持；旧 sidecar 不自动兼容。
- 版本不匹配时宿主失败开放：无记忆注入，对话继续。

### 10.5 MCP 复用已启动 sidecar

MCP 启动/切换时：

1. 读 `<home>/memory-runtime.json`。
2. `/health`（200ms 超时）。
3. 校验 `cloudId`、`profileId`、`runtimeVersion`、`capabilityApiVersion`。
4. 兼容 → attach；不兼容 → `stop` 旧进程 → 启动新版本。
5. discovery 缺失/健康失败 → 清理 stale 文件 → 启动。

## 11. 错误码

### 11.1 Sidecar host API

| HTTP | code | 含义 |
|---|---|---|
| 400 | `invalid_request` | JSON/schema 非法 |
| 400 | `legacy_sync_unsupported` | 请求带 `sync` / `checkpoint.sync` / `self.sync` |
| 400 | `legacy_config_unsupported` | 配置含已删除键 |
| 400 | `domain_invalid` | 域语法非法 |
| 400 | `domain_mismatch` | 跨域 compact/checkpoint |
| 401 | `unauthorized` / `invalid_token` / `token_expired` | host token |
| 403 | `loopback_required` / `forbidden_origin` / `forbidden_scope` | 网络/权限 |
| 404 | `not_found` | 对象/抽取/trace 不存在 |
| 409 | `revision_mismatch` | checkpoint/self 冲突 |
| 409 | `checkpoint_lease_held` | 其他 host 持租约 |
| 413 | `payload_too_large` | body/chunk/state 超限 |
| 422 | `validation_failed` | 候选/请求校验失败 |
| 429 | `rate_limited` | 限流 |
| 500 | `internal` | 未分类 |
| 503 | `capability_unavailable` | MCP capability 不可用 |
| 503 | `outbox_full` | outbox 满，停止接收新写 |
| 503 | `storage_full` | 本地磁盘满 |
| 503 | `model_unavailable` | 模型不可用且不允许回退 |
| 503 | `sidecar_starting` / `stopping` | 生命周期状态 |
| 503 | `version_incompatible` | 版本握手失败 |

### 11.2 启动退出码

| 退出码 | 原因 |
|---|---|
| 0 | 正常停止 |
| 2 | `version_incompatible` / `capability_disabled` |
| 3 | 配置非法（`config_invalid` / `legacy_config_unsupported`） |
| 4 | 端口/绑定失败（`bind_failed` / `bind_not_loopback`） |
| 5 | token 缺失/权限不安全 |
| 6 | 本地存储不可写（`storage_unavailable`） |
| 7 | 锁竞争失败（已有实例） |
| 1 | 未分类 |

- 退出码写入 `logs/sidecar.jsonl` 和 MCP `memoryRuntime.lastError`。
- 不把错误详情（含路径/token）暴露给宿主；只给 code + 短句。

## 12. 失败开放与降级

### 12.1 宿主侧预算

| 操作 | 建议超时 | 超时行为 |
|---|---|---|
| health/discovery | 200ms | 视为不可用 |
| recall | 800ms | 跳过注入，对话继续 |
| context | 800ms | 跳过注入，对话继续 |
| ingest | 2s（同步部分） | 返回 202/queued；不阻塞下一轮 |
| checkpoint PUT | 2s | 入 outbox，返回 pending |
| self PUT | 2s | 入 outbox，返回 pending |

- 宿主必须使用自己的超时，不能依赖 sidecar 永远响应。
- 每个用户 turn 最多一次注入；工具循环不重复。

### 12.2 降级矩阵

| 故障 | sidecar | 宿主 | MCP 公共工具 |
|---|---|---|---|
| sidecar 未启动 | `not_installed/stopped` | 无注入 | 正常 |
| sidecar 启动失败 | `failed` + code | 无注入 | 正常 |
| capability 不可达 | 缓存只读 + outbox；`degraded` | 可能返回缓存/无结果 | 正常 |
| 模型失败 | 回退 heuristic；`degraded` | 正常注入 | 正常 |
| 本地磁盘满 | 只读；`storage_full` | 无新注入/沉降 | 正常 |
| outbox 满 | 停止新写；`outbox_full` | 明确 warning | 正常 |
| token 失效 | 重读一次；仍失败 `degraded` | 无注入 | 正常 |
| 版本不兼容 | 退出 | 无注入 | 正常 |
| MCP daemon 停止 | sidecar 退出/只读 | 无注入 | 不可用 |
| 同步不可用 | 本地可写；`sync.degraded` | 正常 | 正常 |

### 12.3 不得做的事情

- 不得因 sidecar 故障阻塞 MCP 启动、29 工具、同步、鉴权。
- 不得把空结果伪装成“没有记忆”而不标 `degraded`。
- 不得用旧缓存冒充最新云端状态；必须标 `source='cache'`/`stale`。
- 不得在模型失败时自动切换第三方 API；只回退 heuristic。
- 不得在 capability 失败时把候选写进本地“第二记忆库”；只能进有界 outbox 或丢弃并 warning。

## 13. 单写者与并发

### 13.1 写路径

```text
sidecar → capability client → MCP capability API → MemoryService → GraphStore → EventLog
```

- sidecar 没有 `GraphStore` / `EventLog` / `storage` 的 import 或文件访问。
- 所有写请求带 `Idempotency-Key`；capability 服务端去重。
- 并发：sidecar 内部按 `(agentId, threadId, domain)` 串行化 ingest/checkpoint/self/compact；不并行写同一域。
- 多个 Agent：按 Agent 队列隔离；可并行不同 Agent，但全局写并发 ≤ 4（可配）。

### 13.2 单写者约束

- MCP daemon 仍是唯一图写入者；现有 `serve`/stdio 锁不变。
- 一个 home 一个 sidecar；启动锁 + discovery。
- 一个 sidecar 只连一个 MCP daemon（按 `<home>/runtime.json`）；不跨 daemon 双写。
- 同一 MCP daemon 被多个 sidecar 连接：启动锁阻止；capability 幂等是第二道防线。
- 跨设备不共享 sidecar；每台设备各自运行，通过忆云同步。

### 13.3 并发冲突

| 场景 | 处理 |
|---|---|
| 两个 host 同时写 checkpoint | capability revision + lease；409；不覆盖 |
| 两个 host 同时写 self | revision；取最大；旧节点隐藏 |
| 同一候选重复 ingest | `clientItemId`/内容 hash 去重 |
| 两个 sidecar 同时启动 | 锁；后到 attach 或失败 |
| 两个 MCP daemon 同 home | 现有单写者锁阻止；sidecar 只认一个 |
| 同步与本地写并发 | 现有事件/向量时钟；sidecar 不参与合并 |

## 14. 宿主接入

### 14.1 发现流程

```text
1. 读 <home>/memory-runtime.json
2. GET <healthUrl>（200ms）
3. 读 tokenFile → Authorization
4. GET /status（可选）
5. 调 /ingest、/recall、/context
```

- 发现失败 → 宿主进入“无记忆”模式；不报错给用户（可日志 warning）。
- 不硬编码端口；不扫描端口；不读 MCP `runtime.json` 当 sidecar 地址。
- 云/profile 不匹配 → 不使用；等待正确实例。

### 14.2 各宿主

| 宿主 | 接入点 | 注意 |
|---|---|---|
| DSH | 插件 `memory-runtime.js` | base path `/memory-runtime/v1`；`agentId='dsh'`（稳定）；token 发现 |
| Hermes | companion 插件 / HTTP | `agentId='hermes'`；host candidates 走 `ctx.llm`，不反向读凭据 |
| OpenChamber | 插件/服务端 adapter | `agentId='openchamber'`；注入块标 `untrusted` |
| OpenCode | `@mebular/opencode-plugin` | `agentId='opencode'`；每 turn 最多一次注入；工具循环不重复 |
| 其他 | HTTP | 必须实现发现/token/超时/失败开放 |

- 宿主不得直接调用 `/internal/memory/v1`；那是 sidecar 专用。
- 宿主不得直接写图；不得 import `@mebular/core`。
- 宿主必须把注入块当背景数据，不得作为系统指令/工具调用。

### 14.3 注入契约（摘要）

- 每个用户 turn 最多注入一次；工具循环不重复。
- 硬预算 ≤ 8 KiB / `maxContextTokens`；超限截断并标记。
- 不写会话历史、不写 instruction entry、不冒充用户消息。
- 无 cue/无命中：沉默；不编造。
- 任何失败：跳过注入，对话继续。
- 详细召回契约见 `0.3.0-fragmented-recall.md`（G0-B/W4）。

## 16. 运维命令

```text
mebular memory-runtime install [--version V] [--check]
mebular memory-runtime uninstall [--purge]
mebular memory-runtime start [--foreground]
mebular memory-runtime stop [--timeout 5000]
mebular memory-runtime restart
mebular memory-runtime status [--json]
mebular memory-runtime health
mebular memory-runtime logs [--tail N] [--follow]
mebular memory-runtime config get|set|validate
mebular memory-runtime doctor
```

- `status` 只读，返回 `state/degraded/version/url/outbox/model`；不返回 token。
- `mebular-memory-runtime` 是独立可执行文件；`mebular memory-runtime` 是 MCP CLI 的包装（install/start/status 等）。两者语义一致；包装不改变 sidecar 的独立安装方式。
- `doctor` 检查：包版本、配置 schema、端口、token 权限、capability 可达、磁盘、outbox、模型文件、版本握手。
- 所有命令输出中文短句 + `--json` 机器可读；退出码见 §11.2。
- `mebular runtime ...` 不转发到 sidecar；`mebular memory-runtime ...` 不触碰 daemon 安装。
