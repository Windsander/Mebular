# Memory Runtime（0.3.0）

> **用户文档已被取代。** 本页描述的是冻结前的内嵌原型（`/runtime/v1`、本地 checkpoint
> 模式、`sync=cloud`）。当前用户指南见
> [Memory Runtime 用户指南（0.3.0）](../guides/MEMORY_RUNTIME_CN.md)。冻结架构见
> [contract v2](0.3.0-memory-runtime-contract-v2.md)。本页仅作历史参考保留。

[English](0.3.0-memory-runtime.md) · [返回文档索引](../README.md)

Mebular 0.3 把记忆从「一组工具」变成「一层运行时」。同一个本机守护现在可以替助手
召回、抽取、压缩和保存检查点，而数据仍然留在原有的图、事件日志和同步层里。

这是面向用户的说明。实现契约见
[`0.3.0-memory-runtime-contract.md`](0.3.0-memory-runtime-contract.md)。

## 记忆是运行时，不只是工具

0.2 里，思考由宿主模型完成：它判断什么值得记住，就调用 `memory_write`；需要时再调用
`memory_query`。Mebular 是工具面背后的记忆服务。

0.3 里，宿主还可以把一段对话、一个任务状态或一组候选记录交给 Mebular。运行时代为完成：

```text
宿主对话 / 任务
  -> 宿主适配器（MCP client、DSH 插件、Hermes provider、OpenCode 插件）
  -> /runtime/v1  ingest · recall · context · checkpoint
  -> RuntimeService
  -> 现有图 + 签名事件 + 同步 + 忆云
```

这仍然是同一张 Mebular 图。运行时没有新建第二份存储、第二套同步协议或第二个守护；
它复用 0.2 已有的节点、事件、墓碑和订阅。

不改变的部分：

- 29 个 MCP 工具（`memory_*`、`task_*`）的名字、参数和语义不变。没有 `runtime_*`
  MCP 工具。
- 旧节点、事件、namespace、tag 和历史不迁移、不重写。
- MCP 仍是一等路径。只想显式调用工具的宿主，完全不需要碰 Runtime API。
- HTTP Runtime 在同一个 `mebular serve` 进程内，遵守同一个单写者锁。stdio 的
  `mebular mcp` 不承载 `/runtime/v1`；需要沉浸式处理的宿主应连接守护。

## 两种接入方式

模式是**设备级设置**。同一忆云里，一台设备可以用轻量 MCP，另一台可以用沉浸式
Runtime；共享的 MemoryRecord 完全一致。

| | 轻量 MCP（默认） | 沉浸式 Runtime（opt-in） |
|---|---|---|
| 谁主导 | 宿主模型 | Runtime 与宿主适配器 |
| Mebular 做什么 | 提供记忆工具 | 抽取、召回、上下文组装、压缩、检查点 |
| 原始对话 | 不采集 | 只有设备或适配器请求 `capture=local` 时才保留 |
| 模型调用 | 无 | 只用你配置的来源 |
| 0.2 行为 | 不变 | 未切换前不启用 |
| 写端点 | `/runtime/v1` 写接口返回 `409 mode_mismatch` | 启用 |

### 轻量 MCP

这是默认值，也是兼容路径。助手自己决定何时写、何时查。Mebular 不读对话、不调用
模型，也不会自动产生 RawChunk、Compact 或 Checkpoint；只有管理员显式调用 Runtime
API 时才会创建。

适合这些情况：希望记忆是显式工具、不想装本地模型、或者希望多个助手以最小意外共用
一张图。

### 沉浸式 Runtime

宿主适配器把要处理的对话或任务片段送到 `/runtime/v1/ingest`。运行时可以：

- 在 capture 为 `local` 时把原文作为 RawChunk 留在本机（设备默认关闭；适配器可以按次
  请求）；
- 用规则、本地 Qwen、宿主候选或 OpenAI-compatible API 抽取 MemoryRecord；
- 为下一次模型调用组装 `context`；
- 把一次压缩折叠成 `ContextCheckpoint`；
- 为 Agent 写入 `SelfRecord`。

宿主仍可继续用 MCP 做显式治理、搜索和任务管理。沉浸式不是「Runtime 接管所有对话」：
只有适配器主动送来的内容才会被处理。

### 切换模式

`mcp` ↔ `immersive` 切换时：

- 只影响当前设备；
- 不迁移、不复制、不重写、不删除任何节点；
- 所有 MemoryRecord、Compact、SelfRecord、云 Checkpoint、本地 Raw/Trace 原样保留；
- 切回 `mcp` 后停止新的采集、抽取和检查点写入；
- `status`、`recall`、`context`、checkpoint 读取和 self 读取仍然可用。

切换不是数据转换。切回 0.2 行为后，Runtime 对象仍在图里，只是默认不出现在普通记忆
查询中。

## 共享底座与对象落点

这里的「云」指忆云：共用同一把用户主密钥的设备。没有中心记忆服务器；数据由现有事件
日志和直接同步承载。

| 对象 | 存在哪里 | 跨设备共享 | 进入普通记忆查询 | 用途 |
|---|---|---|---|---|
| **MemoryRecord** | 现有图节点（`entity` / `fact` / `episode` / `skill`） | 是，按 namespace 订阅 | 是 | 长期用户记忆：事实、偏好、情节、技能 |
| **Compact** | 图节点，与来源同一 namespace | 是，随该 namespace | 否 | 带 `sourceIds` 的派生摘要，从不替代源记录 |
| **SelfRecord** | 图节点（默认云）或本地文件 | 默认是；按 `agentId` 逻辑过滤 | 否 | 单个 Agent 的长期自我模型，不是用户画像 |
| **ContextCheckpoint** | 默认本地文件；`sync=cloud` 时才进图 | 仅云模式 | 否 | 带 revision 和 lease 的任务/线程恢复点 |
| **RawChunk** | 本机 `<home>/runtime/` | 永不 | 否 | 采集到的原文，不进图、不进事件日志 |
| **RecallTrace** | 本机 `<home>/runtime/traces.jsonl` | 永不 | 否 | 本地召回诊断与反馈 |

背后的规则：

- **只有 MemoryRecord 进入普通记忆查询。** 它沿用现有五类节点和现有边。
- **Compact 是派生且非破坏性的。** 它只存摘要和来源 ID；源记录被删除或修改后，读取时
  标记 `stale`，不会自动删除。
- **SelfRecord 和 Checkpoint 不是用户记忆。** 默认不出现在 `query`、`search`、
  `history`、`profile`、`skills` 和 `graph` 中。
- **Raw 和 Trace 永不离开设备。** 它们不在图、事件日志、快照或同步里。
- **不新增事件类型或线协议。** Runtime 节点就是普通节点；旧对端可以存储，只是不显示。

## 四种模型来源

运行时不替你偷偷选模型。四种来源：

| 来源 | 是什么 | 网络 | 默认 | 适合 |
|---|---|---|---|---|
| **无模型**（`heuristic`） | 内置规则抽取 | 无 | 是 | 永远可用的基线；可预测、隐私友好 |
| **本地 Qwen**（`local`） | 本机运行的精选 Qwen 包 | 安装后无 | 关 | 离线抽取与摘要，质量更好 |
| **当前对话模型**（`host`） | 宿主提交结构化 `CandidateRecord` | 由宿主决定 | 关 | 复用用户正在使用的模型 |
| **第三方 API**（`api`） | 单个 OpenAI-compatible 端点 | 有，需显式允许 | 关 | 没有本地算力的设备 |

### 无模型：规则抽取

确定性的规则会抽取明确的偏好、事实、决策和任务情节，并扩展召回关键词。它始终可用，
不需要下载，不向任何地方发送数据。新安装默认就是它：没有模型也必须能工作。

### 本地 Qwen：精选包

Mebular 只支持四个显式安装的包。不会静默下载或自动更新；在控制台
**设置 → Runtime → 本地精选模型** 下载并选择后才会使用。

| 包 | 定位 | 量化 | 上下文 | 下载体积 | 最低内存 | 建议内存 |
|---|---|---|---|---|---|---|
| Qwen3 8B | 默认 | Q4_K_M | 32k | 5.03 GB | 16 GB | 24 GB |
| Qwen3 30B-A3B | 高端 MoE | Q4_K_M | 32k | 18.56 GB | 48 GB | 64 GB |
| Qwen3 14B | 高质量 | Q4_K_M | 32k | 9.00 GB | 24 GB | 32 GB |
| Qwen3 4B | 轻量 | Q4_K_M | 32k | 2.50 GB | 8 GB | 12 GB |

四个包均来自 Apache-2.0 的 Qwen3 GGUF 仓库，并用 commit revision 固定。30B-A3B 是
MoE 模型（总参数 30B，每 token 约 3B 激活）；精确文件、哈希与硬件门槛见
[`0.3.0-model-catalog.md`](./0.3.0-model-catalog.md)。

运行时会以 loopback 启动 `llama-server`，生成随机本地 token，再走它的
OpenAI-compatible 端点。模型在本机运行，prompt 和记忆文本不会被上传。未安装、manifest
或校验和失败的包不会被使用；运行时失败则标记降级并回退规则抽取。

> **当前源码树不内置模型权重与 `llama-server` 二进制。** 精选 manifest（文件列表、
> 大小与 sha256）已内置于 `@mebular/memory-runtime`；`llama-server` 需来自校验过的
> 引擎资产或 `MEBULAR_LLAMA_SERVER`。缺少已安装模型包或引擎时，Console 显示
> `not_installed` / `engine_unavailable`，Runtime 回退 heuristic；它不会猜下载 URL
> 或伪造哈希。

### 当前对话模型：只接受宿主自然提供的结果

Mebular **不会**读取宿主凭据、探测宿主 endpoint 或反向调用宿主模型。宿主必须自己产出
候选并提交：

- DSH：可选的 idle `maintenance` 使用当前 DSH 会话模型；
- Hermes：可选的 `mebular-companion` 插件使用 `ctx.llm`；
- OpenCode/OpenChamber：可选插件在一轮结束后使用 `ctx.session.generate`。

如果宿主要求 `extractor=host` 却没给候选，Runtime 不会编造，也不会静默换模型。直接调
API 会得到 `202 pending`；宿主之后可以回填候选或改用其他来源。

### 第三方 API：显式且设备本地

API 来源只接受一个 OpenAI-compatible base URL、模型名和密钥引用。远端调用必须同时满足
`runtime.model.api.allowRemote=true` 与请求级 `allowRemote=true`。密钥只以引用形式保存：

- `env:MEBULAR_RUNTIME_MODEL_API_KEY`
- `keychain:mebular-runtime/<cloudId>`（0.3 只实现 macOS Keychain）
- `file:secrets/runtime-model.key`（相对 Mebular home，`0600`）

明文密钥永远不会写进 `config.json`、图 metadata、事件、日志、控制台或
`/runtime/v1/status`。URL 会被规范化，拒绝非 HTTPS（loopback HTTP 例外）、userinfo 和
云 metadata 地址。超时、5xx 或 429 会回退规则抽取；Mebular 不会自行切换供应商。

### 来源如何选择

`runtime.model.source` 是配置来源。运行时在 `/runtime/v1/status` 里同时报告「配置来源」
和**实际使用**。`auto` 的顺序是：

1. 本次请求带的宿主候选；
2. 已安装的本地包；
3. 已允许的 API 配置；
4. 规则抽取。

本地包已配置但不可用时回退规则抽取，不会改走 API。模型失败会以 `degraded`、原因和
warnings 暴露，不会静默当成成功。

## 宿主边界

每个宿主保留自己的产品面。Mebular 只增加一条记忆路径，不接管宿主原生记忆。

| 宿主 | 默认路径 | 沉浸式路径 | 原生记忆 | 当前模型 |
|---|---|---|---|---|
| **DSH** | MCP（`mcp__mebular__*`） | 可选 `memoryRuntime` bridge | 不触碰 | 可选 idle `maintenance` 使用 DSH 会话模型 |
| **Hermes** | MCP | 可选 `MemoryProvider` 插件 | `MEMORY.md` / `USER.md` 继续工作；不导入、不双写 | `MemoryProvider` 没有模型；可选 `companion` 使用 `ctx.llm` |
| **OpenChamber / OpenCode** | 通过 OpenCode global 配置使用 MCP | 可选 `@mebular/opencode-plugin`（OpenCode >= 2.2） | 只读共存；永不导入、替换或写入 | 仅在显式选择时；一轮结束后 `ctx.session.generate` |

### DSH

DSH 插件仍是 attach 优先。`memoryRuntime` 默认关闭；关闭时不注册监听器、不启动定时器、
不发任何 Runtime 请求。开启后处理召回、ingest 和压缩检查点；`maintenance` 可用当前会话
模型提交宿主候选。普通 Agent 的记忆工具可以被隐藏，`task_*` 和治理白名单保留。不新增
MCP 工具。

见 [DSH 集成说明](../integrations/DSH_CN.md)。

### Hermes

Hermes 只允许一个外部 `MemoryProvider`。Mebular 的 provider 接入这个位置，但内置
`MEMORY.md` / `USER.md` 仍然工作；Mebular 不导入、不镜像、不双写它们。Provider 不暴露
工具，MCP 仍是显式治理面。由于 `MemoryProvider` 接口没有当前模型字段，宿主模型抽取由
独立的可选 companion 完成，它通过 `ctx.llm` 调用。

见 [Hermes 集成说明](../integrations/HERMES_CN.md)。

### OpenChamber / OpenCode

OpenChamber 复用 OpenCode 的 global 配置。Mebular 只增加 `mcp.servers.mebular`，永不写
OpenChamber 私有的 `opencode.managed.json`。沉浸式插件是显式 opt-in，只使用 OpenCode 的
`context` hook 和会话事件。OpenChamber 原生记忆只做只读探测，永不导入、替换、写入或暴露
成 Mebular 工具。当前模型抽取只在用户选择 `host`/`current` 时运行；`session.generate`
不可用时回退规则抽取。

见 [OpenChamber 集成说明](../integrations/OPENCHAMBER_CN.md)。

## 隐私、治理、删除与失败回退

### 数据边界

- **Raw 留在本机。** `runtime.capture` 的设备默认是 `off`；适配器可以针对某次 ingest
  请求 `capture=local`，文本仍然只留在本机。`local` 时 RawChunk 存在
  `<home>/runtime/raw/`，文件 `0600`、目录 `0700`，默认保留 7 天。Raw 不进图、事件、
  快照或同步。
- **Trace 留在本机。** 召回轨迹只保留脱敏后的查询预览、命中 ID 和耗时，不保留全文或
  模型 prompt；默认保留 7 天或 2,000 条。
- **模型设置留在设备上。** 模型来源、包路径、API URL 和密钥引用都不进入共享记忆。
- **记录只带来源，不带秘密。** 共享记录可以说明哪个抽取器/模型产生它，但其他设备不能
  重放该模型或使用它的密钥。
- **Prompt 安全。** 召回内容作为不可信背景数据注入，不作为指令；模型输出只按 schema
  解析和校验，绝不执行。

### 治理与删除

- 内部对象（`compact`、`context_checkpoint`、`self_record`，以及防御性保留的
  `raw_chunk` / `recall_trace`）默认不出现在查询、图遍历和控制台记忆列表中；管理面可用
  `includeInternal=1` 显式查看。
- `memory_delete` / `memory_archive` 拒绝内部对象；Runtime 管理端点才是显式操作路径。
- 删除 MemoryRecord 会写墓碑并同步。这是合作式语义：离线对端已持有的副本可能在对端
  重连前继续存在。没有「删除整个域」操作。
- 删除 RawChunk 是立即的本地删除。删除 Checkpoint 会删除本地文件或墓碑化云节点。删除
  Compact 不会影响源记录。
- 0.3 仍是**单忆云、单用户**。`agentId` 是断言，不是认证边界；SelfRecord 和 Checkpoint
  的隔离是逻辑过滤，不是加密。`memory.read` 仍是云内全量读；namespace ACL 不在本版。

### 失败与回退

| 情况 | 行为 |
|---|---|
| 本地模型未安装或失败 | `model_unavailable`；回退规则抽取；`degraded=true` |
| API 未允许 / 未配置 | 不发起请求；`remote_not_allowed` 或 `model_unavailable` |
| API 超时、5xx、429 | 最多重试一次，然后回退规则抽取；不切换供应商 |
| 要求宿主来源但没给候选 | API 返回 `202 pending`；不静默换模型 |
| Ingest 抽取失败 | chunks 仍可用（开启 local capture 时已落本地）；抽取标记失败，可重试 |
| Compact 失败 | 源记录不受影响；不生成 compact |
| Context 组装失败 | 返回已有 blocks 和 warnings；损坏的 checkpoint 会被跳过 |

只有你配置了来源、宿主也提交了所需数据，Mebular 才会调用模型。失败会出现在
`status.degraded` 和 `warnings` 中；不会静默假装记忆已写入。

## 0.3 不做什么

- 不做单忆云内的多自然人账号或成员 ACL。
- 不做按 Agent 的密码学隔离。SelfRecord 和 Checkpoint 按 `agentId` 逻辑过滤，不是按
  Agent 加密。
- 不做 namespace 级 ACL；`memory.read` 仍读取整个忆云。
- 不自动采集全部对话；只有显式 `/ingest` 的内容才会被处理。
- 不做云端 Raw/Trace、不静默下载模型、不自动更新模型。
- 不同步模型配置到其他设备。
- 不做破坏性压缩，不自动合并冲突事实。
- 不做跨忆云合并或联邦。
- 不新增 MCP 工具；工具面仍为 29 个。

## 兼容与回滚

- 0.2 客户端的默认 `query`、`search`、`history`、`profile`、`skills`、`graph` 结果不变；
  内部 Runtime 对象会被防御性过滤。
- 0.2 数据按 legacy 读取。不补字段、不改 ID、不重签事件。
- 混合版本可以同步：旧对端可能存储未知的 Runtime 节点类型，但默认查询不显示。
- 回滚到 0.2 不会破坏图。Runtime 对象仍被存储但隐藏；本地 `runtime/` 文件只是被旧代码
  忽略。回滚时保留 `runtime` 配置段，后续升级可以继续使用。
