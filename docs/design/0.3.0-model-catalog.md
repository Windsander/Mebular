# 0.3.0 精选模型目录与 llama.cpp 引擎资产

> 状态：C8b 实现契约（2026-10-31）。本文描述 `@mebular/memory-runtime` 的
> `src/inference/catalog.ts` 与 `src/inference/engine-assets.ts`；不包含下载、
> 解压或启动实现（分别由 C8a/C8c 完成）。

## 1. 决策摘要

- 精选目录使用 **真实 Qwen3 GGUF 仓库**：4B（轻量）、8B（默认）、14B（高质量），
  以及可选的 30B-A3B（高端 MoE）。
- `DEFAULT_MODEL_PACK_ID = qwen3-8b-instruct-q4_k_m`。
- 旧的 `qwen3.5-*` 坐标不存在，已全部移除；目录不再接受 Qwen3.5 或 32B。
- 每个精选包内置完整 `ModelManifest`：`packId`、`modelId`、格式、量化、上下文、
  文件列表（路径/大小/sha256/URL）、license、硬件要求、runtime 与来源。
- 模型下载 URL 只由 `source.repository`（provider/repo/revision）与文件名推导：
  `https://huggingface.co/<repo>/resolve/<revision>/<file>`。
  调用方不能把任意 URL 塞进精选目录。
- 模型权重不进入 npm tarball、源码仓库或测试夹具。
- llama.cpp 使用官方 `ggml-org/llama.cpp` release `b12017`；本阶段只提供资产清单、
  大小与 sha256，不下载、不解压、不执行。

### 2.2 为什么加入 30B-A3B，以及它的门槛

`Qwen3-30B-A3B` 是 MoE 模型：总参数 30B，但每个 token 只激活约 3B 参数，因此
CPU/统一内存设备上的推理速度通常明显好于同总参数量的稠密模型。代价是权重文件
仍有 18.56 GB，且需要更多内存余量。精选目录把它放在 `high` 档，并设置：

- 最低 48 GiB 内存；
- 建议 64 GiB 内存（推荐算法只有在 64 GiB 及以上才主动选择它）；
- 最低 24 GiB 可用磁盘；
- GPU 可选，不强制独立显卡。

48–63 GiB 的机器仍可手动安装/选择 30B，但推荐算法会优先选择达到建议内存的 14B。
`qwen3-32b` 仍不在精选目录；30B-A3B 不是 32B 的替代别名。

### 2.3 推荐行为

`recommendModel()` 先按平台、最低内存、磁盘和可选 GPU 过滤，再按档位
（`high` > `quality` > `default` > `light`）排序：

- 最高档达到建议内存：选择最高档；
- 最高档可运行但低于建议内存：退到“达到建议内存”的次高档（例如 48 GiB 上
  30B-A3B 未达 64 GiB 建议值，选择 14B）；
- 最高档只是 `default` 且低于建议内存：保留默认 8B，不因为 4B 达到建议值而降档；
- 没有任何精选包满足最低要求：返回 `heuristic`。

## 3. Manifest 规则

### 3.1 内置与覆盖

```ts
import {
  createModelCatalog,
  resolveCuratedManifest,
  resolveModelManifest,
  listCuratedManifests,
} from '@mebular/memory-runtime';

const packs = createModelCatalog();               // 默认带完整 manifest
const manifest = resolveCuratedManifest('qwen3-8b-instruct-q4_k_m');
const all = listCuratedManifests();
```

- `createModelCatalog()` 默认返回带 `manifest` 的精选包。
- `createModelCatalog({ includeManifests: false })` 只返回旧的坐标/硬件视图。
- `createModelCatalog({ manifests })` 仍接受显式注入，用于测试、离线镜像或高级
  覆盖；注入只能匹配精选项的 `packId`/`modelId`。
- `resolveModelManifest(packId)` 保留兼容：有注入时返回注入结果，否则返回内置
  manifest；只有 `includeManifests:false` 且没有注入时才抛 `manifest_missing`。
- `resolveCuratedManifest(packId)` / `listCuratedManifests()` 只返回内置 manifest，
  供 sidecar 安装直接使用，不需要调用方再注入。

### 3.2 安全约束

- `packId` 必须属于精选目录；未知 pack 抛 `unknown_pack`。
- `modelId` 必须与精选包一致；否则抛 `manifest_mismatch`。
- 32B（`32b` token）在任何注入/查询路径都抛 `excluded_model`。
- manifest 文件路径必须是包内相对 POSIX 路径；拒绝绝对路径、盘符、反斜杠、
  `..` 和空段。
- `sha256` 必须是 64 位十六进制；大小必须是正安全整数。
- 精选目录生成的下载 URL 只能来自 `source.repository` + 文件名。仓库覆盖为
  HuggingFace 时重新推导 URL；非 HuggingFace provider 不保留任意 `url`/`mirrors`，
  下载器必须显式提供 mirrors。
- 注入 manifest 即使携带任意 URL，在进入精选目录时也会被仓库坐标推导结果替换或
  移除；不在精选目录里信任调用方 URL。

### 3.3 不放进仓库的东西

- 不提交 `.gguf`、llama.cpp 归档或解压后的二进制。
- 不把模型权重放进 npm `files`。
- 测试只读取内置常量，不访问 HuggingFace/GitHub，不下载大文件。

## 5. 为什么不用 Qwen3.5

现有目录里的 `Qwen/Qwen3.5-4B-GGUF`、`Qwen/Qwen3.5-9B-GGUF`、
`Qwen/Qwen3.5-27B-GGUF` 并不存在，也没有可核对的 revision、文件大小或 sha256。
继续使用它们会导致：

- 安装时 404；
- 无法验证哈希；
- 目录展示的“9B/27B”与实际可下载模型不一致。

C8b 因此改用已核对的 Qwen3 4B/8B/14B/30B-A3B 仓库，并把默认档从 9B 改为 8B。
未知或旧的 Qwen3.5 packId 一律按 `unknown_pack` 拒绝。

## 6. Llama 的 gated 许可边界

Qwen3 GGUF 仓库为 Apache-2.0 且未 gated，因此默认精选目录只用 Qwen。

Llama 模型（Meta Llama 系列）的许可和下载通常受 gated/地区/账号接受条款约束，
不能假设存在公开、无需 token 的 GGUF 下载地址。后续如果要加入 Llama：

- 必须先实现 license 展示与用户显式接受；
- 必须支持 HuggingFace token/授权流程，且 token 只存设备本地密钥引用；
- 不得伪造公开镜像 URL、不得绕过 gated 检查；
- 目录条目应带 `license.requiresAcceptance=true` 或等价标记；
- 未完成授权流程前，精选目录继续只提供 Qwen。

## 7. 剩余风险

- **llama.cpp nightly 可变**：`b12017` 是 prerelease，GitHub release 的 `immutable`
  为 false；资产哈希是 2026-10-31 从 GitHub API `digest` 核对的。若上游替换资产，
  下载校验会失败而不是静默使用。升级 release 必须同时更新资产名、大小与哈希。
- **归档布局**：本清单假定归档根为 `llama-b12017/`、二进制为 `llama-server`
  （Windows 为 `llama-server.exe`）。C8c 解压后必须验证 `binaryPath` 存在；若官方
  布局变化，应显式更新清单，不能猜测备用路径。
- **解压安全**：zip/tar 条目可能包含 `..`、绝对路径或符号链接。C8c 必须逐条目
  校验并拒绝逃逸路径，不能直接 `tar -x`/`unzip` 到最终目录。
- **30B 内存门槛**：48 GiB 最低值偏保守但仍是估算；实际可用内存取决于 KV cache、
  上下文长度和系统占用。推荐算法只在 64 GiB 及以上主动选择 30B。
- **HuggingFace 可用性**：安装仍依赖 huggingface.co；运行期不使用 metadata API，
  但下载本身需要网络或显式离线导入。
