# 0.4.0 — Memory Intervention Policy

[中文要点见下文](#中文要点) · [Discussion #325](https://github.com/Windsander/Mebular/discussions/325) · [Memory Runtime guide](../guides/MEMORY_RUNTIME.md#intervention-policy-040) · [0.4.0 verification](../quality/0.4.0-intervention/0.4.0-verification.md)

**Status:** target 0.4.0, implemented on the 0.4 integration line and still
**unreleased**. Default `off`; upgrading does not change 0.3.x recall behavior. The
production selector is `model.source`; missing source means `off`. `model` and adaptive
thresholds are part of the 0.4.0 implementation, but their quality is not yet proven by
a real-model/golden-set gate. Adaptive applies only to `heuristic` decisions and
defaults to the internal `shadow` stage. Real API, DSH, Hermes, OpenChamber Desktop and
real host-model evidence remain `blocked_external`; this document describes the design
and boundaries, not a release verdict.

## 1. Problem

Mebular's immersive recall already goes from coarse to fine: cue → fuzzy recall →
candidate scoring → gist → expand → quote, assembled under a byte/token budget.
What it does not decide is **timing**: every human turn tries recall once and injects
whatever scores high enough.

That leaves three failures:

- A relevant but mistimed memory distracts the model and spends tokens.
- A memory that should have appeared does not, and the user only sees a vague answer.
- Nothing attributes whether the last recall **helped**, so the policy never learns.

0.4.0 adds an intervention layer: keep the existing retrieval, but decide **whether
this turn should carry long-term memory fragments**, and **how deep** they should be.

## 2. When × how deep

`when` and `how deep` are orthogonal:

| | `gist` | `detail` | `quote` |
|---|---|---|---|
| **speak** | default / ambient memory | task continuation, follow-up | exact value, command, quote |
| **defer** | checkpoint only | — | — |
| **silent** | chitchat, negation, governance | — | — |

The policy only chooses among `speak` / `defer` / `silent` and
`gist` / `detail` / `quote`. Most turns should not become silent; the cheap default
is a gist, and `silent` is the last resort.

## 3. Boundary: memory fragments only

The context order stays **self → checkpoint → compact/fragment**. SelfRecord and
ContextCheckpoint are loaded and injected by the existing path, before and
independently of the policy. The policy only filters/expands the **memory fragment**
part of that order.

Consequences:

- Disabling or rolling back the policy cannot damage immersive self-recovery.
- The policy affects **what is read this turn**, never what is stored.
- A host can still call `/recall/:id/expand` or MCP `memory_query` to go deeper.

## 4. Data model

### 4.1 Decision

`/context` always returns an additive `decision`:

```ts
type InterventionAction = 'speak' | 'defer' | 'silent';
type RecallDepth = 'gist' | 'detail' | 'quote';

interface InterventionDecision {
  action: InterventionAction;
  depth: RecallDepth;
  confidence: number;       // 0..1
  reason: string;           // must_speak:*, defer_explicit, conflict, greeting, meta, ...
  policyVersion: string;    // v0-baseline / v0-rules / heuristic:<hash> / model:<hash>
  enforced: boolean;        // false for off and shadow
  scores?: { top; specificity; novelty; recentUseless; depthFit };
  mustSpeak?: boolean;
  degraded?: boolean;       // must_speak unavailable, model fallback, depth unavailable
}
```

`off` records a `v0-baseline` decision that mirrors the old behavior (`enforced:false`).
It changes no injection, but it still writes the **applied** baseline counts (spoken /
silent) to the local policy store and its traces; it does not apply policy advice or
adapt thresholds. `shadow` records the policy's advice but applies the baseline.

**One production selector:** effective mode is derived from `memoryRuntime.enabled` plus
`model.source`. A missing `source` is `off` with `model_source_missing`, not implicit
`heuristic`; `heuristic` runs rules; `local` / `host` / `api` / `auto` run the model
planner. The legacy `intervention.mode` is compatibility input only and emits
`legacy_intervention_mode_ignored` when it differs from the derived mode. Diagnostic
`shadow` is internal and cannot be enabled by the old config. No second persisted mode
field is added.

**Input-level exception:** explicit `defer_explicit` (including cue-level
`user_negated`) is a user instruction, not policy advice, so it applies in every mode.
In `off` the decision is `defer` with `policyVersion=v0-baseline` / `enforced:false` and
no policy warning; in `shadow` the actual injection is `defer`, not the baseline. The
shadow trace does not record a baseline `wouldAction`, because the defer is not a policy
suggestion.

### 4.2 Applied

`applied` describes what actually happened, which can differ from `decision` in
`off`/`shadow` and when the budget drops a fragment. `defer` means: inject no memory
fragments this turn, keep the existing checkpoint/self path available, and record
`applied.action=defer` (not `speak`) so later attribution sees a deliberate deferral:

```ts
interface AppliedIntervention {
  action: InterventionAction;
  depth: RecallDepth;
  fragments: number;        // injected memory fragments, excluding self/checkpoint
  domain?: string;
  suppressed?: string[];    // fragment IDs the policy declined
  wouldAction?: InterventionAction;  // shadow only
  wouldDepth?: RecallDepth;          // shadow only
  degraded?: boolean;
}
```

### 4.3 Outcome

`POST /memory-runtime/v1/recall/:traceId/outcome` accepts:

```json
{ "kind": "missed", "source": "host", "confidence": 0.7, "bindingToken": "obt_…" }
```

Kinds: `accepted`, `ignored`, `reasked`, `corrected`, `dismissed`, `missed`,
`too_shallow`, `too_deep`. `source=host` must present the `bindingToken` returned by
`/context`; it binds `traceId + agentId + threadId + turnId + hostApp`, is TTL-scoped
and is rejected when tampered, cross-trace, expired or issued under a rotated host
token. `source=console` uses the independent MCP admin secret through
`POST /admin/api/memory-runtime/outcome`; the browser never receives the host token.
The same trace + kind is idempotent; different kinds update the latest outcome and keep
at most five in `outcomeHistory`. New-protocol notes are rejected with
`outcome_note_unsupported`; a legacy 0.3 no-token note returns `outcome_note_ignored`
and is not stored.

### 4.4 Trace

`RecallTrace` gains additive `decision`, `applied`, `outcome`, and `outcomeHistory`.
The trace schema is not bumped; old traces stay readable and old readers ignore the
new fields. The policy does not write a second store: `RecallTrace` stays
`<home>/memory-runtime/traces.jsonl`.

### 4.5 PolicyStore

`PolicyStore` keeps **aggregates only**, never queries, bodies or traces:

- `<home>/memory-runtime/policy/state.json`, directory `0700`, file `0600`;
- atomic temp-file + fsync + rename; write-behind (250 ms / 25 changes);
- `(agentId, domain)` buckets with `spoken/silent/accepted/ignored/reasked/corrected/
  dismissed/missed/too_shallow/too_deep`;
- TTL 30 days, at most 100 domains, local only (no policy sync across devices).

## 5. Policy

### 5.1 Hard-rule priority matrix

The rules short-circuit in this order. The first matching row decides:

| # | Rule | Decision | Notes |
|---|---|---|---|
| 1 | `defer_explicit` | `defer` | User/host explicitly says “not now / hold off / don't use memory”. This is the one path that may override an automatic `must_speak`. `applied.action=defer`; `self`/checkpoint still inject. |
| 2 | `conflict` | `speak` | Only when the user explicitly asks which record is right / which to trust (`哪个对 / 以哪条为准 / 信哪个 / which record is correct`) and at least one candidate belongs to a conflict group. Exact intent uses `depthForCue()` → `quote`; otherwise `detail`. If detail is unavailable, fall back to `gist` + `degraded`. Bare statements such as “记录不一致 / 记录打架 / they disagree” do **not** trigger conflict. |
| 3 | `greeting` / `meta` | `silent` | Whole-turn greeting, thanks, assistant identity/capability/time. The regex is anchored to the whole turn, so a mixed turn with a real memory request falls through to `must_speak`. |
| 4 | `must_speak` | `speak` | Automatic policy floor, not an upper bound on explicit user intent. The heuristic threshold, negative rate, novelty, exploration and max-silent-streak cannot veto it. With no candidate it degrades to checkpoint-only (`must_speak_unavailable`). |
| 5 | `no_candidates` | `silent` | No memory fragment can be injected. |
| 6 | `no_novelty` | `silent` | Anti-repeat exception: only when **all** candidates are already injected. It does not weaken `maxSilentStreak` / exploration for fresh candidates. `must_speak` still wins when both apply. |
| 7 | heuristic | `speak` / `silent` | Remaining turns: score, cue specificity, novelty, recent negative rate, max silent streak, exploration. |

**Contract:** `must_speak` is an automatic policy floor. It exists so the heuristic
cannot learn to stay mute, not to cap what the user explicitly asked for. An explicit
`defer` is a user/host instruction and therefore wins over the automatic floor; an
ordinary `must_speak` turn is still not vetoable by heuristic signals.

`must_speak` does **not** guarantee a `speak` decision. With candidates it speaks, using
`gist` when the requested detail is unavailable. With **no candidate at all** it degrades
to checkpoint-only: `decision.action=silent`, `reason=must_speak_unavailable`,
`degraded:true`, `applied.fragments=0`, while `self` / checkpoint still inject through
the existing path. It never invents a fragment or fails silently.

`defer_explicit` is a deliberate user/host deferral, not policy silence: traces record
`decision.reason=defer_explicit` and `applied.action=defer`, so later attribution can
distinguish it from `silent`. Cue-level `user_negated` (for example “别用记忆 / 不要提”)
is normalized to the same explicit defer instead of a recall-layer short-circuit:
`self`/checkpoint are loaded first and remain available, while memory fragments are
suppressed.

### 5.2 `heuristic` (v0)

A turn speaks when the first fresh candidate's score passes the threshold, the cue is not
broad (or the score is high), the candidate is novel, and recent negative feedback is
below 40%. `silent` reasons include `low_confidence`, `broad_cue`, `recent_false_alarm`,
`no_candidates`. `no_novelty` is the anti-repeat hard exception from 5.1: it applies only
when every candidate is already injected and is not overridden by the maximum silent
streak or exploration. A maximum silent streak and a small exploration rate prevent the
policy from learning to be mute for **fresh** candidates.

Depth follows the cue: quote/command/exact → `quote` (including conflict + exact);
why/follow-up/task/entity/conflict without exact intent → `detail`; everything else →
`gist`.

### 5.3 `model` sources

`planIntervention()` receives only cue aggregates, top-3 gists, scores, and aggregate
statistics. It does **not** receive raw query bodies, detail text, checkpoint content,
or tokens. The model must answer strict JSON. Timeout (500 ms default), invalid JSON,
missing model, or provider failure fall back to `heuristic` with `degraded:true` and
`intervention_model_fallback`. Rule-decided turns (`defer_explicit`, `conflict`,
`greeting`/`meta`, `must_speak`, `no_novelty`) do not call the model.

The model planner has four sources:

- `local` consumes a fresh assisted plan generated after the previous turn (cue
  signature or topic/entity Jaccard ≥0.8, 60 s TTL). It never calls the local model on
  the `/context` path, and it is **not authoritative** in 0.4.0. Authoritative local
  planning is the separate 0.4.2 line.
- `host` consumes a session-prior plan generated by the host adapter after the previous
  turn (60 s TTL, identity/basis/cue checks). Deterministic host planners are rejected;
  `/context` never calls the host model.
- `api` is the only synchronous source. It requires an explicit endpoint/model/keyRef
  and `allowRemote=true`, is capped at 1500 ms, shares the overall `/context` deadline,
  and never retries.
- `auto` resolves host → fresh local plan → configured API (only when local is not
  configured) → heuristic. A configured local miss stays heuristic and never falls
  through to API.

### 5.4 Adaptive (heuristic only, default shadow)

For a domain with at least 20 samples, the threshold moves by at most ±0.03 every 50
decisions or weekly, clamped to `[0.45, 0.80]`: high useless rate raises the
threshold, high missed rate lowers it. Smaller domains pool with global statistics.
Only `heuristic` decisions that actually took effect are samples. `model`, diagnostic
`shadow`, `off` and gate/non-intervention turns write diagnostic counts but never feed
the adjustment. The internal stage defaults to `shadow` (learn/observe, do not apply);
`canary` applies only to a stable `(agentId, domain)` hash bucket and `on` applies to
all heuristic decisions. These are internal settings, not a Console control. Reset
clears this local learning. Legacy `adaptive.enabled` / `adaptive.shadow` keys are
compatibility input only and emit `adaptive_experimental_ignored`.

### 5.5 `/context` deadline, queue and trace skip

`/context` has one absolute deadline, default 1500 ms and clamped to `[200, 1500]`.
Response assembly reserves 150 ms and trace persistence 50 ms. The intervention planner
runs in an independent queue (concurrency 1, max 8, drop-oldest); queue timeout or
overflow falls back to heuristic and does not cancel a started model call. If the
deadline leaves no room to persist the trace, the response reports
`tracePersisted=false`, `traceId=null` and `bindingToken=null`; hosts must not report an
outcome for that turn. Read-only queue metrics live at `/status.policy.planner`.

### 5.6 Shadow (internal diagnostic)

`mode=shadow` computes the policy decision but injects exactly the baseline result. It
records `wouldAction` / `wouldDepth` so operators can compare advice with actual
injection before enabling `heuristic`.

**Input-level defer exception:** `defer_explicit` (including `user_negated`) is a user
instruction, not a policy suggestion. It applies in `shadow` as well: actual injection
is `defer` (memory fragments suppressed, self/checkpoint kept), and the trace does **not**
record a baseline `wouldAction` / `wouldDepth`, because there is no baseline to compare
against. This exception is documented so `applied.action=defer` never contradicts a
shadow `wouldAction=speak`.

## 6. Host integration (OpenCode first)

The OpenCode plugin records every `/context` with a `traceId`, including silent
responses, and attributes the next user turn:

| Signal | Outcome |
|---|---|
| previous `silent`/`defer` + explicit memory follow-up or high overlap | `missed` |
| previous `speak` + re-ask | `reasked` |
| previous `speak` + correction | `corrected` |
| previous `speak` + `gist` + request for detail | `too_shallow` |
| previous `speak` + `detail`/`quote` + request for a shorter answer | `too_deep` |
| explicit positive confirmation | `accepted` |
| idle/window elapsed with no follow-up | `ignored` (weak, delayed) |

The attribution window is 120 s by default; `ignored` uses at least 10 minutes.
Attribution uses `applied`, so a shadow `silent` advice with a baseline `speak` is never
counted as a real silence. Failures never block the host; `trace=off` disables
attribution and learning. DSH and Hermes can reuse the same host API later; 0.4.0
validates OpenCode first.

The host-level `alreadyInjectedIds` fragment-ID alias table is **process-local**: it maps
the `mf_…` IDs the plugin sends back to source record IDs for the lifetime of the sidecar
process. Within a normal session it is effective; after a sidecar restart, an old `mf_…`
from before the restart may no longer resolve and may be ignored. Source/record IDs remain
directly valid.

## 7. Evaluation

The intervention is judged on outcomes, not only on “fewer injections”:

- useless injection rate = `(reasked + corrected + dismissed) / spoken`;
- missed-intervention rate = `missed / silent`;
- depth mismatch rate = `(too_shallow + too_deep) / spoken`;
- acceptance rate = `accepted / spoken`;
- context token cost per turn;
- `/context` p95 latency;
- shadow disagreement rate;
- answer quality: no-memory / always-inject / policy, with a judge and spot checks.

A canary is Go only when useless injection is not worse than baseline, missed
intervention is at most baseline + 2 pp, answer quality is not worse than baseline
− 2 pp, token cost does not increase, p95 stays inside budget, and rollback is one
switch away.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Attribution noise (a re-ask can mean a bad answer, not a bad injection) | `ignored` is weak; only explicit negatives move thresholds; a single event never changes the global policy |
| Feedback loop that learns to be silent | exploration rate, max silent streak, `must_speak` floor |
| Small-model misjudgment | prefer speak when uncertain, timeout/fallback, shadow and canary |
| Latency | heuristic <1 ms; model 500 ms budget; never blocks the model answer path |
| Privacy | trace/policy local, model sees gist only, no token/body in logs |
| Compatibility | additive fields, old hosts ignore them, `trace=off` is explicit |
| Scope creep | 0.4.0 is decision/outcome/shadow/heuristic; consolidation is separate |

## 9. Non-goals

- Desktop screenshots or OS-level observation.
- Per-user LoRA or fine-tuning.
- Visible proactive pop-ups or reminders (a later, separately opted-in feature).
- Cross-device policy sync.
- Changing `self`/checkpoint recovery semantics.
- Full observation → proposition consolidation (a separate 0.4.x line).
- Putting policy state into `__policy__`; policy is carried by local state plus
  auditable traces, not a memory namespace.

## 10. Rollback and privacy

- Roll back by removing `model.source` (or disabling `memoryRuntime.enabled`). Traces and
  policy statistics remain; no migration runs. Setting the legacy `intervention.mode` to
  `off` alone no longer changes the effective mode.
- `POST /intervention/reset` clears local policy statistics and in-memory runtime state
  (silent streak, last decision, reset guard) only. It does not delete memory records,
  details, checkpoints, traces or outcome history.
- Policy state is local and contains counters plus agent/domain keys. It never contains
  query text, detail bodies, prompts or tokens.
- The Console Runtime page is **observability only**: decision/outcome/would* fields on
  traces and a confirmed reset action. It is not a new UI surface or an intervention
  control panel.

## 中文要点

- 0.4.0 的主线是**介入机制**：在 `self → checkpoint → compact/fragment` 顺序不变的前提
  下，只决定本次是否带长期记忆片段、带多深；`self/checkpoint` 始终自动注入。
- 默认 `off`，升级不改变 0.3.x 行为；生产只有 `model.source` 一个选择器，缺失即
  `off`，旧 `intervention.mode` 只做兼容 warning。`heuristic` 走规则；`local` / `host` /
  `api` / `auto` 走模型 planner；`shadow` 只是内部 diagnostic。
- `local` 在 0.4.0 是 assisted/shadow，不是权威 planner；权威 local 属于独立的 0.4.2
  线。`api` 是唯一同步来源（1500ms 上限、不重试）；`host` 只消费上一轮后的
  session-prior plan。自适应阈值只对 `heuristic` 生效，内部 stage 默认 `shadow`。
- `/context` 绝对 deadline 默认 1500ms；planner 有独立队列（concurrency 1、max 8、
  drop-oldest），超时/overflow 回退 heuristic。trace 来不及写入时返回
  `tracePersisted=false` / `traceId=null` / `bindingToken=null`，宿主不得上报 outcome。
- `decision`（action/depth/confidence/reason/policyVersion/enforced）解释“为什么说/为什么
  不说”；`applied` 记录实际注入；`outcome` 记录 accepted/ignored/reasked/corrected/
  dismissed/missed/too_shallow/too_deep。
- `must_speak` 是**自动策略下限**，不是用户显式意图的上限：显式 defer 可以覆盖自动
  must_speak，并记录 `defer_explicit` / `applied.action=defer`。完整优先级为
  `defer_explicit → conflict → greeting/meta → must_speak → no_candidates →
  no_novelty → heuristic`；`no_novelty` 只在全部候选已注入时 anti-repeat silent。
- `must_speak` 不保证 100% speak：完全没有候选时降级为 checkpoint-only
  （`silent` + `must_speak_unavailable` + `degraded`）。
- `off` 不改注入，但仍会把 baseline 的 spoken/silent 写进本机 policy 统计和 trace；
  它不应用策略建议，也不做阈值自适应。
- 结果归因先接 OpenCode，并按 `applied` 而不是 shadow 建议归因；policy 只存本机聚合
  计数，不存 query 正文、detail 正文或 token。`alreadyInjectedIds` 的 fragment ID 别名表
  是进程内的，sidecar 重启后旧 `mf_…` 可能无法解析。
- 回滚只需 `mode=off`；reset 只清 policy 统计与运行态（沉默 streak / 上一轮决策），
  不删记忆与 trace。Console 只做可观测性和 reset，不是新 UI，也不是介入控制台。
