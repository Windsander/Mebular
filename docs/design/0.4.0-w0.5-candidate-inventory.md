## 1. 结论摘要

1. **推荐 4 个严肃候选进入首轮零样本横评**：Qwen2.5-1.5B-Instruct、Qwen3-1.7B、
   Qwen2.5-0.5B-Instruct、Qwen3-0.6B。四者均为 Apache-2.0、未 gated、有官方 GGUF 仓库，
   首轮只使用官方产物，合计 **4,082,593,472 B ≈ 3.80 GiB**。
2. **可选第 5 个对照**：SmolLM2-1.7B-Instruct（Apache-2.0、官方 Q4_K_M），但官方卡明确
   “primarily English”，对中文 golden set 大概率是负面对照，不作为权威 planner 候选。
3. **明确不进入下载名单**：
   - `Qwen2.5-3B-Instruct`：**Qwen Research License，仅限非商业**，不能按当前 Apache-2.0
     目录打包；
   - `Llama 3.2 1B / 3B`：**gated=manual**，Llama 3.2 Community License；当前产品没有
     HF token / license acceptance 流程；
   - `Gemma 3 1B`：**gated=manual**，Gemma Terms；同上；
   - `SmolLM2-360M`：Apache-2.0，但英文为主、360M 太小，官方 GGUF 仅 Q8_0；不占首轮名额。
4. **没有任何候选有 planner 证据**。现有唯一真实本地 planner canary 是 Qwen3-4B：
   p50 7,890 ms / p95 11,686 ms、action 61.9%、depth 0/7，已证明 4B 不适合同步权威 planner。
   小模型能否在 1.5 s 内完成结构化决策，**全部未知，必须实测**，不能按参数量外推。
5. **不自动等于可进 catalog**：HF 有 repo、GGUF 可下载、license 标签为 Apache-2.0，只说明
   “可作为评测候选”；新增 pack 仍要过 `CURATED_SPECS`、manifest 哈希、Console 数据变化、
   默认 pack 不变、显式下载/回滚等产品 gate。
6. **当前 catalog 的许可证是硬编码的**：`buildCuratedManifest()` 固定
   `license.id='apache-2.0'`、`requiresAcceptance=false`。Qwen Research / Llama / Gemma
   不是“改一条数据”就能加入，必须先改 manifest 构建与 gated 下载流程。

## 2. 方法与证据边界

### 2.1 实际做了什么

- 通过 Hugging Face API 镜像 `https://hf-mirror.com/api/models/<repo>?blobs=true` 查询：
  - 仓库是否存在、`gated` 状态、license tag、revision（`sha`）、safetensors 参数总量；
  - GGUF siblings、文件大小、LFS `sha256`；
- 读取官方 `README.md` 与 `LICENSE`（仍经镜像）核对许可证文本、上下文、语言与能力声明；
- 对照 `packages/memory-runtime/src/inference/{types,store,catalog,detect}.ts` 的 catalog /
  manifest / license / recommendation 约束；
- 未下载模型权重，未启动 llama.cpp，未运行推理，未改任何产品代码或 UI。

### 2.2 网络与 transport（重要）

| 目标 | 结果 | 说明 |
|---|---|---|
| `https://huggingface.co/api/models/Qwen/Qwen3-0.6B` | **超时**（curl 28，20 s） | 官方 HF 在本环境不可达 |
| `https://hf-mirror.com/api/models/Qwen/Qwen3-0.6B` | **200**（约 1 s） | 元数据、LICENSE、README 均经此镜像读取 |
| 模型/引擎权重下载 | **未执行** | 本会话不下载 |

这与 `0.3.2-model-smoke` / `0.4.0-w0-local-model-benchmark` 记录的“官方 HF、github.com
release 主机不可达，使用 test-only mirror / GitHub REST asset API”一致。本文中的所有大小、
sha256、license tag 都是**镜像 API 元数据**，不是对官方 HF 的独立二次确认。

**因此：**
- 不要把这篇文章当成“官方 HF transport 已验证”；
- W0.5 真正下载前，必须在可访问官方 HF 的环境（或经批准的产品 transport）重新核对
  repo、revision、文件大小、sha256、LICENSE，并记录 `model.transport`；
- 镜像可用性不构成产品承诺，也不把 mirror 写进产品配置。

### 2.3 证据等级

| 项 | 等级 |
|---|---|
| repo 存在 / gated / license tag / 参数 / revision | 镜像 API 元数据，**已核对** |
| GGUF 文件大小 / LFS sha256 | 镜像 API 元数据，**已核对**；待官方复核 |
| 架构是否被 llama.cpp 支持 | 按 GGUF + 发布时间判断，**未启动引擎验证** |
| 质量 / 延迟 / 内存 RSS | **未知**；仅有 Qwen3-4B 的历史实测可作参照 |
| 许可证是否允许商用/再分发 | 已读 license 文本/标签，**结论见逐项**；不是法律意见 |

### 3.2 一句话排序

**首轮优先顺序：Qwen2.5-1.5B > Qwen3-1.7B > Qwen2.5-0.5B ≈ Qwen3-0.6B。**

理由不是“参数量越大越好”，而是：

- 1.5B/1.7B 是“可能同时满足质量与 1.5 s 预取预算”的唯一区间；
- 0.5B/0.6B 是速度下限与质量下限，用来判断“小模型是否根本不具备语义能力”；
- 3B 质量可能更好，但 Qwen2.5-3B 的许可证直接阻断打包，不能作为发布候选；
- Llama/Gemma 被 gated 阻断；SmolLM2 被英文能力阻断。

### 3.3 现有 canary 参考（仅 Qwen3-4B）

| 指标 | 实测 |
|---|---|
| 模型 / 量化 | `qwen3-4b-instruct` / Q4_K_M，文件 2,497,280,256 B（2.33 GiB） |
| 引擎 / 硬件 | llama.cpp b12017 / macOS x64，Intel i7-8850H，4 threads |
| 热态 p50 / p95 | **7,890 ms / 11,686 ms**；min 4,567 ms，max 12,917 ms |
| JSON schema 合法率（完成调用） | 30/30 = 100%；含超时 30/32 = 93.8% |
| action 命中人工预期 | 13/21 = 61.9% |
| depth 命中人工预期 | **0/7 = 0%**（全部塌缩为 gist） |
| llama-server RSS | 约 5.15–5.60 GiB（显著高于 2.33 GiB 权重文件） |
| 结论 | 只适合 shadow / 后台 / 离线；不能作为同步权威 planner |

这张表是 W0.5 的“负面基线”：4B 都已经无法进入 1.5 s，小模型必须用实测证明自己，
不能靠“参数量更小”推断可达标。它也说明本文的最低内存估算必须用真实 RSS 校正，不能只看
GGUF 文件大小。

## 5. 与 Mebular 当前 catalog / manifest / license 的冲突

### 5.1 目录是白名单，不是任意 `packId`

`catalog.ts` 的 `CURATED_SPECS` 只有 4 个 Qwen3 pack：4B / 8B / 14B / 30B-A3B。
`packId` 必须属于精选目录，未知 pack 直接 `unknown_pack`。因此：

- 本文任何候选都**不能**仅靠“下载一个 GGUF + 写 manifest”进入产品；
- 新增 pack 必然改 `catalog.ts`（代码），不是纯数据操作；
- 本会话明确不改 catalog / manifest / 代码。

### 5.2 许可证被硬编码为 Apache-2.0

`buildCuratedManifest()` 当前固定：

```ts
license: {
  id: 'apache-2.0',
  name: 'Apache License 2.0',
  url: licenseUrl,
  requiresAcceptance: false,
}
```

这意味着：

- Qwen3 / Qwen2.5 / SmolLM2 的 Apache-2.0 可以映射；
- **Qwen2.5-3B 的 Qwen Research License、Llama 3.2 Community License、Gemma Terms
  不能靠现有 spec 表达**；必须先扩展 `CuratedModelSpec` / manifest builder，并实现
  license 展示 + 显式接受；
- `requiresAcceptance` 字段虽然有类型，但当前精选目录固定 `false`，没有对应的 UI/流程。

### 5.3 没有 gated 下载 / HF token 流程

`ModelStore` 可以注入 `fetch` / headers，但产品层没有：

- HF token 的本地密钥引用；
- license acceptance 状态；
- gated repo 的 401/403 处理与重试；
- 用户可见的“接受许可后才能下载”。

`0.3.0-model-catalog.md` §6 已明确：Llama 系列要先实现 license 展示与用户显式接受、
HF token/授权流程，且 token 只存设备本地密钥引用；未完成前精选目录继续只提供 Qwen。
**因此 Llama 3.2 / Gemma 3 不是“质量不够”，而是“当前产品路径不允许”。**

### 5.4 新增 pack 会改变推荐与 Console 数据

- `recommendModel()` 遍历全部 packs；新增一个小 pack 会进入 `alternatives`，在低内存设备上
  甚至可能成为唯一可运行 pack，从而改变“本地模型推荐”的语义；
- `tier='custom'` 的排序最低（`TIER_RANK.custom=0`），在有 4B `light` 可用的机器上不会
  顶掉 4B；但在 <8 GiB 设备上可能变成默认推荐，这对“通用抽取”是错误语义；
- 如果 planner pack 出现在 Console 模型列表，属于“Console 可见数据变化”，按计划必须
  单独确认，不能借零 UI diff 悄悄越过。

**设计建议（不在本会话实现）：** planner pack 需要独立 role / 独立列表 / 显式选择，
不要混进通用 `recommendModel()` 的质量排序；默认 pack 必须保持
`qwen3-8b-instruct-q4_k_m` 不变。

### 5.5 格式与哈希约束

| 约束 | 本文候选是否满足 |
|---|---|
| `format: 'gguf'` | 全部满足 |
| 文件路径为包内相对 POSIX 路径 | 满足（单文件） |
| 正安全整数 size + 64 位 sha256 | 推荐项已取得 LFS sha256；待官方复核 |
| `source.repository` 为 `owner/name` + pinned revision | 推荐项已记录 revision |
| 下载 URL 由 repo + revision + 文件名推导 | 满足；不要写任意 URL/mirror 进 catalog |
| 32B token 排除 | 不涉及 |
| `context.length` | Qwen 32k；SmolLM2 8k，需要按 8k 预算裁剪 prompt |

### 5.6 量化约定

现有精选目录统一 `Q4_K_M`。候选里：

- Qwen2.5 / SmolLM2-1.7B：官方有 Q4_K_M，完全符合；
- Qwen3-0.6B/1.7B：**官方 GGUF 只有 Q8_0**；Q4_K_M 来自 unsloth / ggml-org；
- SmolLM2-360M：官方只有 Q8_0；Q4_K_M 来自 unsloth。

如果产品坚持“官方仓库 + Q4_K_M”，Qwen3 两个候选只能：
1. 首轮用官方 Q8_0（本文建议）；
2. 二轮引入社区 Q4_K_M，并单独做来源/转换脚本审查；
3. 或者放弃 Qwen3，只用 Qwen2.5 官方 Q4。

## 8. 风险

1. **许可风险**：最容易踩的坑是把“社区 GGUF 仓库 `gated=false`”当成“许可证允许”。
   Llama/Gemma 的原始模型仍 gated，社区转换不改变许可；Qwen2.5-3B 是明确非商业。
2. **gated 流程缺失**：当前 catalog 固定 `requiresAcceptance=false`，`ModelStore` 没有
   HF token / acceptance 状态；Llama/Gemma 不能按现有产品路径安装。
3. **质量风险**：没有任何候选有 planner 证据；4B 已失败，小模型可能更差。JSON 合法率
   100% 也可能只是 grammar 把输出“夹”成合法 JSON，语义仍然错。
4. **延迟风险**：4B 最短 4.57 s，1.5 s 只够约 10 个 output token；1.7B/0.6B 的真实
   p50/p95 未知，不能按参数量线性外推。若 1.7B Q8 仍 >1.5 s，Q4 二轮才有意义。
5. **中文能力**：SmolLM2 官方卡明确 English-only；Qwen 多语言，但 0.5B/0.6B 的中文
   语义质量未知。golden set 必须中英混合并分别统计。
6. **catalog/UI 风险**：新增 pack 会改变 Console 可见模型列表与 `recommendModel()`
   的 alternatives；默认 pack 必须保持不变，planner pack 需要独立 role，不能混入通用推荐。
7. **来源/量化风险**：Qwen3 官方 GGUF 只有 Q8；Q4_K_M 依赖 unsloth/ggml-org。首轮用官方
   Q8 规避；二轮必须审查转换来源、license 与 sha256。
8. **网络风险**：官方 HF/GitHub 在本环境不可达；本文数据来自 mirror。正式打包前必须在
   官方 transport 复核；mirror 不是产品承诺。
9. **8k context 风险**：SmolLM2 只有 8,192 context；如果 golden set 的候选片段 + 指令
   超过 8k，必须裁剪，否则会把“上下文不够”误判成“模型不会”。
10. **过拟合风险**：60–100 条 golden set 很容易被调参/选型过拟合；每个模型至少 2 次运行，
    记录硬件/线程/量化/引擎版本，保留原始 JSON。
