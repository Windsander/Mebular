## 0. 决策摘要

| 问题 | 决策 | 条件 |
|---|---|---|
| 在本机训练 0.5B LoRA/SFT | **NO-GO** | 本机没有已验证的 CUDA/MPS 训练环境，未安装 torch/transformers/peft；CPU-only 只能做冒烟，不能做质量实验 |
| 直接进入产品 SFT / 发布 adapter | **NO-GO** | 当前没有任何 SFT 证据；W0.5 零样本全部未达 `local-authoritative` |
| 做一次有边界的 Stage-1 SFT 可行性实验 | **GO（有条件）** | 外部 NVIDIA GPU、2,500–3,000 条分层标签、500 条隔离 held-out、规则优先 hybrid、按 Q4 成品复测 |
| 把 0.5B 当作同步 `local-authoritative` 候选 | **GO 仅作为假设** | 必须先过本文 §6 的质量/延迟 gate；未过之前不得宣称权威 |
| 2,500–3,000 条是否足够 | **只够 Stage-1 判断学习信号，不够产品验收** | 产品级建议 8,000–12,000 条 + 1,000 条 held-out |
| 1.7B / 4B 作为同步替代 | **NO-GO** | 1.7B p95 4.84 s，4B p95 11.69 s；只能 shadow/async/teacher |
| `local-authoritative` 0.4.0 发布 | **当前 NO-GO** | 若 Stage-1/2 仍失败，回到规则层 + API/async，不为了“本地”牺牲介入正确性 |

**一句话结论**：
**0.5B 是唯一有延迟希望的底座，但“能跑得快”不等于“能学会沉默”。**
先做“规则硬判 + 模型只处理灰区”的 hybrid；用 2,500–3,000 条数据验证 0.5B 能否学会
silent / depth，而不是先堆 8,000 条。Stage-1 失败就停，不升级到 1.5B 做同步权威；
Stage-1 通过才值得投入 8,000–12,000 条和产品级 gate。

**最小验证实验**（详见 §8）：
1. **Stage 0（无 GPU，2–4 人日）**：在 88 条 + 300–500 条真实/合成 turn 上实现规则优先
   hybrid 的 test-only 评估，测“硬规则覆盖率”和“灰区占比”。若灰区 <10%（硬规则覆盖
   ≥90%），**NO-GO 训练**，规则层 ROI 更高。
2. **Stage 1（外部 GPU，1–2 周）**：2,500–3,000 条分层标签 + 500 条模板/领域隔离 held-out，
   训练 Qwen2.5-0.5B-Instruct LoRA，合并后导出 Q4_K_M，复用 W0.5 harness 复测。
3. **Stage 2（可选，2–4 周）**：只有 Stage-1 全 gate 通过，才扩到 8,000–12,000 条 + 1,000 条
   held-out，做产品级许可/分发/回滚 gate。

## 1. 已知证据：0.5B 的起点和上限

W0.5 在 88 条 golden set（115 次调用/模型）上的真实结果：

| 模型 | JSON | action | must_speak | novelty=0 沉默 | conflict detail | depth | silent 特异度 | defer | p50 / p95 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| Qwen2.5-0.5B-Instruct Q4_K_M | 100% | **50.4%** | 100% | **0%** | 27.3% | 15.5% | **0%** | **0%** | 1,358 / 1,923 ms |
| Qwen3-0.6B Q8_0 | 100% | 50.4% | 100% | 0% | 72.7% | 53.4% | 0% | 0% | 1,651 / 2,733 ms |
| Qwen2.5-1.5B Q4_K_M | 100% | 57.4% | 100% | 7.7% | 0% | 24.1% | 17.4% | 0% | 2,163 / 2,837 ms |
| Qwen3-1.7B Q8_0 | 100% | 60.9% | 100% | 0% | 100% | 74.1% | 26.1% | 0% | 3,969 / 4,840 ms |
| heuristic（同集） | — | **82.95%** | 100% | 100% | 75% | **90.9%** | 80.6% | 0% | <1 ms |

三个必须继承的事实：

1. **模型退化为“几乎总是 speak”**。0.5B 在 115 次里 114 次 speak、1 次 defer、0 次 silent；
   0.6B 是 115/115 speak。JSON 100% 合法不代表策略正确。
2. **silent / novelty=0 / defer 是主失败面，不是 depth 微调问题**。0.5B 的 depth 只有 15.5%，
   但更严重的是它不会在寒暄、低相关、已注入时关掉注入。
3. **0.5B 是唯一 p95 <2 s 的模型**，但这是 32 个输出 token（中位数）的零样本结果；
   产品若去掉自由文本 `reason`、把输出压到 ≤16 token，延迟还有下降空间（§6.4）。

**推论**：不要把 0.5B SFT 的目标定成“替代全部 heuristic”。must_speak、novelty=0、conflict
本来就可以由代码硬判；模型只需要处理“有候选、无硬规则、相关度模糊”的灰区。否则训练数据会
被大量硬规则样本淹没，模型也会学到“看到候选就 speak”的捷径——这正是零样本失败的原因。

## 2. 规则层与模型的分工（先定契约，再谈数据）

### 2.1 决策优先级

`local-authoritative` 的 hybrid 必须按下面顺序短路，模型不能覆盖硬规则：

| 顺序 | 条件 | 决策 | 由谁执行 |
|---:|---|---|---|
| 1 | 无候选 | `silent` / `gist` | 规则 |
| 2 | 所有候选 `novelty=0`（已注入） | `silent` / `gist` | 规则 |
| 3 | `must_speak`：显式回忆、精确值、命令、任务续接 | `speak`，depth 按规则（quote/detail） | 规则 |
| 4 | `conflict=true` | `speak` / `detail` | 规则 |
| 5 | 显式 `defer`：先别回忆、等下再说、跳过旧上下文 | `defer` / `gist` | 规则 |
| 6 | 寒暄、感谢、meta（“你是谁/在吗”） | `silent` / `gist` | 规则 |
| 7 | 以上都不命中，但存在候选、相关度中等/模糊 | `speak|silent` + `gist|detail|quote` | **模型灰区** |
| 8 | 模型超时/非法/不可用 | 显式失败（authoritative）或 heuristic（assisted） | 产品契约 |

### 2.2 灰区的定义

灰区 = **有候选、没有命中 1–6、查询不是显式回忆/冲突/defer/寒暄**，模型需要判断：

- 是否值得注入（`speak` vs `silent`）；
- 若注入，深度是 `gist` / `detail` / `quote`。

因此模型的实际输出空间只有 4 类（speak-gist / speak-detail / speak-quote / silent），
不是完整的 3×3。`defer` 在显式语义下由规则处理；如果产品希望模型处理“隐性 defer”，
必须单独定义标签，不能和显式 defer 混在一起。

### 2.3 为什么这决定数据预算

如果对 88 条 golden set 套用上表，1–6 几乎覆盖全部 case：must_speak/task/exact 30 次、
greeting/meta 18 次、no_candidates 5 次、novelty 13 次、conflict 11 次、defer 11 次。
这说明 **88 条集合不能用来衡量“灰区模型”的价值**——它被设计成覆盖所有切片，而不是真实分布。

所以必须增加 Stage 0：在真实/合成的 300–500 条 turn 上统计硬规则覆盖率。若真实流量中
灰区只占 5–10%，那么训练 0.5B 的收益上限很低，应该先做规则层；若灰区占 20–40%，
模型才值得做。这个比例目前**未知**，不能用 88 条集合外推。

**结论：本机不是训练环境。**
- 没有 CUDA；
- MPS 没有安装/验证，且 4 GB VRAM + Intel 平台不能作为“已支持”的依据；
- 没有 torch/transformers/peft；
- 32 GiB 内存中当前空闲只有约 4.7 GiB，训练时还要和 App/IDE 争内存；
- CPU-only 训练在数量级上不可接受：按 6 核 AVX2 的有效算力粗估，0.5B、seq 512、
  2,500 条 × 2–3 epoch 的单轮训练是**数十小时/epoch 量级**（未实测，仅数量级估算）。
  这还不含合并、量化、评估和 2 个 seed 的复跑。

> 本机可以做的只有：**GGUF 推理评估**（W0.5 已做）、**CPU 上 50–100 step 的管线冒烟**
> （需要先装 torch，且不构成质量证据）。这两者都不能替代 GPU 训练。

## 4. 数据方案

### 4.1 任务形态

- 输入：合成/脱敏的 query + 候选列表（`kind/domain/gist/score/confidence/ageDays/novelty/conflict`），
  不含 detail 正文、token、真实路径、用户数据。
- 输出：`action` + `depth`（可选 `confidence`），**不生成自由文本 `reason`**。
  理由：W0.5 的 0.5B 中位数 32 个 completion token，其中大量是 `reason`；
  去掉后输出可压到 8–16 token，直接决定能否进入 1.5 s。
- 有效类别：产品规则下是 4 类灰区输出（speak-gist / speak-detail / speak-quote / silent）；
  若做“全策略容量探测”，再加入 `defer-gist`，共 5 类。不要按 3×3=9 类准备数据，
  因为 `defer` 只允许 gist、`silent` 只允许 gist（见 §2）。

### 4.2 为什么最少 2,500–3,000，建议 8,000–12,000

**最少 2,500–3,000 的理由：**

- 4–5 个有效类别，按每类 ≥250 条才能做分切片判断；10–12 个切片 × 200–250 ≈ 2,500–3,000。
- 分切片 250 条时，若真实准确率 90%，95% 置信区间约 ±3.7 pp；500 条约 ±2.6 pp；
  1,000 条约 ±1.9 pp。2,500 条只能支持“大方向”判断，不能支撑 1–2 pp 的产品承诺。
- 稀有切片（defer、novelty=0、conflict、greeting-with-high-score）必须单独凑够 250，
  不能靠随机采样“碰运气”；否则训练集里这些切片可能只有几十条。
- 2,500 条足以让 0.5B 学会输出格式和粗粒度策略；不足以证明模板/领域泛化。

**建议 8,000–12,000 的理由：**

- 每切片 ≥800 条，才能在中英文、不同 domain、不同模板下稳定估计；
- held-out 1,000 条，才能把 5 pp 级别的“比 heuristic 好”与噪声分开；
- 0.5B 容量小，8k–12k 通常接近饱和；再往上加数据的边际收益需要学习曲线验证，
  不要默认“越多越好”；
- 需要留出 10–20% 做双人复核/冲突裁决，实际可用训练量会小于标注量。

**结论**：2,500–3,000 是 **Stage-1 最小实验**，不是产品训练量；8,000–12,000 才是
Stage-2/产品候选量。Stage-1 不通过就不扩数据。

### 4.3 标签来源与防偏差

| 来源 | 能做什么 | 不能做什么 | 偏差控制 |
|---|---|---|---|
| heuristic / 规则 | 硬规则切片（must_speak、novelty=0、no_candidates、conflict、显式 defer）的确定性标签；候选挖掘 | **不能**给灰区做 ground truth；heuristic 的 defer=0%、greeting 有高分候选时只有 37.5% silent、conflict detail 75%、meta 66.7% | 灰区 heuristic 标签占比为 **0%**；只作为特征/先验；单独统计“heuristic 分歧集” |
| Qwen3-1.7B teacher | 草拟 depth 候选、生成 paraphrase、做对照 | **不能**当 action 老师：action 60.9%、silent 26.1%、defer 0%、novelty 0% | 只用于 draft，必须人工复核；在 200 条人工校准集上先测 teacher 一致率，未达 ≥90% 的切片不用 |
| 更大 teacher（Qwen3-32B 等 Apache-2.0 模型；或经批准的 API） | 灰区 action/depth 草拟；扩大覆盖 | 不能直接信 confidence；API teacher 可能受 ToS 限制 | 每切片 200 条人工校准，≥90% 一致才批量；记录 provenance；API 必须先过许可评审 |
| 真实 outcome | 评估/校准；发现“注入后用户重问/忽略”的硬负例 | 不能当批量标签：W4 尚未实现，outcome 稀疏、迟到、有选择偏差 | 只用显式事件，不读 raw query/detail；只做 eval/加权，不做主标签 |
| 人工规则/人工标注 | 硬边界、冲突、defer、greeting 高分候选；10–20% 随机复核 | 成本高，不能全量 | 双人独立标注 + 裁决；硬切片一致率 ≥95%，灰区 Cohen's κ ≥0.7 |

**避免“只蒸馏 heuristic”的具体做法：**

1. 先定义 heuristic 的弱项切片（defer、greeting-with-high-score、meta、conflict detail），
   这些切片**禁止**用 heuristic 标签训练；用人工/更强 teacher。
2. 构造“heuristic 分歧集”：在同一输入上同时跑 heuristic 和 teacher/人工，只保留
   heuristic 与人工不一致的样本做重点训练/评估；如果学生只是在复刻 heuristic，
   它在分歧集上不会提升。
3. 训练集里记录 `labelSource`，训练后按来源分层评估；若学生只在 heuristic 标签子集上高、
   在人工子集上低，说明在蒸馏偏差，不是学会了策略。
4. teacher 只给“候选标签”，人工做最终裁决；不要用 teacher 的 `confidence` 当校准真值。
5. 目标不是“超过 teacher”，而是“在 held-out 上超过 heuristic 且不破坏硬规则”。

### 4.4 切片与配比

Stage-1 建议按“决策数”分层，而不是按句子随机：

| 切片 | 2,500 条 | 10,000 条 | 说明 |
|---|---:|---:|---|
| must_speak（显式回忆/精确值/命令） | 300 | 1,200 | 硬规则；也用于容量探测 |
| task_continue | 200 | 800 | 任务延续，偏 detail |
| exact_quote | 200 | 800 | 精确值/原文，偏 quote |
| gist | 250 | 1,000 | 默认浅注入 |
| detail | 300 | 1,200 | 冲突/why/follow-up/实体问题 |
| defer（显式） | 300 | 1,200 | 零样本全灭，必须单独足量 |
| greeting / meta | 300 | 1,200 | 寒暄、感谢、“在吗/你是谁” |
| silent_low_relevance | 250 | 1,000 | 有候选但查询不相关 |
| novelty_zero（已注入） | 250 | 1,000 | 硬规则；命名用 `alreadyInjected=true` 更直观 |
| conflict | 200 | 800 | 硬规则；必须 100% 人工复核 |
| **合计** | **2,550** | **10,200** | 可微调配比，但每个关键切片不低于 200/800 |

语言：中英各半；同一语义至少 3–5 个 paraphrase，避免模型只记住“你好”“hello”这类字符串。
领域：至少 6–8 个 domain（偏好、工作流、项目、人物、工具、时间、地点、健康/生活等），
每个 domain 在训练/held-out 中不能重叠（见 §4.5）。

### 4.5 held-out 500–1,000 条与隔离

- **规模**：Stage-1 500 条；Stage-2 1,000 条。其中至少 200 条硬规则安全样本
  （must_speak/novelty/conflict/defer），300 条灰区样本。
- **隔离维度**：按 `templateFamily` + `domain` + `entity` 划分，不按随机句子划分。
  - 留出整个模板族（例如所有“早安/在吗/今天怎么样”的变体只出现在 held-out）；
  - 留出 2–3 个完整 domain；
  - held-out 与训练集的 gist/entity 不得重复；
  - 用 13-gram MinHash / Jaccard >0.8 去重；对 held-out 每条检查最近邻，禁止 >0.7 的近似重复。
- **不训练 88 条 golden set**：它只做跨版本回归和与 W0.5 数字对比，永远不进训练集。
- **不把 held-out 提交到公开仓库**：公开仓库只放 held-out 的 SHA-256、切片计数和聚合指标；
  逐条 held-out 放在外部评估目录。否则公开仓库本身就是泄漏源。
- **冻结**：held-out 生成后记录 SHA-256；任何改动都视为新 benchmark，不能和旧结果直接比。

### 4.6 数据格式与质量门

建议 JSONL 字段：

```json
{
  "id": "sft-000001",
  "lang": "zh",
  "slice": "defer",
  "templateFamily": "explicit_wait_v3",
  "domain": "workflow",
  "input": {
    "query": "先别翻旧的了，等我说完",
    "candidates": [
      {"kind": "fact", "domain": "workflow", "gist": "用户在做发布检查", "score": 0.78,
       "confidence": 0.8, "ageDays": 2, "novelty": 1, "conflict": false}
    ]
  },
  "output": {"action": "defer", "depth": "gist"},
  "labelSource": "human",
  "labelConfidence": 0.95,
  "split": "train"
}
```

质量门：
- 双人独立标注；硬切片一致率 ≥95%，灰区 κ ≥0.7；不一致进入裁决，不直接取平均。
- 拒绝：JSON 非法、标签与规则冲突、无法解释、含 PII/raw detail/token、模板重复跨 split。
- 每条样本必须有 `templateFamily` 和 `domain`，否则无法做隔离划分。
- 训练/验证/held-out 的比例建议 80/10/10；验证集用于 early stop，held-out 只在最后看一次。

## 5. 训练方案

### 5.1 底座：Qwen2.5-0.5B-Instruct

**合适，但要区分“训练底座”和“推理成品”。**

- 训练底座：`Qwen/Qwen2.5-0.5B-Instruct` 的 fp16/bf16 safetensors。Apache-2.0、未 gated、
  有官方 GGUF，许可和分发路径清楚。
- 推理成品：合并 LoRA 后转 GGUF，再量化到 Q4_K_M。**不要直接训练 Q4 GGUF**。
  Q4 是推理量化格式；在 Q4 上做 LoRA 训练是非标准路径，量化和训练误差会叠加。
- 为什么不是 0.6B：Qwen3-0.6B 官方只有 Q8_0，W0.5 实测 p95 2.73 s、RSS 4.3 GiB，
  质量不优于 0.5B，性价比差。
- 为什么不是 1.5B/1.7B：零样本 p95 2.84/4.84 s，只能 async/assisted；SFT 不会让它们变快。
- 为什么不是 3B/4B：4B 已实测 p95 11.69 s；3B 许可（Qwen Research）阻断。参数更大
  不会自动进入 1.5 s。

**0.5B 的能力风险**：它的零样本 depth 只有 15.5%，说明“按 reasons 选 depth”对它并不容易。
SFT 可能把它拉到 80%+，也可能只学会“输出格式”而学不会策略。Stage-1 的容量探测就是
为了尽早回答这个问题，而不是等 8k 数据做完才发现。

### 5.2 LoRA / QLoRA / 全参

| 方案 | 是否推荐 | 理由 |
|---|---|---|
| **LoRA（fp16/bf16）** | **推荐** | 0.5B 只需 16 GB GPU；r=16、alpha=32、dropout=0.05，target 覆盖 q/k/v/o + gate/up/down；可训练参数约几 M–十几 M；合并/导出简单；适合快速迭代 |
| QLoRA（4-bit + LoRA） | 不推荐 | 0.5B 不需要省显存；bitsandbytes 依赖 CUDA，CPU/MPS 不可用；4-bit 量化误差会干扰“silent/depth”这种细决策；增加变量 |
| 全参 SFT | 不推荐（Stage-1） | 0.5B 全参在 16 GB 上勉强可行，但优化器状态/激活更重，易灾难性遗忘；没有证据表明全参比 LoRA 更适合这个 4 类任务；分发和复现也更重 |

LoRA 建议：
- `r=16`，`alpha=32`，`dropout=0.05`，`bias="none"`；
- target modules：`q_proj,k_proj,v_proj,o_proj,gate_proj,up_proj,down_proj`；
- 学习率 `1e-4–2e-4`，cosine，warmup 3%，weight decay 0.01；
- epoch 2–3，early stop on held-out loss + 切片指标；
- max seq 512（若 prompt 超长再评估 768）；batch 8–16，梯度累积到 effective 32；
- gradient checkpointing 开启；T4 用 fp16，A10/L4 用 bf16；
- 至少 2 个 seed（13/42），报告均值与极差；如果 seed 间 action 差 >3 pp，先查数据/训练稳定性。

### 5.3 训练目标与输出格式

训练样本的 assistant 输出只保留：

```json
{"action":"speak","depth":"gist"}
```

可选 `confidence` 字段，但只在产品确实消费它时保留；不要为了“看起来更可解释”生成
自由文本 `reason`。如果产品需要 reason，用规则/枚举短码（如 `high_relevance`、
`conflict`、`task_continue`）在推理后附加，不占生成 token。

`max_tokens=16`（含 JSON 括号/引号），严格 JSON schema/grammar。这样做的目的不是
“省 token”，而是把 p95 从 1.92 s 拉回 1.5 s 以内（§6.4）。

### 5.4 导出与量化

1. 合并 LoRA 到 fp16 safetensors；
2. 用 llama.cpp 官方 `convert_hf_to_gguf.py` 转 GGUF；
3. 量化到 `Q4_K_M`（与 W0.5 的 0.5B 成品一致，便于对比）；
4. 记录合并前/后、fp16/Q4 的 SHA-256 和大小；
5. **用 Q4 成品做最终评估**，不要用 fp16 成绩代替；量化可能让 silent/depth 掉几个点。
6. 如果 Q4 掉点超过 action 2 pp 或 silent 5 pp，先试 Q5_K_M/Q8_0；不要直接假设
   “Q4 没问题”。

## 6. 评估方案

### 6.1 复用 W0.5 harness

复用 `design/0.4-w05-bench@90a4575` 的：
- `tests/integration/model-bench/small-planner-bench.test.ts`：真实 llama.cpp、strict JSON、
  默认 skip、临时目录下载/校验；
- `tests/integration/model-bench/small-planner-golden-set.ts`：88 条固定标签，作为跨版本回归；
- 指标定义：action/depth/must_speak/novelty/conflict/silent/defer/JSON/p50/p95/timeout/RSS/disk。

需要新增的 **test-only** 能力（不在本设计里实现）：
- `MODEL_KIND=local-gguf` + `MODEL_PATH`：加载本地 SFT Q4 成品，不下载；
- `PROMPT_MODE=sft-short`：与训练一致的短 prompt，输出 schema 只有 action/depth；
- `HELDOUT_PATH`：外部 500–1,000 条 held-out，不提交仓库；
- `RULES=on/off`：同一批 case 上跑“纯模型”和“规则优先 hybrid”，分别报告；
- `MAX_TOKENS=16`：与产品候选一致。

对照必须同集、同 prompt、同硬件、同线程：
- heuristic（同集基线）；
- 0.5B zero-shot（已有 90a4575 数字，作为起点）；
- 0.5B SFT fp16 / Q4（本实验）；
- 1.7B Q8（质量上界/teacher 对照）；
- 4B 只有在单独批准资产后做 20–30 条核心子集，不默认重下。

### 6.2 指标

- **端到端 hybrid**：action、depth、must_speak、novelty 沉默、conflict detail、
  silent 特异度、defer、JSON、p50/p95、timeout、RSS。
- **灰区单模型**：action/depth、false-speak（该 silent 却 speak）、false-silent
  （该 speak 却 silent）、confidence ECE（若用 confidence）。
- **规则层**：硬规则命中率、误触发率（尤其 must_speak 被 silent）、规则覆盖的 turn 占比。
- **统计**：Wilson 95% CI；2 个 seed 的均值/极差；与 heuristic 用 paired bootstrap
  （同一批 case）比较，报告差值 CI，不只看绝对分数。

### 6.3 门槛

W0.5 定义的 `local-authoritative` 门槛（不是产品 SLA）：

| 指标 | 门槛 |
|---|---:|
| JSON 合法 | ≥99% |
| action 准确 | ≥90% |
| must_speak recall | ≥98% |
| novelty=0 沉默 | ≥90% |
| conflict detail | ≥80% |
| depth 准确（speak 期望） | ≥80% |
| silent 特异度 | ≥85% |
| defer 准确 | ≥70% |
| p95 | ≤1,500 ms |
| timeout | ≤1% |

本文追加两条“比基线有意义”的门槛：
- 灰区 action ≥ heuristic 同集 +5 pp，且 paired bootstrap 差值 95% CI 下界 >0；
- 硬规则切片（must_speak/novelty/conflict）相对 heuristic 不得回退 >1 pp；
  规则层本身应接近 100%，模型不得覆盖。

**Stage-1（2,500 条）用略宽的“学习信号”门槛，避免把数据不足误判为模型不行：**

| 指标 | Stage-1 通过 | Stage-2/产品候选 |
|---|---:|---:|
| action | ≥85% | ≥90% |
| depth | ≥80% | ≥85% |
| silent 特异度 | ≥85% | ≥85% |
| novelty 沉默 | ≥95%（规则层） | ≥95%（规则层） |
| conflict detail | ≥90%（规则层） | ≥95%（规则层） |
| defer | ≥70% | ≥70% |
| must_speak | ≥98% | ≥98% |
| JSON | ≥99% | ≥99% |
| p95 | ≤1,500 ms | ≤1,500 ms（stretch ≤1,000 ms） |
| 训练/验证差 | ≤8 pp | ≤5 pp |

Stage-1 的 85% action 不是产品门槛；它只回答“0.5B 有没有学会”。如果 Stage-1 只有
80–85%，可以扩到 8k 再试一次；低于 80% 或 silent 仍 <85%，直接停。

### 6.4 延迟：从 1.92 s 到 1.5 s 的可行路径

W0.5 的 0.5B 是 32 个 completion token（中位数）的零样本结果。对 115 次调用做线性拟合
（仅用于估算，R²≈0.50，残差 sd≈257 ms）：

```text
latency ≈ 111 ms + 37.6 ms × completion_tokens
```

按此估算，输出 12 token 时中位约 0.56 s，p95 约 0.9 s；16 token 时中位约 0.71 s，
p95 约 1.06 s。**这不是保证**，因为 prompt 长度、grammar、CPU 负载都会变；但它说明
“去掉 reason + 限制 max_tokens=16”是有依据的延迟优化，不是拍脑袋。

必须实测：
- 同一台 i7-8850H / 4 threads / 32k context / Q4_K_M；
- warm-up 后至少 115 次调用；
- 记录 p50/p95/min/max、timeout、completion token 分布；
- 如果 p95 仍 >1.5 s，先试 8–12 token / 更短 prompt / 更多线程；仍不行则 0.5B 在本机
  不满足同步预算，不能靠“换更大模型”解决。

### 6.5 通过/不通过矩阵

| 质量 | 延迟 | 结论 |
|---|---|---|
| 全过 | p95 ≤1.5 s | **GO Stage 2 / 产品 gate** |
| 全过 | p95 1.5–2.0 s | 只能 `local-assisted`/async；不宣称 authoritative；优化输出/硬件后再测 |
| silent/novelty 失败 | 任意 | 回到规则层；不要继续加数据超过 2 轮；0.5B 不适合独立 silent 判断 |
| action <85% | 任意 | NO-GO；0.5B 容量不足，不要直接上 1.5B 做同步 |
| depth <80% 但 action 好 | 任意 | 可考虑“只让模型选 depth，action 由规则”的降级方案；不是 authoritative |
| 任意 | p95 >2.0 s | 本机不可用；换硬件/异步；不靠缩小模型继续压 |

### 6.6 如果 0.5B 上限不足

按顺序，不要跳步：

1. **规则层吸收**：silent/novelty/conflict/defer 继续代码硬判；模型只保留 depth 或灰区
   action。这样即使模型一般，也不会破坏安全项。
2. **换任务形态**：如果灰区主要是表格特征（score/age/novelty/conflict/reasons），
   先用 GBDT/逻辑回归/小型分类器做基线。它可能比 0.5B 更准、更快、更可解释；
   不要因为“有 LLM”就跳过。
3. **1.5B Q4 LoRA 仅 async/assisted**：零样本 p95 2.84 s；SFT 不会显著降低推理成本。
   可以在后台预取/下一轮使用，但不能承诺 1.5 s 同步权威。
4. **放弃 local-authoritative**：0.4.0 用 heuristic + API/async；等有更强硬件或更小专用
   分类器再回来。不要为了“本地”牺牲介入正确性。

## 7. 风险

| 风险 | 可能性/影响 | 缓解 | 停止信号 |
|---|---|---|---|
| 2,500 条不足以超过 heuristic 82.95% action / 90.9% depth | 中高 / 高 | 分层 250/切片；500 held-out；Stage-2 扩到 8–12k；paired bootstrap | held-out 差值 CI 跨 0；action <85% |
| 过拟合 / 模板泄漏 | 高 / 高 | 按 templateFamily+domain 隔离；13-gram 去重；early stop；2 seeds | train-val gap >8 pp；held-out 明显低于 val |
| silent 学不会 | 高 / 高 | 类别平衡/加权；高分候选 + 寒暄硬负例；规则层兜底；2 轮标签迭代 | 两轮后 silent 特异度仍 <85% |
| novelty/conflict 被模型学坏 | 中 / 高 | 代码硬判，模型不接触；只评估 hybrid；规则层 100% 测试 | 任一硬规则切片回退 >1 pp |
| Q4 量化掉点 | 中 / 中 | 评估 Q4 成品；对比 fp16；备选 Q5/Q8 | action 掉 >2 pp 或 silent 掉 >5 pp |
| 许可/再分发 | 中 / 高 | 只用 Apache-2.0 底座/teacher；adapter 走 legal review；不打包权重 | teacher ToS 不允许蒸馏/再分发 |
| 训练产物进 repo | 中 / 高 | 外部 SFT_HOME；大文件/后缀阻断；只提交 manifest+hash | 分支出现 `.gguf/.safetensors/adapter_model` |
| 预算/工期 | 高 / 中 | Stage-0 先做；Stage-1 小预算；Stage-2 只在通过后 | 无 GPU 预算或无标注 owner |
| benchmark 污染 | 中 / 高 | 88 条只做回归；held-out 不公开；只提交 hash/聚合 | held-out 与训练集有近重复 |
| 硬件外推 | 高 / 中 | 只在同机同线程比较；Apple Silicon/Metal 另测 | 用 x64 数字宣称所有平台 |

### 7.1 2,500 条到底够不够超过 heuristic？

- **统计上**：如果真实 action 是 90%，500 条 held-out 的 95% CI 约 87.4–92.6%，
  下界高于 heuristic 82.95%，可以说“显著更好”。如果真实只有 85%，500 条的 CI 约
  81.9–88.1%，下界会压到 heuristic 附近，不能宣称更好。
- **depth 更难**：heuristic 90.9%，0.5B 零样本 15.5%。SFT 需要 +75 pp 才能接近；
  2,500 条可能只到 75–85%。这是本文最大的质量风险。
- **结论**：2,500 条足以做“有没有学习信号”的判断，不足以承诺“稳定超过 heuristic”。
  要承诺产品级优势，至少 8,000–12,000 条 + 1,000 held-out + 2–3 seeds。

### 7.2 许可与分发

- 底座 `Qwen/Qwen2.5-0.5B-Instruct`：Apache-2.0、未 gated；官方 GGUF Q4_K_M。
- Adapter：作为底座 derivatives，通常可在 Apache-2.0 下再分发，但必须保留 LICENSE/NOTICE、
  标注修改；**是否可再分发取决于训练数据与 teacher 的条款**。如果 teacher 是 API，
  先做 ToS/法务评审；不能默认“模型输出可以随便用于训练/再分发”。
- 训练数据：合成数据由项目拥有；真实 outcome 只保留事件元数据，不含 raw query/detail；
  不跨用户混用。
- 分发：基础模型和 adapter 都走“显式下载 + size/SHA-256 + license 展示”；
  **adapter 也不进 repo/npm/App/CI**。如果法务未放行，adapter 只能内部评估，不能发布。
- 如果只能“下载模型、不打包权重”，adapter 也应视为模型权重；不要把它 base64 进 JS
  或塞进 npm 包规避规则。

### 7.3 预算 / 工期 / GPU

以下为工程估算，Stage-1 必须实测校正：

| 阶段 | 人力 | GPU | 现金（按 $0.5–1/GPU-h） | 墙钟 |
|---|---|---|---|---|
| Stage 0 规则覆盖/数据 pilot | 2–4 人日 | 0 | 0 | 3–5 天 |
| Stage 1 2,500–3,000 条 | 标注 40–70 人时 + 复核 | 2–6 GPU-h（2 seeds + 评估） | $1–6 | 1–2 周 |
| Stage 2 8,000–12,000 条 | 标注 120–200 人时 + 复核 | 10–30 GPU-h | $5–30 | 2–4 周 |
| 产品打包/许可/下载/回滚 | 另立 W0.5 gate | — | — | 不在本估算 |

- 人力是主要成本，不是 GPU；如果没有标注 owner，直接 NO-GO。

## 8. 最小验证实验

### Stage 0 — 规则优先与灰区测量（无 GPU，必须先做）

**目的**：先证明“值得训模型”，而不是先训再看。

1. 在 88 条 + 300–500 条真实/合成 turn 上实现规则优先 hybrid 的 **test-only** 评估
   （不改产品代码；可以是独立脚本/测试，放在外部或 test-only）。
2. 统计：
   - 硬规则覆盖的 turn 占比；
   - 灰区占比；
   - heuristic 在灰区的 action/depth；
   - 需要模型处理的切片分布。
3. 如果灰区 <10%（硬规则覆盖 ≥90%）：**NO-GO 训练**，规则层 ROI 更高。
4. 如果灰区 10–20%：**条件 GO**，只在灰区误判代价高（false-silent/错误 depth 影响大）且
   标注成本可控时做 Stage 1；否则先做规则层。
5. 如果灰区 ≥20%：进入 Stage 1。
6. 同时做 200 条 pilot 标注，测双人一致率；一致率不达标先改 label guide，不急着训。

**产出**：`docs/quality/0.4.0-w0.5a-rule-coverage.json`（未来 MR）+
`docs/design/0.4.0-w0.5a-sft-feasibility.md` 的本节更新；**不训练**。

### Stage 1 — 2,500–3,000 条 LoRA 学习信号

**前置**：外部 GPU 已就绪；Stage 0 判定灰区 ≥20%（或 10–20% 且误判代价高）；
标注 owner 确认。

1. 按 §4.4 分层采 2,550 条（可微调），500 条 held-out 按模板/领域隔离。
2. 训练 `Qwen2.5-0.5B-Instruct` LoRA（§5.2），2 个 seed。
3. 合并 → GGUF → Q4_K_M；用 Q4 成品评估（§6）。
4. 同时跑两个 adapter：
   - **A：全策略容量探测**（含 must_speak/novelty/conflict/defer），回答“0.5B 能否学会 silent”；
   - **B：灰区产品候选**（只训灰区），回答“hybrid 是否超过 heuristic”。
5. 门槛：§6.3 Stage-1 表；全部通过才进入 Stage 2。
6. 产出：`manifest.json` + 聚合 `eval.json` + 文档；权重/adapter/数据留在外部目录。

**如果 Stage-1 失败**：
- silent/novelty 失败 → 停 0.5B 独立判断，转规则层；不要加数据硬堆。
- action <80% → 停；0.5B 容量不足，不要直接上 1.5B 同步。
- 只有 depth 好 → 考虑“模型只选 depth、action 由规则”的降级产品，不叫 authoritative。
- 延迟 >2 s → 本机不可用；换硬件/异步，不靠缩小模型继续压。

### Stage 2 — 8,000–12,000 条产品候选（可选）

**前置**：Stage-1 全 gate 通过；法务/许可预审通过；有产品级评估 owner。

1. 扩到 10,000 条左右，1,000 条 held-out，覆盖 6–8 个 domain、中英各半。
2. 3 个 seed；报告均值/极差；做学习曲线（2.5k/5k/10k）确认是否饱和。
3. 产品 gate：§6.3 产品列 + 许可/分发/下载/回滚/默认 pack 不变 + Console 数据变化确认
   （这些是 W0.5 产品 gate，不在本设计实现）。
4. 只有全部通过，才把 adapter/GGUF 作为独立模型包候选；仍不打包权重。

## 9. 明确的 GO / NO-GO

### GO（有条件）

**GO 到 Stage-1 最小实验**，当且仅当：
1. 有外部 NVIDIA 16 GB+ GPU（或同等 MPS 设备）和 2 台可复跑的评估机；
2. 有标注 owner，能交付 2,500–3,000 条分层标签 + 500 条隔离 held-out；
3. Stage 0 证明灰区 ≥20%，或 10–20% 且灰区误判代价高（否则规则层优先）；
4. 规则优先 hybrid 的 test-only harness 已能跑通；
5. 接受“Stage-1 失败就停”，不把失败解释成“数据还不够”。

### NO-GO（明确）

**NO-GO**：
1. 在本机训练 0.5B LoRA/SFT；
2. 在当前证据下直接产品化 0.5B adapter；
3. 用 1.7B/4B 做同步 authoritative；
4. 把 adapter/GGUF 提交到 repo/npm/App/CI；
5. 用 API teacher 训练并在未过法务前再分发 adapter；
6. 在 Stage-1 silent <85% 时继续堆 8k 数据“再试试”。

### 升级/放弃条件

- 0.5B 在 2,500 和 8,000 两轮后仍 silent <85%：**放弃 0.5B 独立 silent**，转规则层。
- 0.5B action <85% 且 depth <80%：**放弃同步 LLM planner**；考虑 GBDT/分类器或 API。
- 0.5B 质量过但 p95 >2 s：**放弃本机同步**；换硬件/异步，不换更大模型。
- 0.5B 只过 depth：**降级为 depth 选择器**，action 由规则；不宣称 local-authoritative。
- 任何硬规则切片回退：**立即回滚**，不进入下一阶段。

## 13. 附录：关键数字与推导

### A. W0.5 0.5B 延迟-输出长度拟合

对 115 次真实调用（completion tokens vs wall latency）做最小二乘：

```text
latency_ms ≈ 111 + 37.6 × completion_tokens
R² ≈ 0.50，残差 sd ≈ 257 ms
```

仅用于判断“缩短输出是否值得做”，不替代实测。12 token 估算：
中位 ~0.56 s，p95 ~0.9 s；16 token：中位 ~0.71 s，p95 ~1.06 s。
实际还要加 grammar/排队/CPU 抖动；以 §6.4 的复测为准。

### B. 置信区间粗算

- n=250，p=0.90：SE=√(0.9×0.1/250)=1.9%，95% CI ≈ ±3.7 pp；
- n=500：±2.6 pp；
- n=1,000：±1.9 pp。

因此：
- 250/切片只能判断“明显好/坏”；
- 500 held-out 能区分“90% vs 82.95%”这种大差值；
- 1,000 held-out 才能稳定谈 5 pp 级别差异。

### C. 为什么 2,500 不是产品量

2,500 / 10 个切片 = 250/切片；扣掉 10–20% 复核/丢弃，实际每切片可能只有 200–225。
这足够 Stage-1 看趋势，但不足以覆盖中英、6–8 个 domain、3–5 个 paraphrase 的交叉组合。
8,000–12,000 才能做到每切片 800+，并把 held-out 扩到 1,000。
