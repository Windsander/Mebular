## 1. 范围与硬边界

- 只做 host plan **session-prior 预取**：宿主在上一 turn 后生成，下一 turn `/context` 消费。
- `/context` 不等待宿主模型，也不发起新的宿主调用。
- TTL 60s；cue 主题/实体 Jaccard ≥0.6；当前 top-1 必须在 basis top-3；
  `follow_up` / `task_continue` / `correction` 豁免主题 Jaccard。
- 首轮、新 cue、过期、重放、非法、缺 host identity → `prefetched=false` + heuristic。
- `must_speak` / 显式 `defer` / conflict / greeting / meta / no_candidates 仍由 sidecar 硬规则决定。
- 不改 W0.5c defer/conflict/novelty、W1a effective mode、W2 local/API、公共 MCP 工具、
  graph/event/sync 格式、UI。
- 不读宿主私有 DB/session/log/spool/managed config；host plan 只由 adapter 显式上报。
- 确定性启发式不能冒充 `source=host`；只接受 `plannerKind=host-model`。

## 2. 统一信封

`packages/memory-runtime/src/sidecar/host-plan.ts`：

- `schema: 1`
- `planId`（`hp_...`，单次消费）
- `host`（`opencode|openchamber|dsh|hermes`）
- `hostInstanceId`、`agentId`、`threadId`（`hostInstanceId` 必须等于 `x-mebular-host-instance`）
- `scope`（`session|turn`）、`basedOnTurnId`、`forTurnId?`
- `cueSignature?`、`cueFingerprint[]`（token hash，最多 32）
- `basisCandidateFingerprint[]`（稳定候选 key hash，最多 3）
- `createdAt`、`expiresAt`（≤60s）
- `action`、`depth`、`confidence`、`reasonCode`（稳定枚举）
- `plannerKind`、`plannerVersion?`、`policyVersion?`

校验：

| 场景 | fallbackReason |
|---|---|
| 无 plan | `host_plan_missing` |
| 结构/枚举/置信度/TTL 结构非法 | `host_plan_invalid` |
| 过期 | `host_plan_expired` |
| host/agent/thread/hostInstanceId 不符；basis 不是 sidecar 记录的上一轮；缺 host identity | `host_plan_scope_mismatch` |
| cue Jaccard <0.6（非豁免） | `host_plan_cue_mismatch` |
| 当前 top-1 不在 basis top-3 | `host_plan_candidates_changed` |
| 同一 planId 再次出现 | `host_plan_replayed` |
| 确定性 planner | `host_plan_not_model` |
| 硬规则覆盖 host 决策 | `host_plan_overridden_by_hard_rule` |

Anti-replay 在完整校验前按 planId 标记；即使后续 cue/候选不匹配，planId 也不能再次使用。
`basisCandidateFingerprint` 使用稳定记录 ID hash，不使用每次召回随机生成的 `mf_*`，
并且**保留相关性顺序**：索引 0 是 top-1，不排序；`candidateMatchesBasis()` 只检查
`current[0]` 是否属于 basis top-3。

`hostApp` / `hostInstanceId` 只从 `x-mebular-host-app` / `x-mebular-host-instance`
header 读取；server 会删除 body 中同名伪造字段。缺 header 时 plan 一律
`host_plan_scope_mismatch`，不允许冒充。

`/context` 响应新增 `interventionMeta`（additive）：

- `source / resolvedSource / configuredSource / prefetched`
- `planId / planScope / cueMatched / cueJaccard / fallbackReason`
- `turnId / hostApp`
- `cueFingerprint[] / candidateFingerprint[]`（供 adapter 下一轮构造 basis）

## 3. 四宿主接线

| 宿主 | 生成 | 消费 | 身份 |
|---|---|---|---|
| OpenCode | `session.idle` / `execution.succeeded` 后 `ctx.session.generate` | 下一 `context` hook inline `hostPlan` + `previousTurnId` | `opencode` + 进程 `hostInstanceId` |
| OpenChamber | 同 OpenCode 插件 | 同 OpenCode | `MEBULAR_HOST_APP=openchamber` → `openchamber` + `hostInstanceId` |
| DSH | `session/event assistant/message` / `turn/end` 后在 `agent.runMaintenance` run scope 用 `ctx.llm` | 下一 `agent/pre-step` inline `hostPlan` | `dsh` + `hostInstanceId` |
| Hermes | companion `post_llm_call` 后台用 `ctx.llm`，写 adapter-owned `$HERMES_HOME/mebular-memory/hostplan/plan-*.json` | provider 下一 `prefetch` 读 plan 并 inline 到 `/context` | `hermes` + plan 的 `hostInstanceId` |

共同点：

- plan 只在 adapter 进程内（或 Hermes adapter-owned 目录）缓存；60s TTL，单次消费。
- 生成失败/超时/非法输出 → 不写 plan，下一 turn heuristic。
- 生成调用发生在上一 turn 结束后，不占用 `/context` 的交互预算。
- 只传 hash/枚举/统计；plan 文件与请求不含 raw query、assistant 正文、token。
- planner 隔离按消息而不是按 session 时间窗口：
  - OpenCode：generate 期间的 assistant/tool/execution 事件先排队；generate 返回后用输出
    hash / `assistantMessageID` 只丢弃 planner 消息，真实 user/assistant 事件重放并正常 ingest。
    重放前先 `settled=true`，重放期间新到的事件直接判定，不再入 pending。显式 `internal`
    标记的事件直接丢弃。`captureSessionContext()` 也按 planner prompt/output hash 与
    messageId 过滤 `ctx.session.context()`；planner record 尚未 settled（output 未返回）时
    只保留真实 user 消息，assistant/tool 暂不 ingest，避免 pending planner 文本污染。
  - DSH：planner 事件先排队，输出 hash / messageId / 显式 `internal` / `source.kind`
    命中才丢弃；真实 user/assistant/tool/checkpoint 事件重放，不因 planner 在途而被吞。
  - Hermes companion 有 reentrancy guard，`post_llm_call` 不会递归生成。
- 残余边界：若 OpenCode `ctx.session.generate` 超时且宿主已经回放了无法识别的 planner
  assistant 文本，排队事件会按真实事件重放；需要 W7 真宿主验证/更细粒度 host event ID。
- adapter 在 sidecar `configuredSource` 变化时主动清空 host plan/basis；Hermes provider
  还拒绝 `configuredSource!=host|auto` 的旧 plan，不只依赖 sidecar `lastContextTurns`。

## 4. Hermes 版本/隔离门禁

companion 注册 `post_llm_call` 前检查：

- Hermes `>= v0.21.6`；未知/更低版本 → 不注册，状态 `hermes_version_unsupported|hermes_version_unknown`。
- `plugins.isolation` 必须是 `in_process`（缺省视为 in_process）；显式 `host` → `hermes_isolation_unsupported`。
- `api_mode=codex_app_server` → `hermes_api_mode_unsupported`（不经过 `finalize_turn`，无 `post_llm_call`）。
- `ctx.llm` 缺失 → `ctx_llm_unavailable`。

provider 消费时再次校验版本/隔离/API mode；不支持则丢弃 plan 并 fallback heuristic。
`pre_llm_call` 在模型路由变化时删除旧 plan。

## 6. 残余风险（留 W7）

1. 真实 OpenCode / OpenChamber / DSH / Hermes 二进制 + 真实 sidecar + 真实模型的
   `R-RSM` 证据仍为 0；本会话只有 unit/hermetic/fake sidecar。
2. DSH 没有真实 CLI 的 hermetic E2E；本会话只做 fake host fixture，明确未 E2E。
3. OpenChamber 独立 App 多实例/session 隔离仍未证明；W3 只保证显式 identity header。
4. Hermes 版本/隔离探测依赖 `ctx` 暴露字段；真实 Hermes 需 W7 锁定 v0.21.6/v0.21.7。
5. OpenCode 不暴露模型 ID；模型切换仍只能靠 60s TTL + `modelSource` 失效。
6. 宿主模型生成质量（action/depth）未在本会话评测；W7 需真实模型非 fallback 证据。
7. `plannerKind=host-model` 的信任边界：sidecar 只能验证 host token、显式 header、
   plan 结构与绑定；无法密码学证明 adapter 真的调用了宿主模型。`host-adapter-deterministic`
   一律拒绝，真实调用仍需 W7 宿主 E2E/模型证据。
8. `interventionMeta` 只含 hash/枚举；既有 `RecallTrace.queryPreview` 仍保留 0.3 行为，
   本文不宣称 trace 完全无 raw 文本。
