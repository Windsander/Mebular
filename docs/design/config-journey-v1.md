# UX-2 · 配置旅程交互设计规格（v1）

> 状态：设计定稿（阶段 1+2）。配套：全量 HTML 原型 [`prototype/`](./prototype/README.md)、
> 接入契约 [`.opencode/skills/mebular-assistant-integration/SKILL.md`](../../.opencode/skills/mebular-assistant-integration/SKILL.md)。
> 目标：让「初始化 → 接入 → 验证 → 日常」全程便捷、诚实、无死交互。

本规格正面解决已定位硬伤（逐条对应第九节验收断言）：

| # | 硬伤 | 对策（落点章节） |
|---|---|---|
| ① | 支持列表写死 7 家，Hermes 查不到 | 助手=数据：注册表（内置+自定义），UI 禁写死（§3、§6） |

| ③ | OpenChamber 落面指错（应为 `~/.config/openchamber/opencode.managed.json`） | descriptor.config 声明式落面 + 格式适配器（§3.1；具体条目以 F-EXP-1 勘察为准，本规格留占位） |
| ④ | 未安装卡片收起、无动作、却给「接入」= 死交互 | 三态诚实 + 禁死卡片（§3.2、§5） |

| ⑥ | 无接入后验证闭环 | 验证器四步闭环（§3.3、§5.4） |

## 1. 旅程图

```
安装 App
  │
  ▼
[首启] 守护自检 ──缺守护──▶ ① 启动/装常驻（向导步骤①）
  │                              │ 失败 → 诊断与日志（自动展开+人话结论）
  ▼
引导态? ──是──▶ [初始化] 建新 / 加入（provision 页；桌面壳=一键重启，web=命令指引）
  │ 否                            │ 完成后待重启 → 重启 → 正常态
  ▼                               ▼
[接入] 连接 AI 助手（控制台连接页 / 向导步骤②）
  │   三态卡片 → 接入 → 回读校验 → CLI 验证 → 重启清单 → 重新验证 → 已接入✓已验证
  ▼
[扩展] 添加设备（邀请/加入；向导步骤③）
  │
  ▼
[日常] 直达控制台（完成态/跳过均持久）；托盘=守护控制；设置/诊断/关于本机=日常入口
       向导永不强挡路：随时「跳过」；事后随时可「返回向导」（回想入口）
```

## 2. 信息架构（归属判定）

| 面 | 职责 | 不承担 |
|---|---|---|
| **桌面壳**（托盘/窗口/生命周期） | 守护托管（启动/停止/重启）、常驻开关、登录启动、唯一真退出、窗口隐藏/重建 | 任何配置内容、任何助手细节 |
| **桌面向导**（壳内本地页） | 首启三步编排与进度（守护→助手→设备）、跳过/回想入口、诊断与日志 | 助手逐项操作（交给控制台连接页） |
| **控制台**（daemon 托管 web） | 一切配置内容：初始化（provision）、**连接 AI 助手**（三态卡片/新增助手/验证闭环）、设备邀请/加入、设置、诊断、关于本机 | 守护进程托管（只发意图，由壳/服务层执行） |

路由原则：**壳管守护，控制台管配置，向导只做编排与进度**。助手接入的唯一操作面 = 控制台连接页；向导②只做状态摘要 + 深链（`?view=connect`）+ 计数。

## 3. 核心模型

### 3.1 助手 = 数据（descriptor 注册表）

注册表 = 内置条目（随发布）∪ 自定义条目（`<home>/assistants.custom.json`，前端「新增助手」写入）。
schema 六要素见接入契约 §2：**probe（探测）/ landing（落面+格式适配器）/ writer（写入：命令/策略/备份）/ verify（验证：命令+判据）/ activation（生效语义）/ risks（风险注记）**。

- probe 多信号并集：`config-path` / `cli` / `app-bundle` / `process`，每条信号独立证伪；命中详情随状态上报。
- 落面以 F-EXP-1 实测为准（修硬伤③，真实值已入契约 §2.1/§2.2）：
  - **OpenChamber**：global `~/.config/opencode/opencode.json` 的 `mcp.servers.mebular`
    （`OPENCODE_CONFIG` 合并而非取代，global 会被读取）；**禁写** `~/.config/openchamber/opencode.managed.json`（App 私有会被重写）；
    生效 = 用户在 App 侧重载/重启（产品不得发 `opencode reload`）；验证 `opencode mcp list`（只读、勿频繁）。
  - **Hermes**：`~/.hermes/config.yaml` 的 `mcp_servers.mebular`；写入**必须**经
    `hermes config set --force`（保注释；无法 env 沙箱 → 字节级备份+失败回滚为硬要求）；
    **免重启**（新会话即用 / `/reload-mcp`）；验证黄金样例 `hermes mcp test mebular`（rc=0 + `✓ Connected` + `Tools discovered: N≥1`）。
- 实现注意（契约 §2.3）：疑似 schema 缺陷——现有产出 `mcp.<name>`，正确可能是 `mcp.servers.<name>`（以 `opencode mcp add` 产出为真源）；实现轮须沙箱对照 `opencode mcp list` 验证修正后才算完成。
- 格式适配器注册表内置：`opencode-json`、`hermes-yaml`、`json-mcpServers`、`toml`、`yaml`、`generic-snippet`（manual）。
- 生效语义分派：hot（Hermes）跳过重启清单；user-reload（OpenChamber）走重启清单。

### 3.2 客户端三态（诚实 + 判据与动作分离）

| 态 | 判据 | 主动作 | 失败恢复 |
|---|---|---|---|
| 未安装 | 全部 detect 信号阴性 | 「怎么装」（指引+链接） | 重新检测；「已装好？重新检测」；手动登记 |
| 已装·未接入 | ≥1 信号阳性 ∧ 配置面无 mebular 条目 | 「接入」（merge-key）/「查看片段」（manual） | 写入失败 → 原因+备份位置+手动流；重新检测 |
| 已接入 | 配置面有条目 ∧ 回读通过 | （收编态标「已接入 ✓」） | 验证/回滚/查看改动（次级） |

派生态（一等状态，有专属视觉与主动作）：
- **已写入·待重启**（黄）：主按钮「我已重启，重新验证」。
- **已写入·验证未过**（黄）：主按钮「重新验证」，次级「查看验证输出」「回滚」。
- **检测失败**（灰）：主按钮「重试检测」，次级「手动登记为已装」。

### 3.3 验证闭环（接入后必走）

`接入 → ① 回读校验（必有）→ ② CLI 验证（有 verify.cli 则必跑）→ ③ 重启清单 → ④ 重新验证 → 已接入✓已验证`。
任一步失败都落到具体失败态并给出下一步（§5.4 文案表）。「完成」只授予 ④ 通过之后。

## 4. 状态机规格

### 4.1 守护（桌面壳）

| 态 | 判据 | 主动作 | 失败恢复 |
|---|---|---|---|
| 缺失 | /healthz 不通 ∧ 端口未被占 | 「启动」 | 反复失败 → 诊断与日志（自动展开+人话结论） |
| child | 壳 spawn 子进程 ∧ /healthz 通 | （无）退出确认声明「将停止守护」 | 崩溃 → 托盘黄点 → 重启 |
| service | launchd 登记 ∧ /healthz 通 | （无）退出确认**不**提停守护 | `service status` 异常 → 「修复常驻」 |
| reused | 外部已跑 ∧ /healthz 通 | （无）退出确认**不**提停守护 | 提示外部实例来源 |

### 4.2 引导（向导）

步骤：① 启动 Mebular（含 provision 子态）→ ② 连接 AI 助手 → ③ 添加设备。

| 项 | 规格 |
|---|---|
| 步骤① done | `daemonHealthy ∧ !provisionRequired`（provision 子态给「建新/加入→」深链） |
| 步骤② done | `已验证接入数 ≥ 1`（**修硬伤⑤**：计数 = 已验证数/已装数，判据 = descriptor 三态机；不再 n/7） |
| 步骤③ done | 曾生成邀请（持久标记）∨ 已知对端 ≥ 1 |
| complete | 三步全 done ∨ `skipped`（持久）。complete → 启动直达控制台 |
| **跳过** | 任何时刻「跳过，直接进入控制台」（持久化，不弹确认） |
| **回想入口** | 控制台连接页「← 返回向导」+ 托盘「返回向导」（随时可回，状态实时） |
| 徽章 | 进行中「第 N/3 步 · <名称>」；完成「已就绪」 |

### 4.3 设备

| 态 | 判据 | 主动作 | 失败恢复 |
|---|---|---|---|
| 未邀未连 | 无邀请记录 ∧ 对端 0 | 「生成邀请」（loading 禁用「正在生成…」） | join 未启用 → 指路设置开启；失败给原因 |
| 已邀请 | 有持久邀请标记 | 「重新生成邀请」（二次确认） | — |
| 已连 | 对端 ≥ 1 | （收编） | 对端详情/断开（控制台设备卡） |

## 5. 每屏规格 + 文案表

文案原则：人话（无 409/nohup/ENOENT 黑话）；**空态/加载/错误/成功关闭**四态俱全；**无死按钮**。

### 5.1 初始化（provision 页）

| 元素 | 文案 |
|---|---|
| 页眉 | `首次上手 · 建新 / 加入 Mebular` |
| 空主指引 | `家目录为空：建新（本机是根）或加入已有 Mebular（用一次性令牌）。` |
| 待重启主指引（唯一） | `家目录已完成初始化（<home>）：重启后进入正常态。` |
| 桌面壳主动作 | `重启守护`（一键 IPC）；hint：`也可回到向导第①步点「重启守护」。` |
| web 主动作 | 命令 + `复制命令`；hint：`若已重启，点下方「已重启？刷新页面」。` |
| 成功关闭 | `已建新完成：按上方指引重启。` / `已加入完成：按上方指引重启。` |
| 错误 | `失败：<人话原因>`（409 重复 → 已完成态，不裸报错） |

### 5.2 向导页

| 元素 | 文案 |
|---|---|
| 顶栏 | `跳过，直接进入控制台` · `打开控制台` |
| 步骤① 未就绪 | `守护未就绪：点「启动」；想开机自启就点「让 Mebular 常驻」。` |
| 步骤① provision 子态 | `还差一步初始设置（数据都在本机）：` + 主按钮 `建新 / 加入 →` |
| 步骤① done（临时运行） | `守护运行中。当前是临时运行——关机后不自动拉起，可「让 Mebular 常驻」。` + 徽章 `临时运行` |
| 步骤② 摘要 | `已验证接入 n/m 家（m=已检测到的已装助手）`；未过① → `先完成第①步` |
| 步骤③ | `另一台设备装同一个 Mebular App，扫码（或粘贴令牌）即可加入。` |
| 日志区 | 默认折叠 `诊断与日志`；异常自动展开 + 一行结论 |
| 完成态 | 主按钮 `进入控制台 ✦`；三步卡折叠为回顾 |

### 5.3 连接页（控制台）

结构：常驻运行卡 → `＋ 新增助手`（一等按钮）→ 分组（已装可接入·默认展开 / 未安装·展开 / 需手动合并·收起；空组不渲染）。

| 元素 | 文案 |
|---|---|
| 分组标题 | `已装可接入（n）` / `未安装（n）` / `需手动合并（n）` |
| 卡片判据注脚 | `判据：配置 <path> 存在；CLI <cmd> 可用`（逐信号命中/未命中） |
| 未安装主按钮 | `怎么装` → 展开：安装命令/官网链接 + `我已装好，重新检测` + `手动登记为已装` |
| 已装未接主按钮 | `接入`（merge-key）/ `查看片段`（manual） |
| 已接入 | 态标 `已接入 ✓`（验证过后 `已接入 ✓ 已验证`） |
| overflow「更多」 | 查看改动 · 回滚（二次确认）· 安装 Skill · 复制片段 · 重新检测 |
| 检测失败卡 | `检测失败：<人话原因>` + `重试检测` + `手动登记为已装` |
| 加载 | `正在检测本机 AI 助手…` |
| 空（注册表空） | `还没有登记任何助手：点「＋ 新增助手」开始。` |

### 5.4 接入 → 验证闭环（卡片内联展开）

| 阶段 | 文案 |
|---|---|
| 写入中 | `正在写入（先自动备份）…`（按钮禁用） |
| 回读通过 | `已写入并回读确认（备份于 <file>.bak-<ts>）。` |
| CLI 验证中 | `正在验证：<cmd> …` |
| CLI 验证通过 | `验证通过：<cmd> 已看到 mebular。` |
| 需重启清单（仅 `user-reload`；`hot` 条目如 Hermes 跳过本步） | `最后一步：重载 <name>`（OpenChamber：在 App 侧重载/重启，产品不代发 `reload`）+ `① 完全退出该助手（退出进程，不是关窗口）② 重新打开 ③ 工具列表应出现 mebular` + 主按钮 `我已重载，重新验证` |
| 写入失败 | `没能写入：<人话原因>。原配置未动；可改用手动合并（给片段）。` + `查看片段` + `重试` |
| 验证失败 | `已写入，但验证未过：<摘要>。查看验证输出 / 回滚。` + `重新验证` |
| 完成关闭 | `已接入 ✓ 已验证`（收编，无后续强制动作） |

### 5.5 添加设备 / 日常 / 壳标注

- 邀请面板：QR + 文本令牌 + `复制令牌`；警告（回环端点）人话提示；已生成再点 → 二次确认。
- 日常入口：设置（常用/高级/诊断）+ 关于本机（含常驻服务文件路径）+ 托盘分组菜单。
- 壳行为（托盘/窗口/退出确认）无法在 HTML 演示 → 原型 `06-shell.html` 标注屏 + 本文 §4.1。

## 6. 「新增助手 / 自定义」流程规格

1. 入口：连接页 `＋ 新增助手`（一等按钮，常驻分组之上）。
2. 两步：**① 基本信息**（名称；id 自动派生可改，冲突报错）→ **② 登记方式**：
   - `选配置文件`：填/选路径 → 推断格式适配器（json/toml/yaml/snippet）→ 预览将写入的键位；
   - `粘贴片段`：粘入该助手期望的 MCP 片段 → 生成 `write.strategy=manual` 条目。
3. 可选：填验证命令（`verify.cli`）；不填 → 仅配置级验证并明示。
4. 保存 → 落 `<home>/assistants.custom.json` → 立即入三态机（按声明路径/CLI 检测）。
5. 自定义条目卡片带 `自定义` 标，可编辑/删除；删除不动已写入的目标配置（另给「回滚」）。
6. manual 条目「接入」= 片段 + 人话步骤 + `我已手动合并，重新检测`。

## 7. 视觉语言

一律复用 `mebular-console-design` 契约（深空蓝面板 + CRT 绿 token、系统字体栈、暗色唯一、
零运行时依赖）。原型直接使用该 token 集，避免「原型好看实现不像」。派生态用色：
待重启/验证未过 = 琥珀警示（既有 `--crt-tag-warn` 系），检测失败 = 灰（`--muted`）。

## 9. 可判别验收断言清单

实现/复核直接引用；每条可机器判别（A）或走查判别（M）。

**模型与检测**
- A-1 注册表驱动：`/admin/api/clients` 输出 = 内置 ∪ 自定义条目；前端无写死名单/数量（grep 无 `n/7` 式常量）。
- A-2 三态判据随状态上报：每条客户端含 `evidence`（逐信号命中/未命中 + 来源）。
- A-3 OpenChamber 落面 = global `~/.config/opencode/opencode.json` 的 `mcp.servers.mebular`；**禁写** `opencode.managed.json`（实现 grep 无该路径写入分支）；验证钩子 `opencode mcp list` 只读调用。
- A-4 配置文件不存在但 CLI 存在 → 判「已装·未接入」（不假阴性）；配置存在 CLI 不在 → 仍「已装」但 evidence 标明（不假阳性静默）。
- A-5 Hermes 内置条目：落面 `~/.hermes/config.yaml` 的 `mcp_servers.mebular`；写入仅经 `hermes config set --force`；写前字节级备份+失败回滚；验证 `hermes mcp test mebular` rc=0 ∧ 输出含 `✓ Connected` ∧ `Tools discovered: N≥1`；activation=hot（无重启清单步）。

**无死交互**
- A-6 未安装卡无「接入」按钮；主按钮恒为「怎么装」（DOM 断言）。
- A-7 任意态主按钮点击必有反馈（状态迁移或错误文案）；空分组不渲染。
- A-8 向导②计数 = 已验证数/已装数（分母≠注册表总数）。

**验证闭环**
- A-9 接入成功 → 回读校验必跑；`verify.cli` 存在 → CLI 验证必跑；结果入卡片态。
- A-10 「已写入·待重启」为一等态：主按钮 =「我已重启，重新验证」；点击后重跑回读+CLI。
- A-11 写入失败 → 原配置未动（备份存在）+ 给手动流入口；验证失败 → 黄态 + 输出摘要 + 回滚。

**自定义**
- A-12 「＋ 新增助手」登记（选文件/粘片段）→ `<home>/assistants.custom.json` 新增条目 → 列表即时出现并入三态机。
- A-13 manual 条目不出现自动写「接入」；「我已手动合并，重新检测」触发重判。

**引导与壳**
- A-14 完成/跳过持久：重启 App 直达控制台；「返回向导」随时可回（控制台连接页 + 托盘）。
