> 接入契约 [`.opencode/skills/mebular-assistant-integration/SKILL.md`](../../.opencode/skills/mebular-assistant-integration/SKILL.md)。

> 设置 IA 部分仍然有效。

| # | 硬伤 | 对策（落点章节） |
|---|---|---|
| ① | 支持列表写死 7 家，Hermes 查不到 | 助手=数据：注册表（内置+自定义），UI 禁写死（§3、§6） |

| ④ | 未安装卡片收起、无动作、却给「接入」= 死交互 | 三态诚实 + 禁死卡片（§3.2、§5） |

视图（域视图/审计/记忆/对端面板）**原样保留**，不在本规格范围（见 §5.6 红线）。

## 1. 旅程图

```
安装 App
  │
  ▼
[一屏引导]（星野舞台 + 里程碑轨道，永远只有一个主按钮，纯点击）
  │   ① 开始部署（启动本机守护 + 自动接入已装助手；按钮区原位展开子步骤流水；
  │      完成后进入锁定主控制台，建新 / 加入在顶栏弹框内同进程完成）
  │   ② 接入助手（只列已装；行级「已接入」不自动翻段；用户点「已完成」才翻段）
  │   邀请设备不进引导 —— 完成页提一句
  │   已设置过的机器 → 直达控制台（不出现引导）
  ▼
[日常] 控制台为家（首屏=看状态）；助手接入管理收进 设置 → AI 助手（单列表 + 行内闭环）；
       邀请设备、诊断、关于本机各归其位；完成/跳过均持久；回想入口 =「重启向导」（设置·常用 + 托盘）
```

设计原则（本轮修正确立）：**引导 = 一屏纯点击**，不分页、不要求阅读、不出现命令行；
未安装助手不进引导（引导只走 happy path + 一行式失败）；命令/路径只在「详情」里。

## 2. 信息架构（归属判定）

| 面 | 职责 | 不承担 |
|---|---|---|
| **桌面壳**（托盘/窗口/生命周期） | 守护托管（启动/停止/重启）、常驻开关、登录启动、唯一真退出、窗口隐藏/重建 | 任何配置内容、任何助手细节 |
| **一屏引导**（壳内本地页，首启一次性） | 单屏完成「开始部署 → 自动接入助手 → 进入锁定主控制台」；跳过/回想入口；启动失败子步骤定位+续跑 | 助手逐项管理（交给 设置 · AI 助手）、建新 / 加入忆云（交给控制台顶栏）、多页编排、任何命令行展示 |
| **控制台**（daemon 托管 web） | 一切配置内容：初始化（provision）、设备邀请/加入、设置（含 **AI 助手专区**：单列表接入管理/新增助手/验证闭环）、诊断、关于本机 | 守护进程托管（只发意图，由壳/服务层执行） |

路由原则：**壳管守护，控制台管配置，引导屏只做一次性编排**。助手接入的唯一操作面 = 控制台 **设置 → AI 助手**（专区）；引导段②是其精简视图；`?view=connect` 保留为别名并重定向到设置 · AI 助手。接入是低频任务，不占控制台一级页面（控制台首屏 = 看状态）。

## 3. 核心模型

### 3.1 助手 = 数据（descriptor 注册表）

注册表 = 内置条目（随发布）∪ 自定义条目（`<home>/assistants.custom.json`，前端「新增助手」写入）。
schema 六要素见接入契约 §2：**probe（探测）/ landing（落面+格式适配器）/ writer（写入：命令/策略/备份）/ verify（验证：命令+判据）/ activation（生效语义）/ risks（风险注记）**。

- probe 多信号并集：`config-path` / `cli` / `app-bundle` / `process`，每条信号独立证伪；命中详情随状态上报。
- 落面以 F-EXP-1 实测为准（修硬伤③，真实值已入契约 §2.1/§2.2）：
  - **OpenChamber**：global `~/.config/opencode/opencode.json` 的 `mcp.servers.mebular`
    （`OPENCODE_CONFIG` 合并而非取代，global 会被读取）；**禁写** `~/.config/openchamber/opencode.managed.json`（App 私有会被重写）；
    生效 = 用户在 App 侧重载/重启（产品不得发 `opencode reload`）；验证 `opencode mcp list`（只读、勿频繁）。
  - **Hermes**：`~/.hermes/config.yaml` 的 `mcp_servers.mebular`；写入**必须**经
    `hermes config set --force`（保注释；无法 env 沙箱 → 字节级备份+失败回滚为硬要求）；
    **免重启**（新会话即用 / `/reload-mcp`）；验证黄金样例 `hermes mcp test mebular`（rc=0 + `✓ Connected` + `Tools discovered: N≥1`）。
- 实现注意（契约 §2.3）：疑似 schema 缺陷——现有产出 `mcp.<name>`，正确可能是 `mcp.servers.<name>`（以 `opencode mcp add` 产出为真源）；实现轮须沙箱对照 `opencode mcp list` 验证修正后才算完成。
- 格式适配器注册表内置：`opencode-json`、`hermes-yaml`、`json-mcpServers`、`toml`、`yaml`、`generic-snippet`（manual）。
- 生效语义分派：hot（Hermes）跳过重启清单；user-reload（OpenChamber）走重启清单。

### 3.2 客户端三态（诚实 + 判据与动作分离）

| 态 | 判据 | 主动作 | 失败恢复 |
|---|---|---|---|
| 未安装 | 全部 detect 信号阴性 | 「怎么装」（指引+链接） | 重新检测；「已装好？重新检测」；手动登记 |
| 已装·未接入 | ≥1 信号阳性 ∧ 配置面无 mebular 条目 | 「接入」（merge-key）/「查看片段」（manual） | 写入失败 → 原因+备份位置+手动流；重新检测 |
| 已接入 | 配置面有条目 ∧ 回读通过 | （收编态标「已接入 ✓」） | 验证/回滚/查看改动（次级） |

派生态（一等状态，有专属视觉与主动作）：
- **已写入·待重启**（黄）：主按钮「我已重启，重新验证」。
- **已写入·验证未过**（黄）：主按钮「重新验证」，次级「查看验证输出」「回滚」。
- **配置已过期**（黄）：配置里的 Mebular URL 是旧 loopback 地址（端口/路径与当前 runtime `/mcp` 不一致；仅末尾 `/` 差异视为一致，stdio 条目不适用）→ runtime ready 后**自动 reconcile** 到当前端点（幂等、只改 Mebular 入口）；自动自愈失败时才显示该状态，主按钮「自动修复」作显式兜底。用户自定义的非 loopback 远端 URL 不自动覆盖，显示「需要修复/请确认」。
- **检测失败**（灰）：主按钮「重试检测」，次级「手动登记为已装」。

### 3.3 验证闭环（接入后必走）

`接入 → ① 回读校验（必有）→ ② CLI 验证（有 verify.cli 则必跑）→ ③ 重启清单 → ④ 重新验证 → 已接入✓已验证`。
任一步失败都落到具体失败态并给出下一步（§5.4 文案表）。「完成」只授予 ④ 通过之后。

## 4. 状态机规格

### 4.1 守护（桌面壳）

| 态 | 判据 | 主动作 | 失败恢复 |
|---|---|---|---|
| 缺失 | /healthz 不通 ∧ 端口未被占 | 「启动」 | 反复失败 → 诊断与日志（自动展开+人话结论） |
| child | 壳 spawn 子进程 ∧ /healthz 通 | （无）退出确认声明「将停止守护」 | 崩溃 → 托盘黄点 → 重启 |
| service | launchd 登记 ∧ /healthz 通 | （无）退出确认**不**提停守护 | `service status` 异常 → 「修复常驻」 |
| reused | 外部已跑 ∧ /healthz 通 | （无）退出确认**不**提停守护 | 提示外部实例来源 |

### 4.2 引导（一屏引导）

单屏两段里程碑：① 开始部署（启动本机守护 + 自动接入已装助手 + 进入锁定主控制台）→ ② 接入助手（自动接入结果确认；失败可在控制台重试）。
邀请设备**不进引导**，完成页提一句即可（首启邀请低频）。建新 / 加入忆云不在向导里完成，而是进入锁定主控制台后由顶栏两个入口完成。

| 项 | 规格 |
|---|---|
| 段① 交互 | 点「开始部署」后按钮区**原位展开实时子步骤流水**（✓启动本机守护 → ✓接入 AI 助手 → 进入控制台）；建新 / 加入由控制台顶栏弹框完成（同一守护进程、同一页面，不重启、不刷新）；失败**定位到具体子步骤**并给「从此处续跑」，不是笼统重试 |
| 段① done | `daemonHealthy`（UNINITIALIZED 是正常引导阶段，不阻塞；建新 / 加入交给控制台锁定壳） |
| 段② 交互 | 行级接入：点「接入」→ 行内「已接入 ✓」（**不自动翻段**）；段尾 `[已完成]`（≥1 已接入才可用）+ `先不接 ›`；用户点「已完成」才翻段——接几个由用户定 |
| 段② 诚实口径 | 行级只承诺「已接入」；段内一行注脚 `重载对应助手后生效（可到控制台验证）`；完成页对已接未重载的助手给一条提醒（不把「待生效」藏掉） |
| 段② 空态 | 0 个已装助手 → `没检测到已装的 AI 助手——可以先跳过，装好后再到控制台接`；「已完成」不渲染，只留 `先不接 ›` |
| 段② done | 用户点「已完成」（≥1 已接入）∨「先不接 ›」 |
| complete | 两段全 done ∨ `skipped`（持久）。complete → 启动直达控制台（已设置过的机器首启即直达，不出现引导） |
| **done 段可回** | 完成段折叠为一行回顾，**点回顾行可重新展开**（再接一个 / 查看刚才做了什么） |
| **跳过** | 右下常驻「跳过引导 ›」（整局跳过，持久化）；段②「先不接 ›」（只跳过该段）——两处文案不混用 |
| **回想入口** | 改名「**重启向导**」（重走首次设置，不动已有配置）：放在 **设置 · 常用区** + 托盘菜单（随时可回，状态实时）；不放 AI 助手区 |
| 失败 | 仅段①可失败 → 流水中定位 + 「从此处续跑」（日志摘要入详情） |
| 完成页 | `已就绪 ✦` + `进入控制台` + 一句 `之后想接更多助手、邀请其他设备，都在控制台里`；有未重载助手时加一行提醒 |
| 状态模型 | 设计稿只定义交互与状态展示；真实状态订阅/重连恢复的实现模型**留 chief 会话定夺**（不预设定时器/轮询方案） |

### 4.3 设备

| 态 | 判据 | 主动作 | 失败恢复 |
|---|---|---|---|
| 未邀未连 | 无邀请记录 ∧ 对端 0 | 「生成邀请」（loading 禁用「正在生成…」） | join 未启用 → 指路设置开启；失败给原因 |
| 已邀请 | 有持久邀请标记 | 「重新生成邀请」（二次确认） | — |
| 已连 | 对端 ≥ 1 | （收编） | 对端详情/断开（控制台设备卡） |

## 5. 每屏规格 + 文案表

文案原则：人话（无 409/nohup/ENOENT 黑话）；**空态/加载/错误/成功关闭**四态俱全；**无死按钮**。

### 5.1 一屏引导（首启唯一屏）

结构：星野舞台（稀疏缓慢，不抢戏）→ 品牌区（✦ / MEBULAR / 一句 tagline）→ 里程碑轨道
（左轨线 + 节点灯：当前=呼吸、完成=✓、未到=暗）→ **两段**面板（当前段展开，完成段折叠为一行回顾、
点回顾行可重新展开，未到段置灰不可点）→ 完成时刻「已就绪 ✦」+ 发光主按钮。右下常驻「跳过引导 ›」。

| 元素 | 文案 |
|---|---|
| tagline（进行中） | `点两下，把它接进你的日常。` → 段①后 `很好，再接一个助手就完成。` → 完成 `全部就绪。` |
| 段① 标题/正文 | `开始` / `在这台机器上启动 Mebular。数据只存在这台机器上，不上云。` |
| 段① 主按钮 | `开始部署`（启动本机守护 + 自动接入已装助手，然后进入锁定主控制台；建新 / 加入在控制台顶栏完成） |
| 段① 流水（点击后原位展开） | `✓ 启动本机守护` → `✓ 接入 AI 助手` → `进入控制台` |
| 段① 失败（子步骤定位） | 失败步骤打 `✗` + 主按钮 `从此处续跑`；日志摘要入详情 |
| 段① 完成回顾行 | `✓ 已就绪 · 守护已启动` |
| 段② 标题/正文 | `连接你的 AI 助手` / `检测到 n 个已装助手。点「接入」；都接好了点「已完成」。`（**未装不出现**） |
| 段② 助手行 | 名称 + `接入`（点击→行内 `接入中…`→`已接入 ✓`；**不自动翻段**） |
| 段② 注脚 | `接入只改它的一条配置；重载对应助手后生效（可到控制台验证）。` |
| 段② 段尾 | `[已完成]`（≥1 已接入才可用；未满 hint `接好一个即可点「已完成」`，满后 `还可以继续接其他助手`）+ `先不接 ›` |
| 段② 空态 | `没检测到已装的 AI 助手 —— 可以先跳过，装好后再到控制台「连接 AI 助手」。`（不渲染「已完成」） |
| 段② 完成回顾行 | `✓ 已接好 <名称> · 重载对应助手后生效` / 跳过：`— 已跳过 · 随时可以在控制台接` |
| 完成时刻 | `已就绪 ✦` + `进入控制台` + `之后想接更多助手、邀请其他设备，都在控制台里。`；有未重载助手时加一行 `提醒：重载 <名称> 后，mebular 才会出现在它的工具列表。` |
| 已设置过（直达变体） | `欢迎回来 · 这台机器已经设置好，Mebular 正在后台运行。` + `进入控制台` |

### 5.3 设置 · AI 助手（日常唯一操作面）

归属：接入是低频任务 → 收进设置，新开「AI 助手」专区（与常用/高级/诊断并列）。
结构：设置侧栏 → 专区页头（标题 + `＋ 新增助手`）→ 一句注脚 → **单列表**（与引导同语言，
不分组）→ 底部 `未安装（n）›` 折叠行。常驻运行卡**移出**（归设置 · 常用）。

| 元素 | 文案 |
|---|---|
| 注脚 | `接入只改助手的一条配置，写前自动备份；重载对应助手后生效。` |
| 行 | 名称 + 状态词 + **一个**动作（与引导段②同语言）；判据/路径/CLI/生效语义一律收进行内「详情」（默认收起） |
| 状态词 | `未安装` / `未接入` / `待生效` / `验证未过` / `检测失败` / `需手动` / `已接入 ✓`（S-1/S-2 合并后） |
| 排序 | 需处理优先（未接入/验证未过/待生效/检测失败在前），已接入在后 |
| 未接入动作 | `接入`（merge-key/cli-set）/ `查看片段`（manual） |
| 已接入动作 | `详情 ›`（查看改动 · 回滚（二次确认）· 复制片段 · 重新检测） |
| 失败态（一行式，行内展开） | 一行话 + 一个行动（如 `验证未过：没找到 mebular 工具` + `重新验证`）；输出/回滚/备份位置入详情 |
| 未安装 | 底部折叠行 `未安装（n）›`；展开后每行动作 `怎么装 ›`（安装指引 · 重新检测 · 手动登记入详情） |
| 加载 | `正在检测本机 AI 助手…` |
| 空（注册表空） | `还没有登记任何助手：点「＋ 新增助手」开始。` |
| 回想入口 | 不在此区；「重启向导」在设置 · 常用区（§4.2） |

### 5.4 接入 → 验证闭环（行内展开）

| 阶段 | 文案（一行式：一行话 + 一个行动；完整输出进「详情」） |
|---|---|
| 写入中 | `正在写入（先自动备份）…`（按钮禁用） |
| 回读通过 | `已写入并确认没动其他内容，正在验证…` |
| CLI 验证通过 | （不停留，直接进生效语义对应态） |
| 待生效（仅 `user-reload`） | `已接好，在 App 侧重载 <name> 后生效` + 主按钮 `我已重载，重新验证`；checklist 与「不代发 reload」说明入详情 |
| 写入失败 | `没能写入：<人话原因>，原配置没动` + `查看片段`；备份位置/重试入详情 |
| 验证失败 | `验证未过：没找到 mebular 工具` + `重新验证`；原始输出/回滚入详情 |
| 完成关闭 | `已接入 ✓`（收编，无后续强制动作；验证痕迹入详情） |

### 5.5 添加设备（邀请）

单动作页：**一个主按钮 → 结果**，与引导同语言。

| 态 | 文案 |
|---|---|
| 未邀未连 | `另一台设备装同一个 App，扫码（或粘贴令牌）即入。令牌一次性、15 分钟有效。` + 主按钮 `生成邀请`（loading `正在生成…` 禁用） |

| 已连 | 一行 `✓ <对端> 已加入` 收编；`再邀请一台 ›` 折叠（点开才见生成按钮）；已知对端列表在同页上方 |
| 加入服务未启用 | 一行 `加入服务还没启用，先去设置里打开` + `去设置开启`（→ 设置 · 常用） |

## 6. 「新增助手 / 自定义」流程规格

1. 入口：设置 · AI 助手 页头 `＋ 新增助手`（一等按钮）。
2. 两步：**① 基本信息**（名称；id 自动派生可改，冲突报错）→ **② 登记方式**：
   - `选配置文件`：填/选路径 → 推断格式适配器（json/toml/yaml/snippet）→ 预览将写入的键位；
   - `粘贴片段`：粘入该助手期望的 MCP 片段 → 生成 `write.strategy=manual` 条目。
3. 可选：填验证命令（`verify.cli`）；不填 → 仅配置级验证并明示。
4. 保存 → 落 `<home>/assistants.custom.json` → 立即入三态机（按声明路径/CLI 检测）。
5. 自定义条目行带 `自定义` 标（详情内），可编辑/删除；删除不动已写入的目标配置（另给「回滚」）。
6. manual 条目「接入」= 片段 + 人话步骤 + `我已手动合并，重新检测`。

### 8.1 评审脚手架 vs 产品界面（防再犯）

原型 = **产品界面** + **评审脚手架**，两者必须在视觉上明确区隔，禁止混淆：

- **评审脚手架**（页面导航、场景切换、覆盖说明）：统一收进顶部灰色「评审工具」条
  （灰底、虚线分隔、小字号、带「评审工具」标签）。它不属于产品，视觉上一眼可辨。
- **产品界面内零批注**：设计解释（为什么三态/为什么禁写）、覆盖率说明、「要点」框
  一律只留在规格文档，不进产品区域；「原型假数据」等标注只允许出现在评审工具条。
- 判据/路径/CLI/术语是**产品真实需要的详情**，收进行/卡「详情」折叠（默认收起），
  不作为正文平铺；正文 = 名称 + 状态词 + 一个动作。

### 8.2 简化建议（状态/信息合并裁掉，非挪位置）

- S-1 「检测失败」不单独成态：并入「未安装」，一行提示 + 「重试检测」（减少态数，
  判据细节进详情）。
- S-2 「已接入」与「已接入已验证」合并为一态「已接入 ✓」；验证痕迹（命令、备份位置）
  收进详情，避免两个观感相同的收编态。
- S-3 常驻卡平铺四操作 → 状态行 + 按状态唯一主操作（未常驻→「让 Mebular 常驻」）；

- S-4 「手动登记为已装」从卡片表面撤下，只留在详情（低频自救路径，不值得占主层）。
- S-5 连接页顶部「接入只会合并…」说明段删除：写入保障在接入流程的反馈里体现，
  不靠前置阅读。
- S-6 引导三屏（provision 页 + 三步向导）合并为**一屏引导**：启动 + 自动接入合并为
  「开始部署」一次点击，随后进入锁定主控制台；建新 / 加入在控制台顶栏完成（同进程、不重启、
  不刷新）；未装助手不进引导；邀请降级为可选段；命令行细节全部出屏（本轮已采纳为 §4.2/§5.1）。

## 9. 可判别验收断言清单

实现/复核直接引用；每条可机器判别（A）或走查判别（M）。

**模型与检测**
- A-1 注册表驱动：`/admin/api/clients` 输出 = 内置 ∪ 自定义条目；前端无写死名单/数量（grep 无 `n/7` 式常量）。
- A-2 三态判据随状态上报：每条客户端含 `evidence`（逐信号命中/未命中 + 来源）。
- A-3 OpenChamber 落面 = global `~/.config/opencode/opencode.json` 的 `mcp.servers.mebular`；**禁写** `opencode.managed.json`（实现 grep 无该路径写入分支）；验证钩子 `opencode mcp list` 只读调用。
- A-4 配置文件不存在但 CLI 存在 → 判「已装·未接入」（不假阴性）；配置存在 CLI 不在 → 仍「已装」但 evidence 标明（不假阳性静默）。
- A-5 Hermes 内置条目：落面 `~/.hermes/config.yaml` 的 `mcp_servers.mebular`；写入仅经 `hermes config set --force`；写前字节级备份+失败回滚；验证 `hermes mcp test mebular` rc=0 ∧ 输出含 `✓ Connected` ∧ `Tools discovered: N≥1`；activation=hot（无重启清单步）。
- A-20 旧 loopback MCP URL（如 56007）在 runtime ready 后自动 reconcile 到当前 `mcpUrl`（幂等、只改 Mebular 入口、保留其他 MCP servers/配置、不 force Skill）；用户自定义非 loopback 远端 URL 不自动覆盖，状态为「需要修复/请确认」；手动「自动修复」仅作显式兜底。

**无死交互**
- A-6 未安装卡无「接入」按钮；主按钮恒为「怎么装」（DOM 断言）。
- A-7 任意态主按钮点击必有反馈（状态迁移或错误文案）；空分组不渲染。
- A-8 引导段②只列已检测到的已装助手（未装不出现）；无 n/N 计数上屏。

**验证闭环**
- A-9 接入成功 → 回读校验必跑；`verify.cli` 存在 → CLI 验证必跑；结果入行态。
- A-10 「已写入·待重启」为一等态：主按钮 =「我已重启，重新验证」；点击后重跑回读+CLI。
- A-11 写入失败 → 原配置未动（备份存在）+ 给手动流入口；验证失败 → 黄态 + 输出摘要 + 回滚。

**自定义**
- A-12 「＋ 新增助手」登记（选文件/粘片段）→ `<home>/assistants.custom.json` 新增条目 → 列表即时出现并入三态机。
- A-13 manual 条目不出现自动写「接入」；「我已手动合并，重新检测」触发重判。

**引导与壳**
- A-14 完成/跳过持久：重启 App 直达控制台；「重启向导」随时可回（设置 · 常用区 + 托盘）。
- A-15 引导全程一屏：无分页、无命令行展示；段①「开始部署」内部串行完成 启动→自动接入→进入锁定主控制台（桌面壳无终端命令）；建新 / 加入在控制台顶栏弹框完成（同进程、不重启、不刷新）；命令行启动场景的重启指引不入引导屏（属控制台 provision 兜底页）。
- A-16 守护四态退出确认口径正确（仅 child 提「将停止守护」）。

**勘察事实（F-EXP-1）**
- A-17 schema 缺陷修复：写入产出键位 = `mcp.servers.<name>`（非 `mcp.<name>`）；实现轮沙箱对照 `opencode mcp list` 通过后才允许宣布接入完成。
- A-18 探针/验证输出卫生：日志、错误摘要、诊断包不回显凭据值（只打印变量名/键名）。
- A-19 OpenChamber 生效路径 = 用户在 App 侧重载/重启；实现 grep 无 `opencode reload` 调用。
