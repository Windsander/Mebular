# UX-2 全量 HTML 交互原型

零依赖、零构建、假数据；**双击 `index.html`（file://）即可点**，无需起服务。
对应规格：[`../config-journey-v1.md`](../config-journey-v1.md)；视觉 token 直接复用控制台契约。

**批注边界**（规格 §8.1）：每页顶部灰色「评审工具」条 = 评审脚手架（页面导航 + 场景切换），
不是产品界面；产品界面内零批注，判据/路径/CLI 一律收进卡片「详情」折叠。

## 页面

| 页 | 覆盖 |
|---|---|
| `index.html` | 总览 + 旅程图 + 推荐路线（评审页） |
| `01-setup.html` | **一屏引导**（核心）：星野舞台 + 里程碑轨道，永远只有一个主按钮：一键开始（启动+建新/加入）→ 接入助手（接好一个即可）→ 可选邀请 → 已就绪 ✦；场景：启动失败（一行提示+重试）/ 已设置过·直达控制台 |
| `03-connect.html` | 连接助手（日常操作面）：三态卡片（名称+状态词+一个主按钮，判据入详情）、＋新增助手全流程、接入→验证→待生效→重新验证→已接入 ✓；场景条覆盖**检测失败 / 写入失败 / 验证失败 / 需重启未重启**（一行式） |
| `04-device.html` | 邀请：生成（loading 禁用）→ 二次确认再生 → 已连收编；加入服务未启用指路 |
| `05-daily.html` | 日常入口：完成态直达控制台，设置/诊断/关于本机 |
| `06-shell.html` | 壳行为标注屏（评审页）：托盘分组菜单 / 关窗=隐藏 / 退出确认口径 / 单实例 |

## 推荐路线

1. `01`（多停一会）：点「一键开始」→ 给 OpenChamber 点「接入」→「生成邀请」或「跳过 ›」→「已就绪 ✦」；评审条切「启动失败」「已设置过·直达」各看一眼。
2. `03`：日常再进连接页的场景——三态卡片、四个失败场景（评审条）、「＋ 新增助手」登记流；展开卡片「详情」看判据与次级动作。
3. `04`：生成邀请 → 重新生成的二次确认。
4. `05`/`06`：日常与壳行为（标注）。
