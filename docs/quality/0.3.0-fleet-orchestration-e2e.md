## 3. P6 硬化项

| 项 | 处理 |
|---|---|
| `finalizeOlderVersions` 旧 root 悬挂 | 旧版本缺失 root 会补建并写 `SUPERSEDED_BY:<newVersion>`；无 MR 的旧版本同时清理 |
| 旧 MR 与当前版本进度 | pending 等待不撤销；done 收敛旧/当前 root done；failed/acceptance failed 保留失败证据，不重试 |
| pending MR cancel | 明确取消该 MR（`CANCELLED`）；terminal done MR 永不撤销；root 已终态 `already-terminal` |
| 并发 MR 竞态 | 确定性 taskId/eventId + 同进程串行 + 跨进程 eventId 去重；新增并发 materializer 测试 |
| 角色卡旧卡/远端旧卡 | embedded、daemon、DaemonRoleCardStore 读时统一重建 `summary` |
| provenance/agent 自由文本 | `agent` 与 `provenance.source/generator` 只接受安全 token；拒绝空白/路径/引号/原文 |
| `generateRoleCards` summaries | 直接传入的 summary 必须带本机 `device`；无 device/异设备不参与证据与意图 |
| `plan.example` join/reduce | 补齐 `to`，保证协议合法且运行时可执行 |
| G3 assigned why | `task_status.plan` 对已物化 step additive 返回确定性 route `why`，不改变状态 |
| G1/G2 边界说明 | RUNBOOK 增补 root sentinel、daemon verified peers、旧版本/MR/cancel 收敛与限制 |

## 4. 兼容性与边界

- **MCP**：`TASK_TOOLS` 仍 16 项；名称、必填字段未变；无 `plan_*`/`agent_card_*`/`role_card_*`。
- **UI**：无新导航/页面/设置/Advanced/Fleet/任务面板；plan/card/role 默认隐藏。
- **旧端**：旧 worker 只执行普通 task，跳过 `__plan__` root；旧 config 仍通过 `validateFleetConfig`；旧 peer 不认识 plan/card 节点类型时按内部记忆忽略。
- **线格式**：无新 TaskEvent 类型/字段；plan/card 是 internal 记忆节点，不是 task 事件。
- **隐私**：角色卡只存安全标签/证据 ID/摘要；不存 intent/对话原文、command、env 或凭据。

## 5. 已知限制 / 非阻塞风险

1. 五节点 embedded E2E 使用进程内 `InMemoryHub` loopback + 确定性 event bridge（任务事件按 eventId 幂等复制到各 device store），以隔离 anti-entropy 调度抖动并专注编排正确性。真实 libp2p 证据仅 `verify:fleet:tasks`（2 节点）与 `verify:daemon:cluster`（双守护 2 节点）；`routing-e2e` 同样使用 `InMemoryHub`，不作为真实 libp2p 证据。本报告不声称真实 3+ 节点 plan E2E 或 5 节点真实 WAN 性能；该项作为发布前已知限制保留到 P7 审核。
2. daemon 远端卡片验证依赖 `/app/peers` 中**当前在线**的已认证 peer 公钥；peer 离线或旧守护无该端点时，远端 route/显式 `to` fail-closed（不伪造通过）。
3. 本期没有 leader 选举/开放抢单；owner 设备是唯一正常 coordinator，不要让两台设备同时对同一 plan 运行 `coordinateForeignPlans`。
4. `plan.example.json` 的 join/reduce 步骤必须带 `to` 或 `route`；协议合法不等于运行时可执行。
5. 角色卡生产软排序仍未启用；`roleCards.enabled=true` 仍是内部/测试配置，需真实 shadow 报告与 P7 审核。
