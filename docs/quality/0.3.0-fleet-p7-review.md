## B1-R 最终 planAgent 必须是真实配置 Agent

| 场景 | 期望 | 证据 |
|---|---|---|
| 默认 MCP plan（无 ctx.agent，agents=[worker]） | owner=board 归一化为 worker；MR 到 worker；root done | `tests/fleet/p7-blockers.test.ts` |
| `defaultAgent="ghost-agent"`（agents 只有 worker） | 配置校验失败；plan/root 不写 | `validateFleetConfig` 负例 + p7-blockers 配置拒绝测试 |
| `ctx.agent="ghost-agent"` | `PLAN_POLICY` + `PLAN_OWNER_UNEXECUTABLE`；plan/root 不写 | `tests/fleet/p7-blockers.test.ts` |
| 非 board ghost owner + ghost planAgent | 拒绝；plan/root 不写 | `tests/fleet/p7-blockers.test.ts` |
| 普通 task 无 ctx.agent | `from.agent` 仍为 `board`（旧语义不变） | `tests/fleet/p7-blockers.test.ts` |
| `defaultAgent` 不在 agents 中 | `validateFleetConfig` 返回错误 | `tests/fleet/capability-cards.test.ts` |

规则：`planAgent = ctx.agent ?? config.defaultAgent ?? config.agents[0]?.name ?? "board"`；最终值必须是 `config.agents[].name` 之一。`board` 只有在 config 真有 board 时才允许。sub-plan 仍需宿主注入与父 step `to.agent` 一致的 `ctx.agent`；默认配置不会自动对齐。

## 测试边界（P7）

`tests/fleet/p7-blockers.test.ts` 是 **handler 级** E2E：直接调用 `TASK_TOOLS` 的 `task_submit` handler，使用真实 Mebular、任务/plan store、materializer 和 worker；它验证默认 plan owner 归一化与 MR 执行，但不经过真实 MCP stdio/HTTP transport。

真实 MCP transport 的默认 plan E2E 未在本轮新增，作为 P7 证据限制记录；真实 MCP stdio/HTTP 工具注册与调用仍由 `tests/fleet/surface.test.ts`、`tests/mcp/task-tools-live-app.test.mjs` 和既有 MCP 套件覆盖。若 P7 复审要求 transport 级默认 plan，可作为补充证据另开步骤，不改变本修复的 handler 契约。
