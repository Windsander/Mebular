## 4. 产品缺陷与修复状态

### D1. DSH 注入写入 durable session history（C6b 冻结为平台限制）

- **现象**：`session.v4.jsonl` 出现 `type="user/message"`，`data.source.kind="mebular-memory"`，正文为完整 `<mebular_memory ...>` 块。
- **影响**：注入进入 DSH 的持久会话日志；刷新/重放/后续 turn 都可能把它当作历史消息。UI 当前不渲染成用户气泡，但契约要求「不写 session history」。
- **证据**：`dsh-session-history.txt`；`dsh-context.html`（DOM 无该块，说明只是日志/模型历史泄漏，不是 UI 气泡）。
- **建议**：DSH 适配器改用不落 session log 的 context 通道；若 DSH 没有该通道，应在宿主能力里显式标记 `injection_channel_unsupported`，不要写入 `user/message`。

### D2. 无命中轮次仍携带上一轮注入（C6b 已修复）

- **现象**：无命中 turn 的完整模型请求 `messages` 中仍有上一条 `source.kind=mebular-memory`；来源序列为 `["user","mebular-memory","model","user"]`。
- **影响**：sidecar 已经沉默（`no_hits`、`injected=[]`），但模型仍看到旧记忆，可能把旧偏好当成当前上下文；「无命中沉默」只在注入层成立，在模型上下文层不成立。
- **证据**：`dsh-llm-requests.json` 中无命中 turn 的 request；`dsh-silence.txt`。
- **建议**：注入消息不能进入后续 request 的 `messages`；每 turn 重新构造，或用 DSH 的临时 context 字段。

### D3. OpenCode 修正后旧值仍与新值同块召回（C6c 已修复，C6d 旅程验证）

- **原现象**：写入 7331 后，模型请求的同一 `<mebular_memory>` 块同时包含 7332 和 7331。
- **修复**：C6c `a9e66bf` 实现记录级 `supersedes`：写新事实时结束旧记录 `validTo`、写 `supersedes` 边与 `metadata.supersededBy`；召回默认排除被替代记录。
- **C6d 验证**：旅程的旧值/新值改为同一 `subject/predicate` 的 fact，显式 `supersedes` 后模型请求只含 7331；默认 query 不再返回 7332。
- **证据**：`opencode-recall.json` 的 `new.request`、`supersede.currentQuery`。

### D4. 没有 `validTo` / `SUPERSEDES` 修正语义（C6c 已修复，C6d 旅程验证）

- **原现象**：capability `/update` 拒绝 `patch.validTo`；没有 `SUPERSEDES` 边，旧记录仍是当前事实。
- **修复**：C6c 支持受控 `validTo` 更新与 `/write supersedes`；旧记录保留内容与详情，默认 query/召回排除，`includeHistory` 可读。
- **C6d 验证**：`includeHistory` 返回旧记录且 `validTo > 0`、`supersededBy = 新记录 id`；旧详情 `7332` 仍可读；新记录 7331 为当前事实。
- **证据**：`opencode-recall.json` 的 `supersede.history`、`supersede.oldDetail`、`supersede.newCurrent`。

### 附加观察（C6b 已修复）

1. **同会话热切换不回溯隐藏工具**：C6b 已修复；旅程中同会话热切换后 model tools 立即隐藏 `memory_*`，新会话同样隐藏。
2. **详情展开一次混入 assistant raw chunk**：C6b 已修复；recall 详情按 `role=user` 优先选择，旅程断言 expand 只返回用户原话。

## 5. 未覆盖边界

1. **无真实 LLM**：DSH 使用测试用确定性 adapter；OpenCode 使用 fake OpenAI-compatible provider；Hermes 不启动 LLM。模型是否遵守 `trust=untrusted` 不在此验收。
2. **DSH 不是真实 DeepSeek 账号/模型**：真实 DSH Web/插件/session 生命周期是真实的，但 provider 是测试 adapter；没有远程模型/网络。
3. **P2P 传输是 `InMemoryHub`**：真实 `P2PNode` 认证、`SyncManager`、事件/墓碑/详情同步语义是真的；mDNS 是内存总线，未验证真实 LAN/WAN/libp2p。
4. **Hermes 未启动真实 gateway**：使用仓库同款 `agent.memory_provider` stub 与真实插件方法；未验证真实 Hermes 多 profile 进程隔离。
5. **OpenCode 无图形 UI 证据**：CLI/TUI 环境使用 outgoing model request + sidecar trace + 删除响应 + 文件 hash；未验证 OpenCode Desktop/OpenChamber Desktop 的视觉呈现。
6. **DSH checkpoint 由真实 compaction seam 的 probe 触发**：不是真实模型压缩；checkpoint 的 schema 2、sidecar 持久化、跨设备读取是真实的。
7. **跨 Agent `agent:dsh` 详情**：按 D09 设计，Hermes actor 不能读 DSH 的 agent 私有域；跨设备详情用 `user` 域验证。若产品希望 Hermes 展开 DSH 的 agent 私有详情，需要先定义授权，而不是放开读取。
8. **Console 截图使用 seeded admin 数据**：不是用户真实 home；控件与文案断言是真实 DOM。
9. **截图无 DSH injection 行**：DSH 当前 UI 没有 context injection 面板，因此以「DOM 无泄漏 + 真实 model request」为证据；这符合「无感」，但无法提供契约 §5.5 建议的 injection 行截图。
10. **未验证 10k 详情性能/配额淘汰**：本旅程只验证跨设备同步、展开、删除和失败开放。
