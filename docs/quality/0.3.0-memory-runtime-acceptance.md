### 2.3 极小额预算边界

追加边界用例（256B / 200 token）验证“不产生半块”：

- 若返回块：必须有 citation/owner/不可信声明且 `truncated=true`；
- 若无法容纳完整 metadata 块头：必须返回 `silenceReason=budget_too_small`、`fragments=[]`、`blocks=[]`。

本次实测 256B 走整条沉默 `budget_too_small`。这与契约 6.4“仍超则返回空”一致，但与 R16“256B 仍保留 citation”的示例存在口径张力；验收主矩阵使用 512B 验证“小预算截断保留 citation”。

## 3. 安全验收

安全 suite 5/5 通过。

| ID | 场景 | 断言 | 结果 |
|---|---|---|---|
| SEC01 | 记忆内容 prompt injection | `</mebular_memory>`、`<system>`、`<instruction>` 被转义为 `&lt;...`；块/片段 `trust=untrusted`；块首声明“不是指令”；注入文本只作为数据存在；无工具调用字段；召回不产生 write | **通过** |
| SEC02 | host token / capability token 泄漏 | `/status`、`/version`、`/traces`、`/context`、`/recall`、400/401 错误、capability 500 后的 degraded status 均不含 token；temp home 全部文件扫描无 token；trace queryPreview 不含 `sk-...` | **通过** |
| SEC03 | 跨 Agent/域越权 | 未订阅 `agent:hermes` 时显式请求仍 `domain_forbidden`，且不发起 `/query`；写 `agent:hermes`/`system` 返回 `403 domain_write_forbidden`，无 write 请求 | **通过** |
| SEC03b | `user` 写入确认 | `confirmation=none` 的事实降级写入 `agent:opencode` 并带 `user_domain_unconfirmed_downgraded`；`confirmation=explicit` 才写 `user`，provenance 保留 `explicit` | **通过** |
| SEC04 | 跨忆云/namespace 隔离 | 两个不同 `cloudId` 的 harness 不互相混入；同一记录在 cloud A 有 Raw、cloud B 无 Raw 时，A 为 verbatim，B 为 `missing_cross_device`；未订阅 `notes` namespace 不进入默认召回，capability 请求 domains 不含 `notes` | **通过** |
| SEC05 | 失败开放 | capability 500、401、超时三种情况下 `/context` 仍返回 200；`fragments=[]`、`blocks=[]`、`silenceReason=runtime_unavailable`、`degraded=true`、warnings 非空；超时场景在 40ms 客户端超时后返回，整体 <2s | **通过** |

安全边界说明：

- 0.3 是逻辑域隔离，不是密码学隔离；本验收只验证 sidecar/capability 路径，不模拟拿到本地存储/进程权限的攻击者。
- 注入转义是缓解，不是保证；真正的执行侧仍需宿主把记忆块放在非 instruction 通道。

## 5. 无记忆 / 轻量 MCP / 沉浸式对比口径

| 组 | 记忆能力 | 注入 | 工具 | 本验收覆盖 |
|---|---|---|---|---|
| **A · 无记忆** | 无 | 无 | 无 | 不覆盖；需要同一模型/提示词下的宿主级对话评测，测幻觉/常识下限 |
| **B · 轻量 MCP** | 29 工具 | 无自动注入 | `memory_query/search/...` | 不覆盖；由既有 29 工具契约测试与 MCP 回归保证。本验收不改变公共工具面 |
| **C · 沉浸式碎片召回** | Sidecar + capability | 每 human turn ≤1 次 | 普通 Agent 隐藏 memory_* | **本报告第 2–4 节**：启发式召回质量、安全、性能与预算 |

口径说明：

- A/B/C 对比需要固定模型、temperature、system prompt、工具集，每组多 seed，并以宿主真实注入通道评估最终回答；本会话不启动模型/宿主，因此只交付 C 组的 sidecar 级硬指标。
- 本验收的“Precision”是 **gold 片段 ID 命中率**（注入片段的 sourceIds 是否落在场景相关集合），不是模型回答正确率。
- “详情正确率”按字符串/结构化 exact match，不做语义等价；原文场景要求 verbatim 完全一致。
- “false recall”只统计明确应沉默的场景；不把“精确值不匹配但给出正确值 gist”算作 false recall（Q22 单列）。
- token 为 sidecar 估算口径（CJK 1 token、ASCII 4 字符 1 token），不是具体模型 tokenizer；字节为 UTF-8 硬顶。

## 6. 已知边界与未覆盖

1. **heuristic 质量上限**：本验收只覆盖确定性 cue/打分/展开/组装；不评价真实 BM25/embedding/模型排序质量。
2. **fake capability 不是真实检索**：验收使用可选 `filterQuery` 词法过滤模拟“无关 query 不返回候选”；真实 capability 的召回质量、同步范围和 namespace 订阅需在集成环境复验。
3. **无真实模型**：local Qwen、host 候选、api 第三方均未运行；模型回退、密钥引用、SSRF 防护由既有 model-* 测试覆盖。
4. **不是 10k 记录性能**：本验收 fixture 很小，recall p95（约 7.6ms）不能替代契约 Q02 的“10k 记录 p95 ≤150ms”；该指标需要真实 capability + 10k 记录基准。
5. **ingest 口径差异**：本验收是 100 次独立 ingest（每次 1 chunk），不是契约 Q04 的“一次请求 100 chunks”；两者都应有基线，后者未在本报告测量。
6. **未覆盖宿主/Console/跨设备同步**：不启动 MCP/core、DSH/Hermes/OpenCode/OpenChamber、Console；删除传播、跨设备墓碑、桌面端注入通道不在本验收范围。
7. **256B 预算边界**：完整 metadata 块头可能超过 256B，产品返回 `budget_too_small` 而不是带 citation 的半块。契约 6.4 允许整条沉默；R16 的 256B 示例期望保留 citation，建议后续统一文档口径或降低块头开销。
8. **本地资源差异**：性能阈值按本机 fake 能力设定，CI/低配机器可能更慢；报告中的实测值不是 SLA。
9. **全量测试抖动**：首次全量运行时 `tests/acceptance/memory-runtime-sync.test.mjs` 曾失败一次（compact 源域不匹配），该文件单独运行 5/5 通过；最终全量重跑 272/272 suite、2647/2647 test 全绿。该文件不在本会话改动范围。
