## 4. 本次修复的阻断项

真实 smoke 第一次运行发现两个产品问题；本次一并修复并复测通过。

### 4.1 官方引擎归档的 symlink 链

**原问题**：`EngineInstaller` 拒绝所有 symlink/hardlink，官方 macOS arm64 归档含 18 个相对符号链接，产品路径在解压阶段失败。

**修复**：

- 允许 symlink 目标为归档内相对路径；
- 解析后必须仍在 `archiveRoot` 内；
- 允许 symlink → symlink → 普通文件的链；
- 拒绝绝对路径、`..` 逃逸、目录链接、硬链接、悬空链接和环；
- 解压分两遍：先写目录/普通文件，再创建 symlink；不支持 symlink 的文件系统降级为复制已校验目标；
- 新增测试覆盖：同根相对 symlink、链、悬空、逃逸、环、硬链接。

### 4.2 Qwen3 thinking 耗尽 query plan 预算

**原问题**：`planQuery` 固定 `maxTokens: 160`，Qwen3 默认 thinking 返回 `finish_reason=length`、`content=""`、`reasoning_content` 710 字符，provider 判定 `model_invalid_response`。

**修复**：

- 本地结构化推理显式发送 `chat_template_kwargs.enable_thinking=false`；
- `planQuery` 预算从 160 提升到 512，给结构化输出留余量；
- 远程 API 不发送该字段，避免不兼容；
- 新增测试断言本地请求关闭 thinking 且预算 ≥512。

### 4.3 引擎下载重试

**原问题**：引擎下载遇到瞬时 `fetch failed` 会直接失败；模型下载有重试，引擎没有。

**修复**：

- `EngineInstaller` 支持 `maxDownloadAttempts`（默认 2）与 `retryDelayMs`（默认 500ms）；
- 只重试可重试的下载/HTTP 错误；校验失败、大小不匹配和取消不重试；
- 新增测试覆盖“首次失败、第二次成功”。

## 5. 剩余风险与未覆盖

### 5.1 只验证 Qwen3-4B / macOS arm64

未下载/运行 8B、14B、30B-A3B；不能据此推断更大模型的速度、内存或输出稳定性。
Linux/Windows 引擎归档布局未验证；Windows zip 的 symlink/目录布局仍需真实 CI/机器 smoke。

### 5.2 产品默认 `fetch` 的 HF 吞吐

本机 50 MiB Range 探测：全局 `fetch`（undici）约 **1.5 MiB/s**；`node:https` / `curl` 约 **18–24 MiB/s**。
本次 smoke 用 `node:https` 测试 transport 才在 30 分钟预算内完成 2.5 GB 下载。
这不是 mock：字节、sha256、安装都是真实的；但产品默认 transport 的性能需要在真实网络/多地区复测。若确认是 undici 与 HF CDN 的交互问题，建议评估专用下载 transport 或镜像回退。

### 5.3 模型输出非确定

`extract` 得到 5 个候选、summary 126 字符、query 50 字符是本次观测，不是固定期望。
测试只断言结构化成功与非空字段；真实模型输出会随版本/量化/采样变化。

### 5.4 未覆盖完整宿主/UI 路径

本 smoke 覆盖 sidecar 的模型供应 primitives 与 `InferenceProvider`，不覆盖：

- MCP capability / 29 公共工具；
- Console 模型下载 UI / 自动启用；
- DSH / Hermes / OpenCode 宿主注入；
- 跨设备同步与忆云沉降。

这些由 C6/C8f 及最终 C10 门禁覆盖。

### 5.5 大文件不进入仓库

`.gguf`、llama.cpp 归档、解压后的二进制均不进入仓库；证据 JSON 只有哈希、大小、耗时、计数和稳定错误码，无 token、绝对路径或模型响应原文。
