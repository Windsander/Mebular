## 1. 结论

- 统一执行层 `BaseExecutor` + `ExecutorAdapter` 已落地；`command` / `hermes` / `openchamber` / `dsh` / `opencode` / `claude-code` 共用并发、超时、AbortSignal、env 白名单、输出截断与错误归一。
- **fresh-session 不变量已落地**：所有 first-class adapter 声明 `sessionMode='fresh'`；`baseArgs` / `promptArgs` 在配置与 registry 两条路径拒绝 `--continue` / `--resume` / `--session` / `--fork` / `-r` 等 resume 参数。
- DSH/OpenCode/Claude Code adapter 已实现；`fleet quickstart` / `fleet join` 会自动探测本机 CLI。
- OpenChamber 已切换为**公开 runner**（`@mebular/opencode-plugin/fleet-runner`），每次任务新开 session；私有 `oc-hermes-bridge` / `HttpOpenChamberSeam` / `OPENCHAMBER-SEAM.md` 已从 Fleet 移除。
- `executable`（boolean）、`executionMode`（`cli|http|json-rpc|in-process`）、可选 `health` 已进入 Agent 目录、能力卡、route 硬过滤与 `task_targets`。
- plan owner/MR 守卫已收紧：`echo`、`board`、无 `command` 的 `command` 不能作为 owner/MR；`fleet doctor` 会报告 `plan owner 就绪` 与 `defaultAgent`。
- 代码与测试通过；OpenChamber runner 已在真实 OpenCode 宿主完成 E2E，真实 OpenChamber Desktop UI、DSH/Claude/Hermes 宿主任务仍未覆盖，见 §4。

## 2. 复跑结果

环境：macOS arm64，Node.js `v26.8.1`；证据机 `opencode` 为 `v2.0.29`，`dsh` 与 `claude` 未安装，`hermes` 在 PATH。

| 检查 | 命令 | 结果 |
|---|---|---|
| Fleet Jest | `node --experimental-vm-modules node_modules/jest/bin/jest.js tests/fleet --runInBand` | **54 suites / 438 tests passed** |
| OpenChamber runner 真实宿主 E2E | `npm run verify:openchamber:runner` | **25 passed / 0 failed / 1 skipped** |
| 全量覆盖率 | `node --experimental-vm-modules node_modules/jest/bin/jest.js --coverage --maxWorkers=2` | **300 suites / 3064 tests passed** |
| P6 五节点 + 双守护 | `npm run verify:fleet:p6` | **21/21** |
| 双守护集群 | `npm run verify:daemon:cluster` | **6/6** |
| Surface parity | `npm run check:surface-parity` | **11/11** |
| 任务面 | `npm run verify:fleet:tasks` | **10/10** |
| 上车 | `npm run verify:fleet:onboard` | **16/16** |
| Agent E2E（fake executor） | `npm run verify:fleet:agents` | **9/9** |

复跑说明：首次全量 `tests/fleet` 有一次 2 个同步/卡片时序用例失败（`routing-e2e`、`capability-cards-sync`）；两者单独运行均通过，随后全量复跑为 55/55、423/423。该抖动记录在此，不把“单次全绿”写成“从未失败”。WS-C（`feat/fleet-openchamber-cleanup`）删除私有 bridge 测试后复跑为 54/54、438/438。WS-D 后本机默认并行覆盖率在系统高负载（load average ~20）下出现无关的 DSH/MCP/sync 时序失败；同一 SHA 以 `--maxWorkers=2` 复跑为 300/300 suites、3064/3064 tests 全绿。该差异是测试机资源争用，不是产品行为变化；CI 使用独立 runner，仍以 PR 的 coverage job 为准。本文件其余 0.3.0/0.3.2 历史结论不因此改写。

## 4. 真实 / fake 边界（不夸大）

| 宿主 | 当前证据 | 尚未完成 |
|---|---|---|
| **DSH** | fake CLI adapter 测试通过；`dsh --version` health 路径由 fake 覆盖 | 本机未安装 `dsh`；**真实 DSH 任务 smoke 待补** |
| **OpenCode** | 本机 `opencode v2.0.29` 的 `--version` health 已验证；真实 `opencode serve` 宿主 + runner E2E 通过（fake model） | **真实 `opencode run` Fleet 任务 smoke 待补** |
| **Claude Code** | fake CLI adapter 测试通过 | 本机未安装 `claude`；**真实 Claude Code 任务 smoke 待补** |
| **Hermes** | 内置 adapter 与既有 9/9 `verify:fleet:agents`（fake executor） | 本轮未跑真实 Hermes 任务；不要把这 9/9 写成真实 Hermes E2E |
| **OpenChamber** | 真实 `opencode serve`（OpenChamber 使用的 plugin 宿主）+ 真实 `fleet-runner` + 真实 Fleet HTTP adapter；新 session、sentinel 不变、协议负例、token 不出日志均通过；fake OpenAI 模型。runner 默认关闭，未启用时 fail-closed | **OpenChamber Desktop UI 未验证**；本报告不把 OpenCode 宿主 E2E 写成 Desktop E2E |

网络边界：

- P6 五节点 plan E2E 使用进程内 `InMemoryHub` + 确定性 event bridge；**不是真实 3+ 节点 libp2p plan E2E**。
- 真实 libp2p 证据仍只有 `verify:fleet:tasks`（2 节点）与 `verify:daemon:cluster`（双守护 2 节点）。
- 本报告不声称真实 WAN 性能、真实 5 节点 plan E2E 或真实 DSH/Claude 宿主 E2E。
