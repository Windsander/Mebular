## 1. How to read this matrix

- Counts are from actual runs on the final integrated line after merging `origin/main`
  `325b006` and including the close fix `266d4d4`; the portability test commit `25d839a`
  only adjusts Windows/CI test guards. Every release gate must still be rerun on the final
  release candidate.
- Historical v0.3.0 results are not reused as v0.3.2 evidence. Host counts are fresh for
  this line; they are not copied from the 0.3.0 acceptance report.
- Real, fake and stub boundaries are part of the result. A green unit suite is not a real
  host, real model, real scale or upgrade result.
- **Pass** means the listed checks actually ran. **Pass with boundary** means they ran but
  the stated environment or scope limit prevents a general claim. **Pending** means not run
  or not completed; it must not be rendered as passed.

### 2.1 Final rerun and coverage contention

The recorded full-suite result is 307 suites / 3,388 tests (1 skipped), 0 failed, from
`npm test -- --runInBand` on the final integrated line with `origin/main` `325b006` and
close fix `266d4d4`; `25d839a` only adjusts Windows/CI test guards. This supersedes the
earlier docs-worktree rerun note.

`npm run test:coverage -- --runInBand` reproduced the final 307 suites / 3,388 tests and
reported statements 89.16% / branches 77.92% / functions 90.26% / lines 92.20%. An earlier
coverage run with Jest's default parallel workers ended with six timeouts (including a CLI
`degraded` case and ingest/perf timeouts); these were resource contention in that parallel
run, not product failures. The sidecar-only coverage run passed 27 suites / 327 tests with
statements 78.31% / branches 68.61% / functions 83.13% / lines 81.87%.

The four host E2E suites all exited 0: DSH 115, Hermes 57, OpenCode 41 and OpenCode
checkpoint recovery 32. The OpenCode host gate used a temporary-HOME `opencode v2.2.0`
installed with the official V2 installer because the machine default is 2.0.29, below the
plugin requirement of `>=2.2.0`; the gate ran through PATH and the user environment was not
changed.

## 5. Evidence hygiene

- No test artifact in this matrix contains tokens, keys, message bodies or a real user
  home path.
- Scale and upgrade artifacts use temporary homes and report cleanup/residual PIDs.
- The model canary keeps both the successful JSON and the failed network JSON; the failed
  download is preserved, not rewritten. The success JSON has no git field, so the
  product-code SHA `277a838` is recorded from the run context and is not injected into the
  JSON. Model files and llama.cpp archives are not committed.
- The 1k benchmark is explicitly a smoke. The 10k run passed on `c37e74b`; the original
  `7386495` failure (10,023/10,000) remains in the scale report and preserved failure JSON
  and is not rewritten. The historical 0.3.0 reports keep their original SHA, host/model
  boundaries and counts.
