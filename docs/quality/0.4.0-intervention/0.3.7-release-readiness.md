## 4. 延后与发布门禁

| 项 | 本版状态 | 说明 |
|---|---|---|
| 真实 API provider | **deferred** | 无真实 `baseUrl` / `model` / `keyRef`，未提取任何凭据；本版不以模拟 API 代替 |
| DSH 真实宿主 | gate | 本机无可用真实 DSH CLI，未跑真实宿主 E2E |
| Hermes 真实宿主 | gate | 隔离 `hermes chat` 未在时限内返回；未跑受控真实 companion/provider |
| OpenChamber Desktop | gate | 未启动 Desktop 宿主；内置 CLI 版本低于插件最低要求 |
| 真实 host 模型 | gate | host 两轮仍是确定性 fake plan，未提升到 `R-RSM` |

以上任一项都不能用仓库内 hermetic/fixture/unit 测试替代；替代结果只能标 `unit_only`，
不能标真实通过。**API 真测延后不等于通过**，发布记录不得写成“API 已验证”。

### 4.1 `maxMcpVersion` 收回为 `0.3.x`（final review blocking 已修）

- 评审结论：`maxMcpVersion=0.4.x` 与 0.3.7 发布口径不一致，是唯一 blocking。总控决定
  回退到 `0.3.x` 上界，不保留未验证的 0.4 forward-compat 窗口。
- 代码改动：
  `packages/memory-runtime/src/sidecar/config.ts` 的 `SIDECAR_MAX_MCP_VERSION` 与
  `packages/mcp/src/memory-runtime-supervisor.mjs` 的两处 discovery fallback（`0.4.x`
  → `0.3.x`）。
- 语义：0.3.7 sidecar 只接受 `0.3.x` MCP（`minMcpVersion=0.3.0`，
  `maxMcpVersion=0.3.x`）。`0.3.7` 被接受，`0.4.0` / `0.4.9` 被拒绝并返回
  `version_incompatible`。握手内容本身仍没有 wire/schema 变化。
- 测试/夹具同步：`config.test.ts` 的断言改为「0.3.7 接受 / 0.4.0、0.4.9 拒绝」，
  supervisor、sidecar server/main、opencode plugin、host-e2e 与 MCP fake-sidecar 的
  `maxMcpVersion` 夹具统一为 `0.3.x`；仓库中不再有“`0.4.x` accepted”的断言。
