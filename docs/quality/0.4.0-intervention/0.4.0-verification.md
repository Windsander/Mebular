## 3. B1 修复前后

B1 缺陷：真实 OpenCode 插件在 `rememberInjected()` 中把 `/context` 返回的**所有 fragments**都加入 `alreadyInjectedIds`，而不是只加入实际渲染/注入的片段。结果是第二轮同 cue 召回时 sidecar 把所有候选标成 `filteredReason=already_injected`，local/host planner 无法消费。

修复（`7874163` + `a9937c3`）：

1. 插件 `rememberInjected()` 只记录实际渲染进 request context 的 blocks；
2. sidecar 在 enforced `/context` 下把完整 eligible 窗口交给 planner（`promoteFreshForPlanner`），最终注入再按新鲜候选/预算/冲突规则选择，避免旧高分已注入候选挤掉新鲜候选。

| 场景 | B1 前（`3bbd284`） | B1 后（merge `96629f12`） |
|---|---|---|
| OpenCode local 两轮 | 14/16；`local-hit` fail；后续轮 `already_injected` | **16/16**；`prefetched=true`、`model` speak、注入新鲜片段 |
| OpenCode host 两轮 | 13/16；`host-hit`/`host-hit-source`/`host-new-cue` fail | **16/16**；`host-plan:v1`、`applied.speak`、注入新鲜片段 |
| OpenChamber local 两轮 | `blocked_product` | **16/16**（adapter identity，`R-RSM`） |
| OpenChamber host 两轮 | `blocked_product` | **16/16**（adapter identity，`RH+RS+FM`） |
| sidecar 本地模型直连 | 5/5 | **5/5**（未受 B1 影响） |
| sidecar host plan 直连 | 6/6 | **6/6**（未受 B1 影响） |

### 3.1 本次重跑修正了哪些“测不到”

这些是 harness 测量修正，不是产品语义变化：

1. `GET /traces` 只返回 preview，持久化 trace 也不含响应顶层 `interventionMeta`。host 命中在持久化 trace 中的权威签名是 `decision.policyVersion=host-plan:*` + `applied.action=speak` + 非空 `injected`；本次改为读取 `/traces/:id` 全量 trace 后判定。
2. 本地模型冷启动 ~40–46s。旧 harness 用“每 5s 发一条同 cue 用户 turn”轮询，每条 heuristic turn 会先注入一个新鲜片段，几分钟内就把候选耗尽；等本地 plan ready 时只剩 anti-repeat。本次在首轮后等待 60s 再发第二轮，不额外注入，prefetch plan TTL 60s 内消费。报告中的 `prefetchReadyMs≈60.5s` 包含这段有意等待，不是新增产品延迟。
3. outcome 重问必须紧接命中轮；如果先跑 new-cue，上一轮 context 是无关 silent，插件不会产生可归因 outcome。
4. `opencode run` 偶发与刚启动的 server 竞争（本机约 1/5）；harness 对首轮重试，只有真实 exit 0 + sessionID 才算通过。

## 8. 残余风险

1. **host 两轮仍是 `RH+RS+FM`**：plan JSON 由确定性 fake 返回；真实 host 模型质量、prompt 遵循和延迟仍未验证。
2. **OpenChamber 只有 adapter identity**：Desktop UI、独立进程、多实例仍无证据。
3. **本地模型冷启动 ~40–46s**：`/context` 仍 <1.5s，但 prefetch-ready 远超 5s 目标；4B 只能 shadow/后台。
4. **本地模型 reason 是自由文本**：trace 中出现模型解释句；若契约要求稳定 `reasonCode`，需要 provider 层归一化/截断，且不得落 raw 正文。
5. **OpenCode outcome E2E 4 个失败**：与 B1 无关且前后一致；W8 前必须定位。
6. **API/DSH/Hermes 完全未真跑**：不能用 hermetic/stub 结果替代。
7. **模型/引擎来自镜像**：size/SHA 与官方清单一致，但传输不是默认 HF/GitHub 路径；发布证据需在可访问官方源的网络复跑一次。
8. **未提交权重/引擎**：仅保留在用户 cache，仓库无大文件；`evidence.json` 不包含 raw query/detail/token/keyRef。

3. **Hermes**：隔离 profile/home + `plugins.isolation: in_process`，允许安装 companion/provider，或批准一次受控真实运行。
4. **OpenChamber Desktop**：≥2.2 的 OpenChamber 宿主与独立 E2E 条件。
5. **真实 host 模型**：可用的宿主模型/API，用于把 host 两轮从 `RH+RS+FM` 提升到 `R-RSM`。

在这些条件满足前，0.4.0 的 api/auto 与 DSH/Hermes/OpenChamber Desktop 覆盖格不得标记通过；host 两轮只能按 `RH+RS+FM` 记录。
