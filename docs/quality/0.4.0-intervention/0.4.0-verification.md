## 3. 阻断项（blocking）

### B1（产品缺陷，阻断 local/host 两轮）

真实 OpenCode 插件在 `rememberInjected()` 中把 `/context` 返回的**所有 fragments**都加入 `alreadyInjectedIds`，而不是只加入实际注入/应用的片段。结果是：

- 第二轮同 cue 召回时，sidecar 把上一轮所有候选都标成 `filteredReason=already_injected`；
- `candidates.length===0` 后不再进入 model/host planner；
- local 预取和 host session prior 都无法在真实 adapter 上被消费；
- 直接 sidecar HTTP 两轮（不经过插件 dedupe）是 5/5 命中，证明模型与 sidecar 路径本身可用。

证据：

- [`w7/w7-local-opencode.json`](w7/w7-local-opencode.json)：14/16，失败项 `local-hit`；trace 显示后续轮次 `silenceReason=already_injected`、无 `decision.planner`。
- [`w7/w7-host-opencode.json`](w7/w7-host-opencode.json)：13/16，失败项 `host-hit`、`host-hit-source`、`host-new-cue`。
- 原始 trace 的 `candidates[].filteredReason=already_injected` 已在运行目录中核对；未保留用户正文。

**需要的修复（不由 W7 自行改产品语义）**：宿主 adapter 只把实际 `applied`/注入的 source IDs 记入 dedupe；或 sidecar 对 model/host planner 使用独立的“已注入”集合。修复后必须重跑本报告 §2.1/§2.2 的真实宿主两轮，并把 `w7-intervention-evidence.mjs --source local|host` 跑到全绿。该修复属于 W3/W4 契约，需要 owner 和独立评审。

### B2（外部条件：真实 API）

当前没有可用的 `baseUrl/model/keyRef`。本会话没有从 Hermes 配置、环境变量或用户 home 中提取任何凭据，也没有用 fake 补格。

需要用户提供：
- `baseUrl`（OpenAI-compatible，https 或 loopback）
- `model`
- `keyRef` 类型与值：`env:NAME`、`file:/abs/path` 或 `keychain:service/account`
- 是否允许 `allowRemote=true`

提供后运行真实 API smoke，至少覆盖：未触发 fallback 的一次 `api` planner、`allowRemote=false` 拒绝、timeout、invalid JSON、auto→heuristic fallback。

### B3（外部条件：DSH）

本机 `which dsh` 为空，没有可启动的真实 DSH CLI。仓库里的 `dsh-real-runtime.mjs` / DSH hermetic 测试不能替代真实宿主 E2E。

需要：安装可用的 DSH CLI（或提供 `DSH_BIN`），并确认版本能加载 `@mebular/dsh-plugin`；然后跑四来源 + host plan + outcome。

### B4（外部条件：Hermes 真实进程）

Hermes v0.21.7+261.g427d605 已安装，但：

- 一次 `HERMES_HOME=<temp>`、`hermes chat -q ... --oneshot -Q` 在 180s 内没有返回；
- 未建立真实 companion `post_llm_call` + `ctx.llm` 的 host plan，也没有 provider 下一轮消费证据；
- 未验证实际 `plugins.isolation: in_process`（只确认版本 ≥ v0.21.6）。

需要：一个隔离的 Hermes profile/home，允许安装 `mebular-companion` 与 `mebular-memory`，并确认 `plugins.isolation: in_process`；或用户批准在现有 profile 做一次受控 E2E。不得读取 Hermes 私有 session/log/凭据来伪造 plan。

### B5（外部条件：OpenChamber Desktop）

OpenChamber Desktop 未启动；其内置 opencode CLI v2.0.29 低于插件最低 2.2。当前只证明了 adapter identity，不证明 Desktop 独立进程/多实例。

需要：可用且 ≥2.2 的 OpenChamber 宿主，跑独立 identity、两轮 host plan、outcome、多实例隔离。

## 7. 残余风险

1. **B1 adapter dedupe 是发布阻断**：它同时影响 local 和 host 的 session-prior 命中，OpenCode 与 OpenChamber 共用该 adapter。
2. **本地模型冷启动 45s**：虽然 `/context` 仍 <1.5s，但 prefetch-ready 远超 5s 目标；4B 只能 shadow/后台，不能当权威。
3. **本地模型输出 reason 是自由文本**（trace 中 `reason` 出现模型解释句）；如果契约要求稳定枚举 `reasonCode`，需要 provider 层归一化/截断，且不得落 raw 正文。
4. **OpenCode outcome E2E 4 个失败**：可能是 W6 后 policy 统计/reset/note 契约变化，也可能是产品回归；W8 前必须定位。
5. **Hermes/DSH/API 完全未真跑**：不能用现有 hermetic/stub 结果替代。
6. **OpenChamber 只有 adapter identity**：Desktop UI、独立进程、多实例仍无证据。
7. **模型/引擎来自镜像**：size/SHA 与官方清单一致，但传输不是默认 HF/GitHub 路径；报告已显式记录，发布证据需在可访问官方源的网络复跑一次。
8. **未提交权重/引擎**：仅保留在用户 cache，仓库无大文件；`evidence.json` 不包含 raw query/detail/token/keyRef。
