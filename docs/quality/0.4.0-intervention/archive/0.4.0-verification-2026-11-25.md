### 4.1 Shadow 归因（`opencode-intervention-shadow.mjs`）

同一套真实宿主/插件/sidecar/capability，只是 sidecar `intervention.mode=shadow`，
`minConfidence=0.99`、`explorationRate=0`、`maxSilentStreak=99`，让第一轮建议确定性地
沉默，而 baseline 仍注入候选。

| # | 场景 | 真实断言 | 结果 |
|---|---|---|---|
| S0 | 能力位 | `/version` 的 intervention `shadow=true`、`mode=shadow` | 通过 |
| S1 | shadow 决策 vs 实际 | 第一轮 `decision.action=silent`、`enforced=false`、`applied.action=speak`、`applied.wouldAction=silent`、`counts.injected>=1` | 通过 |
| S1b | 决策不等于实际 | `decision.action` 与 `applied.action` 不同（silent vs speak） | 通过 |
| S1c | 本机计数 | policy `spoken>=1` 且 `silent=0`（按 applied 计，不按 shadow 建议） | 通过 |
| S2 | 下一轮重问 | 真实插件上报 `reasked/source=host` | 通过 |
| S2b | 不产生 missed | trace 的 `outcome.kind` 与 `outcomeHistory` 均不含 `missed` | 通过 |
| S2c | outcome 计数 | policy `reasked>=1` 且 `missed=0` | 通过 |

> 这组断言直接覆盖 B1 review fix：如果插件仍按 `decision` 归因，第一轮的 shadow
> `silent` 会被下一轮显式重问记成 `missed`，S2b 会失败。

## 8. 已知限制

1. **0.4.0 未发布。** 默认 `off`；`model` 与按域自适应阈值是 experimental，发布前仍需
   canary / Go-No-Go。
2. **真实模型 smoke 未跑。** 本机无本地模型；E2E 的宿主只使用 fake OpenAI-compatible
   provider，模型 planner 由 `intervention-model*.test.ts` 的 fake gateway 覆盖。因此
   本报告不证明真实模型延迟、质量或 prompt 安全在真实模型上的表现。
3. **E2E 不验证答案质量。** 它验证 decision/outcome 的真实 HTTP 闭环，不评估模型回答是否
   更好；答案质量评估仍需 golden set + judge。
4. **Console 截图是 fixture 证据。** 截图来自 `verify:console:ui` 的 fake sidecar 数据，
   用于 UI 状态；真实 sidecar 的 trace 字段由 §4 单独断言。
5. **归因启发式有噪声。** `reasked/corrected/too_*` 由插件正则和上一轮 decision 推断，
   本报告只证明它按设计触发并落库，不证明长期策略效果。
6. **仅 OpenCode 宿主。** DSH / Hermes 复用同一 outcome API，但 0.4.0 未接；跨设备策略
   同步不在范围内。
7. **性能数字是单机样本。** 非空闲开发机，全量 suite 中有 IO 抖动；性能只作为回归证据，
   不是 SLA。
8. **`off` 不是“零状态”。** `off` 不改变注入，也不应用策略建议或自适应阈值，但仍会把
   baseline 的 applied spoken/silent 计数写进本机 `policy/state.json` 和 trace；
   “零学习”只应理解为“不影响召回行为”，不是“不写统计”。
9. **`must_speak` 是自动策略下限，不是用户显式意图的上限。** 硬规则优先级为
   `defer_explicit` → `conflict` → `greeting/meta` → `must_speak` → `no_candidates` →
   `no_novelty` → heuristic。显式 defer（用户/宿主明确“暂时不要提/先别用记忆”，含
   cue 层 `user_negated`）可以覆盖自动 must_speak，`self`/checkpoint 仍先加载并保留，
   trace 记录 `reason=defer_explicit` / `applied.action=defer`；该输入级 defer 适用于所有
   mode：`off` 记 `v0-baseline` / `enforced:false` 且不产生策略警告，`shadow` 实际注入
   `defer` 而不是 baseline，也不记录 baseline `wouldAction`；conflict 只在“哪个对/
   以哪条为准/该信哪个”且候选带 conflict group 时触发，exact 用 quote、否则 detail，
   仅陈述“不一致/打架”不触发；`no_novelty` 是 anti-repeat 例外，只在全部候选已注入时
   silent，不影响 maxSilentStreak/exploration 对新颖候选的作用。
10. **`must_speak` 不是 100% speak。** 完全没有候选时降级为 checkpoint-only：
   `silent` + `must_speak_unavailable` + `degraded:true`，`self`/checkpoint 仍注入；
   只有有候选时才保证 speak（detail 不可用时降为 gist）。
11. **fragment ID 别名表是进程内的。** `alreadyInjectedIds` 里的旧 `mf_…` 只在同一
    sidecar 进程内可靠解析；sidecar 重启后，重启前产生的 `mf_…` 可能无法命中，宿主级
    去重/novelty 可能退化。source/record ID 始终有效。
12. **Phase 3/4 不是真实模型 Gate。** `model` 与按域自适应阈值只有 fake gateway/单测
    证据；真实模型 smoke、延迟/质量、golden set 与 judge 均未运行，继续标 experimental。
13. **outcome/reset 语义边界。** outcome note 上限统一 200 字符；显式 defer 记录为
    `reason=defer_explicit` / `applied.action=defer`（不是 speak/silent）；reset 只清
    policy 统计与运行态（streak / 上一轮决策 / reset guard），不删记忆、trace 或
    outcome 历史。

## 9. 生产问题（已修复）

0.4.0 E2E 中发现、自 0.3.0 起存在的去重契约不一致，已在 `feat/0.4-dedup-fix`
修复（commit `2c21325`，基于 `feat/0.4-integration@c82969d`）。

- **问题。** OpenCode 插件在 `rememberInjected()` 中把 `/context` 响应的 **fragment
  ID**（`mf_…`）放进 `alreadyInjectedIds`；sidecar 的 `buildCandidates()` 只拿它与
  片段的 **source/record ID**（`sourceIds`）比较，`intervention.ts` 的 `noveltyOf()`
  也只比较 `candidate.sourceIds`。结果是宿主级“已注入”去重/novelty 可能不生效，
  重复 turn 仍会重新召回同一记录（除非其他策略原因造成 silent）。
- **根因。** fragment ID 按 0.3 契约是“本次召回的临时 ID”、每次召回重新生成，因此
  只做字面比较永远无法命中上一轮回传的 `mf_…`。
- **修复。**
  - `buildCandidates()`：`alreadyInjectedIds` 同时匹配 `sourceIds` 与 `fragment.id`；
    另用进程内有界别名表（`fragment ID → source IDs`，最多 4096 条、FIFO 淘汰）
    把宿主回传的旧 `mf_…` 解析为源记录 ID，保证真实插件回传的 fragment ID 能命中。
