# 混合版本政策（C3 · 护栏包⑥）· 一页稿

> **状态**：建议稿（只读审计产出，非现行承诺）。基线 `main@bbc2e13`（协议串 `/mebular/1.0.0`，
> 包版本 `0.1.0`）。**适用对象**：跨设备线协议（握手 `auth-*`、同步 `sync-*`、事件/策略记录的
> 采纳语义、libp2p protocol 串）；不含本地存储格式（`*.sync-state.json` 等自属私有）。

## 1. 兼容承诺（建议）

1. **N-1 双向互操作**：相邻两代版本（N 与 N-1）的任意两端**必须**能完成会话并按本政策第 3 节
   降级规则同步；**跨代（N-2 及更早）不做承诺**——部署纪律要求升级窗口 ≤ 1 个版本步进。
2. **安全方向不劣化**：混合窗口内任何降级都只能是「少收/少同步/显式失败」，**绝不**出现
   「越权/多收/静默错误授权」。默认拒绝、吊销、成员闸门在窗口内均以**保守侧**生效。
3. **同族策略一致**：策略推导（`derivePolicyState`）的输入语义（含 `iterationBound = 2·|entries|+2`）
   属**协议语义**；产生可见差异的语义变更按第 2 节 **B 类**管理。

## 2. 变更分级与发布纪律

| 档 | 定义 | 例子（本仓已发生） | 发布要求 |
|---|---|---|---|
| **A · 加法式** | 旧端**能安全忽略**：新增可选字段 / 新事件类型 / 新记录类型 | `namespace` 可选字段；`sync-offer.snapshot` / `sync-ack.snapshotApplied` 可选字段；`namespace_membership` 新记录类型（旧端忽略 ⇒ legacy-empty）；`authorCertificateChain` 可选字段 | 随时发布；不需要全端同步；旧端降级必须是「少收」。（注意：**新增消息类型**默认不属 A 类——旧端的帧序校验会把未知 type 当协议违例，见 §2 注意事项） |
| **B · 语义式** | 改变**采纳/判定**结果的规则 | 策略推导规则（R-a/R-b 迭代上限）、成员闸门启用条件、令牌/证书校验收紧或放宽 | 发布说明**强制标注**；限「全端同版本族」窗口内生效；必须附混合版本验证（§5）与保守侧论证 |
| **C · 传输式** | 破坏帧序列/编码本身 | 改变 hello 必填字段集；改变内容寻址字段集（`canonicalEventData`）；bump libp2p protocol 串 | 等同 B 类，并要求旧端收到**显式**错误而非静默错位 |

**注意事项（A 类边界）**：`sync-nudge` 是已发生的教训——它本身是「新增消息类型」，对不认识它的
旧端，第一个异常帧就会触发 `Protocol violation: expected sync-hello, got sync-nudge`
（`src/sync/protocol.ts:224-250`）→ 会话中止。**新增消息类型只对「同代或明确支持」的对端安全**；
本政策要求：新消息类型的引入必须评估「旧端把该帧读进既有等待点」的后果，必要时通过版本标识先行、
或在升级窗口内禁用触发方（本项目现状：nudge 已在 main 发布，N-1 窗口内有效；更早版本属于跨代，
不在承诺内）。

## 3. 行为降级规则表（混合窗口内，旧端 ↔ 新端的期望行为）

| 能力 | 新端 → 旧端 | 旧端 → 新端 | 安全方向 | 规则/兜底 |
|---|---|---|---|---|
| 基础会话（hello/offer/ack/done） | 帧集相同，必填字段一致 | 同 | —— | **这是 N-1 承诺的主体** |
| `sync-nudge` | 旧端视为协议违例 → 该轮会话失败 | 不适用 | 少同步（可重试） | 新端不依赖单一 nudge；anti-entropy/重连兜底（升级窗口内接受） |
| 快照（`sync-offer.snapshot`） | 旧端缺快照能力：只发事件流即可（新端对「自报空水位」可直接走事件流；快照是发送方主动选择，**降到事件流即安全**） | 新端收到旧端事件流照常应用 | 少/慢，不劣化安全 | 快照门禁（R2/R3）不放松；发送方在未知对端时**允许**主动不发快照（成本是首同步慢） |
| `namespace_membership`（M1–M3） | 旧端忽略该记录 → 该分区按 legacy-empty 处理 | 新端看到「旧端未启用成员资格」→ 沿用 hello 声明 | 少收（不 fail-open） | 已有政策锚点（`POLICY-INVARIANTS.md` §9）；**全端升级后**严格成员资格自动生效，无需迁移动作 |
| `policy_issuer_declare`（C1） | 旧端忽略 → 该声明不生效（授权可能少） | 同 | 少授权（不越权） | 配置 `policyIssuers` 是旧端兜底路径，窗口内保留 |
| 委派证书链（T2） | 旧端无法验证带链证书的**中继**事件 → 拒绝 | 同 | 少收 | 直连快路径不受影响；窗口内建议委派设备优先直连 |
| 新增事件类型（如 `net_endpoints`） | 旧端：**入日志但不物化**（`apply.ts:97-100`），数据「日志有、图无」 | 同 | 少物化 | 属 A 类可发布；新端应容忍旧端不回传（幂等/重放安全） |
| 反熵/自动签发/推送节奏 | 纯本地行为，对旧端表现为普通会话 | 同 | —— | 节奏参数不是协议 |
| 策略语义变更（B 类） | **扩权方向**（新增授权/放宽闸门）：窗口内不得生效（生效点 = 最后一方升级完成）；**收紧方向**（少授权）可先行 | 同 | 只允许「少授权」 | 发布说明标注 + 窗口 ≤ 1 周 + 附混合验证；扩权类变更要求全端先升级 |

## 4. 升级窗口（建议）

- **窗口长度**：默认 ≤ **7 天**（或 1 个发布周期，取先到者）；强制升级（安全修复）单独公告；
- **升级顺序**：不敏感（root 与 delegated 均可先升）；但 **B 类变更的“生效点”定义为最后一方升级完成**；
- **窗口内操作纪律**：① 不启用依赖新语义的功能（如主张扩权的新 grant 规则）；② 发现混合窗口内
  不可解释的「零同步/反复会话失败」，先按 §3 表核对再排查其他原因；
- **skip-version**：跨代对端被视为**不支持**；doctor/巡检应输出明确告警（当前无版本标识，退化表现为
  随机协议错误——见 §6 建议）。

## 5. 验证义务（当前缺口，移交 C5 跟踪）

每个 B 类或「帧序列相关」的 A 类变更，PR 必须附**混合版本测试计划**。当前仓库**没有任何混合版本
自动化**；最接近的是 `scripts/accept-auto-grant.mjs` ④a「老订阅端行为模拟」（新代码扮演只 hello、
不写 membership 的旧订阅端）。建议的最低可行自动化为：

1. **行为模拟级**（可用现有代码达成）：用一个「旧端适配器」剥离/忽略新字段与新消息（如禁用 nudge、
   禁用快照、不物化新事件类型），跑双向矩阵；
2. **真双版本级**（CI 可选）：两个 git ref 各建一份 dist，跑 `verify-daemon-cluster` 变体；
3. 明细与落点见 `TEST-MATRIX.md` 缺口表 G-3/G-4。

## 6. 建议（未来，非本波实现）

- 在 `sync-hello` 增加**可选**字段 `appVersion`（A 类加法）或 bump libp2p protocol 串，使跨代对端
  从「随机协议错误」变为**显式拒绝 + 可读原因**；在此之前 §4 的 skip-version 只能靠部署纪律；
- `auth-*` 各帧同理（可选 `appVersion`），供握手阶段直接判定跨代。
