# 范围声明：阶段边界（C4 · 护栏包⑦）· 一页建议稿

> **主旨**：《去中心的分布式记忆共享》——**本阶段 = 一人多机**（同一用户、多台设备之间的
> 去中心记忆共享）；**多人共享（多个用户之间）为未来阶段**，本阶段既不做承诺，也不做半成品实现。
> **状态**：建议稿。基线 `main@bbc2e13`；与 `SEALING_CN.md`（红线/协议契约）配套阅读。

## 1. 本阶段承诺（一人多机）

| 维度 | 本阶段口径 | 机制锚点（现状） |
|---|---|---|
| 参与者 | **一个用户**的**多台设备**（root + 委派设备，链到**同一**用户主密钥） | 证书链校验：只有链到该用户主密钥的设备被承认（`SEALING_CN.md` §1.3；`trust.ts`） |
| 共享对象 | 记忆/图（分区 = namespace）、授权（grant）、成员资格、策略声明 | `__policy__` / 用户分区 / `__net__` |
| 信任根 | **用户主密钥**（单根；私钥可完全离线，委派签发不要求指定设备在线） | T2 信任模型（`SEALING_CN.md` §1.3） |
| 一致性 | 共同授权域内最终收敛；水位 per-(对端, 分区, 作者) | `SEALING_CN.md` §2 |
| 拓扑 | 无中心、设备直连；跨网经 relay（传输不构成权威） | `SEALING_CN.md` §1.1/1.6 |

**验收对齐**：计划中「三机预演」= 同一用户的三台设备（含至少一台委派设备）——落在本阶段范围之内。

## 2. 明确的阶段外（本阶段不做、不承诺）

1. **多人共享**：多个用户（各自持不同用户主密钥）之间的记忆共享、联邦或协作空间。
2. **跨用户信任**：B 用户的设备凭 A 用户主密钥之外的根接入 A 的数据；今天这类设备**无法完成
   可信验签**——别家主密钥签的记录在校验阶段被忽略（`POLICY-INVARIANTS.md` §1「伪造」行；
   `LIMITATIONS_CN.md` §2「跨机信任仍需一条链到用户主密钥的证书链」）。
3. **命名空间的多租户归属**：不存在「namespace 属于谁」的跨用户语义；授权是**用户内**设备级白名单。
4. **跨用户吊销/恢复语义**：`device_revoke`、成员注销、交接等全部定义在单用户 Fleet 内。
5. **面向多租户的隐私边界**：`__policy__` 对**本用户全部已认证设备**（含被吊销者）可读，是单用户
   模型内的**有意取舍**（bootstrap/恢复所需，`SEALING_CN.md` §1.7）；该取舍**不适用于**跨用户场景，
   多人阶段必须先重新设计可见性。
6. **多用户场景的滥用/配额治理**：跨用户 DoS、配额、审计入口均不在本阶段。
7. **单域收回的粒度（语义收窄，产品确认接受）**：不存在「这台设备别看 notes、但还能看 work」
   的**单域收回**——收回信任的最小粒度 = **整台屏蔽该设备**（设备级 `device_revoke`；
   `namespace_revoke` 保留为 CLI/审计层能力，GUI 不提供）。恢复 = 重新邀请兑换（入网信任
   一次性建立、不逐域重审）。单用户设备群模型下（网内 = 用户的设备）接受该收窄。
   （2026-10-16 产品确认；依据：MEMSHARE-CLOSEOUT 决策 3 / core 落差评审 落差 5。）

## 3. 为什么现在可以安全地“不承诺多人”

- **默认拒绝**：未授权 = 不流动（`SEALING_CN.md` §1.5）；成员闸门叠加在上（M1–M3）。
- **信任过滤单向收敛**：只有本用户主密钥链的设备可被采纳；伪造成本=主密钥泄露。因此系统
  **不会意外地变成多人共享**——两个用户的 Fleet 即使物理连通，也只会互不可见（各自 `[]`）。
- **协议面没有半成品**：不存在“为多人预留但未定义”的线上字段；`__policy__` 的可见性取舍、
  成员/交接语义全部是单用户闭环（`SEALING_CN.md` §3「破坏性协议变更」清单）。

## 4. 未来阶段的入口条件（设计前置清单，未开工）

多人共享立项前，至少需要先回答（每一项都可能改变协议语义，需按 C3 的 B 类管理）：

1. **跨根信任模型**：用户之间如何互认（互白名单主密钥？信任中介？）与撤销。
2. **命名空间归属与租户**：namespace 的所有者、邀请、转让、退出时的数据处置（复用 2b/2c 的经验）。
3. **可见性边界重估**：`__policy__`（含授权图）在跨用户下是否可见、可见粒度。
4. **跨用户吊销连坐与恢复**：R-b/R-d 语义的跨根推广，防「以撤销为武器的拒绝服务」。
5. **配额/防滥用/审计**：跨用户量的边界与可追责性。
6. **混合版本前提**：进入多人阶段时，C3 的版本标识（明文版本字段）应先落地（否则跨代问题放大）。

## 5. 对外表述口径（建议，用于 README / 发布说明）

- ✅ 可以说：「同一用户的设备之间，去中心地共享记忆；授权、吊销、成员与策略都在图上，可审计。」
- ⛔ 避免暗示：「任意几台设备（不同的人）加入同一个域即可共享」——本阶段**不是**多人共享产品。
- ⚠️ 涉及 `__policy__` 可见性时，注明「对**同一用户**已入网设备可见」单用户前提。
